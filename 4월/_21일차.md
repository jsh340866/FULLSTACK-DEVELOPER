## 1. Object 클래스 (`JAVA03/Ch01/C01ObjectMain`)

### ❗ 문제
객체를 출력하면 왜 주소값 형태로 나올까?


### ✔ 코드

```java
class A {
    int x;
    int y;

    @Override
    public String toString() {
        return "A [x=" + x + ", y=" + y + "]";
    }
}
```

### ⭐ 중요

* 모든 클래스는 Object를 상속
* toString() 기본 → 클래스명@주소값
* 재정의 → 객체 정보 출력 가능

---
  
### 2. equals() / hashCode() (`JAVA03/Ch01/C02EqualsMain`)

### ❗ 문제

값이 같은데 왜 비교하면 false일까?

### ✔ 코드
```java
@Override
public boolean equals(Object obj) {
    if(obj instanceof C02Simple) {
        C02Simple down = (C02Simple)obj;
        return down.n == this.n;
    }
    return false;
}
```

### ⭐ 중요

* 기본 equals → 주소 비교
* 재정의 equals → 값 비교
* equals 재정의 시 hashCode도 함께 고려

  
### 3. Exception (예외 처리) (`JAVA03/Ch02/C01NullPointerExceptionMain`)

### ❗ 문제

프로그램이 갑자기 종료되는 이유는?

### ✔ 코드
```java
try {
    String str = null;
    str.toString();
} catch(NullPointerException e) {
    e.printStackTrace();
}
```

### ⭐ 중요
* 예외 발생 시 프로그램 종료 가능
* try-catch로 흐름 유지
* Exception 하나로 전체 처리 가능 (권장 X)

### 4. 업캐스팅 / 다운캐스팅 (`JAVA03/Ch02/C02ClassCastExceptionMain`)

### ❗ 문제

왜 캐스팅하다가 에러가 날까?

### ✔ 코드

```java
Animal poppy = new Dog(); // 업캐스팅
Dog down = (Dog)poppy;   // 다운캐스팅
```

### ⭐ 중요
* 업캐스팅 → 자동, 안전
* 다운캐스팅 → 강제, 위험
* 실제 객체 타입 기준으로 동작

### 5. Generic (제네릭) (`JAVA03/Ch03/C01GenericMain`)
### ❗ 문제

타입마다 클래스를 계속 만들어야 할까?

```java
✔ 코드
class 호빵<T extends 호빵재료> {
    private T 재료;
}
```

### ⭐ 중요
* `<T>` → 타입을 외부에서 결정
* `<T extends 클래스>` → 타입 제한
* 타입 안정성 + 코드 재사용

---

### 6. 제네릭 메서드 (`JAVA03/Ch03/C02GenericMethodMain`)

```java
public static <T extends Animal> void PrintGeneric(T[] arr)
```

### ⭐ 중요
* 메서드 단위 제네릭 가능
* 다양한 타입 처리 가능

### 7. Generic 심화 문제 (`JAVA03/Ch03/C06Ex`)


### ✔ 코드

```java
class Box<T> {
    T item;

    void setItem(T item) {
        this.item = item;
    }

    T getItem() {
        return item;
    }
}
```

### ✔ 문제

```java
Box<Object> b = new Box<String>();
Box<Object> b = (Object) new Box<String>();
new Box<String>().setItem(new Object());
new Box<String>().setItem("ABC");
```

### ✔ 정답
* a → ❌
* b → ❌
* c → ❌
* d → ⭕

### ⭐ 중요
* 제네릭 타입은 서로 다른 타입으로 취급
* 타입 불일치 시 컴파일 오류 발생

### 9. 와일드카드 (`JAVA03/Ch03/C03WildcardMain`)

```java
Box<?> b = new Box<Object>();
Box<Object> b = new Box<Fruit>();
Box<? extends Fruit> b = new Box<Apple>();
```

### ✔ 정답
* d → ❌
* g → ❌

### ⭐ 중요
* `<?>` → 모든 타입
* `<? extends T>` → T 또는 자식
* 생성자에는 와일드카드 사용 불가

---

### 10. 제네릭 메서드 변환 (`JAVA03/Ch03/C04GenericMethodMergeMain`)

```java
public static <T extends Product> ArrayList<T> merge(
    ArrayList<T> list, ArrayList<T> list2) {

    ArrayList<T> newList = new ArrayList<>(list);
    newList.addAll(list2);
    return newList;
}
```

### ⭐ 중요
* 제네릭 → 읽기 + 쓰기 가능
* 와일드카드 → 제한적 사용

## 오늘 핵심 정리
* Object → 모든 클래스의 부모
* equals → 값 비교 핵심
* Exception → 프로그램 안정성
* Casting → 타입 변환 주의
* Generic → 재사용 + 타입 안정성
* Wildcard → 유연한 타입 처리

## 한 줄 요약

> Java는 Object, Exception, Generic을 기반으로 안정성과 재사용성을 확보하며, 제네릭에서는 타입 일치 여부가 핵심이다.
