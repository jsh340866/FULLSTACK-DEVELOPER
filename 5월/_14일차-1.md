# 2026-05-22 Servlet 전체 흐름 요약 정리

## 오늘자 주요 태그

`#Servlet` `#JSP` `#MVC패턴` `#Forward` `#Redirect` `#Session` `#DAO` `#DTO`

## 오늘 배운 것

이번 프로젝트는 Servlet과 JSP를 연결해서 회원가입 / 로그인 / 로그아웃 흐름을 만드는 구조이다.

코드 하나하나의 문법보다는 전체적인 웹 흐름을 이해하는 것이 핵심이며,
브라우저 요청 → Servlet 처리 → DAO DB 접근 → JSP 화면 출력 구조로 이어진다.

---

# 전체 프로젝트 흐름

## 1. 사용자가 URL 요청

사용자가 브라우저에서 특정 주소를 요청한다.

예시:

* `/main.do`
* `/join.do`
* `/login.do`
* `/logout.do`

이 요청은 Servlet이 먼저 받는다.

즉:

```text
브라우저 → Servlet
```

구조로 시작된다.

---

## 2. Servlet이 요청 처리

Servlet은 중간 관리자 역할을 한다.

Servlet에서 하는 일:

* 사용자의 요청 받기
* 입력값 확인
* DB 작업 요청
* JSP로 결과 전달
* 페이지 이동 처리

즉 MVC 구조에서 Controller 역할이다.

```text
사용자 요청
   ↓
Servlet(Controller)
   ↓
DAO 호출
   ↓
DB 처리
   ↓
JSP 화면 출력
```

---

# 파일별 흐름 정리

## 1. 서블릿 생명주기 확인 (`Servlet/C01Servlet_Test.java`)

이 파일은 Servlet이 어떻게 동작하는지 확인하기 위한 테스트용 코드이다.

흐름:

```text
서버 최초 실행
→ init()

사용자 요청 발생
→ service()

서버 종료 또는 코드 변경
→ destroy()
```

핵심:

* init() : 최초 1번 실행
* service() : 요청마다 실행
* destroy() : 종료 직전 실행

즉 Servlet은 객체를 계속 새로 만드는 것이 아니라,
처음 생성 후 계속 재사용한다.

---

## 2. web.xml 서블릿 등록 (`WEB-INF/web.xml`)

web.xml은 Servlet 연결 설정 파일이다.

여기서:

```text
URL 요청 → 어떤 Servlet이 처리할지
```

매핑한다.

예시:

```text
/TEST_02 요청
→ C02Servlet_Test 실행
```

또한 시작 페이지도 지정한다.

```xml
<welcome-file>main.do</welcome-file>
```

즉 프로젝트 실행 시:

```text
main.do 자동 실행
→ C03Servlet_Test 동작
```

흐름이 된다.

---

## 3. 메인 페이지 이동 (`Servlet/C03Servlet_Test.java`)

사용자가 `main.do` 요청 시 동작한다.

흐름:

```text
브라우저 요청
→ C03Servlet_Test
→ main.jsp forward
→ 화면 출력
```

여기서 중요한 것은 `forward` 이다.

### forward 특징

```text
Servlet 내부에서 JSP로 넘김
주소 유지됨
```

즉:

```text
main.do 주소 그대로
→ main.jsp 실행
```

된다.

MVC 구조에서 가장 많이 사용하는 방식이다.

# 회원가입 흐름

## 4. 회원가입 페이지 이동 (`Servlet/C04Servlet_Test.java`)

### GET 요청 흐름

사용자가 회원가입 페이지 접근:

```text
/join.do 요청
→ doGet()
→ join.jsp forward
→ 회원가입 화면 출력
```

즉 GET은 보통:

```text
화면 열기
```

역할이다.

---

## 5. 회원가입 처리 흐름

### POST 요청 흐름

회원가입 버튼 클릭:

```text
사용자 입력
→ doPost()
→ DTO 저장
→ 유효성 검사
→ DAO DB 저장
→ 결과 처리
```

세부 흐름:

```text
1. 사용자가 form 입력
2. BeanUtils로 DTO 자동 저장
3. 입력값 검증
4. UserDAO.insert() 호출
5. DB 저장
6. 성공 시 login.do 이동
```

---

## DTO 역할

`UserDTO`는 사용자 데이터를 저장하는 객체이다.

즉:

```text
아이디
비밀번호
이름
전화번호
이메일
```

같은 데이터를 한 번에 묶어서 전달한다.

구조:

```text
Servlet ↔ DTO ↔ DAO
```

DTO는 데이터를 운반하는 역할이다.

---

## DAO 역할

`UserDAO`는 실제 DB 작업 담당 객체이다.

역할:

* INSERT
* SELECT
* UPDATE
* DELETE

즉 SQL 실행 전담 클래스이다.

흐름:

```text
Servlet
→ DAO 호출
→ DB 접근
→ 결과 반환
```

이렇게 역할을 분리해서 유지보수를 쉽게 만든다.

---

## 회원가입 성공 흐름

회원가입 성공 시:

```text
resp.sendRedirect("/login.do")
```

실행된다.

### redirect 특징

```text
브라우저에게 다시 요청하라고 시킴
주소 변경됨
```

즉:

```text
/join.do
→ /login.do
```

주소 자체가 바뀐다.

## 7. 로그인 처리 흐름

### POST 요청

로그인 버튼 클릭:

```text
사용자 입력
→ AuthDTO 저장
→ 유효성 검사
→ DB 조회
→ 비밀번호 확인
→ 세션 저장
→ 메인 이동
```

---

## 로그인 인증 흐름

```text
1. 아이디 조회
2. 사용자 존재 여부 확인
3. 비밀번호 비교
4. 세션에 로그인 정보 저장
5. main.do 이동
```

여기서 가장 중요한 개념은 Session이다.

---

# Session 흐름

## 세션 역할

로그인 상태 유지용 저장공간이다.

로그인 성공 시:

```java
session.setAttribute("isAuth", true);
```

실행된다.

즉 서버가:

```text
"이 사용자는 로그인 완료"
```

상태를 기억한다.

---

## 권한(Role) 처리

admin 계정이면:

```text
ROLE_ADMIN
```

일반 사용자는:

```text
ROLE_USER
```

저장한다.

즉:

```text
관리자 / 일반사용자 구분
```

가능해진다.

---

## 세션 유지시간

```java
session.setMaxInactiveInterval(60);
```

의미:

```text
60초 동안 요청 없으면 자동 로그아웃
```

이다.

# 전체 MVC 흐름 최종 정리

## 회원가입 흐름

```text
브라우저
→ join.do 요청
→ Servlet
→ DTO 저장
→ DAO
→ DB INSERT
→ redirect(login.do)
→ login.jsp
```

---

## 로그인 흐름

```text
브라우저
→ login.do 요청
→ Servlet
→ DAO 조회
→ 비밀번호 확인
→ Session 저장
→ redirect(main.do)
→ main.jsp
```

---

## 로그아웃 흐름

```text
브라우저
→ logout.do 요청
→ Session 제거
→ main.jsp 이동
```

---

# 오늘 핵심 정리

* Servlet은 Controller 역할 수행
* JSP는 화면(View) 출력 담당
* DAO는 DB 처리 담당
* DTO는 데이터 전달 객체
* forward는 내부 이동
* redirect는 재요청 방식
* Session은 로그인 상태 유지
* MVC 구조로 역할 분리
