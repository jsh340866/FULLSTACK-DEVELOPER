## 오늘 배운 것

이번 학습에서는 Servlet 기반 웹 프로젝트에서

* Filter

가 전체 웹 흐름에서 어떤 역할을 수행하는지 중심으로 학습했다.


를 중심으로 정리했다.

## 1. Filter 처리 흐름 (`04_FILTER/Filter/C01UTF8Filter`)

### 설명

Filter는 사용자의 요청이 Servlet에 도착하기 전에 먼저 실행되는 전처리 기능이다.

즉:

```text
브라우저 요청
→ Filter
→ Servlet
```

순서로 동작한다.

Servlet마다 공통 코드를 반복 작성하지 않기 위해 사용한다.

대표 역할:

* 로그인 인증 검사
* UTF-8 인코딩 처리
* 관리자 권한 체크
* 요청/응답 공통 처리

등이다.

---

### 전체 흐름

```text
사용자 요청
→ Filter 실행
→ 조건 검사
→ 통과 시 Servlet 실행
→ JSP 응답
```

즉 Filter는:

```text
웹 요청의 중간 검문소
```

주요 코드 흐름:

```java
chain.doFilter(request, response);
```

→ 다음 Servlet 또는 Filter로 요청 전달

역할을 수행한다.

---

### 핵심 정리

* Servlet 이전 단계에서 실행
* 공통 작업 중앙 처리 가능
* 인증 및 권한 검사에 자주 사용
* MVC 구조에서 Controller 앞단 역할 수행

---

## 2. Listener 처리 흐름 (`04_LISTENER/Listener/C01ServletContextListener`)

### 설명

Listener는 특정 이벤트가 발생했을 때 자동으로 실행되는 감지 기능이다.

즉:

```text
이벤트 발생
→ Listener 자동 실행
```

구조이다.

사용 예시:

* 서버 시작
* 서버 종료
* Session 생성
* Session 제거
* 사용자 접속 감지

등이다.

---

### 전체 흐름

```text
웹 서버 실행
→ Listener 감지
→ 초기 설정 수행
```

또는:

```text
사용자 로그인
→ Session 생성
→ Listener 감지
→ 접속 상태 처리
```

형태로 동작한다.

---

### ServletContextListener 흐름

프로젝트 시작 시:

```text
Tomcat 실행
→ Listener 실행
→ DB 연결 정보 준비
→ 프로젝트 초기화
```

처리가 수행된다.

즉 프로젝트 전역 설정을 담당하는 역할이다.

주요 코드 흐름:

```java
public void contextInitialized(ServletContextEvent sce)
```

→ 서버 시작 시 자동 실행

---

### HttpSessionListener 흐름

```text
사용자 로그인
→ Session 생성
→ Listener 감지
→ 사용자 수 증가
```

```text
로그아웃 또는 세션 만료
→ Session 제거
→ 사용자 수 감소
```

형태로 접속 상태를 관리할 수 있다.

---

### 핵심 정리

* Listener는 이벤트 감지 전용 기능
* 서버 시작/종료 처리 가능
* Session 생성/삭제 감지 가능
* 프로젝트 초기화 작업에 자주 사용
* 사용자 접속 상태 관리 가능

---

## 3. Resource 처리 흐름 (`05_RESOURCE/Resource/C01DataSource`)

### 설명

Resource는 프로젝트에서 공통으로 사용하는 자원(DB 연결 정보 등)을 관리하는 구조이다.

대표적으로:

```text
DB Connection
DataSource
환경설정 정보
```

등을 관리한다.

---

### 기존 방식 문제점

기존에는:

```text
Servlet마다 직접 DB 연결 생성
```

방식을 사용했다.

문제점:

* 속도 저하
* 자원 낭비
* 코드 중복 증가

가 발생한다.

---

## DataSource 기반 흐름

Resource를 사용하면:

```text
서버가 미리 DB 연결 준비
→ Servlet이 필요할 때 가져다 사용
```

구조가 된다.

흐름:

```text
Tomcat
→ Resource 생성
→ Connection Pool 준비
→ Servlet 요청
→ DB Connection 사용
→ 반환
```

즉 DB 연결을 효율적으로 재사용하는 방식이다.

주요 코드 흐름:

```java
DataSource ds = (DataSource)ctx.lookup(...);
Connection conn = ds.getConnection();
```

→ Connection Pool에서 DB 연결 가져오기

---

### Connection Pool 흐름

```text
DB 연결 미리 생성
→ Pool 저장
→ 요청 시 꺼내 사용
→ 사용 후 다시 반환
```

형태로 동작한다.

즉 매번 새로 DB 연결을 만들지 않기 때문에:

* 속도 향상
* 서버 부하 감소
* 자원 효율 증가

효과를 얻을 수 있다.

---

### 핵심 정리

* Resource는 공통 자원 관리 구조
* DataSource로 DB 연결 재사용 가능
* Connection Pool로 성능 향상
* 유지보수성과 효율성 증가
* 실무 웹 프로젝트에서 필수 구조

---

# 전체 웹 흐름 최종 정리

```text
브라우저 요청
→ Filter(전처리)
→ Servlet(Controller)
→ DAO(DB 처리)
→ Resource(Connection Pool)
→ DB 처리
→ JSP(View)
→ 응답 반환
```

추가적으로:

```text
서버 시작/종료
세션 생성/삭제
```

이벤트는 Listener가 감지하여 처리한다.

즉:

* Filter = 요청 제어
* Listener = 이벤트 감지
* Resource = 공통 자원 관리

역할로 서로 연결되어 동작하는 구조이다.

---

## 오늘 핵심 정리

* Filter는 요청 전처리 담당
* Listener는 이벤트 감지 담당
* Resource는 DB 자원 관리 담당
* MVC 구조에서 역할이 분리되어 동작
* Connection Pool로 성능 향상 가능
* Session 기반 사용자 상태 관리 가능
* 웹 프로젝트의 전체 요청 흐름 이해

---

## 한 줄 요약

> Filter, Listener, Resource 구조를 통해 웹 요청 제어, 이벤트 감지, DB 자원 관리가 MVC 기반 웹 프로젝트에서 어떻게 연결되어 동작하는지 전체 흐름 중심으로 학습했다.
