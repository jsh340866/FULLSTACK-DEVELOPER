- JDBC 기반 시스템 간 인터페이스 구조 이해
- SEND → RECV → MONITOR 전체 흐름
- Outbox / Inbox 패턴 기반 데이터 연동

## 1. 프로젝트 전체 구조 (`EX 프로젝트 전체`)

### 설명

이번 프로젝트는 단순 CRUD 예제가 아니라 **인사(HRM) 시스템과 그룹웨어 시스템 연동 구조**를 JDBC로 구현한 프로젝트입니다.

전체 흐름은 다음과 같습니다.

```text
입사 등록
↓
Employee 저장
↓
Outbox 생성
↓
Batch 실행
↓
Account 생성
↓
Inbox 결과 기록
↓
Monitor 조회 / 재시도
```

핵심은 **DB 직접 공유가 아니라 인터페이스 테이블을 통한 데이터 송수신** 구조입니다.

---

### 실제 코드

프로젝트 패키지 구조:

```text
common
send
recv
monitor
```

흐름 중심 구조:

```java
send  → Employee + Outbox 생성
recv  → Outbox 읽기 + Account 생성
monitor → 상태조회 + 재처리
```

---

### 핵심 정리

- send = 데이터 송신 준비
- recv = 데이터 수신 처리
- monitor = 운영 관리 및 재시도

---

## 2. 송신 영역(SEND) (`src/send`)

### 설명

SEND는 **HRM 입사 등록 시스템 역할**을 담당합니다.

사용자가 사원을 등록하면 employee 테이블 저장 후, 실제 연동을 위한 **송신 데이터(if_outbox)** 까지 함께 생성합니다.

흐름:

```text
사용자 등록 요청
↓
Employee 생성
↓
Employee 저장
↓
JSON payload 생성
↓
if_outbox 생성
↓
Batch 대기
```

즉, 아직 계정은 생성되지 않고 **"보낼 데이터만 준비하는 단계"** 입니다.

---

### 실제 코드

Servlet 요청 처리:

```java
@WebServlet("/send/emp")
protected void doPost(...)
```

사원 객체 생성:

```java
Employee emp =
    new Employee(empNo,name,dept,...);
```

DAO 저장 처리:

```java
employeeDAO.createEmployeeWithOutbox(emp);
```

트랜잭션 시작:

```java
conn.setAutoCommit(false);
```

JSON payload 생성:

```java
JsonUtil.toJson(payload)
```

Outbox 생성:

```java
INSERT INTO if_outbox(...)
VALUES(...)
```

트랜잭션 완료:

```java
conn.commit();
```

---

### 핵심 정리

- 입사 등록 수행
- Employee 저장
- JSON 데이터 생성
- Outbox 생성
- 트랜잭션 기반 처리

---

## 3. 수신 영역(RECV / Batch 처리) (`src/recv`)

### 설명

RECV는 **그룹웨어 수신/배치 처리 영역**입니다.

SEND가 생성해둔 Outbox 데이터를 읽어서 실제 업무 데이터(Account)로 반영합니다.

흐름:

```text
미처리 Outbox 조회
↓
payload 조회
↓
JSON 파싱
↓
Account 생성
↓
Inbox 결과 기록
↓
상태 업데이트
```

성공/실패 처리도 여기서 수행됩니다.

---

### 실제 코드

배치 실행:

```java
@WebServlet("/recv/batch")
```

미처리건 조회:

```java
outboxDAO.fetchPending(limit)
```

JSON 역직렬화:

```java
JsonUtil.fromJson(payload)
```

계정 생성:

```java
accountDAO.insertAccount(...)
```

수신 결과 저장:

```java
inboxDAO.insertInbox(...)
```

성공 처리:

```java
outboxDAO.markSuccess(id)
```

실패 처리:

```java
outboxDAO.markFailure(id,msg)
```

---

### 핵심 정리

- Batch 수행
- Outbox 수신
- Account 생성
- Inbox 기록
- 성공/실패 분기 처리

---

## 4. 모니터링(MONITOR) (`src/monitor`)

### 설명

MONITOR는 **인터페이스 운영 관리 영역**입니다.

연동 시스템에서는 실패 건이 발생할 수 있으므로 **상태조회 + 재처리 기능**이 중요합니다.

흐름:

```text
Outbox 조회
↓
Inbox 조회
↓
Account 조회
↓
실패건 재오픈
```

운영자가 전체 인터페이스 상태를 관리하는 영역입니다.

---

### 실제 코드

모니터링 조회:

```java
@WebServlet("/monitor/list")
```

상태 조회:

```java
outboxDAO.listAll()
inboxDAO.listAll()
accountDAO.listAccounts()
```

JSP 전달:

```java
request.setAttribute(...)
```

재시도 처리:

```java
@WebServlet("/monitor/retry")
```

실패건 재오픈:

```java
outboxDAO.reopen(id)
```

Retry 증가:

```java
retry_cnt = retry_cnt + 1
```

---

### 핵심 정리

- 인터페이스 상태 조회
- 성공/실패 관리
- 재처리 지원
- Retry 관리

---

모든 모듈의 기반 역할을 수행합니다.

## 6. 인터페이스 테이블 구조 (`DB Schema`)

### 설명

이번 프로젝트 핵심은 **Outbox / Inbox 인터페이스 테이블 구조**입니다.

송신측 구조:

```text
employee
↓
if_outbox
```

수신측 구조:

```text
account
↓
account_history
↓
if_inbox
```

employee / account 는 실제 업무 데이터이고,

if_outbox / if_inbox 는 **시스템 간 연동 데이터 관리용 테이블**입니다.

---

### 실제 코드

Outbox 상태:

```sql
N = 미처리
S = 성공
F = 실패
```

Retry 관리:

```sql
retry_cnt
```

상태 변경:

```java
markSuccess(...)
markFailure(...)
reopen(...)
```

---

### 핵심 정리

- Outbox = 송신 대기
- Inbox = 수신 결과
- Account = 실제 업무 데이터
- Retry = 실패 재시도 관리

---

## 오늘 핵심 정리

이번 프로젝트는 **JDBC CRUD 학습보다 시스템 인터페이스 구조 이해**에 초점이 있는 프로젝트였습니다.

핵심 흐름:

```text
SEND
(Employee + Outbox 생성)
↓
RECV
(Batch + Account 생성)
↓
MONITOR
(조회 + 재시도)
```

Outbox / Inbox 패턴과 Batch 처리 개념이 중심입니다.
