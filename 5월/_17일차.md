## 1. Spring Boot 프로젝트 초기 구성 (`01_INIT`)

### 설명

Spring Boot 프로젝트의 기본 MVC 실행 구조를 학습했습니다.

흐름은 다음과 같습니다.

```txt
사용자 요청
 ↓
Controller
 ↓
View 반환
 ↓
JSP 렌더링
```

Spring Boot에서는 `Application` 클래스가 실행 시작점이 되고, Controller가 요청을 처리한 뒤 View 이름을 반환합니다.

### 실제 코드

#### HomeController

```java
@Controller
@Slf4j
public class HomeController {

    @GetMapping("/")
    public String home() {

        log.info("GET /");

        return "index";
    }
}
```

### 예상 출력

```txt
GET /
```

브라우저 접속 시 `index.jsp` 출력

### 핵심 정리

- `@Controller` → 요청 처리 담당
- `@GetMapping` → GET 요청 매핑
- 문자열 반환값 = View 이름
- Spring MVC 기본 흐름 이해

## 2. Lombok + DI 구성 (`02_LOMBOK_DI`)

### 설명

반복적인 DTO 코드를 Lombok으로 자동 생성하고, Spring Bean 등록 및 DI 개념을 학습했습니다.

Spring Container가 객체를 생성·관리하며, 필요한 위치에 주입하는 구조를 이해하는 단계였습니다.

Bean 등록 방식은 크게 두 가지를 사용했습니다.

- `@Component`
- `@Configuration + @Bean`

### 실제 코드

#### DTO + Lombok

`02_LOMBOK_DI/src/main/java/.../PersonDTO.java`

```java
@Data
@AllArgsConstructor
@NoArgsConstructor
@Builder
@Component
public class PersonDTO {

    private String name;
    private int age;
    private String addr;
}
```

#### Bean 등록

`02_LOMBOK_DI/src/main/java/.../PersonConfig.java`

```java
@Bean
public PersonDTO personBean01(){

    return PersonDTO.builder()
            .name("김범수")
            .age(50)
            .addr("인천")
            .build();
}
```

### 예상 출력

Spring Container 내부 Bean 생성

```txt
PersonDTO Bean 등록
PersonConfig Bean 등록
```

### 핵심 정리

- `@Data` → Getter / Setter 자동 생성
- `@Builder` → 객체 생성 간소화
- `@Component` → 클래스 Bean 등록
- `@Bean` → 메서드 반환 객체 등록
- DI → 객체 생성/주입 자동화

## 3. 요청 파라미터 처리 (`03_PARAM`)

### 설명

Spring MVC에서 **클라이언트 요청 데이터를 Controller가 받는 여러 방식**을 학습했습니다.

사용자의 입력값은 URL, Form, QueryString 형태로 전달되며, Spring은 이를 자동으로 변수 또는 객체에 바인딩합니다.

전체 흐름은 다음과 같습니다.

```txt
사용자 입력
 ↓
HTTP Request
 ↓
Controller
 ↓
Parameter Binding
 ↓
View 반환
```

---

## 3-1. 기본 요청 매핑 구조 (`03_PARAM`)

### 설명

Controller 내부에서 공통 URL 경로를 지정하고, 각 메서드별 요청을 분기했습니다.

### 실제 코드

```java
@Controller
@RequestMapping("/param")
public class ParamController {
```

```java
@GetMapping("/p01")
```

최종 요청 주소

```txt
/param/p01
```

### 핵심 정리

- `@RequestMapping` → 공통 URL 설정
- `@GetMapping` → GET 요청 처리
- 클래스 URL + 메서드 URL 조합

---

## 3-2. 단일 파라미터 수신 (`03_PARAM`)

### 설명

URL로 전달된 값을 Controller 매개변수로 직접 받는 방식입니다.

Spring이 요청 데이터를 자동으로 매핑합니다.

### 실제 코드

```java
@GetMapping("/p01")
public String paramHandler_1(

    @RequestParam(required=false)
    String name
){

    log.info(name);

    return "param/page01";
}
```

요청 예시

```txt
GET /param/p01?name=hong
```

### 예상 출력

```txt
hong
```

### 핵심 정리

- `@RequestParam` → 요청 데이터 수신
- 변수명 기준 자동 매핑
- `required=false` → 값 누락 허용

---

## 3-3. 다중 파라미터 처리 (`03_PARAM`)

### 설명

웹 요청에서는 여러 데이터를 동시에 전달하는 경우가 많습니다.

Spring은 각각의 요청 데이터를 개별적으로 자동 바인딩합니다.

### 실제 코드

```java
@GetMapping("/p02")
public String handler(

    @RequestParam String userid,
    @RequestParam String password
){
```

요청 예시

```txt
GET /param/p02?userid=admin&password=1234
```

### 핵심 정리

- 다중 Parameter 처리 가능
- 이름 기준 자동 매핑
- Form 데이터 처리 기본 구조

---

## 3-4. DTO(Parameter Object) 바인딩 (`03_PARAM`)

### 설명

파라미터 개수가 많아지면 매개변수 관리가 어려워집니다.

Spring은 DTO 객체를 사용해 요청 데이터를 한 번에 매핑할 수 있습니다.

### 실제 코드

```java
public String handler(PersonDto dto)
```

요청 예시

```txt
/param/p03?name=홍길동&age=20&addr=서울
```

자동 바인딩 결과

```txt
dto.name
dto.age
dto.addr
```

### 핵심 정리

- DTO 자동 바인딩 지원
- 필드명 = Parameter명
- 실무에서 자주 사용하는 방식

## 3-5. Model 데이터 전달 (`03_PARAM`)

### 설명

Controller에서 처리한 데이터를 View(JSP)로 전달할 때 `Model` 객체를 사용했습니다.

### 실제 코드

```java
model.addAttribute(
    "name",
    "홍길동"
);
```

JSP 접근

```jsp
${name}
```

### 데이터 흐름

```txt
Controller
 ↓
Model 저장
 ↓
View 전달
 ↓
JSP 출력
```

### 핵심 정리

- `Model` → Controller → View 데이터 전달
- `addAttribute()` 사용
- JSP EL 표현식 접근

## 3-6. Redirect / Forward 흐름 (`03_PARAM`)

### 설명

Spring MVC의 요청 이동 방식인 **Forward** 와 **Redirect** 차이를 학습했습니다.

#### Forward

서버 내부 이동

```txt
Controller
 ↓
Forward
 ↓
View
```

URL 변경 없음

#### Redirect

새 요청 발생

```txt
Controller
 ↓
Redirect 응답
 ↓
브라우저 재요청
 ↓
새 URL 이동
```

URL 변경 발생

### 실제 코드

```java
return "forward:/param/p04";
```

```java
return "redirect:/param/p05";
```

### 핵심 정리

- Forward → 내부 이동 / 요청 유지
- Redirect → 재요청 발생
- Redirect → URL 변경
- 로그인 처리에서 자주 사용

## 오늘 핵심 정리

Spring Boot MVC 구조는 다음 순서로 동작합니다.

```txt
사용자 요청
 ↓
Controller
 ↓
Parameter Binding
 ↓
Model/View 처리
 ↓
JSP 렌더링
```

또한 Spring Container가 Bean 객체를 생성·관리하며, Lombok으로 DTO 작성량을 줄일 수 있습니다.

`03_PARAM` 챕터에서는 단순 `@RequestParam` 사용법뿐 아니라,

**요청 데이터 수신 → DTO 자동 바인딩 → Model 전달 → Redirect / Forward 흐름**

까지 이어지는 Spring MVC 요청 처리 전체 구조를 학습했습니다.
