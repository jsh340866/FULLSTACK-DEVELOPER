## 1. 소켓 통신 기초 (`Ch09/C01Server.java`, `Ch09/C01Client.java`)

### 설명

* `ServerSocket`으로 서버 생성
* `Socket`으로 클라이언트 연결
* 입력/출력 스트림을 이용해 문자열 송수신
* 서버는 `accept()`로 클라이언트 접속 대기

### 실제 코드

```java

```

```text

[CLIENT] SERVER와의 연결이 완료되었습니다.
```

### 핵심 정리

* 서버는 먼저 실행되어야 함
* `accept()`는 클라이언트 접속 전까지 대기 상태
* 소켓 연결 후 스트림으로 데이터 송수신 가능

## 5. 공유 자원 문제와 동기화 (`Ch10/C04ThreadMain_Ex_*.java`, `Ch10/C05ThreadMain_Ex_Sync.java`)

### 설명

* 여러 스레드가 하나의 공유 변수(`counter`)를 동시에 수정하면 값이 꼬이는 문제가 발생
* `counter++` 연산은 실제로 여러 단계로 나뉘어 처리됨
* 한 스레드가 값을 읽는 도중 다른 스레드가 접근하면 예상과 다른 결과 발생 가능
* 이런 문제를 경쟁 상태(Race Condition)라고 함
* 이를 해결하기 위해 `synchronized` 키워드를 사용하여 임계 영역(Critical Section)을 보호
* 동기화된 영역에는 한 번에 하나의 스레드만 진입 가능
* 스레드 간 작업 순서를 제어하기 위해 `wait()`와 `notifyAll()` 사용 가능

### 실제 코드

```java
class IncrementThread implements Runnable {
	private static int counter = 0;

	private static final Object lock = new Object(); // 자물쇠

	@Override
	public void run() {
		for (int i = 0; i < 100000; i++) {
			
			synchronized(lock) {
				counter++; // 공유변수값증가
				System.out.println(Thread.currentThread().getName() + "s counter : " + counter);
				
				lock.notifyAll();
				try {
					lock.wait(5);
				} catch (InterruptedException e) {
					e.printStackTrace();
					break;
				}
			}
		}
	}
}
```

```java
synchronized(obj) {
    wait();
    notifyAll();
}
```

### 예상 출력

```text
Thread-0's counter : 1
Thread-1's counter : 2
Thread-0's counter : 3
```

### 핵심 정리

* 여러 스레드가 같은 데이터를 동시에 수정하면 데이터 충돌 발생 가능
* `counter++`도 원자적(Atomic) 연산이 아니므로 동기화 필요
* `synchronized`는 공유 자원을 안전하게 보호하기 위한 키워드
* `wait()`는 현재 스레드를 대기 상태로 전환
* `notify()` 또는 `notifyAll()`은 대기 중인 스레드를 다시 실행 가능 상태로 변경
* 멀티스레드 환경에서는 실행 순서가 항상 일정하지 않음

## 6. 멀티 채팅 프로그램 구조 (`Ch11/*`)

* 송신/수신을 각각 스레드로 분리하면 동시 채팅 가능
