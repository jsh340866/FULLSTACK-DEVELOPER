## 1. Firebase 알림 기능 (`12_RESTFULAPI/C08FCM`)

### 설명

FCM(Firebase Cloud Messaging)은 서버에서 특정 사용자 또는 여러 사용자에게 푸시 알림을 보낼 수 있는 기능입니다.

프로젝트에서는 Firebase SDK를 사용하여 특정 토큰으로 알림을 전송합니다.

동작 순서

```text
사용자 앱
 ↓
FCM Token 발급
 ↓
DB 저장
 ↓
서버 요청
 ↓
Firebase 서버
 ↓
사용자 기기 알림 수신
```

### 실제 코드

```java
Message message = Message.builder()
        .setToken(targetToken)
        .setNotification(Notification.builder()
                .setTitle(title)
                .setBody(body)
                .build())
        .build();

return FirebaseMessaging.getInstance().send(message);
```

### 예상 출력

```text
메시지 전송 성공

projects/.../messages/0:1234567890
```

### 핵심 정리

- FCM Token이 사용자 식별자 역할
- Notification 객체에 제목과 내용 저장
- FirebaseMessaging.send()로 실제 전송
- 모바일 앱 푸시 알림 구현 가능

## 2. 파일 업로드 / 다운로드 (`13_FILEUPDOWNLOAD/Controller/FileUpDownloadController.java`)

### 설명

Spring의 MultipartFile을 사용하여 파일을 서버에 업로드합니다.

업로드 순서

```text
사용자 파일 선택
 ↓
MultipartFile 생성
 ↓
업로드 폴더 생성
 ↓
파일 저장
```

### 실제 코드

```java
@PostMapping("/upload")
@ResponseBody
public void upload_post(
        @RequestParam("file") MultipartFile file
) throws IOException {
```

파일 저장

```java
File fileObject = new File(uploadPath, filename);
file.transferTo(fileObject);
```

업로드 폴더 생성

```java
File dir = new File(uploadPath);

if (!dir.exists())
    dir.mkdirs();
```

### 예상 출력

```text
FILE NAME : test.jpg
FILE SIZE : 102400 Byte
```

### 핵심 정리

- MultipartFile이 업로드 파일 객체
- transferTo()가 실제 저장 수행
- mkdirs()로 폴더 자동 생성
- 단일 업로드와 다중 업로드 모두 가능

## 3. AOP (`14_AOP/Aop/LogginAspect.java`)

### 설명

AOP(Aspect Oriented Programming)는 공통 관심사를 분리하는 기술입니다.

예를 들어

```text
로그 기록
실행 시간 측정
트랜잭션 처리
권한 검사
```

등을 비즈니스 로직과 분리할 수 있습니다.

실행 흐름

```text
AOP BEFORE
 ↓
실제 서비스 메서드
 ↓
AOP AFTER
```

### 실제 코드

```java
@Around("execution(* com.example.demo.Domain.Common.Service.*.*(..))")
```

실행 전 시간 측정

```java
long start_time = System.currentTimeMillis();
```

실제 메서드 실행

```java
Object returnValue = pjp.proceed();
```

실행 시간 계산

```java
long end_time = System.currentTimeMillis();
```

### 예상 출력

```text
[AOP] AROUND BEFORE

타겟 함수 리턴값 : success

[AOP] AROUND AFTER

[AOP] 소요시간 : 15 ms
```

### 핵심 정리

- @Aspect로 AOP 클래스 선언
- @Around는 전후처리 모두 가능
- pjp.proceed()가 실제 메서드 호출
- 성능 측정 및 공통 로그 처리에 활용

## 4. Interceptor 와 Filter (`15_INTERCEPTOR`)

### 설명

둘 다 요청을 가로채는 기능이지만 실행 위치가 다릅니다.

실행 순서

```text
Client
 ↓
Filter
 ↓
DispatcherServlet
 ↓
Interceptor
 ↓
Controller
 ↓
Interceptor
 ↓
View
 ↓
Filter
 ↓
Client
```

---

### 실제 코드

#### Filter

```java
public void doFilter(
        ServletRequest request,
        ServletResponse response,
        FilterChain chain)
```

전처리

```java
System.out.println("[FILTER] MemoFilter START");
```

다음 요청 진행

```java
chain.doFilter(request,response);
```

후처리

```java
System.out.println("[FILTER] MemoFilter END");
```

---

#### Interceptor

컨트롤러 실행 전

```java
public boolean preHandle(...)
```

컨트롤러 실행 후

```java
public void postHandle(...)
```

응답 완료 후

```java
public void afterCompletion(...)
```

등록

```java
registry.addInterceptor(memoInterceptor)
        .addPathPatterns("/memo/**");
```

### 예상 출력

```text
[FILTER] MemoFilter START

[INTERCEPTOR] 컨트롤러 실행 전

Controller 실행

[INTERCEPTOR] 컨트롤러 실행 후

[INTERCEPTOR] 요청 응답 완료

[FILTER] MemoFilter END
```

### 핵심 정리

- Filter는 Servlet 레벨
- Interceptor는 Spring MVC 레벨
- Interceptor가 Controller 정보를 알 수 있음
- 로그인 검사, 권한 체크에 많이 사용

## 5. Scheduled (`16_SCHEDULED/Scheduled/ScheduledTasks.java`)

### 설명

정해진 시간마다 자동으로 작업을 수행합니다.

대표 사용 예

```text
주가 수집
환율 수집
배치 실행
로그 정리
알림 발송
```

### 실제 코드

```java
@Scheduled(cron = "0 * * * * *")
public void task3(){
    log.info("task3...." + System.currentTimeMillis());
}
```

Cron 형식

```text
초 분 시 일 월 요일
```

예시

```java
@Scheduled(fixedRate = 3000)
```

```java
@Scheduled(fixedDelay = 3000)
```

```java
@Scheduled(cron = "0 */5 * * * *")
```

### 예상 출력

```text
task3....1750000000000
```

매 분 0초마다 실행

### 핵심 정리

- fixedRate : 시작 기준 반복
- fixedDelay : 종료 기준 반복
- cron : 특정 시각 실행
- 자동 데이터 수집 작업에 활용

## 6. Spring Batch (`22_BATCH/Batch/BatchConfig.java`)

### 설명

대량 데이터를 안정적으로 처리하기 위한 프레임워크입니다.

구조

```text
Job
 ├─ Step1
 └─ Step2
```

실행 흐름

```text
Job 시작
 ↓
Step1 실행
 ↓
Step2 실행
 ↓
Job 종료
```

### 실제 코드

Job 생성

```java
@Bean
public Job basicJob(
        JobRepository jobRepository,
        Step step1,
        Step step2)
```

Step 생성

```java
@Bean
public Step step1(
        JobRepository jobRepository,
        JpaTransactionManager tx)
```

Tasklet 방식

```java
.tasklet((contribution,chunkContext)->{

    log.info("[STEP1] - hello world batch..");

    return RepeatStatus.FINISHED;

},tx)
```

### 예상 출력

```text
[STEP1] - hello world batch..

[STEP1] - hello world batch..1
[STEP1] - hello world batch..2
[STEP1] - hello world batch..3
[STEP1] - hello world batch..4
[STEP1] - hello world batch..5
```

### 핵심 정리

- Job = 배치 전체 작업
- Step = 개별 처리 단위
- Tasklet = 단순 작업 방식
- RepeatStatus.FINISHED 반환 시 종료
- 대량 데이터 처리에 사용
