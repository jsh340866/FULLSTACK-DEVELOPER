## 1. Spring Event Listener (`17_LISTENER`)

### 설명

Spring은 특정 시점에 이벤트를 발생시킬 수 있으며 해당 이벤트를 감지하는 Listener를 등록할 수 있습니다.

이벤트 기반 구조를 사용하면 객체 간 결합도를 낮추고 기능을 분리할 수 있습니다.

### 실제 코드

```java
public class C01CustomContextRefreshedListener
        implements ApplicationListener<ContextRefreshedEvent> {

    @Override
    public void onApplicationEvent(ContextRefreshedEvent event) {
        System.out.println("invoke...");
    }
}
```

### 예상 출력

```text
invoke...
```

### 핵심 정리

- ApplicationListener 인터페이스 구현
- 특정 이벤트 발생 시 자동 실행
- 스프링 컨테이너 초기화 완료 시 동작

## 2. ContextRefreshedEvent (`17_LISTENER`)

### 설명

Spring Container가 모든 Bean 생성 및 초기화를 완료하면 발생하는 이벤트입니다.

프로젝트 시작 시 초기 작업을 수행할 때 자주 사용됩니다.

### 실제 코드

```java
implements ApplicationListener<ContextRefreshedEvent>
```

```java
public void onApplicationEvent(ContextRefreshedEvent event) {
    System.out.println("invoke...");
}
```

### 예상 출력

```text
invoke...
```

### 핵심 정리

- Spring 시작 완료 시 실행
- Bean 생성 완료 확인 가능
- 초기 데이터 로딩 작업에 활용

## 4. 사용자 정의 이벤트 생성 (`17_LISTENER`)

### 설명

Spring 기본 이벤트 외에도 개발자가 직접 이벤트를 생성할 수 있습니다.

### 실제 코드

```java
public class MemoAddEvent extends ApplicationEvent {
```

```text
MemoAddEvent 발생
```

### 핵심 정리

- ApplicationEvent 상속
- 비즈니스 이벤트 구현 가능
- 이벤트 기반 구조 구성

## 5. 사용자 정의 이벤트 리스너 (`17_LISTENER`)

### 설명

사용자 정의 이벤트가 발생하면 Listener가 자동 실행됩니다.

### 실제 코드

```java
public class MemoAddEventListener
        implements ApplicationListener<MemoAddEvent> {

    @Override
    public void onApplicationEvent(MemoAddEvent event) {
        System.out.println("[LISTENER] MEMO ADD EVENT");
    }
}
```

### 예상 출력

```text
[LISTENER] MEMO ADD EVENT
```

### 핵심 정리

- 이벤트 감지
- 자동 실행
- Controller와 기능 분리 가능

## 6. BeanNameUrlHandlerMapping (`18_HANDLER_MAPPING`)

### 설명

Bean 이름을 URL과 연결하는 HandlerMapping 방식입니다.

### 실제 코드

```java
@Bean(name="/custom_01")
public CustomHandler customHandler() {
    return new CustomHandler();
}
```

```java
@Bean
public BeanNameUrlHandlerMapping beanNameUrlHandlerMapping() {
    return new BeanNameUrlHandlerMapping();
}
```

### 예상 출력

```text
/custom_01 요청 처리
```

### 핵심 정리

- Bean 이름 = URL
- Controller 없이 요청 처리 가능
- Spring 초기 Handler 방식

```text
/custom_02 요청 처리
```

### 핵심 정리

- URL 직접 등록
- Handler 직접 연결
- 단순한 매핑 구조

## 8. RequestMappingHandlerMapping (`18_HANDLER_MAPPING`)

### 설명

현재 Spring MVC에서 가장 많이 사용하는 매핑 방식입니다.

메서드 단위로 URL을 연결합니다.

### 실제 코드

```java
Method method =
    RequestCustomHandler.class
        .getMethod("hellWorld");
```

```java
handlerMapping.registerMapping(
        info,
        new RequestCustomHandler(),
        method
);
```

### 예상 출력

```text
HELLO WORLD
```

### 핵심 정리

- 메서드 기반 매핑
- Reflection 사용
- @RequestMapping 방식의 핵심 구조

## 9. ResponseBody 처리 (`18_HANDLER_MAPPING`)

### 설명

View를 찾지 않고 데이터를 직접 응답합니다.

REST API의 기본 동작 방식입니다.

### 실제 코드

```java
@ResponseBody
public String hellWorld2() {
    return "HELLOWORLD!!!";
}
```

### 예상 출력

```text
HELLOWORLD!!!
```

### 핵심 정리

- View Resolver 사용 안함
- 문자열 직접 응답
- REST API 핵심 기능

## 11. DispatcherServlet 동작 흐름 (`18_HANDLER_MAPPING`)

### 설명

Spring MVC의 모든 요청은 DispatcherServlet이 가장 먼저 받습니다.

이후 HandlerMapping을 통해 실행할 대상을 찾습니다.

### 실제 흐름

```text
Client
 ↓
DispatcherServlet
 ↓
HandlerMapping
 ↓
Handler
 ↓
View Resolver
 ↓
Response
```

### 예상 출력

```text
요청 → Handler 탐색 → 실행 → 응답
```

### 핵심 정리

- Spring MVC의 Front Controller
- HandlerMapping 조회
- Handler 실행 관리
- 응답 반환 담당
