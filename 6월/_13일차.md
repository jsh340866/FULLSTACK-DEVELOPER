## 2. CSRF(Cross Site Request Forgery) (`Config/SecurityConfig.java`)

### 설명

CSRF(Cross Site Request Forgery)는 사용자가 로그인된 상태를 악용하여 의도하지 않은 요청을 서버에 보내도록 만드는 공격입니다.

예를 들어 사용자가 은행 사이트에 로그인한 상태에서 악성 사이트에 접속하면 공격자가 만든 요청이 자동으로 전송될 수 있습니다.

Spring Security는 기본적으로 CSRF Token을 생성하여 이러한 공격을 방어합니다.

### 공격 예시

```text
사용자 로그인
 ↓
은행 사이트 접속
 ↓
세션 유지
 ↓
악성 사이트 방문
 ↓
자동 송금 요청 발생
 ↓
사용자는 모르는 상태에서 송금
```

### CSRF 방어 방식

```text
브라우저 요청
 ↓
CSRF Token 포함
 ↓
서버 검증
 ↓
Token 일치
 ↓
요청 허용
```

```text
브라우저 요청
 ↓
CSRF Token 없음
 ↓
서버 검증 실패
 ↓
403 Forbidden
```

### 실제 코드

```java
http.csrf((config)->{
    config.disable();
});
```

### 왜 비활성화 했는가?

실습 환경에서는 Postman, REST API 테스트, Ajax 요청 등을 편하게 하기 위해 CSRF를 비활성화하는 경우가 많습니다.

### 핵심 정리

- CSRF = 사용자의 인증 정보를 악용하는 공격
- Spring Security는 기본적으로 활성화
- Token 검증으로 공격 방어
- REST API 서버는 비활성화하는 경우가 많음
- 일반 웹 서비스는 활성화 권장

## 3. URL 권한 설정 (`Config/SecurityConfig.java`)

### 설명

URL별 접근 가능한 사용자 권한을 지정합니다.

### 실제 코드

```java
auth.requestMatchers("/","/join","/login")
        .permitAll();
```

```java
auth.requestMatchers("/user")
        .hasAnyRole("USER","ADMIN");
```

```java
auth.requestMatchers("/manager")
        .hasAnyRole("MANAGER");
```

```java
auth.requestMatchers("/admin")
        .hasAnyRole("ADMIN");
```

```java
auth.anyRequest().authenticated();
```

### 권한 구조

```text
/
├── permitAll
│
├── /join
├── /login
│
├── /user
│    └── USER, ADMIN
│
├── /manager
│    └── MANAGER
│
└── /admin
     └── ADMIN
```

### 핵심 정리

- permitAll() : 누구나 접근
- authenticated() : 로그인 필요
- hasAnyRole() : 권한 필요
