## 1. Spring Security 전체 흐름 (`Config/SecurityConfig.java`)

### 설명

Spring Security는 모든 요청을 먼저 가로채서 인증과 권한을 검사합니다.

이번 프로젝트의 흐름은 다음과 같습니다.

```text
회원가입
 ↓
비밀번호 암호화 저장
 ↓
로그인 요청
 ↓
PrincipalDetailsService 호출
 ↓
DB 사용자 조회
 ↓
PrincipalDetails 생성
 ↓
인증 성공
 ↓
세션 저장
 ↓
권한 검사
 ↓
페이지 접근 허용
```

Spring Security의 핵심은

```text
인증(Authentication)
+
인가(Authorization)
```

입니다.

- 인증 : 누구인지 확인
- 인가 : 접근 권한 확인

---

### 실제 코드

```java
http.authorizeHttpRequests((auth)->{
    auth.requestMatchers("/","/join","/login").permitAll();

    auth.requestMatchers("/user")
            .hasAnyRole("USER","ADMIN");

    auth.requestMatchers("/manager")
            .hasAnyRole("MANAGER");

    auth.requestMatchers("/admin")
            .hasAnyRole("ADMIN");

    auth.anyRequest().authenticated();
});
```

---

### 예상 동작

```text
비회원
 ├─ /login 가능
 ├─ /join 가능
 └─ /admin 불가

ROLE_USER
 ├─ /user 가능
 └─ /admin 불가

ROLE_ADMIN
 ├─ /user 가능
 └─ /admin 가능
```

---

### 핵심 정리

- authorizeHttpRequests()가 URL 권한 설정 담당
- authenticated()는 로그인된 사용자만 허용
- hasRole()은 특정 권한 보유 여부 검사

---

## 2. CSRF 비활성화 (`Config/SecurityConfig.java`)

### 설명

CSRF(Cross Site Request Forgery)는 사용자가 의도하지 않은 요청을 보내게 만드는 공격입니다.

Spring Security는 기본적으로 CSRF 보호가 활성화되어 있습니다.

현재 예제에서는 학습용으로 비활성화했습니다.

비활성화하지 않으면 Logout 요청도 POST 방식으로만 허용됩니다.

---

### 실제 코드

```java
http.csrf((config)->{
    config.disable();
});
```

---

### 예상 동작

```text
CSRF 활성화
 → POST /logout 필요

CSRF 비활성화
 → GET /logout 가능
```

---

### 핵심 정리

- 실무에서는 가능하면 활성화
- 학습용 프로젝트에서는 편의를 위해 비활성화하는 경우 많음

---

## 3. 회원가입 처리 (`Controller/UserController.java`)

### 설명

회원가입 시 가장 중요한 작업은 비밀번호 암호화입니다.

비밀번호를 평문으로 저장하면 보안상 매우 위험합니다.

그래서 BCryptPasswordEncoder를 사용하여 암호화 후 저장합니다.

---

### 실제 코드

```java
User user = User.builder()
        .username(userDTO.getUsername())
        .password(
            passwordEncoder.encode(
                userDTO.getPassword()
            )
        )
        .role("ROLE_USER")
        .build();

userRepository.save(user);
```

---

### 예상 출력

```text
입력 비밀번호
1234

DB 저장값
$2a$10$xxxxxxxxxxxxxxxxxxxxx
```

---

### 핵심 정리

- 사용자가 입력한 비밀번호는 절대 그대로 저장하지 않음
- BCrypt가 단방향 암호화 수행
- 로그인 시 암호화된 값끼리 비교

---

## 4. UserDetails 구현 (`Config/auth/PrincipalDetails.java`)

### 설명

Spring Security는 User 엔티티를 직접 사용하지 않습니다.

반드시 UserDetails 객체로 변환해야 합니다.

즉,

```text
DB User
 ↓
PrincipalDetails
 ↓
Spring Security
```

구조가 됩니다.

---

### 실제 코드

```java
public class PrincipalDetails
        implements UserDetails
```

```java
@Override
public String getUsername() {
    return userDTO.getUsername();
}

@Override
public String getPassword() {
    return userDTO.getPassword();
}
```

---

### 권한 변환 코드

```java
String[] roles = userDTO.getRole().split(",");

for(String role : roles){
    authorities.add(
        new SimpleGrantedAuthority(role)
    );
}
```

---

### 왜 사용하는가?

Spring Security는

```java
User
```

를 이해하지 못합니다.

반드시

```java
UserDetails
```

형태여야 인증 객체로 사용할 수 있습니다.

---

### 핵심 정리

- UserDetails는 Security 전용 사용자 객체
- 사용자 정보와 권한을 보관
- 인증 성공 시 세션에 저장됨

---

## 5. UserDetailsService 구현 (`Config/auth/PrincipalDetailsService.java`)

### 설명

로그인 시 Spring Security가 가장 먼저 호출하는 클래스입니다.

사용자명을 받아 DB 조회를 수행합니다.

---

### 실제 코드

```java
Optional<User> userOptional =
        userRepository.findById(username);
```

```java
principalDetails =
        new PrincipalDetails(userDTO);
```

---

### 전체 흐름

```text
로그인 요청
 ↓
PrincipalDetailsService
 ↓
DB 조회
 ↓
UserDTO 생성
 ↓
PrincipalDetails 생성
 ↓
Spring Security 반환
 ↓
인증 완료
```

---

### 왜 사용하는가?

Security는

```text
아이디 입력
 ↓
DB 조회
```

방법을 모릅니다.

그래서 개발자가

```java
loadUserByUsername()
```

를 구현해줘야 합니다.

---

### 핵심 정리

- 로그인 인증의 시작점
- DB 조회 담당
- UserDetails 객체 생성 담당

## 6. 로그인 처리 (`SecurityConfig.java`)

### 설명

Spring Security 기본 로그인 화면 대신 커스텀 로그인 페이지를 사용합니다.

---

### 실제 코드

```java
http.formLogin((login)->{
    login.permitAll();
    login.loginPage("/login");

    login.successHandler(
        new CustomLoginSuccessHandler()
    );

    login.failureHandler(
        new CustomLoginFailureHandler()
    );
});
```

---

### 흐름

```text
사용자 로그인
 ↓
인증 시도
 ↓
성공 → SuccessHandler
실패 → FailureHandler
```

---

### 핵심 정리

- formLogin()이 로그인 기능 담당
- 성공/실패 후 동작을 직접 지정 가능

---

## 7. 로그인 성공 핸들러 (`CustomLoginSuccessHandler.java`)

### 설명

로그인 성공 후 권한에 따라 다른 페이지로 이동시킵니다.

---

### 실제 코드

```java
for(GrantedAuthority authority
        : authentication.getAuthorities()) {

    String role =
            authority.getAuthority();

    if(role.contains("ROLE_ADMIN")) {
        redirectUrl="/admin";
    }
    else if(role.contains("ROLE_MANAGER")) {
        redirectUrl="/manager";
    }
    else {
        redirectUrl="/user";
    }
}
```

---

### 예상 출력

```text
ROLE_USER
 → /user

ROLE_MANAGER
 → /manager

ROLE_ADMIN
 → /admin
```

---

### 핵심 정리

- 인증 성공 후 실행
- 사용자 권한에 따라 분기 가능

---

## 8. 로그인 실패 핸들러 (`CustomLoginFailureHandler.java`)

## 11. 로그아웃 처리 (`CustomLogoutHandler.java`)

### 설명

로그아웃 시 세션을 제거합니다.

---

### 실제 코드

```java
HttpSession session =
        request.getSession(false);

if(session != null)
    session.invalidate();
```

---

### 흐름

```text
로그아웃
 ↓
세션 삭제
 ↓
인증 정보 제거
```

---

### 핵심 정리

- 세션 기반 인증 종료
- 로그인 상태 제거

로그인
 ↓
PrincipalDetailsService
 ↓

 ↓

 ↓

 ↓

 ↓

### Security 객체들의 역할

```text
SecurityConfig
 → 전체 보안 정책 설정

PrincipalDetails
 → Security 전용 사용자 객체

PrincipalDetailsService
 → DB 사용자 조회

SuccessHandler
 → 로그인 성공 처리

FailureHandler
 → 로그인 실패 처리

AuthenticationEntryPoint
 → 미인증 사용자 처리

AccessDeniedHandler
 → 권한 부족 처리

LogoutHandler
 → 로그아웃 처리
```
