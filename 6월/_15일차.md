## 1. JWT 기본 개념 (`Config/auth/jwt`)

### 설명

JWT(Json Web Token)는 서버가 사용자 인증 정보를 토큰으로 만들어 클라이언트에게 전달하는 방식입니다.

기존 Session 방식은

```text
사용자 로그인
    ↓
Session 생성
    ↓
SessionID 저장
    ↓
서버 메모리에서 사용자 관리
```

구조입니다.

JWT 방식은

```text
사용자 로그인
    ↓
JWT 생성
    ↓
클라이언트 전달
    ↓
매 요청마다 JWT 전달
```

방식입니다.

따라서 서버가 Session을 관리하지 않아도 됩니다.

현재 프로젝트 역시

```java
sessionConfig.sessionCreationPolicy(SessionCreationPolicy.STATELESS);
```

로 Session을 사용하지 않는 Stateless 구조입니다.

### 실제 코드

```java
http.sessionManagement((sessionConfig)->{
    sessionConfig.sessionCreationPolicy(SessionCreationPolicy.STATELESS);
});
```

### 핵심 정리

- Session 사용 안함
- JWT가 인증정보 역할 수행
- 서버 확장성이 좋아짐

## 2. JWT 토큰 생성 (`JWTTokenProvider.java`)

### 설명

JWT 생성은 로그인 성공 후 수행됩니다.

토큰 내부에는

- username
- 권한정보(role)
- 만료시간

등이 저장됩니다.

현재 코드에서는

```java
.claim("username",authentication.getName())
.claim("auth",authorities)
```

를 통해 사용자 정보가 저장됩니다.

### 실제 코드

```java
String accessToken = Jwts.builder()
        .setSubject(authentication.getName())
        .setExpiration(new Date(now + JWTProperties.ACCESS_TOKEN_EXPIRATION_TIME))
        .signWith(key, SignatureAlgorithm.HS256)
        .claim("username",authentication.getName())
        .claim("auth",authorities)
        .compact();
```

### 예상 토큰 구조

```text
Header.Payload.Signature
```

Payload

```json
{
  "username":"user",
  "auth":"ROLE_USER"
}
```

### 핵심 정리

- JWT 안에 사용자 정보 저장
- 서명(Signature)으로 위변조 방지
- 인증 시 DB 조회 없이 정보 활용 가능

## 3. Access Token / Refresh Token (`JWTTokenProvider.java`)

### 설명

JWT는 보통 두 종류를 사용합니다.

#### Access Token

서비스 접근용 토큰

```text
로그인
 ↓
Access Token 발급
 ↓
API 호출
```

#### Refresh Token

Access Token 만료 시 재발급용 토큰

```text
Access 만료
 ↓
Refresh 검증
 ↓
새 Access 발급
```

현재 코드도 두 개를 동시에 생성합니다.

### 실제 코드

```java
String accessToken = Jwts.builder()
        ...
        .compact();

String refreshToken = Jwts.builder()
        ...
        .compact();
```

### 핵심 정리

- Access = 서비스 사용
- Refresh = Access 재발급
- 보안성과 편의성 확보

---

## 4. 로그인 성공 시 JWT 발급 (`CustomLoginSuccessHandler.java`)

### 설명

사용자가 로그인에 성공하면

```text
ID/PW 검증 성공
        ↓
Authentication 생성
        ↓
JWT 생성
        ↓
Cookie 저장
        ↓
DB 저장
```

순서로 동작합니다.

Spring Security에서는 로그인 성공 시

```java
onAuthenticationSuccess()
```

가 실행됩니다.

### 실제 코드

```java
TokenInfo tokenInfo =
        jwtTokenProvider.generateToken(authentication);
```

```java
Cookie cookie =
        new Cookie(
                JWTProperties.ACCESS_TOKEN_COOKIE_NAME,
                tokenInfo.getAccessToken()
        );
```

### 핵심 정리

- 로그인 성공 시 JWT 생성
- Access Token을 Cookie로 전달
- Refresh Token은 DB 저장

## 5. Refresh Token 저장 (`CustomLoginSuccessHandler.java`)

### 설명

Access Token은 쿠키에 저장되고

Refresh Token은 DB에 저장됩니다.

현재 구조

```text
Browser
 └─ Access Token

DB
 └─ Refresh Token
```

### 실제 코드

```java
JwtToken tokenEntity = JwtToken.builder()
        .accessToken(tokenInfo.getAccessToken())
        .refreshToken(tokenInfo.getRefreshToken())
        .username(authentication.getName())
        .auth(auth)
        .build();
```

```java
jwtTokenRepository.save(tokenEntity);
```

### 핵심 정리

- Refresh Token은 서버가 관리
- 탈취 위험 감소
- 재발급 처리 가능

## 6. JWTAuthorizationFilter 역할 (`JWTAuthorizationFilter.java`)

### 설명

JWT Filter는 모든 요청마다 실행됩니다.

현재 프로젝트의 핵심 인증 처리 클래스입니다.

흐름

```text
사용자 요청
      ↓
JWT Filter
      ↓
Cookie 확인
      ↓
JWT 검증
      ↓
Authentication 생성
      ↓
SecurityContextHolder 저장
      ↓
Controller 실행
```

### 실제 코드

```java
http.addFilterBefore(
        jwtAuthorizationFilter,
        LogoutFilter.class
);
```

### 핵심 정리

- 요청마다 JWT 검사
- 인증 성공 시 SecurityContext 저장
- Session 없이 인증 유지

## 7. Access Token 추출 (`JWTAuthorizationFilter.java`)

### 설명

쿠키에서 Access Token을 찾습니다.

오늘 수업에서 Stream API 사용법도 확인했습니다.

### 실제 코드

```java
token = Arrays.stream(cookies)
        .filter(cookie ->
                cookie.getName()
                        .equals(JWTProperties.ACCESS_TOKEN_COOKIE_NAME))
        .findFirst()
        .map(cookie -> cookie.getValue())
        .orElse(null);
```

### 코드 해설

#### filter()

조건에 맞는 쿠키만 선택

```java
.filter(cookie ->
    cookie.getName().equals(...)
)
```

#### findFirst()

첫 번째 쿠키 반환

```java
.findFirst()
```

#### map()

Cookie → String 변환

```java
.map(cookie -> cookie.getValue())
```

#### orElse(null)

없으면 null 반환

```java
.orElse(null)
```

### 핵심 정리

- Stream API 활용
- Access Token 추출
- Optional 처리 학습

## 9. Authentication 생성 (`JWTTokenProvider.java`)

### 설명

JWT 내부의 사용자 정보를 이용해

Spring Security가 사용하는

```java
Authentication
```

객체를 생성합니다.

### 실제 코드

```java
Claims claims =
        Jwts.parser()
                .setSigningKey(key)
                .build()
                .parseClaimsJws(accessToken)
                .getBody();
```

```java
String username =
        (String)claims.get("username");
```

```java
String auth =
        (String)claims.get("auth");
```

### 권한 생성

```java
authorities.add(
        new SimpleGrantedAuthority(role)
);
```

### Authentication 생성

```java
new UsernamePasswordAuthenticationToken(
        principalDetails,
        null,
        authorities
);
```

### 핵심 정리

- JWT → Authentication 변환
- 사용자 권한 복원
- Spring Security 인증 객체 생성

## 12. SecurityConfig 흐름 (`SecurityConfig.java`)

### 설명

SecurityConfig는 전체 보안 정책을 관리합니다.

흐름

```text
사용자 요청
      ↓
JWT Filter
      ↓
인증 확인
      ↓
권한 확인
      ↓
Controller
```

### 실제 코드

```java
http.authorizeHttpRequests((auth)->{

    auth.requestMatchers("/","/join","/login")
            .permitAll();

    auth.requestMatchers("/user")
            .hasAnyRole("USER","ADMIN");

    auth.requestMatchers("/admin")
            .hasAnyRole("ADMIN");
});
```

### 핵심 정리

- URL별 권한 설정
- 인증/인가 정책 관리
- JWT 인증 구조의 중심

## 오늘 핵심 정리

- JWT는 Session 없이 인증을 처리하는 기술이다.
- 로그인 성공 시 Access Token과 Refresh Token을 발급한다.
- Access Token은 Cookie에 저장된다.
- Refresh Token은 DB에 저장된다.
- JWTAuthorizationFilter가 모든 요청을 검사한다.
- JWT를 Authentication 객체로 변환한다.
- SecurityContextHolder에 저장하여 인증 상태를 유지한다.
- Access Token 만료 시 Refresh Token으로 재발급한다.
- Spring Security는 Stateless 구조로 동작한다.
