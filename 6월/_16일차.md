## 1. 로그인 성공 후 JWT 발급 (`security/handler/CustomLoginSuccessHandler.java`)

### 설명

Spring Security는 로그인 성공 시

```java
Authentication
```

객체를 생성합니다.

이후

```java
CustomLoginSuccessHandler
```

가 실행되어 JWT 생성 및 토큰 저장 작업을 수행합니다.

이번 프로젝트에서 Handler는 단순 성공 알림이 아니라 실제 인증 시스템의 시작점 역할을 합니다.

전체 흐름

```text
로그인 성공
 ↓
Authentication 생성
 ↓
JWT 생성
 ↓
Redis 저장
 ↓
Cookie 저장
 ↓
응답 반환
```

---

### 실제 코드

```java
TokenInfo tokenInfo =
        jwtTokenProvider.generateToken(authentication);
```

```java
// AccessToken, RefreshToken 생성
```

---

```java
redisUtil.setDataExpire(
        "RT:"+authentication.getName(),
        tokenInfo.getRefreshToken(),
        tokenInfo.getRefreshTokenExpirationTime()
);
```

```java
// Redis에 RefreshToken 저장
```

---

```java
Cookie cookie =
        new Cookie(
                JWTProperties.ACCESS_TOKEN_COOKIE_NAME,
                tokenInfo.getAccessToken()
        );
```

```java
// AccessToken Cookie 생성
```

---

```java
response.addCookie(cookie);
```

```java
// 브라우저에 Cookie 전송
```

---

### 예상 출력

```text
로그인 성공

↓

JWT 생성

↓

Redis 저장

↓

Cookie 저장

↓

인증 완료
```

---

### 핵심 정리

- 인증 성공 후 Handler 실행
- JWT 생성 담당
- RefreshToken Redis 저장
- AccessToken Cookie 저장

## 3. Redis를 이용한 RefreshToken 관리 (`redis/RedisUtil.java`)

### 설명

AccessToken은 짧은 시간만 유지됩니다.

따라서 AccessToken 만료 시 새로운 토큰을 발급하기 위해 RefreshToken을 별도로 보관합니다.

이번 프로젝트에서는 DB 대신 Redis를 사용합니다.

Redis는 메모리 기반 저장소이므로 매우 빠른 조회가 가능합니다.

---

### 실제 코드

```java
public void setDataExpire(
        String key,
        String value,
        long duration) {

    redisTemplate.opsForValue()
            .set(
                    key,
                    value,
                    duration,
                    TimeUnit.MILLISECONDS
            );
}
```

---

### 코드 분석

```java
redisTemplate.opsForValue()
```

```java
// String Key-Value 저장 방식 사용
```

---

```java
.set(key,value,duration,...)
```

```java
// 값 저장
// 만료시간(TTL) 설정
```

---

조회

```java
redisTemplate.opsForValue().get(key);
```

```java
// RefreshToken 조회
```

---

삭제

```java
redisTemplate.delete(key);
```

```java
// RefreshToken 삭제
```

---

### 실제 저장 구조

```text
Redis

RT:user1
 └─ eyJhbGciOi...

RT:user2
 └─ eyJhbGciOi...
```

---

### 핵심 정리

- RefreshToken 저장소 역할
- TTL 자동 관리
- 빠른 조회 가능

### 설명

AccessToken은 보안상 짧은 만료시간을 가집니다.

만료된 경우 RefreshToken을 이용하여 재발급을 수행합니다.

---

### 실제 코드

```java
catch(ExpiredJwtException e)
```

---


---

### 처리 흐름

```text
AccessToken 만료

↓

ExpiredJwtException 발생

↓

Redis 조회

↓

RefreshToken 확인

↓

새 AccessToken 생성

↓

Cookie 갱신
```

---

### 예상 출력

```text
AccessToken 만료

↓

RefreshToken 검증 성공

↓

새 AccessToken 발급
```

---

### 핵심 정리

- AccessToken은 짧게 유지
- RefreshToken으로 재발급
- Redis와 연동하여 인증 유지

## 오늘 핵심 정리

1. 로그인 성공 시 CustomLoginSuccessHandler가 실행된다.

2. JWTTokenProvider가 AccessToken과 RefreshToken을 생성한다.

3. AccessToken은 Cookie에 저장된다.

4. RefreshToken은 Redis에 저장된다.

5. JWTAuthorizationFilter가 모든 요청마다 JWT를 검증한다.

6. 검증 성공 시 Authentication을 생성한다.

7. Authentication은 SecurityContextHolder에 저장된다.

8. AccessToken 만료 시 Redis의 RefreshToken을 이용하여 재발급한다.

9. 이번 프로젝트의 핵심은 JWT + Redis 기반 인증 구조이다.
