# 1. React 이벤트 처리 (`04Event`)

### 설명

React에서는 HTML 이벤트를 그대로 사용하는 것이 아니라 Camel Case 형태로 작성한다.

대표적인 이벤트

* onClick
* onMouseEnter
* onMouseLeave
* onKeyDown
* onChange
* onSubmit
* onScroll

이벤트 함수는 JSX 내부에서 함수 자체를 전달해야 하며 즉시 실행하면 안 된다.

---

### 실제 코드

```jsx
const clickHandler = () => {
    alert("클릭");
}

<button onClick={clickHandler}>
    클릭
</button>
```

---

### 예상 출력

```
버튼 클릭

↓

alert 출력
```

---

### 핵심 정리

* 이벤트는 Camel Case 사용
* 함수 호출이 아니라 함수 참조를 전달
* 이벤트 객체(event)를 이용하여 입력값을 제어할 수 있다.

---

# 2. 조건부 렌더링 (`05ConditionRendering`)

### 설명

React에서는 조건에 따라 컴포넌트를 출력하거나 숨길 수 있다.

주로 사용하는 방식

* if문
* 삼항연산자
* &&
* ||

---

### 실제 코드

```jsx
{
    isLogin
        ? <Login />
        : <Logout />
}
```

또는

```jsx
{
    isAdmin && <AdminMenu />
}
```

---

### 예상 출력

```
조건 만족

↓

컴포넌트 출력

조건 불만족

↓

아무것도 출력되지 않음
```

---

### 핵심 정리

* React에서는 조건에 따라 JSX를 반환한다.
* && 연산자는 가장 많이 사용하는 조건부 렌더링 방식이다.
* 삼항연산자는 두 가지 화면을 전환할 때 사용한다.

---

# 3. Props를 이용한 컴포넌트 통신 (`07Component간통신/Props`)

### 설명

Props는 부모 컴포넌트가 자식 컴포넌트에게 데이터를 전달하는 방법이다.

데이터는 단방향으로만 전달된다.

```
Parent

↓

Props

↓

Child
```

자식은 Props를 변경하지 않는다.

---

### 실제 코드

```jsx
<Child name="Hong" />
```

```jsx
const Child = ({name})=>{
    return <h1>{name}</h1>;
}
```

---

### 예상 출력

```
Hong
```

---

### 핵심 정리

* 부모 → 자식 데이터 전달
* 읽기 전용(Read Only)
* React의 기본 데이터 전달 방식

---

# 4. Context API (`07Component간통신/ContextAPI`)

### 설명

Props를 여러 단계 거쳐 전달하는 **Prop Drilling** 문제를 해결하기 위해 사용하는 기능이다.

동작 순서

```
Context 생성

↓

Provider

↓

useContext()

↓

데이터 사용
```

Provider에서 전역 데이터를 저장하고 필요한 컴포넌트에서 가져다 사용한다.

---

### 실제 코드

```jsx
const [globalState, setGlobalState] =
    useState("KOREA_GLOBAL");

<CustomContext.Provider
    value={{
        globalState,
        setGlobalState
    }}
>
    {children}
</CustomContext.Provider>
```

---

### 예상 출력

```
모든 하위 컴포넌트에서

globalState 사용 가능
```

---

### 핵심 정리

* Props 여러 단계 전달을 제거
* 전역 상태 공유 가능
* Provider로 감싼 컴포넌트만 Context 사용 가능

---

# 5. React Router (`08/App.js`)

### 설명

React는 SPA(Single Page Application)이므로 실제 페이지 이동이 아니라 필요한 컴포넌트만 교체한다.

Router 구성

```
BrowserRouter

↓

Routes

↓

Route
```

각 URL마다 다른 컴포넌트를 렌더링한다.

---

### 실제 코드

```jsx
<Router>
    <Routes>

        <Route
            path="/"
            element={<Home />}
        />

        <Route
            path="/About"
            element={<About />}
        />

    </Routes>
</Router>
```

---

### 예상 출력

```
/

↓

Home

/About

↓

About
```

---

### 핵심 정리

* BrowserRouter가 전체 Router 관리
* Routes 안에서 Route 정의
* URL 변경 시 해당 컴포넌트만 변경

---

# 6. Layout 컴포넌트 설계 (`layouts/Layout.jsx`)

### 설명

공통 화면(Header, Footer, Sidebar 등)을 하나의 Layout 컴포넌트로 구성하여 여러 페이지에서 재사용한다.

children을 이용하면 페이지마다 다른 콘텐츠만 교체할 수 있다.

또한 조건부 렌더링을 이용하여 Sidebar 표시 여부를 결정할 수 있다.

---

### 실제 코드

```jsx
<Header />

<main>

    {isShowAside && <Aside />}

    <Section>
        {children}
    </Section>

</main>

<Footer />
```

---

### 예상 출력

```
Header

Aside (조건 만족 시)

본문

Footer
```

---

### 핵심 정리

* 공통 화면을 하나의 Layout으로 관리
* children으로 페이지 내용만 교체
* 유지보수성과 재사용성이 크게 향상

---

# 7. children Props 활용 (`layouts/Layout.jsx`)

### 설명

children은 컴포넌트 태그 사이의 JSX를 자동으로 전달받는 특별한 Props이다.

```jsx
<Layout>

    <Home />

</Layout>
```

↓

```jsx
{children}
```

으로 출력된다.

---

### 실제 코드

```jsx
const Layout = ({children}) => {

    return (

        <Section>

            {children}

        </Section>

    );

}
```

---

### 예상 출력

```
Layout 내부

↓

Home 컴포넌트 출력
```

---

### 핵심 정리

* children은 React에서 자동 전달되는 Props
* 공통 레이아웃 제작 시 가장 많이 사용
* 페이지별 콘텐츠를 유연하게 교체 가능

---

# 오늘 핵심 정리

* React 이벤트는 Camel Case 방식으로 작성하며 함수 참조를 전달한다.
* 조건부 렌더링은 삼항연산자와 `&&`를 활용해 화면을 동적으로 구성한다.
* Props는 부모에서 자식으로 데이터를 전달하는 기본 통신 방식이다.
* Context API는 Prop Drilling을 해결하기 위한 전역 상태 관리 기능이다.
* React Router는 URL에 따라 컴포넌트를 교체하는 SPA 라우팅을 제공한다.
* Layout과 children을 활용하면 공통 UI를 재사용하고 유지보수성을 높일 수 있다.
