## 1. Axios를 이용한 GET/POST 요청 (`01_PARAM/Param.jsx`)

### 설명

Spring Boot와 데이터를 주고받기 위해 **Axios**를 사용했습니다.

이번 수업에서는 GET 요청 시 **Query Parameter**, **Path Variable**을 전달하는 방법과 POST 요청으로 JSON 데이터를 전달하는 방법을 실습했습니다.

---

### 실제 코드

```javascript
// Query Parameter
const handleParam1 = () => {
    axios.get("http://localhost:8095/param/01", {
        params: { name: "홍길동" }
    })
    .then(resp => console.log(resp.data))
    .catch(err => console.log(err));
}

// Path Variable
const handleParam2 = () => {
    axios.get("http://localhost:8095/param/02/홍길동/55/대구")
         .then(resp => console.log(resp.data));
}
```

### 코드 설명

| 코드            | 설명                 |
| ------------- | ------------------ |
| `axios.get()` | GET 요청             |
| `params`      | Query Parameter 전달 |
| `then()`      | 요청 성공 처리           |
| `catch()`     | 요청 실패 처리           |

### 동작 흐름

```text
버튼 클릭 → axios.get() → Spring Boot Controller → Response 반환 → then() 실행
```

### 예상 출력

```text
홍길동
55
대구
```

### 핵심 정리

* Query Parameter는 `params` 옵션으로 전달한다.
* Path Variable은 URL에 직접 포함한다.
* Axios는 Promise 기반이므로 `then()`과 `catch()`를 사용한다.

> 💡 **실무에서는 URL을 직접 작성하기보다 API 파일에서 관리하는 방식을 많이 사용합니다.**

## 2. Validation 결과 처리 (`02_VALIDATION/Memo.jsx`)

### 설명

Spring Boot에서 Validation 검사를 수행한 후 결과를 React에서 받아 화면에 출력했습니다.

정상 등록이면 성공 메시지를, Validation 실패 시에는 오류 메시지를 사용자에게 보여주는 구조입니다.

---

### 실제 코드

```javascript
const handleSubmit = () => {

    axios.post(
        "http://localhost:8095/memo/add",
        {
            id,
            writer,
            text,
            regdate
        }
    )
    .then(resp => {
        setMessage(resp.data);
    })
    .catch(err => {
        setMessage(err.response.data);
    });

}
```

### 코드 설명

| 코드                  | 설명               |
| ------------------- | ---------------- |
| `axios.post()`      | JSON 데이터를 서버로 전송 |
| `resp.data`         | 성공 응답            |
| `err.response.data` | Validation 오류 응답 |
| `setMessage()`      | 결과를 화면에 출력       |

### 동작 흐름

```text
사용자 입력 → POST 요청 → Validation 검사 → 성공/실패 응답 → 화면 출력
```

### 예상 출력

```text
등록 성공
```

또는

```text
작성자는 필수입니다.
```

### 핵심 정리

* Validation 실패도 HTTP 응답으로 전달된다.
* React에서는 `catch()`에서 오류 메시지를 받을 수 있다.
* 성공과 실패를 하나의 state로 관리할 수 있다.

> 💡 **Validation 메시지를 그대로 출력하면 사용자에게 입력 오류를 빠르게 안내할 수 있습니다.**

## 3. 서버 Exception 처리 (`03_EXCEPTION/memo/Post.jsx`)

### 설명

Validation과 달리 **예상하지 못한 서버 오류(Exception)** 도 React에서 처리할 수 있습니다.

Axios는 HTTP 오류(4xx, 5xx)가 발생하면 자동으로 `catch()`를 실행합니다.

---

### 실제 코드

```javascript
axios.post("/memo/add", memo)

    .then(resp => {

        setMessage(resp.data);

    })

    .catch(err => {

        console.log(err.response);

        setMessage(err.response.data);

    });
```

### 코드 설명

| 코드                    | 설명           |
| --------------------- | ------------ |
| `catch()`             | Exception 처리 |
| `err.response.status` | HTTP 상태코드    |
| `err.response.data`   | 서버 오류 메시지    |
| `setMessage()`        | 오류 내용을 화면 출력 |

### 동작 흐름

```text
사용자 입력 → Axios 요청 → Spring Boot Exception → catch() 실행 → 오류 메시지 출력
```

### 예상 출력

```text
500 Internal Server Error
```

또는

```text
존재하지 않는 데이터입니다.
```

### 핵심 정리

* Exception도 Axios가 자동으로 감지한다.
* 서버 오류는 `err.response`에서 확인한다.
* 오류 화면이나 Alert 등 다양한 방식으로 처리할 수 있다.

> 💡 **실무에서는 `console.log()` 대신 공통 Error Handler를 만들어 사용하는 경우가 많습니다.**

## 4. ErrorPage와 React Router (`03_EXCEPTION/App.js`, `03_EXCEPTION/Exception.jsx`)

### 설명

예외가 발생하면 별도의 ErrorPage로 이동하여 오류 정보를 사용자에게 보여주도록 구성했습니다.

`useLocation()`을 이용하면 이전 페이지에서 전달한 데이터를 받을 수 있습니다.

---

### 실제 코드

```javascript
// App.js
<Route path="/exception" element={<Exception />} />
```

```javascript
// Exception.jsx
const location = useLocation();

const { status, message } = location.state || {};
```

### 코드 설명

| 코드                  | 설명         |
| ------------------- | ---------- |
| `Route`             | 페이지 등록     |
| `useLocation()`     | 전달된 데이터 조회 |
| `location.state`    | 이전 페이지 데이터 |
| `status`, `message` | 오류 정보 출력   |

### 동작 흐름

```text
예외 발생 → navigate("/exception") → state 전달 → useLocation() → 오류 화면 출력
```

### 예상 출력

```text
EXCEPTION

Status Code : 404

Message : 게시글을 찾을 수 없습니다.
```

### 핵심 정리

* ErrorPage를 별도로 구성하면 사용자 경험이 좋아진다.
* `useLocation()`은 페이지 이동 시 전달된 데이터를 가져온다.
* 예외 정보는 API를 다시 호출하지 않고 사용할 수 있다.

> 💡 **실무에서는 404, 403, 500 페이지를 각각 분리하여 관리하는 경우가 많습니다.**
