## 1. User ↔ Lend 관계 매핑 (`Domain/Common/Entity/Lend.java`)

### 설명

사용자 한 명은 여러 번의 대여 기록을 가질 수 있습니다.

### 실제 코드

```java
@ManyToOne(fetch = FetchType.EAGER)
@JoinColumn(name="username")
private User user;
```

### 예상 구조

```text
User(1)
  │
  ├─ Lend
  ├─ Lend
  └─ Lend
```

### 핵심 정리

- User 1 : N Lend
- FK는 Lend가 관리

## 3. Foreign Key 생성 (`Domain/Common/Entity/Lend.java`)

### 설명

JPA가 FK 제약조건을 자동 생성합니다.

### 실제 코드

```java
@JoinColumn(
    name="username",
    foreignKey=@ForeignKey(
        name="FK_LEND_USER"
    )
)
```

### 예상 출력

```sql
FOREIGN KEY(username)
REFERENCES user(username)
```

### 핵심 정리

DB 무결성을 자동으로 관리할 수 있습니다.

## 6. Join Fetch (`Domain/Common/Repository/LendRepository.java`)

### 설명

연관 엔티티를 한 번의 SQL로 함께 조회합니다.

### 실제 코드

```java
@Query("""
SELECT l
FROM Lend l
JOIN FETCH l.user
""")
```

### 예상 동작

```text
Lend + User
한 번의 SQL 조회
```

### 핵심 정리

N+1 문제를 해결할 수 있다.

### 실제 코드

```

### 예상 출력

조회 즉시 로딩
```

#### LAZY

```text
사용 시 로딩
```

### 핵심 정리

## 오늘 핵심 정리

```text
@ManyToOne
      ↓
@JoinColumn
      ↓
객체 관계 매핑
      ↓
Repository 조회
      ↓
JPQL Join Fetch
      ↓
성능 최적화
```

- JPA는 객체 간의 관계를 매핑하여 데이터를 관리한다.
- FK는 주로 N(다)쪽 엔티티가 관리한다.
- @ManyToOne과 @JoinColumn으로 관계를 설정한다.
- Join Fetch를 사용하면 연관 엔티티를 한 번에 조회할 수 있다.
- 실무에서는 LAZY Loading을 기본으로 사용하고 필요한 경우 Join Fetch를 활용한다.

## 한 줄 요약

> JPA 연관관계 매핑은 객체 중심으로 데이터를 연결하는 방식이며, ManyToOne과 Join Fetch를 통해 효율적인 데이터 조회와 성능 최적화를 구현할 수 있다.
