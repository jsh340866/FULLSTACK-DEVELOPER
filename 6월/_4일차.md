## 1. Spring Transaction 개념 (`10_TX_JPA`, `10_TX_MYBATIS`)

### 설명

트랜잭션(Transaction)은 여러 SQL 작업을 하나의 작업 단위로 묶는 기술이다.

예를 들어

```text
INSERT
INSERT
INSERT
```

를 수행하다가

```text
오류 발생
```

하면

```text
전부 취소
```

하거나

```text
전부 성공
```

해야 한다.

---

### 실제 코드

```java
insert();
insert();
insert();

throw new SQLException();
```

---

### 예상 출력

```text
트랜잭션 미적용

1건 저장
2건 저장
3건 저장
예외 발생

DB에는 3건 존재
```

```text
트랜잭션 적용

1건 저장
2건 저장
3건 저장
예외 발생

ROLLBACK

DB 저장 건수 0건
```

---

### 핵심 정리

- 트랜잭션은 여러 작업을 하나의 작업 단위로 처리한다.
- 작업 중 오류가 발생하면 전체 작업을 취소한다.
- 데이터 무결성과 일관성을 보장한다.
- All Or Nothing 원칙으로 동작한다.

---

## 2. JPA TransactionManager 설정 (`10_TX_JPA/Config/TxConfig.java`)

### 설명

JPA는 EntityManager를 통해 데이터베이스와 통신한다.

따라서 트랜잭션 역시 JPA 전용 TransactionManager를 사용한다.

---

### 실제 코드

```java
@Configuration
@EnableTransactionManagement
public class TxConfig {

    @Bean(name="jpaTransactionManager")
    public JpaTransactionManager jpaTransactionManager(
            EntityManagerFactory entityManagerFactory) {

        JpaTransactionManager tx =
                new JpaTransactionManager();

        tx.setEntityManagerFactory(entityManagerFactory);

        return tx;
    }
}
```

---

### 예상 출력

```text
Spring 시작

JpaTransactionManager 등록 완료

트랜잭션 사용 가능
```

---

### 핵심 정리

- `@EnableTransactionManagement`
  - Spring 트랜잭션 기능 활성화

- `JpaTransactionManager`
  - JPA 전용 트랜잭션 관리자

- EntityManager와 연동되어 Commit / Rollback 수행

---

## 3. JPA Service 계층 트랜잭션 적용 (`10_TX_JPA/Domain/Common/Service/MemoServiceImpl.java`)

### 설명

기존에는 Controller에서 Repository를 직접 호출하였다.

이번 챕터에서는 Service 계층에서 트랜잭션을 관리하도록 구조를 변경하였다.

---

### 실제 코드

```java
@Transactional(
        rollbackFor = SQLException.class,
        transactionManager = "jpaTransactionManager"
)
public boolean memoRegistration(MemoDTO dto)
        throws Exception {

    memoRepository.save(dto.toEntity());

    return true;
}
```

---

### 예상 출력

```text
Service 시작

트랜잭션 시작

저장 성공

COMMIT
```

---

### 핵심 정리

- Controller는 요청 처리만 담당한다.
- Service가 비즈니스 로직을 담당한다.
- Repository는 DB 접근만 담당한다.
- 트랜잭션은 Service 계층에서 관리한다.

---

## 4. JPA Rollback 실습 (`10_TX_JPA/Domain/Common/Service/TxTestService.java`)

### 설명

동일 데이터를 여러 번 저장한 후 예외를 발생시켜 Rollback 동작을 확인하였다.

---

### 실제 코드

```java
memoRepository.save(memo);

memo.setId(null);
memoRepository.save(memo);

memo.setId(null);
memoRepository.save(memo);

throw new SQLException();
```

---

### 예상 출력

```text
INSERT 3회 수행

SQLException 발생

ROLLBACK

최종 저장 건수 : 0건
```

---

### 핵심 정리

- 여러 save() 작업이 하나의 트랜잭션으로 처리된다.
- 예외 발생 시 모든 작업이 취소된다.
- Commit 되기 전까지 DB에는 최종 반영되지 않는다.

---

## 5. MyBatis TransactionManager 설정 (`10_TX_MYBATIS/Config/TxConfig.java`)

### 설명

MyBatis는 JDBC 기반 프레임워크이다.

따라서 JPA와 다른 TransactionManager를 사용한다.

---

### 실제 코드

```java
@Bean(name = "dataSourceTransactionManager")
public DataSourceTransactionManager transactionManager() {

    return new DataSourceTransactionManager(dataSource);
}
```

---

### 예상 출력

```text
Spring 시작

DataSourceTransactionManager 등록 완료

트랜잭션 사용 가능
```

---

### 핵심 정리

- MyBatis는 JDBC 기반이다.
- DataSource를 통해 DB와 연결된다.
- `DataSourceTransactionManager`가 Commit / Rollback을 관리한다.

---

## 6. MyBatis Mapper 기반 트랜잭션 처리 (`10_TX_MYBATIS/Mapper/MemoMapper.java`)

### 설명

JPA는 Repository를 사용하지만 MyBatis는 Mapper 인터페이스를 사용한다.

---

### 실제 코드

```java
@Insert("""
INSERT INTO tbl_memo
VALUES
(
    #{id},
    #{text}
)
""")
int insert(MemoDTO dto);
```

```java
memoMapper.insert(memo);
```

---

### 예상 출력

```text
Mapper 호출

INSERT 실행

성공 시 Commit
```

---

### 핵심 정리

- JPA → Repository
- MyBatis → Mapper
- 데이터 접근 방식은 다르지만 트랜잭션 원리는 동일하다.

---

## 7. MyBatis Rollback 실습 (`10_TX_MYBATIS/Service/TxTestService.java`)

### 설명

MyBatis에서도 동일하게 여러 INSERT 후 예외를 발생시켜 Rollback을 확인하였다.

---

### 실제 코드

```java
memoMapper.insert(memo);
memoMapper.insert(memo);
memoMapper.insert(memo);

throw new SQLException();
```

---

### 예상 출력

```text
INSERT 3회 수행

SQLException 발생

ROLLBACK

DB 저장 건수 0건
```

---

### 핵심 정리

- MyBatis 역시 Spring이 트랜잭션을 관리한다.
- `@Transactional` 적용 시 자동 Commit / Rollback 처리된다.
- JPA와 동일한 방식으로 트랜잭션을 사용할 수 있다.

## 8. Checked Exception Rollback 처리 (`10_TX_JPA`, `10_TX_MYBATIS`)

### 설명

Spring은 기본적으로 RuntimeException만 Rollback 처리한다.

SQLException은 Checked Exception이므로 별도 설정이 필요하다.

---

### 실제 코드

```java
@Transactional(
        rollbackFor = SQLException.class
)
```

---

### 예상 출력

```text
SQLException 발생

ROLLBACK 수행
```

---

### 핵심 정리

- RuntimeException → 기본 Rollback
- Checked Exception → Rollback 안 됨
- `rollbackFor` 옵션으로 Rollback 대상 지정 가능

---

## 9. JPA와 MyBatis 트랜잭션 비교 (`10_TX_JPA`, `10_TX_MYBATIS`)

### 설명

동일한 Spring 트랜잭션 기능을 사용하지만 내부 구현 방식은 다르다.

---

### 실제 코드

```java
// JPA
memoRepository.save(memo);
```

```java
// MyBatis
memoMapper.insert(memo);
```

---

### 예상 출력

```text
JPA
 ↓
EntityManager
 ↓
JpaTransactionManager

MyBatis
 ↓
DataSource
 ↓
DataSourceTransactionManager
```

---

### 핵심 정리

| 항목 | JPA | MyBatis |
|--------|--------|--------|
| DB 접근 | Repository | Mapper |
| 트랜잭션 관리자 | JpaTransactionManager | DataSourceTransactionManager |
| 저장 | save() | insert() |
| 수정 | save() | update() |
| 삭제 | delete() | delete() |
| 트랜잭션 처리 | @Transactional | @Transactional |
| Rollback | 가능 | 가능 |

---

## 오늘 핵심 정리

- Spring 트랜잭션 기능을 활성화하기 위해 `@EnableTransactionManagement`를 사용하였다.
- JPA는 `JpaTransactionManager`를 이용하여 트랜잭션을 관리한다.
- MyBatis는 `DataSourceTransactionManager`를 이용하여 트랜잭션을 관리한다.
- `@Transactional`을 사용하여 Commit과 Rollback을 자동 처리하였다.
- `rollbackFor = SQLException.class`를 이용하여 Checked Exception도 Rollback 되도록 설정하였다.
- 여러 SQL 작업을 하나의 트랜잭션으로 처리하여 데이터 무결성을 보장하였다.
- Controller → Service → Repository(Mapper) 구조에서 Service 계층이 트랜잭션을 담당한다.
- JPA와 MyBatis는 구현 방식은 다르지만 트랜잭션 처리 원리는 동일하다.
