## 4. 결측치 처리

```python
num_cols = ['age', 'hours.per.week']              # 수치형 데이터
cat_cols = ['workclass', 'occupation', 'native.country']  # 범주형 데이터
for c in num_cols:
    m = train[c].median()            # train 기준 중앙값
    train[c] = train[c].fillna(m)
    test[c] = test[c].fillna(m)
for c in cat_cols:
    m = train[c].mode()[0]           # train 기준 최빈값
    train[c] = train[c].fillna(m)
    test[c] = test[c].fillna(m)
```

- 앞서 `info()`에서 찾은 결측 컬럼을 수치형/범주형으로 나눠 각각 다른 방식으로 채운다: **수치형은 중앙값(median), 범주형은 최빈값(mode)** — 평균 대신 중앙값을 쓰는 이유는 `age`처럼 이상치(`-38`)가 있는 컬럼에서 평균이 왜곡될 수 있기 때문
- **`train`에서 계산한 값을 `test`에도 그대로 적용**하는 게 핵심이다. `test`의 값으로 따로 채우면 모델이 학습 단계에서 보면 안 되는 test 정보가 흘러들어가는 **데이터 누수(data leakage)** 가 생기기 때문에, 반드시 train 기준값만 사용한다
- 처리 후 `train.info()` / `test.info()`를 다시 찍어 **결측치가 실제로 0이 됐는지 확인**하는 절차를 거친다 — 코드를 실행했다고 끝난 게 아니라 결과를 눈으로 검증하는 습관

## 5. 타겟 분리 & 인코딩

```python
y = train['income'].map({'<=50K': 0, '>50K': 1})   # 문자 → 0/1
train = train.drop(columns=['id', 'income'])
test_id = test['id']                                # 제출용 보관
test = test.drop(columns=['id'])

all_df = pd.concat([train, test], axis=0)           # 합쳐서 인코딩
all_oh = pd.get_dummies(all_df)

X = all_oh.iloc[:len(train)]                        # 다시 train 부분
X_test = all_oh.iloc[len(train):]                   # test 부분
```

- 모델은 문자를 그대로 이해하지 못하므로 정답(`income`)을 `map()`으로 **0/1 숫자로 먼저 바꾼다**. 그다음 `train`에서 `id`(식별자, 학습에 무의미)와 `income`(정답, 따로 뺐으니 중복)을 제거해 **순수한 입력 특성(feature)만** 남긴다
- `test`도 `id`를 그대로 두면 제출 파일을 못 만드니 **미리 `test_id`로 따로 빼두고** feature에서는 제거한다
- `train`과 `test`를 **합쳐서** `get_dummies()`로 원핫 인코딩하는 이유: 따로따로 인코딩하면 한쪽에만 있는 범주값(예: train에만 있는 직업 종류) 때문에 **두 데이터의 컬럼 개수가 달라지는 문제**가 생길 수 있다. 합쳐서 인코딩한 뒤 `iloc`으로 다시 잘라내면 컬럼 구성이 항상 동일하게 유지된다

## 6. 검증 데이터 분할 & 학습

```python
from sklearn.model_selection import train_test_split
X_tr, X_val, y_tr, y_val = train_test_split(
    X, y, test_size=0.2, random_state=0, stratify=y)

from sklearn.ensemble import RandomForestClassifier
rf = RandomForestClassifier(n_estimators=100, random_state=0)
rf.fit(X_tr, y_tr)
```

- `train_test_split`으로 학습용(`X_tr`)과 검증용(`X_val`)을 8:2로 나누는 이유: test.csv는 정답이 없어서 모델 성능을 바로 확인할 수 없기 때문에, train 안에서 일부를 떼어 **모델이 안 본 데이터로 미리 성능을 가늠**해보는 것
- `stratify=y`를 쓰는 이유: `income`은 `<=50K`가 `>50K`보다 훨씬 많은 **불균형 데이터**라서, 무작위로 나누면 한쪽에 특정 클래스가 몰릴 수 있다. `stratify=y`는 분할 후에도 원본과 같은 클래스 비율을 유지시켜준다
- 모델로 `RandomForestClassifier`를 고른 이유(수업 맥락): 범주형이 섞인 표 형태 데이터에서 별도 스케일링 없이도 잘 동작하고, 여러 트리의 다수결로 예측하기 때문에 과적합에 비교적 강해 **기본 베이스라인 모델**로 자주 쓰인다

---

## 7. 모델 검증 지표

```python
from sklearn.metrics import accuracy_score, roc_auc_score, classification_report
pred = rf.predict(X_val)
proba = rf.predict_proba(X_val)[:, 1]   # 1(>50K)일 확률 열만 (2차원 슬라이싱)

print('정확도 :', round(accuracy_score(y_val, pred), 4))   # 0.8528
print('ROC-AUC:', round(roc_auc_score(y_val, proba), 4))    # 0.9014
```

- `predict()`는 **최종 클래스(0 또는 1)**, `predict_proba()`는 **각 클래스에 속할 확률**을 반환한다는 차이가 있다. 둘 다 뽑는 이유는 지표마다 필요한 입력이 다르기 때문
- `accuracy_score`는 `predict()`의 결과(딱 잘라진 클래스)로 계산하고, `roc_auc_score`는 `predict_proba()`의 확률값으로 계산한다 — ROC-AUC는 "확률을 얼마나 잘 순서 매겼는가"를 보는 지표라서 0/1이 아니라 **확률이 필요**하기 때문
- `proba[:, 1]`처럼 두 번째 열만 슬라이싱하는 이유: `predict_proba()`는 `[클래스0 확률, 클래스1 확률]` 두 열을 반환하는데, 관심 있는 대상(`>50K`, 양성 클래스)의 확률만 있으면 되므로 인덱스 1번 열만 꺼낸다

---

## 8. test 예측 & 제출 파일 생성

```python
test_proba = rf.predict_proba(X_test)[:, 1]
submit = pd.DataFrame({'id': test_id, 'income': test_proba})
submit.to_csv('submission.csv', index=False)   # index=False 필수
submit.head()
```

- 검증까지 끝난 모델로 **진짜 제출 대상인 `X_test`를 예측**한다. 여기서도 확률(`predict_proba`)을 쓰는 이유는 이 문제의 제출 형식이 클래스가 아니라 **`>50K`일 확률값**이기 때문
- 앞서 따로 빼뒀던 `test_id`를 예측 확률과 **다시 짝지어서** `submit` 데이터프레임을 만든다 — feature에서 `id`를 미리 뺐던 이유가 여기서 회수된다
- `to_csv(..., index=False)`에서 `index=False`가 필수인 이유: 안 붙이면 pandas가 자동으로 매기는 행 번호(0,1,2...)까지 컬럼처럼 저장돼서 제출 형식이 깨진다

## 9. 오늘 배운 것 요약

- 노트북은 **불러오기 → EDA → 결측치 처리 → 타겟 분리/인코딩 → 분할 → 학습 → 평가 → 제출**의 일관된 순서로 짜여 있고, 각 단계는 바로 다음 단계에서 쓸 정보를 준비하는 역할을 한다
- EDA 단계에서 `describe()`의 이상값(음수 나이)과 `info()`의 결측치를 미리 찾아두는 게, 이후 전처리 코드가 **왜 그 컬럼들을 대상으로 하는지**를 결정한다
- 결측치는 train 기준값(중앙값/최빈값)을 test에도 동일 적용해야 **데이터 누수를 막을 수 있다**
- train/test를 합쳐서 원핫 인코딩한 뒤 다시 나누는 이유는 **양쪽의 컬럼 개수를 항상 일치시키기 위함**이다
- `stratify=y`로 분할해야 불균형한 타겟 클래스 비율이 학습/검증 데이터에서도 그대로 유지된다
- `predict()`는 정확도처럼 클래스가 필요한 지표에, `predict_proba()`는 ROC-AUC나 제출 파일처럼 확률이 필요한 곳에 쓰인다는 차이를 명확히 정리했다
