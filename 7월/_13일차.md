## 1. 학습 목표

- **분류(0/1)** 문제를 로지스틱회귀로 풀고, 선형회귀와의 차이(**확률 → 시그모이드 → 임계값**)를 이해한다
- `StandardScaler`로 **스케일을 맞추는 이유**와, 스케일러를 빠뜨리면 예측이 어떻게 망가지는지 직접 확인한다
- 분류 평가지표(**정확도 · ROC-AUC · precision · recall**)를 구분하고, **임계값 조정**으로 recall/precision을 조절한다
- 모델 + 스케일러를 함께 저장(`joblib`)해야 재사용이 가능함을 배운다

## 2. 전체 한 줄 흐름

```
CSV 읽기 → 클래스 균형·상관 확인(EDA) → y 분리 →
train_test_split(stratify) → StandardScaler(fit는 train만) →
LogisticRegression.fit → predict_proba(확률) → 임계값 0.5로 0/1 →
정확도·ROC-AUC·리포트 → 임계값 조정 → 모델+스케일러 함께 저장
```

### 4-3. 시그모이드 — 로지스틱회귀의 심장

```python
z = np.linspace(-8, 8, 100)      # -8~8을 100등분한 배열
sigmoid = 1 / (1 + np.exp(-z))   # 시그모이드 공식
plt.plot(z, sigmoid)
plt.axhline(0.5, color='gray', linestyle='--')
plt.show()
```

| 코드 | 왜 썼는가 | 무슨 뜻인가 |
|---|---|---|
| `np.linspace(-8, 8, 100)` | 곡선을 매끄럽게 그릴 **x축 점**들을 만들려고 | -8부터 8까지 같은 간격으로 100개 값 생성 |
| `np.exp(-z)` | 시그모이드 분모의 e^(-z) 계산 | 배열 z **전체에 한 번에** 지수 적용(numpy 벡터 연산) |
| `1 / (1 + np.exp(-z))` | 어떤 실수든 **0~1 확률**로 눌러 담으려고 | 시그모이드: 큰 z→1, 작은 z→0, z=0→0.5 |

> **핵심:** 선형회귀가 만든 점수 `z`를 시그모이드에 넣으면 **확률(0~1)** 이 된다. 이게 로지스틱회귀가 "회귀"이면서 "분류"인 이유.

## 5. 검증 분할 (stratify가 포인트)

```python
from sklearn.model_selection import train_test_split
y = df['disease']                 # 정답 분리
X = df.drop(columns=['disease'])  # 특성만 남김
X_tr, X_val, y_tr, y_val = train_test_split(
    X, y, test_size=0.2, random_state=0, stratify=y)   # ⭐ stratify=y
```

| 코드 | 왜 썼는가 | 무슨 뜻인가 |
|---|---|---|
| `stratify=y` | 분할 후에도 **59:41 클래스 비율을 train/val 양쪽에 똑같이 유지**하려고 | y의 비율에 맞춰 층화 추출 |
| `random_state=0` | 매번 같은 분할로 재현 | 난수 고정 |

> **출력:** `(800, 4) (200, 4)` → 800개 학습, 200개 검증. stratify 덕분에 양쪽 다 질병 비율이 원본과 같다.
> **분류에서 stratify는 사실상 기본값**으로 챙기는 습관을 들이면 좋다.

## 6. 스케일링 (fit은 train만!)

```python
from sklearn.preprocessing import StandardScaler
scaler = StandardScaler()
X_tr_s  = scaler.fit_transform(X_tr)   # ⭐ train으로 기준 학습 + 변환
X_val_s = scaler.transform(X_val)      # ⭐ 같은 기준으로 변환만
print('배운 평균  :', scaler.mean_.round(2))    # [48.49 24.8 0.31 0.97]
print('배운 표준편차:', scaler.scale_.round(2))  # [17.99 7.8 0.46 0.82]
```

| 코드 | 왜 썼는가 | 무슨 뜻인가 |
|---|---|---|
| `StandardScaler()` | age(수십)·bmi(수십)·smoker(0/1)처럼 **단위가 제각각**이면 계수 비교가 왜곡됨 → 표준화 | 각 특성을 (값-평균)/표준편차로 변환(평균0, 표준편차1) |
| `fit_transform(X_tr)` | **train에서 평균·표준편차를 배우고** 동시에 변환 | 기준(평균/표준편차)을 학습 + 적용 |
| `transform(X_val)` | val을 train과 **같은 기준**으로 맞춰야 공정 | 배운 기준으로 변환만(다시 배우지 않음) |
| `fit`을 val에 안 함 | val 통계로 다시 fit하면 **정보 누수** | 검증 데이터는 "미래"처럼 취급 |

> **암기:** `fit_transform`은 train에만, val/test에는 `transform`만. — 스케일러 누수를 막는 철칙.

## 7. 학습 & 예측

```python
from sklearn.linear_model import LogisticRegression
model = LogisticRegression()
model.fit(X_tr_s, y_tr)
print('계수:', model.coef_[0].round(4))   # [0.3587 0.436 0.1158 -0.2426]
```

```python
pred  = model.predict(X_val_s)               # 0 또는 1
proba = model.predict_proba(X_val_s)[:, 1]   # ⭐ 질병(1)일 확률
```

| 코드 | 왜 썼는가 | 무슨 뜻인가 |
|---|---|---|
| `.predict(...)` | 최종 **0/1 라벨**이 필요할 때 | 확률 0.5 기준으로 잘라 클래스 반환 |
| `.predict_proba(...)` | 확률이 있어야 **임계값 조정·ROC-AUC** 가능 | 각 샘플의 [0확률, 1확률] 반환 |
| `[:, 1]` | 우리가 궁금한 건 "**질병(1)일** 확률" | 2열 중 1번 클래스 열만 슬라이싱 |

> **예측 예시(앞 5명):** 확률 0.641, 0.576, 0.567, **0.346(→0.5 미만이라 예측 0)**, 0.703.
> → **predict = predict_proba를 0.5로 자른 결과**임을 눈으로 확인.

## 8. 평가

```python
from sklearn.metrics import accuracy_score, roc_auc_score, classification_report
print('정확도 :', round(accuracy_score(y_val, pred), 4))    # 0.615
print('ROC-AUC:', round(roc_auc_score(y_val, proba), 4))    # 0.6271
print(classification_report(y_val, pred))
```

| 지표 | 무슨 뜻인가 | 왜 보나 |
|---|---|---|
| **accuracy** | 전체 중 맞힌 비율 | 직관적이지만 불균형에 약함 |
| **ROC-AUC** | 확률로 0/1을 얼마나 잘 **구분**하는가(0.5=찍기, 1=완벽) | 임계값과 무관한 순위 성능 |
| **precision** | 1이라 예측한 것 중 진짜 1의 비율 | 오탐(FP)이 비쌀 때 중요 |
| **recall** | 진짜 1 중 잡아낸 비율 | **놓치면 안 될 때**(질병 등) 중요 |

> **출력:** 정확도 0.615, ROC-AUC 0.627. 질병(1)의 recall 0.74 → 실제 환자를 잘 잡는 편.
> (이 데이터는 특성-질병 관계가 약해 성능 자체는 낮음 — 정상적인 결과.)

```python
loaded_model  = joblib.load('model_disease.pkl')
loaded_scaler = joblib.load('scaler_disease.pkl')

print('스케일러 X -> 질병확률 %.3f' % loaded_model.predict_proba(new)[0, 1])                            # 1.000
```

| 코드 | 왜 썼는가 | 무슨 뜻인가 |
|---|---|---|
| `joblib.dump/load` | 모델을 파일로 저장/재사용하려고 | 파이썬 객체를 `.pkl`로 직렬화/복원 |
| **model + scaler 둘 다 저장** | 모델은 **스케일된 값으로 학습**됐으므로, 새 데이터도 똑같이 스케일해야 함 | 스케일러가 없으면 입력 단위가 달라 결과가 깨짐 |

## 11. (보너스) 스케일링 유무 비교 & 임계값 조정

### 11-1. 스케일 안 한 원본으로 학습하면?

```python
m_raw = LogisticRegression().fit(X_tr, y_tr)   # 스케일 X
# [O] 정확도 0.6150 | AUC 0.6271
# [X] 정확도 0.6150 | AUC 0.6260
```

> 성능(정확도·AUC)은 거의 같지만, **계수 크기 비교가 불가능**해진다(단위가 뒤섞여서). 스케일링의 진짜 이득은 **해석 가능성**.

### 11-2. 임계값을 낮추면 recall이 오른다

```python
from sklearn.metrics import recall_score, precision_score
for t in [0.5, 0.3]:
    pt = (proba >= t).astype(int)
    print('임계값 %.1f -> 정확도 %.4f | recall %.4f | precision %.4f'
          % (t, accuracy_score(y_val, pt), recall_score(y_val, pt), precision_score(y_val, pt)))
```

| 코드 | 왜 썼는가 | 무슨 뜻인가 |
|---|---|---|
| `(proba >= t).astype(int)` | 기준선 t를 바꿔 0/1 판정을 조절하려고 | 확률이 t 이상이면 1, 아니면 0(불리언→정수) |

> **출력:**
> 임계값 0.5 → recall 0.737 / precision 0.654
> 임계값 0.3 → **recall 1.000** / precision 0.605
>
> **트레이드오프:** 임계값을 낮추면 **놓치는 환자↓(recall↑)** 대신 오탐↑(precision↓). 질병처럼 **놓치면 위험한 문제**는 임계값을 낮춰 recall을 확보한다.

## 12. 오늘 배운 것 요약

- 로지스틱회귀 = 선형 점수 `z` → **시그모이드로 확률(0~1)** → **임계값(기본 0.5)으로 0/1**. `predict`는 `predict_proba`를 0.5로 자른 것
- 분류 분할은 `stratify=y`로 **클래스 비율 유지**, 스케일링은 `fit`을 **train에만**(val/test는 `transform`만) — 둘 다 정보 누수 방지
- 저장할 땐 **모델 + 스케일러를 한 세트**로. 스케일러를 빠뜨리면 같은 입력도 결과가 완전히 달라진다(0.806 vs 1.000)
- 평가는 상황에 맞게: 놓치면 안 되는 문제는 **recall**, 오탐이 비싼 문제는 **precision**, 임계값 무관 순위력은 **ROC-AUC**
- 스케일링은 성능보다 **계수 해석(영향력 순위)** 을 위한 것 — 여기선 bmi > age > smoker > (activity_level은 음수, 위험↓)

### 헷갈리기 쉬운 포인트

| 개념 | 기억법 |
|---|---|
| `predict` vs `predict_proba` | predict=0/1 라벨, predict_proba=확률(임계값·AUC에 필요) |
| `fit_transform` vs `transform` | **train만 fit**, val/test는 transform만 |
| `stratify=y` | 분류 분할에서 **클래스 비율 복사기** |
| 임계값 ↓ | recall↑ · precision↓ (놓침 줄고 오탐 늘고) |
| 계수 부호 | 양수=위험↑, 음수=위험↓ (스케일 맞춰야 크기 비교 가능) |
