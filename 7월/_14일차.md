## 1. 학습 목표

- **군집화(Clustering)**: `KMeans`로 데이터를 k개의 무리로 나누고, **실루엣 점수**와 **Elbow Method**로 k가 적절한지 판단한다
- **차원축소(Dimensionality Reduction)**: `PCA`로 특성 개수를 줄이면서 **정보(분산)를 얼마나 지켰는지** 수치로 확인한다
- **연관규칙(Association Rules)**: `apriori` + `association_rules`로 장바구니 데이터에서 "A를 사면 B도 산다"는 규칙을 **지지도·신뢰도·향상도**로 뽑아낸다
- 세 기법이 **정답 컬럼을 쓰지 않는다**는 공통점과, 각각의 전처리 요구사항(스케일링 필요 여부)을 구분한다

## 2. 비지도학습 큰 그림

| 구분 | 지도학습 | 비지도학습 |
|---|---|---|
| 입력 | X(특성) + y(정답) | X만 |
| 목적 | y를 맞히기 | X 안의 숨은 구조 찾기 |
| 대표 | 분류, 회귀 | 군집화, 차원축소, 연관규칙, 이상치 탐지 |
| 평가 | 정확도, RMSE 등 정답 기준 | 실루엣, 설명분산비, 향상도 등 **내부 지표** |

> 핵심: 정답이 없으니 "맞았다/틀렸다"가 아니라 **"잘 뭉쳤나 / 잘 남겼나 / 우연보다 강한가"** 를 본다.

```
원본 데이터 (정답 없음)
   │
   ├─ 군집화   → 행(샘플)을 무리로 묶음      → 고객 세그먼트
   ├─ 차원축소 → 열(특성)을 새 축으로 압축   → 시각화 / 속도 / 노이즈 제거
   └─ 연관규칙 → 항목 간 동시 등장 관계 발견 → 상품 추천 / 진열
```

## 3. 군집화 — K-Means

### 3-1. K-Means가 도는 방식 (알고리즘 4단계)

```
1) 중심점(centroid) k개를 무작위로 찍는다
2) 모든 점을 "가장 가까운 중심점"에 배정한다      ← 유클리드 거리
3) 각 무리의 평균 위치로 중심점을 옮긴다
4) 중심점이 더 안 움직일 때까지 2~3 반복
```

> 2번이 **거리 기반**이라는 점이 뒤에 나오는 `StandardScaler`가 필수인 이유입니다.

### 3-2. 실습 ①: 붓꽃(iris) 3개 무리로 나누기

```python
from sklearn.datasets import load_iris
from sklearn.cluster import KMeans

X = load_iris().data                 # 붓꽃 특성 4개 (정답인 품종은 안 씀)
km = KMeans(n_clusters=3, random_state=0, n_init=10)
labels = km.fit_predict(X)           # 각 꽃이 몇 번 무리인지 (0,1,2)
print(labels[:])
```

**한 줄씩 뜯어보기**

| 코드 | 왜 쓰였나 / 어떻게 작동하나 |
|---|---|
| `load_iris().data` | iris 데이터 객체에서 **특성 행렬만** 꺼냅니다. `.target`(품종 정답)은 일부러 안 씁니다 → 비지도학습이니까. 결과는 `(150, 4)` NumPy 배열 |
| `n_clusters=3` | 무리를 몇 개로 나눌지 **사람이 정하는 값**. K-Means는 k를 스스로 못 정합니다 |
| `random_state=0` | 1단계의 "무작위 중심점 찍기"를 고정 → 실행할 때마다 같은 결과. 재현성 확보용 |
| `n_init=10` | 초기 중심점을 **10번 다르게 시도**해서 그중 가장 잘 뭉친(inertia 최소) 결과를 채택. 운 나쁜 초기값에 빠지는 걸 방지 |
| `fit_predict(X)` | `fit`(학습: 중심점 찾기) + `predict`(각 점에 무리 번호 부여)를 한 번에. 반환값은 길이 150의 정수 배열 |
| `labels[:]` | 전체 슬라이싱. `labels`와 동일 (관행상 `[:10]`처럼 앞부분만 보는 코드에서 숫자를 지운 형태) |

**실행 결과**

```
[1 1 1 ... 1 0 0 2 0 0 ... 2 2 0 2 2 2 ... 2 0]
```

**해석 포인트**

- 앞 50개가 전부 `1` → setosa 품종이 **깔끔하게 한 무리로 분리**됨
- 뒤 100개에서 `0`과 `2`가 섞임 → versicolor/virginica는 특성이 겹쳐서 경계가 흐림
- ⚠️ **라벨 번호 자체에는 의미가 없습니다.** `0`이 특정 품종이라는 뜻이 아니라 그냥 "0번 무리"입니다. `random_state`를 바꾸면 번호가 통째로 뒤바뀔 수 있습니다

### 3-3. 실습 ②: 와인 데이터 + 스케일링 + 실루엣 점수

```python
import numpy as np
from sklearn.datasets import load_wine
from sklearn.preprocessing import StandardScaler
from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score

X = load_wine().data                        # 와인 성분 13개 (단위가 제각각)
X_s = StandardScaler().fit_transform(X)     # 같은 잣대로 맞추기 (거리 기반이라 필수)

km = KMeans(n_clusters=2, random_state=0, n_init=10)
labels = km.fit_predict(X_s)

print('무리별 개수:', np.bincount(labels))
print('실루엣 점수:', round(silhouette_score(X_s, labels), 3))
```

**한 줄씩 뜯어보기**

| 코드 | 왜 쓰였나 / 어떻게 작동하나 |
|---|---|
| `load_wine().data` | 와인 178개 × 성분 13개. **문제는 단위**: `proline`은 수백~수천, `hue`는 0~2 |
| `StandardScaler()` | 각 열을 **평균 0, 표준편차 1**로 변환: `z = (x - 평균) / 표준편차` |
| `.fit_transform(X)` | `fit`(각 열의 평균·표준편차 계산) + `transform`(실제 변환)을 한 번에 |
| 스케일링이 **왜 필수**인가 | 안 하면 `proline` 한 열이 거리 계산을 독점합니다. 두 점의 거리 = √(Σ 각 축 차이²) 인데, 값의 스케일이 1000배면 그 축의 차이²가 100만 배가 되어 나머지 12개 성분이 무시됩니다 |
| `np.bincount(labels)` | 0,1,2… 각 숫자가 **몇 번 나왔는지** 세는 NumPy 함수. `[113 65]` = 0번 무리 113개, 1번 무리 65개 |
| `silhouette_score(X_s, labels)` | 군집이 잘 나뉘었는지 **정답 없이** 채점 |

**실루엣 점수(silhouette) 이해하기**

한 점 i에 대해:

```
a = 같은 무리 안 다른 점들과의 평균 거리   (작을수록 좋음 = 잘 뭉침)
b = 가장 가까운 다른 무리 점들과의 평균 거리 (클수록 좋음 = 잘 떨어짐)

s(i) = (b - a) / max(a, b)
```

| 점수 범위 | 의미 |
|---|---|
| 1에 가까움 | 자기 무리에 딱 붙고 남의 무리와 멀다 → 아주 좋음 |
| 0 근처 | 경계선에 걸쳐 있음 → 애매 |
| 음수 | 남의 무리가 더 가깝다 → **잘못 배정됨** |

**실행 결과**

```
무리별 개수: [113  65]
실루엣 점수: 0.268
```

> 0.268은 낮은 편입니다. 13차원 원본 공간에서는 **차원의 저주**로 점들 사이 거리가 다 비슷비슷해져서 대비가 흐려지기 때문입니다. → 4장 PCA로 이어지는 문제의식.

> ⚠️ `silhouette_score`의 첫 인자는 **군집을 만들 때 쓴 것과 같은 공간의 데이터**여야 합니다. `X_s`로 학습했으면 `X_s`로 평가해야 공정합니다.

### 3-4. 실습 ③: 몰 고객 세그먼트 (실무형)

```python
import pandas as pd
from sklearn.preprocessing import StandardScaler
from sklearn.cluster import KMeans

url = 'https://raw.githubusercontent.com/tirthajyoti/Machine-Learning-with-Python/master/Datasets/Mall_Customers.csv'
df = pd.read_csv(url)                # 고객 200명 (다운로드 불필요)
X = df[['Annual Income (k$)', 'Spending Score (1-100)']]  # 연소득·소비점수
X_s = StandardScaler().fit_transform(X)

km = KMeans(n_clusters=5, random_state=0, n_init=10)
df['segment'] = km.fit_predict(X_s)                       # 고객을 5유형으로

print(df.groupby('segment')[['Annual Income (k$)', 'Spending Score (1-100)']].mean().round(1))
print('실루엣 점수:', round(silhouette_score(X_s, df['segment']), 3))
```

**한 줄씩 뜯어보기**

| 코드 | 왜 쓰였나 / 어떻게 작동하나 |
|---|---|
| `pd.read_csv(url)` | pandas는 로컬 경로뿐 아니라 **URL도 그대로** 읽습니다 → 파일 다운로드 단계 생략 |
| `df[['A', 'B']]` | 대괄호 **두 겹**. 바깥은 인덱싱, 안쪽은 컬럼 이름 리스트 → 결과가 DataFrame(2차원). 대괄호 한 겹이면 Series(1차원)가 나와 sklearn이 거부합니다 |
| 왜 2개 컬럼만? | 세그먼트를 **비즈니스 언어로 해석**하려고. "돈은 있는데 안 쓰는 층" 같은 결론이 바로 나옵니다 |
| `df['segment'] = km.fit_predict(X_s)` | 예측 결과(길이 200 배열)를 **원본 DataFrame에 새 컬럼으로 붙임**. 이제 원래 정보(나이·성별 등)와 함께 볼 수 있습니다 |
| `.groupby('segment')[[...]].mean()` | 세그먼트별로 묶어서 두 컬럼의 **평균 프로필**을 계산 → 각 무리의 성격을 읽는 핵심 단계 |
| `.round(1)` | 소수점 1자리로 정리 (가독성) |

**실행 결과와 비즈니스 해석**

```
         Annual Income (k$)  Spending Score (1-100)
segment
0                      55.3                    49.5
1                      86.5                    82.1
2                      88.2                    17.1
3                      26.3                    20.9
4                      25.7                    79.4
실루엣 점수: 0.555
```

| 세그먼트 | 소득 | 소비 | 이름 붙이기 | 액션 |
|---|---|---|---|---|
| 0 | 중 | 중 | 평범한 다수 | 유지 |
| 1 | 고 | 고 | **VIP** | 프리미엄·멤버십 |
| 2 | 고 | 저 | 지갑은 두꺼운데 안 씀 | 타겟 프로모션 (기회) |
| 3 | 저 | 저 | 저관여 | 비용 최소화 |
| 4 | 저 | 고 | 소득 대비 과소비 | 할인·적립 민감 |

> 실루엣 **0.555** — 3-3의 0.268보다 훨씬 높습니다. 이유는 특성이 2개뿐이라 구조가 선명하기 때문. **차원이 낮으면 군집이 잘 잡힌다**는 사실을 여기서 실감할 수 있습니다.

### 3-5. Elbow Method로 k 정하기 (+ 오늘 만난 에러)

**에러가 났던 코드**

```python
inertia = []
K = df['segment']        # ❌ 여기가 문제

for k in K:
    kmeans = KMeans(n_clusters=k, random_state=42)
    kmeans.fit(X_s)
    inertia.append(kmeans.inertia_)
```

```
InvalidParameterError: The 'n_clusters' parameter of KMeans must be
an int in the range [1, inf). Got 0 instead.
```

**원인 분석**

- `K`에는 **1~10 범위의 후보 k 값**이 들어가야 하는데, `df['segment']`(각 고객의 세그먼트 번호 0~4, 길이 200)를 넣었습니다
- 첫 번째 값이 `0` → `n_clusters=0`은 불가능 → 파라미터 검증 단계에서 즉시 예외 발생
- 설령 0이 없었어도 200번 반복 + 값 중복이라 Elbow 그래프 자체가 성립하지 않습니다

**고친 코드**

```python
from sklearn.cluster import KMeans
import matplotlib.pyplot as plt

inertia = []              # 각 k에 대한 군집 내 거리 제곱합을 저장할 리스트
K = range(1, 11)          # ✅ k 후보 1~10

for k in K:
    kmeans = KMeans(n_clusters=k, random_state=42, n_init=10)
    kmeans.fit(X_s)                  # 학습만 하면 됨 (라벨은 필요 없음)
    inertia.append(kmeans.inertia_)  # 관성값 수집

plt.figure(figsize=(8, 5))
plt.plot(K, inertia, 'bx-')          # b=파랑, x=X마커, -=실선
plt.xlabel('Cluster Count (k)')
plt.ylabel('Inertia')
plt.title('Elbow Method to find k')
plt.show()
```

| 코드 | 설명 |
|---|---|
| `range(1, 11)` | 1부터 10까지. 파이썬 `range`는 **끝 값을 포함하지 않음** |
| `kmeans.inertia_` | **관성(inertia)** = Σ(각 점 → 자기 중심점 거리)². 무리가 얼마나 촘촘한지. 끝의 `_`는 sklearn에서 "학습 후 생성된 값"이라는 표시 |
| `.fit()`만 호출 | Elbow는 라벨이 아니라 inertia만 필요하므로 `fit_predict`까지 안 가도 됩니다 |
| `'bx-'` | matplotlib 축약 포맷 문자열 (color + marker + linestyle) |

**Elbow 읽는 법**

```
inertia
  │＼
  │  ＼
  │    ＼___          ← 여기 꺾이는 지점(팔꿈치)이 적정 k
  │        ＼____
  └──────────────── k
```

- k가 커지면 inertia는 **무조건 감소**합니다 (k = 데이터 개수면 0). 그래서 "최소값"이 아니라 **감소 속도가 확 꺾이는 지점**을 봅니다
- Elbow가 애매하면 **실루엣 점수를 k별로 찍어서** 최대인 지점을 고르는 게 더 명확합니다

## 4. 차원축소 — PCA

### 4-1. PCA가 하는 일

```
원래 축(특성 4개)                 새 축(주성분)
  ↓                                ↓
데이터가 가장 넓게 퍼진 방향을 찾아 → 그 방향을 1번 축(PC1)으로
그와 직각이면서 그다음 넓은 방향  → 2번 축(PC2)으로
...상위 몇 개만 남기고 나머지 버림
```

- **핵심 아이디어**: 데이터가 **많이 퍼진(분산이 큰) 방향 = 정보가 많은 방향**
- 컬럼을 골라내는 게 아니라, **기존 컬럼들을 섞어서 새 축을 만드는 것** (특성 선택 ≠ 특성 추출)

### 4-2. 실습 ①: iris 4차원 → 2차원

```python
from sklearn.datasets import load_iris
from sklearn.decomposition import PCA

X = load_iris().data                  # 특성 4개 (=4차원)
pca = PCA(n_components=2)             # 2차원으로 줄이기
X_2d = pca.fit_transform(X)
print('줄인 뒤 모양:', X_2d.shape)
print('남긴 정보 비율:', pca.explained_variance_ratio_.round(2))
```

| 코드 | 왜 쓰였나 / 어떻게 작동하나 |
|---|---|
| `PCA(n_components=2)` | 남길 주성분 개수. 2로 두면 산점도로 **눈에 보이게** 그릴 수 있습니다 |
| `fit_transform(X)` | `fit`(공분산 행렬 → 고유벡터 계산으로 새 축 찾기) + `transform`(그 축에 데이터 투영) |
| `X_2d.shape` | `(150, 2)` — 행(샘플 수)은 그대로, **열만 4 → 2로 줄었습니다** |
| `explained_variance_ratio_` | 각 주성분이 원본 분산의 몇 %를 설명하는지. 끝의 `_` = 학습 후 값 |

**실행 결과**

```
줄인 뒤 모양: (150, 2)
남긴 정보 비율: [0.92 0.05]
```

- PC1 혼자 **92%**, PC2까지 합치면 **97%** → 열을 절반으로 줄이고도 정보를 거의 다 지켰습니다
- 결과 값 예시: `[-2.684, 0.319]` — **원래 cm 단위와 무관한 새 좌표**입니다. "꽃잎 길이"처럼 직접 해석되지 않는 게 PCA의 대가(代價)

### 4-3. 실습 ②: PCA 후 군집화 — 실루엣 점수가 뛴다

```python
km = KMeans(n_clusters=2, random_state=0, n_init=10)
labels = km.fit_predict(X_2d)          # 2차원 공간에서 군집화

print('무리별 개수:', np.bincount(labels))
print('실루엣 점수:', round(silhouette_score(X_2d, labels), 3))
```

### 4-4. 실습 ③: 와인 품질 11차원 → 2차원 (스케일링의 위력)

## 5. 연관규칙 — Apriori

### 5-1. 세 가지 지표부터 확실히

영수증 5장 예시로 손으로 계산해봅니다.

```
1: 라면, 계란, 우유
2: 라면, 계란
3: 라면, 계란, 콜라
4: 우유, 빵
5: 라면, 콜라
```

| 지표 | 공식 | 의미 | 계산 예 (계란 → 라면) |
|---|---|---|---|
| **지지도(support)** | 해당 조합 포함 영수증 수 ÷ 전체 | 얼마나 **자주** 등장하나 | (계란∩라면) 3장 / 5장 = **0.6** |
| **신뢰도(confidence)** | support(A∩B) ÷ support(A) | A를 산 사람 중 B도 산 **비율** | 0.6 / 0.6 = **1.00** |
| **향상도(lift)** | confidence ÷ support(B) | 우연보다 **몇 배** 강한가 | 1.00 / 0.8 = **1.25** |

**향상도가 가장 중요한 이유**

- 라면은 원래 5장 중 4장(80%)에 나옵니다. 그러니 "신뢰도 100%"만 보면 착각하기 쉽습니다
- 향상도는 그 **기본 인기도를 나눠서 보정**합니다

| 향상도 | 해석 |
|---|---|
| **> 1** | 양의 관계 — 같이 살 확률이 우연보다 높음 |
| **= 1** | 무관 — 그냥 우연 |
| **< 1** | 음의 관계 — 오히려 같이 안 삼 (대체재) |

> ⚠️ 신뢰도만 보면 **인기 상품이 결과(consequents)인 규칙**이 무조건 높게 나옵니다. 향상도로 걸러야 진짜 관계가 남습니다.

### 5-2. 실습 ①: 리스트 → True/False 표 만들기

```python
import pandas as pd
from mlxtend.frequent_patterns import apriori, association_rules

receipts = [
    ['라면', '계란', '우유'],
    ['라면', '계란'],
    ['라면', '계란', '콜라'],
    ['우유', '빵'],
    ['라면', '콜라'],
]

# ① 표로 바꾸기 — 샀으면 True
items = sorted({i for r in receipts for i in r})
items
```

```
['계란', '라면', '빵', '우유', '콜라']
```

**`{i for r in receipts for i in r}` 뜯어보기 — 오늘 가장 헷갈린 문법**

```python
# 집합 컴프리헨션. 읽는 순서는 왼쪽 for부터.
{i for r in receipts for i in r}

# 풀어 쓰면:
result = set()
for r in receipts:      # r = 영수증 한 장 (리스트)
    for i in r:         # i = 그 안의 상품 하나
        result.add(i)   # set이라 중복 자동 제거
```

| 요소 | 역할 |
|---|---|
| `{...}` | **set**(집합) — 중복 자동 제거. `[...]`이면 리스트라 중복이 남습니다 |
| 첫 번째 `for r in receipts` | 바깥 루프 (영수증 단위) |
| 두 번째 `for i in r` | 안쪽 루프 (상품 단위) — **중첩 순서가 왼→오른쪽** |
| `sorted(...)` | set은 순서가 없으므로 정렬해서 **컬럼 순서를 고정**. 결과는 리스트 |

> Java로 치면 `for (List<String> r : receipts) { for (String i : r) { set.add(i); } }` 를 한 줄로 쓴 것입니다.

```python
df = pd.DataFrame([{i: (i in r) for i in items} for r in receipts])
df
```

```
      계란     라면      빵     우유     콜라
0   True   True  False   True  False
1   True   True  False  False  False
2   True   True  False  False   True
3  False  False   True   True  False
4  False   True  False  False   True
```

**이중 컴프리헨션 뜯어보기**

```python
[ {i: (i in r) for i in items}      # ← 안쪽: 딕셔너리 하나 = 표의 한 행
  for r in receipts ]               # ← 바깥: 영수증마다 반복 → 딕셔너리 리스트
```

- `i in r` → 그 영수증에 상품 i가 있으면 `True`
- 결과: `[{'계란': True, '라면': True, ...}, {...}, ...]`
- `pd.DataFrame(딕셔너리 리스트)` → **딕셔너리의 key가 컬럼명**, 각 딕셔너리가 한 행이 됩니다
- 이 **원-핫(one-hot) 형태**가 `apriori`가 요구하는 유일한 입력 형식입니다

### 5-3. 실습 ②: 빈발 항목집합 찾기

```python
freq = apriori(df, min_support=0.4, use_colnames=True)
freq
```

```
   support  itemsets
0      0.6      (계란)
1      0.8      (라면)
2      0.4      (우유)
3      0.4      (콜라)
4      0.6  (계란, 라면)
5      0.4  (라면, 콜라)
```

| 인자 | 역할 |
|---|---|
| `df` | True/False 원-핫 표 (숫자 0/1도 가능) |
| `min_support=0.4` | 지지도 0.4 미만 조합은 **버림**. 5장 기준 2장 미만은 제외 |
| `use_colnames=True` | 결과에 **컬럼 이름**을 표시. `False`면 컬럼 인덱스 숫자로 나와 읽기 어렵습니다 |

**Apriori 알고리즘의 핵심 원리**

```
"자주 나오지 않는 조합의 상위 조합은, 절대 자주 나올 수 없다"
   (계란)이 0.4 미만이면 → (계란, 라면)도 반드시 0.4 미만
```

- 이 **가지치기(pruning)** 덕분에 상품 수가 많아도 조합 폭발을 피합니다
- 상품 n개의 모든 조합은 2ⁿ개 → 그냥 세면 계산 불가. Apriori는 크기 1 → 2 → 3 순으로 올라가며 살아남은 것만 확장합니다
- 빵(0.2), 우유+빵(0.2) 등은 `min_support` 미달로 표에서 사라진 것을 확인할 수 있습니다

### 5-4. 실습 ③: 규칙 뽑기

```python
rules = association_rules(freq, metric='lift', min_threshold=1.0)
print(rules[['antecedents', 'consequents', 'support', 'confidence', 'lift']])
```

```
  antecedents consequents  support  confidence  lift
0        (계란)        (라면)      0.6        1.00  1.25
1        (라면)        (계란)      0.6        0.75  1.25
2        (라면)        (콜라)      0.4        0.50  1.25
3        (콜라)        (라면)      0.4        1.00  1.25
```

| 코드 | 설명 |
|---|---|
| `association_rules(freq, ...)` | 빈발 조합을 **양방향 규칙으로 전개**합니다. `(계란, 라면)` 하나에서 `계란→라면`, `라면→계란` 두 규칙이 나옵니다 |
| `metric='lift'` | 어떤 지표로 규칙을 거를지. `'confidence'`, `'support'`, `'leverage'` 등도 가능 |
| `min_threshold=1.0` | 그 지표가 이 값 이상인 규칙만 남김. lift 1.0 = **우연 이상인 것만** |
| `antecedents` | 조건(선행) — "이걸 사면" |
| `consequents` | 결과(후행) — "저것도 산다" |

**결과 해석 — 방향이 왜 중요한가**

| 규칙 | 신뢰도 | 읽는 법 |
|---|---|---|
| 계란 → 라면 | 1.00 | 계란 산 사람은 **100%** 라면도 삼 |
| 라면 → 계란 | 0.75 | 라면 산 사람 중 **75%**만 계란을 삼 |

- 같은 조합인데 **신뢰도가 다릅니다**. 분모(선행 항목의 지지도)가 다르기 때문
- 향상도는 대칭이라 양쪽 다 1.25 → **관계의 세기는 같고, 방향성만 다르다**
- 실무 적용: 계란 진열대 옆에 라면을 두는 게, 라면 옆에 계란을 두는 것보다 효율이 높음

### 5-5. 실습 ④: `TransactionEncoder`로 간편하게

```python
import pandas as pd
from mlxtend.preprocessing import TransactionEncoder
from mlxtend.frequent_patterns import apriori, association_rules

data = [['라면','계란'], ['라면','계란','콜라'], ['라면','콜라'], ['우유','빵'], ['라면','계란']]
te = TransactionEncoder()
df = pd.DataFrame(te.fit(data).transform(data), columns=te.columns_)   # 0/1 표로

freq = apriori(df, min_support=0.4, use_colnames=True)
rules = association_rules(freq, metric='confidence', min_threshold=0.6)
print(rules[['antecedents','consequents','support','confidence','lift']])
```

```
  antecedents consequents  support  confidence  lift
0        (계란)        (라면)      0.6        1.00  1.25
1        (라면)        (계란)      0.6        0.75  1.25
2        (콜라)        (라면)      0.4        1.00  1.25
```

| 코드 | 설명 |
|---|---|
| `TransactionEncoder()` | 5-2에서 손으로 만든 원-핫 변환을 **한 줄로 대체**하는 도구 |
| `te.fit(data)` | 전체 데이터를 훑어 **고유 상품 목록**을 수집 |
| `.transform(data)` | 각 거래를 True/False **NumPy 배열**로 변환 |
| `te.columns_` | 수집된 상품 이름 리스트. 끝의 `_` = 학습 후 생성 |
| `pd.DataFrame(배열, columns=...)` | 배열에 컬럼명을 붙여 DataFrame으로 |
| `metric='confidence', min_threshold=0.6` | 이번엔 **신뢰도 60% 이상**만. 그래서 `라면→콜라`(0.50)가 탈락했습니다 |

> 앞의 lift 기준 결과와 비교하면, **기준(metric)을 바꾸면 살아남는 규칙이 달라진다**는 걸 바로 확인할 수 있습니다.

**실전 데이터 적용**

```python
import urllib.request

data = [ln.split(',') for ln in lines]         # 한 줄 = 한 번의 장바구니

te = TransactionEncoder()
df = pd.DataFrame(te.fit(data).transform(data), columns=te.columns_)

freq = apriori(df, min_support=0.02, use_colnames=True)        # 2% 이상 등장
rules = association_rules(freq, metric='confidence', min_threshold=0.3)
rules = rules.sort_values('lift', ascending=False)
print(rules[['antecedents','consequents','support','confidence','lift']].head())
```

|---|---|
| `urllib.request.urlopen(url).read()` | 원시 바이트를 받아옵니다. 행마다 상품 개수가 달라 `pd.read_csv`로는 못 읽는 **비정형 CSV**라서 직접 처리 |

## 6. 세 기법 한눈에 비교

| | 군집화 (KMeans) | 차원축소 (PCA) | 연관규칙 (Apriori) |
|---|---|---|---|
| 무엇을 줄이나 | **행**을 그룹으로 | **열**을 새 축으로 | 줄이지 않고 **관계**를 찾음 |
| 입력 형태 | 수치형 행렬 | 수치형 행렬 | True/False 원-핫 표 |
| 스케일링 | **필수** (거리 기반) | **필수** (분산 기반) | 불필요 (0/1이라) |
| 사람이 정할 값 | `n_clusters` | `n_components` | `min_support`, `min_threshold` |
| 평가 지표 | 실루엣, inertia(Elbow) | `explained_variance_ratio_` | support / confidence / **lift** |
| 대표 활용 | 고객 세그먼트 | 시각화·전처리·노이즈 제거 | 장바구니 분석·추천 |
| 결과 해석 | 무리별 평균 프로필 | 새 축은 직접 해석 어려움 | "A 사면 B" 문장으로 바로 |

**연결 고리**: `PCA → KMeans` 파이프라인은 실무 정석입니다. 고차원에서 흐려진 거리 대비를 PCA로 되살린 뒤 군집화하면 실루엣이 올라갑니다 (오늘 iris에서 확인: 0.268 → 0.706 수준의 차이).

## 8. 한 줄 흐름 정리

```
[군집화]   원본 → StandardScaler → KMeans(k) → 실루엣/Elbow로 k 검증 → groupby로 프로필 해석
[차원축소] 원본 → StandardScaler → PCA(n) → explained_variance_ratio_로 손실 확인 → 시각화/모델 입력
[연관규칙] 거래 리스트 → TransactionEncoder(원-핫) → apriori(min_support) → association_rules(lift) → 정렬
```

## 9. 오늘 배운 것 요약

- **K-Means**는 "중심점 찍고 → 가까운 것 배정 → 중심 이동"을 반복하는 **거리 기반** 알고리즘이라 `StandardScaler`가 사실상 필수다
- k는 알고리즘이 아니라 **사람이 정한다**. `Elbow(inertia 꺾이는 지점)` + `실루엣 점수(최대 지점)` 두 가지로 교차 검증한다
- 실루엣은 **-1~1**, 1에 가까울수록 좋고 **차원이 낮을수록 높게 나오는 경향**이 있다 (wine 13D 0.268 vs iris 2D 0.706)
- **PCA**는 분산이 큰 방향을 새 축으로 삼아 열을 압축한다. `explained_variance_ratio_`로 **얼마나 잃었는지 반드시 확인**한다 (iris 2축 97% vs 와인품질 2축 46%)
- PCA 결과 축은 원래 특성 이름으로 해석되지 않는다 — **정보량과 해석 가능성의 트레이드오프**
- **Apriori**는 "자주 안 나오는 조합의 상위 조합도 자주 안 나온다"는 가지치기로 조합 폭발을 막는다
- 규칙 판단은 **support(빈도) → confidence(비율) → lift(우연 대비 배수)** 순서로 보되, **최종 판단은 lift**로 한다
- 세 기법 모두 **정답 컬럼을 쓰지 않는다**. 그래서 "정확도" 대신 **내부 지표(실루엣 / 설명분산비 / 향상도)** 로 품질을 판단한다

## 부록. 같은 흐름의 이상치 탐지 (참고)

비지도학습 계열이라 함께 정리해 둡니다.

| 알고리즘 | 원리 | 핵심 파라미터 | 출력 |
|---|---|---|---|
| **Isolation Forest** | 무작위 트리로 빨리 고립되는 점 = 이상치 | `contamination` | 1 / -1 |
| **LOF** | 주변 이웃 대비 **국소 밀도**가 낮으면 이상치 | `n_neighbors`, `contamination` | 1 / -1, `negative_outlier_factor_` |
| **One-Class SVM** | 정상 데이터만 학습해 **경계**를 그림 | `nu`, `gamma`, `kernel` | 1 / -1, `decision_function()` |
| **DBSCAN** | 밀집 영역 밖 = 노이즈 | `eps`, `min_samples` | 라벨 (-1 = 노이즈) |
| **GMM** | 확률이 매우 낮은 영역 = 이상치 | `n_components` | 확률 밀도 |

```python
from sklearn.neighbors import LocalOutlierFactor
model = LocalOutlierFactor(n_neighbors=20, contamination=0.02)
predictions = model.fit_predict(X_data)      # -1=이상치, 1=정상
scores = model.negative_outlier_factor_      # 낮을수록(음수 폭 클수록) 강한 이상치
```

```python
from sklearn.svm import OneClassSVM
model = OneClassSVM(kernel="rbf", nu=0.1, gamma=0.1)
model.fit(X_train_scaled)                    # 정상 데이터만으로 학습
predictions = model.predict(X_test_scaled)   # 1=경계 안, -1=경계 밖
scores = model.decision_function(X_test_scaled)  # 양수=정상, 음수=이상치
```

> 공통 규약: sklearn 이상치 탐지기는 **정상 = 1, 이상치 = -1**로 반환하고, **점수는 낮을수록 이상치**입니다.
> LOF는 `fit_predict`만 있고 `predict`가 없습니다(새 데이터 예측용이 아닌 배치 탐지용). One-Class SVM은 `fit` 후 `predict`가 가능해 **새 데이터에도 적용**할 수 있습니다.
