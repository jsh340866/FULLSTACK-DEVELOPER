# TIL: PySpark로 공공데이터(착한가격업소) 전처리 · 집계 · Parquet 저장

> 📅 2026-07-28
> 주제: SparkSession 생성 → CSV 로드 → Wide→Long 변환(`stack`) → 정규식 가격 파싱 → groupBy 집계 → Window 함수 → Parquet 파티션 저장
> 데이터: 행정안전부 착한가격업소 현황 (20260630 기준, 12,645행 × 14컬럼)

## 1. 학습 목표

- **SparkSession**을 로컬 모드로 띄우고 Spark DataFrame API의 기본 흐름(로드 → 변환 → 집계 → 저장)을 한 사이클 돌린다
- **Wide 포맷(메뉴1~4, 가격1~4)** 을 `stack()`으로 **Long 포맷(1행 = 1메뉴)** 으로 바꾸는 이유와 방법을 익힌다
- 지저분한 문자열 가격을 **정규식 + `try_cast`** 로 안전하게 정수화한다 (예외 없이 NULL 처리)
- `groupBy().agg()`와 **Window 함수**의 차이를 구분해서 쓴다
- **Parquet + partitionBy** 로 저장하고 다시 읽어 스키마가 어떻게 바뀌는지 확인한다

## 2. 핵심 개념 정리

### 2-1. Spark DataFrame은 "즉시 실행"되지 않는다

| 구분 | 종류 | 예시 | 실행 시점 |
|---|---|---|---|
| **Transformation** | 지연(lazy) | `select`, `filter`, `withColumn`, `groupBy` | 실행 안 됨 (계획만 쌓임) |
| **Action** | 즉시 실행 | `count()`, `show()`, `toPandas()`, `write` | 이때 전체 계획이 한 번에 실행 |

> 💡 그래서 `long_df.count()`를 여러 번 부르면 그때마다 CSV 파싱부터 다시 한다. 이걸 막는 게 `cache()`.

### 2-2. `local[*]` 의 의미

```python
.master("local[*]")
```

- `local` = 클러스터 없이 내 PC 한 대에서 실행
- `[*]` = 사용 가능한 **CPU 코어 수만큼** 스레드를 띄움 (`local[4]` 면 4개)
- 실무 클러스터에서는 `yarn`, `k8s://...` 등으로 바뀌지만 **코드 나머지는 그대로**라는 게 Spark의 장점

### 2-3. Wide vs Long

| | Wide (원본 CSV) | Long (변환 후) |
|---|---|---|
| 1행의 의미 | 업소 1곳 | 업소의 메뉴 1개 |
| 행 수 | 12,645 | 26,762 |
| 메뉴 평균가 구하기 | 컬럼 4개를 일일이 더해야 함 | `avg("price")` 한 줄 |
| 메뉴 5개로 늘면 | **컬럼 추가 + 코드 전면 수정** | 코드 그대로 |

> 💡 집계·통계는 거의 항상 Long 포맷이 유리하다. "컬럼에 값이 들어있으면(메뉴1, 메뉴2…) 그건 데이터지 스키마가 아니다"가 판단 기준.

## 3. 코드 흐름 정리

### 3-1. SparkSession 생성

```python
from pyspark.sql import SparkSession
from pyspark.sql import functions as F

spark = (SparkSession.builder
    .appName("chakhan-price")   # Spark UI에 표시될 앱 이름
    .master("local[*]")         # 로컬 + 전체 코어 사용
    .getOrCreate())             # 이미 있으면 재사용, 없으면 새로 생성
```

> ⚠️ `getOrCreate()`는 **이미 떠 있는 세션이 있으면 설정을 무시하고 그대로 반환**한다. 커널을 재시작하지 않고 `.master()`만 바꿔도 안 먹히는 이유.

### 3-2. CSV 로드

```python
PATH = "/home/jovyan/work/행정안전부_착한가격업소 현황_20260630.csv"

df = (spark.read
    .option("header", True)        # 첫 줄을 컬럼명으로
    .option("inferSchema", True)   # 타입 자동 추론 (파일을 한 번 더 읽음 = 느림)
    .option("encoding", "UTF-8")
    .option("multiLine", True)     # 셀 안에 줄바꿈이 있어도 한 행으로 처리
    .option("escape", '"')         # 따옴표 안의 콤마를 구분자로 오해하지 않게
    .csv(PATH))

df.printSchema()
print("행 수:", df.count())
```

```
root
 |-- 시도: string  |-- 시군: string  |-- 업종: string  |-- 업소명: string
 |-- 연락처: string  |-- 주소: string
 |-- 메뉴1~4: string  |-- 가격1~4: string

행 수: 12645
```

> ⚠️ `inferSchema`는 **컬럼마다 따로 추론**한다. 가격1은 전부 숫자라 `int`, 가격2에 "8,000원"이 하나 섞이면 `string`으로 잡히는 식. 그래서 아래처럼 타입을 강제로 통일해야 `stack()`이 깨지지 않는다.

### 3-3. 컬럼명 영문화 + 가격 컬럼 타입 통일

```python
rename_map = {"시도": "sido", "시군": "sigun", "업종": "category",
              "업소명": "name", "연락처": "tel", "주소": "address",
              "메뉴1": "menu1", "가격1": "price1", ...}

for old, new in rename_map.items():
    df = df.withColumnRenamed(old, new)

# ★ stack()은 같은 위치의 컬럼 타입이 전부 같아야 한다 → string으로 통일
for c in ["price1", "price2", "price3", "price4"]:
    df = df.withColumn(c, F.col(c).cast("string"))
```

> 💡 `withColumnRenamed`는 **원본을 바꾸지 않고 새 DataFrame을 반환**한다. 그래서 `df = df.with...` 로 재할당하는 것. (pandas의 `inplace=True` 같은 개념이 없음)

### 3-4. Wide → Long 변환 (오늘의 핵심)

```python
long_df = (df.select(
        "sido", "sigun", "category", "name", "address",
        F.expr("""
            stack(4,
                1, menu1, price1,
                2, menu2, price2,
                3, menu3, price3,
                4, menu4, price4
            ) as (menu_no, menu, price_raw)
        """)
    )
    # 메뉴가 비어있는 슬롯 제거
    .filter(F.col("menu").isNotNull() & (F.trim(F.col("menu")) != ""))

    # 1) 첫 번째 숫자 덩어리만 추출 (1,000 같은 콤마 표기 허용)
    .withColumn("price_str",
        F.regexp_extract(F.col("price_raw"), r"(\d{1,3}(?:,\d{3})+|\d+)", 1))

    # 2) 콤마 제거 후 try_cast → 실패해도 예외 없이 NULL
    .withColumn("price",
        F.expr("try_cast(regexp_replace(price_str, ',', '') as bigint)"))
    .filter(F.col("price").isNotNull() & (F.col("price") > 0))

    # 3) 상식 밖 값 차단
    .filter((F.col("price") >= 500) & (F.col("price") <= 1000000))
    .drop("price_str")
)

long_df.cache()
print("메뉴 단위 행 수:", long_df.count())
```

```
메뉴 단위 행 수: 26762
```

**`stack(n, ...)` 읽는 법**

```
stack(4,          ← 만들어낼 행 개수
      1, menu1, price1,   ← 1번째 행에 넣을 값 3개
      2, menu2, price2,   ← 2번째 행
      3, menu3, price3,
      4, menu4, price4)
      as (menu_no, menu, price_raw)   ← 새 컬럼 3개의 이름
```

즉 **업소 1행 → 메뉴 4행**으로 늘어난다. 12,645 × 4 = 50,580개 슬롯 중 메뉴가 실제로 채워진 건 26,818개(53%).

**정규식 `(\d{1,3}(?:,\d{3})+|\d+)` 해석**

| 조각 | 의미 |
|---|---|
| `\d{1,3}` | 숫자 1~3자리 (천 단위 앞자리) |
| `(?:,\d{3})+` | `,000` 패턴이 1번 이상 반복 |
| <code>&#124;</code> | 또는 |
| `\d+` | 콤마 없는 순수 숫자 |

앞쪽(콤마 포함)을 **먼저** 두는 게 중요하다. 순서를 바꾸면 `12,000`에서 `12`만 잡힌다.

> 💡 `try_cast`는 변환 실패 시 예외 대신 **NULL**을 반환한다. 일반 `cast`도 Spark에서는 NULL을 주지만, ANSI 모드가 켜져 있으면 예외가 나므로 `try_cast`가 안전하다.

### 4-2. 업종별 가격 통계 (`agg` 다중 집계)

```python
(long_df.groupBy("category")
   .agg(
       F.count("*").alias("menu_cnt"),
       F.countDistinct("name").alias("shop_cnt"),
       F.round(F.avg("price"), 0).cast("int").alias("avg_price"),
       F.expr("percentile_approx(price, 0.5)").alias("median_price"),
       F.min("price").alias("min_price"),
       F.max("price").alias("max_price"),
   )
   .orderBy(F.desc("menu_cnt")).toPandas())
```

| 업종 | 메뉴수 | 평균가 | **중앙값** | 최소 | 최대 |
|---|---|---|---|---|---|
| 한식 | 15,650 | 10,522 | 8,000 | 500 | 176,000 |
| 미용업 | 4,169 | 19,288 | 15,000 | 2,000 | 700,000 |
| 기타요식업 | 2,125 | 3,819 | 3,000 | 500 | 140,000 |
| 중식 | 1,541 | 7,418 | 6,500 | 1,800 | 89,000 |
| 기타비요식업 | 818 | **68,816** | **20,000** | 500 | 1,000,000 |
| 숙박업 | 319 | 64,288 | 50,000 | 10,000 | 300,000 |

> 💡 **기타비요식업이 평균 68,816원 vs 중앙값 20,000원.** 3배 넘게 벌어진다 = 극단적 이상치가 평균을 끌어올렸다는 뜻. 가격처럼 오른쪽 꼬리가 긴 분포에서는 **평균보다 중앙값을 먼저 본다.**
>
> `percentile_approx`는 정확한 중앙값이 아니라 **근사치**다. 분산 환경에서 정확한 중앙값을 구하려면 전체 정렬이 필요해 비용이 크기 때문에, Spark는 기본적으로 근사 알고리즘을 쓴다.

## 5. Window 함수

### 5-1. groupBy vs Window

| | `groupBy().agg()` | `Window` |
|---|---|---|
| 결과 행 수 | **줄어든다** (그룹당 1행) | **그대로** (원래 행 + 계산 컬럼) |
| 용도 | 요약 통계 | 순위 매기기, 원본과 그룹평균 비교 |

### 5-2. 시도별 짜장면 최저가 업소 (`row_number`)

```python
from pyspark.sql.window import Window

w = Window.partitionBy("sido").orderBy(F.asc("price"))
#              ↑ 시도별로 나누고        ↑ 가격 오름차순 정렬

(long_df
   .filter(F.col("menu").contains("짜장면"))
   .withColumn("rn", F.row_number().over(w))   # 그룹 안에서 1,2,3... 번호 부여
   .filter(F.col("rn") == 1)                   # 각 시도의 1등만
   .select("sido", "sigun", "name", "menu", "price")
   .orderBy("price").toPandas())
```

| 시도 | 시군 | 업소명 | 가격 |
|---|---|---|---|
| 대구광역시 | 중구 | 만리장성 | 2,000 |
| 서울특별시 | 금천구 | 왕래성 | 2,000 |
| 울산광역시 | 동구 | 북경 | 2,000 |
| … | | | |
| 전라남도 | 순천시 | 열정짬뽕 | 4,500 |
| 전북특별자치도 | 군산시 | 아서원 | 4,500 |

> ⚠️ `.contains("짜장면")`을 썼기 때문에 `짜장면(소)`, `옛날짜장면`, `짜장면(매장식사)` 처럼 **양이 다른 메뉴가 섞인다.** "가장 싼 곳" 순위로 쓰기엔 공정하지 않다. `==` 완전일치로 바꾸면 표본이 줄고, `contains`면 오염된다 — 이 트레이드오프를 인지하고 쓰는 게 중요.
>
> ⚠️ `row_number`는 동점이어도 무조건 1,2,3을 매긴다. 동점을 모두 살리려면 `rank()`(1,1,3) 또는 `dense_rank()`(1,1,2)를 쓴다. 위 결과에서 2,000원 업소가 여러 시도에 있는데, **같은 시도 안에 2,000원이 2곳이면 1곳은 잘려나간다.**

### 5-3. 같은 업종 평균 대비 얼마나 싼가 (`avg().over()`)

```python
w2 = Window.partitionBy("category")   # orderBy 없음 → 그룹 전체가 계산 범위

(long_df
   .withColumn("cat_avg", F.round(F.avg("price").over(w2), 0))
   .withColumn("gap_pct", F.round((F.col("price") / F.col("cat_avg") - 1) * 100, 1))
   .filter(F.col("category") != "기타비요식업")   # 이상치 업종 제외
   .select("sido", "name", "category", "menu", "price", "cat_avg", "gap_pct")
   .orderBy("gap_pct").limit(20).toPandas())
```

| 시도 | 업소명 | 업종 | 메뉴 | 가격 | 업종평균 | 격차 |
|---|---|---|---|---|---|---|
| 서울특별시 | 월곡동할매떡볶이 | 한식 | 김밥 및 계란 | 500 | 10,522 | **-95.2%** |
| 부산광역시 | 광화식품 | 한식 | 순두부 400g | 500 | 10,522 | -95.2% |
| 경상남도 | 육선생 푸줏간 | 한식 | 한돈 양념돼지불고기 100g | 780 | 10,522 | -92.6% |

> ⚠️ **이 결과는 "싼 가게"가 아니라 "단품 사이드 메뉴"를 찾아냈다.** 어묵 1개(500원)와 설렁탕(9,000원)을 같은 `한식` 평균과 비교했기 때문. 비교 기준이 잘못 잡히면 계산은 맞는데 결론이 틀린다 — 오늘 가장 크게 배운 부분.
>
> 💡 `Window.partitionBy(...)` 에 `orderBy`를 붙이면 계산 범위가 **"첫 행 ~ 현재 행"(누적)** 으로 바뀐다. 그룹 전체 평균을 원하면 `orderBy`를 **빼야 한다.** 여기서는 의도대로 뺐다.

## 6. Parquet 저장 & 파티셔닝

```python
(long_df.write.mode("overwrite")
   .partitionBy("sido")                              # 시도별 디렉터리로 분할

4218
```

> 💡 **파티션 컬럼(`sido`)은 파일 안에 저장되지 않는다.** 디렉터리 이름(`sido=서울특별시`)이 곧 값이고, 읽을 때 경로에서 복원되어 **스키마 맨 뒤에 붙는다.** 그래서 컬럼 순서가 바뀐 것.
>
> 💡 이게 **파티션 프루닝(partition pruning)**의 원리다. `filter(sido == "서울특별시")` 하면 Spark는 나머지 16개 디렉터리를 **아예 읽지 않는다.** CSV였다면 전체를 읽고 걸러야 한다.

| 포맷 | 특징 |
|---|---|
| CSV | 텍스트, 타입 없음, 전체 스캔, 압축 안 됨 |
| **Parquet** | 컬럼 지향, 스키마 내장, 필요한 컬럼만 읽음, snappy 압축 기본 |

## 7. 02.ipynb에서 추가된 것 — 단위 제거 + 품질 플래그

```python
UNIT_PAT = r"\d+\s*(?:g|kg|ml|리터|인분|장|매|시간)"

clean = (long_df
    .withColumn("p_norm",  F.regexp_replace(F.col("price_raw"), UNIT_PAT, " "))
    .withColumn("p_first", F.regexp_extract(F.col("p_norm"), r"(\d{1,3}(?:,\d{3})+|\d+)", 1))
    .withColumn("price",   F.expr("try_cast(regexp_replace(p_first, ',', '') as bigint)"))
    .withColumn("is_multi", F.col("price_raw").rlike(r"\d\s*[~\-/]\s*\d|\d[^0-9]*\d{3,}"))
    .withColumn("flag",
        F.when(F.col("price").isNull(), "파싱실패")
         .when(F.col("price") < 100, "값이상")
         .otherwise("정상"))
)
clean.groupBy("flag").count().toPandas()
```

```
  flag  count
0   정상  26762
```

**왜 이 단계가 필요한가**: `price_raw`가 `"100g 5,000"` 이면 3-4의 정규식은 앞의 `100`을 잡는다. 단위가 붙은 숫자를 먼저 지워야 진짜 가격이 첫 번째 숫자가 된다.

> ⚠️ **하지만 이 검증은 결과가 무의미하다.** `clean`의 입력이 `long_df`인데, `long_df`는 이미 `price.isNotNull() & price >= 500` 필터를 통과한 데이터다. 파싱 실패했던 56건은 **이미 삭제된 뒤**라 `flag`가 100% "정상"으로 나올 수밖에 없다.
>
> **고쳐야 할 방향**: 필터를 걸기 **전**(`stack` 직후 raw 상태)에 `flag`를 붙이고, 그 다음에 필터링한다. 그래야 "무엇이 왜 버려졌는지"가 보인다.

## 10. 오늘 배운 것 요약

1. Spark는 **Transformation은 쌓아두고 Action에서 한 번에 실행**한다. 반복 사용하는 DataFrame은 `cache()`로 재계산을 막는다.
2. **`stack(n, ...)`** 은 Wide → Long 변환의 핵심. 단, **같은 위치의 컬럼 타입이 전부 같아야** 하므로 `inferSchema` 뒤에는 `cast("string")`으로 통일한다.
3. 지저분한 문자열 파싱은 **`regexp_extract` → `regexp_replace` → `try_cast`** 3단 콤보. `try_cast`가 실패를 예외 대신 NULL로 만들어 파이프라인이 죽지 않는다.
4. 정규식 대안(`|`)은 **긴 패턴을 먼저** 써야 한다. `\d+`를 앞에 두면 `12,000`이 `12`가 된다.
5. 전처리 후엔 **손실 건수를 반드시 출력한다** (26,818 → 26,762, 99.8%).
6. 가격처럼 꼬리가 긴 분포는 **평균보다 중앙값**. 기타비요식업 평균 68,816 vs 중앙값 20,000이 그 증거.
7. **`groupBy`는 행을 줄이고, `Window`는 행을 유지**한다. `Window.partitionBy()`에 `orderBy`를 붙이면 누적 계산이 되므로 그룹 전체 평균을 원하면 빼야 한다.
8. **Parquet + `partitionBy`** 로 저장하면 파티션 컬럼이 디렉터리명이 되고, 읽을 때 스키마 맨 뒤로 이동한다. 대신 필터링 시 해당 디렉터리만 읽는 **파티션 프루닝**이 작동한다.
9. **계산이 맞아도 비교 기준이 틀리면 결론이 틀린다.** 어묵 500원을 한식 평균 10,522원과 비교해 "-95% 최저가"라고 부르면 안 된다.
