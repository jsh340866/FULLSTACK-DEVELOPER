# 📅 01_PARAM | React + Spring Boot

## 🔖 태그
#React #SpringBoot #Param #RequestMapping #Axios #CORS

## 🧠 오늘 배운 것
- Spring Boot에서 클라이언트 파라미터를 받는 3가지 방식(QueryString / PathVariable+DTO바인딩 / RequestBody)
- `@CrossOrigin`으로 React(3000) ↔ Spring(8095) 간 CORS 허용
- React에서 axios로 GET/POST 요청을 보내는 기본 패턴

---

## 1. 파라미터 수신 방식 3종 (`controller/ParamController.java`)

### 설명
- REST 통신에서 클라이언트가 서버로 값을 넘기는 대표 방식이 GET 쿼리스트링, GET 경로변수, POST 바디 세 가지임을 실습으로 구분
- `@RequestMapping`에 `method` 배열로 GET/POST를 동시에 열어두고, 실제로는 요청 형식에 따라 바인딩 방식이 달라짐
- `PersonDto`처럼 필드명과 파라미터명이 일치하면 스프링이 자동으로 객체에 바인딩(커맨드 객체)

### 핵심 코드
```java
@RequestMapping(value="/01", method={RequestMethod.GET,RequestMethod.POST}, produces=MediaType.APPLICATION_JSON_VALUE)
public ResponseEntity<Map<String,Object>> param01(@RequestParam(value="name",required=false) String name){ ... }

@RequestMapping(value="/02/{name}/{age}/{addr}")
public ResponseEntity<Map<String,Object>> param02(PersonDto personDto){ ... } // PathVariable → DTO 자동 바인딩

@PostMapping(value="/03", consumes=MediaType.APPLICATION_JSON_VALUE)
public ResponseEntity<Map<String,Object>> param03(@RequestBody PersonDto personDto){ ... } // JSON Body → DTO
```

```jsx
axios.get(`http://localhost:8095/param/01`, { params: { name: '홍길동' } })
axios.get(`http://localhost:8095/param/02/${'홍길동'}/${55}/${'대구'}`)
axios.post(`http://localhost:8095/param/03`, { name: "하하", age: 56, addr: "서울" })
```

### 💡 메모 / 리스크
- `@CrossOrigin(origins="*")`와 `@CrossOrigin(origins={"..."})`가 중복 선언되어 있음 → 실제로는 마지막 선언이 우선 적용되므로 운영 시 정리 필요.

# 📅 02_VALIDATION | React + Spring Boot

## 🔖 태그
#React #SpringBoot #Validation #BindingResult #JakartaValidation

## 🧠 오늘 배운 것
- `jakarta.validation`(`@NotBlank`, `@NotNull`, `@Min/@Max`, `@Email`) 애노테이션으로 DTO 단위 유효성 검증
- `@Valid` + `BindingResult` 조합으로 검증 실패 시 서버가 필드별 에러 메시지를 응답으로 내려주는 패턴
- React 쪽에서 서버가 내려준 에러 맵을 그대로 상태에 저장해 화면에 노출하는 흐름

---

## 1. DTO 검증 규칙 정의 (`domain/dto/MemoDto.java`)

### 설명
- 검증 로직을 컨트롤러가 아닌 DTO에 애노테이션으로 선언 → 관심사 분리
- 검증 실패 메시지를 애노테이션의 `message` 속성에 한글로 직접 지정

### 핵심 코드
```java
@Min(value=10,message="최소 숫자는 10이상 이어야합니다.")
@Max(value=65535,message="최대 숫자는 65535이하 이어야합니다.")
@NotNull(message="ID를 입력하세요")
private Integer id;

@NotBlank(message="작성자를 입력하세요")
@Email(message="example@example.com에 맞게 입력해주세요")
private String writer;
```

## 2. 검증 결과 처리 (`controller/MemoController.java`)

### 설명
- `@Valid` 선언 시 `BindingResult`가 검증 오류를 담아 컨트롤러로 전달됨 (파라미터 순서: `@Valid 대상` 바로 다음이 `BindingResult`여야 함)
- `bindingResult.hasErrors()`로 분기 후 `getFieldErrors()`를 순회하며 필드별 에러를 Map에 적재해 응답

### 핵심 코드
```java
public ResponseEntity<Map<String,Object>> add(@RequestBody @Valid MemoDto memoDto, BindingResult bindingResult){
    if(bindingResult.hasErrors()) {
        for(FieldError error : bindingResult.getFieldErrors()) {
            map.put(error.getField(), error.getDefaultMessage());
        }
        return new ResponseEntity<>(map, HttpStatus.EXPECTATION_FAILED);
    }
    return new ResponseEntity<>(map, HttpStatus.OK);
}
```

```jsx
axios.post(`http://localhost:8095/memo/add`, {...})
  .then(resp => setMessage(resp.data))
  .catch(err => setMessage(err.response.data)) // 검증 실패 메시지도 동일하게 message에 담아 렌더링
```

# 📅 03_EXCEPTION | React + Spring Boot

## 🔖 태그
#React #SpringBoot #ExceptionHandler #ReactRouter #ErrorHandling

## 🧠 오늘 배운 것
- `@ExceptionHandler`로 특정 예외 타입별 응답 처리를 컨트롤러 내부에 위임하는 방식 (전역 처리인 `@ControllerAdvice`의 전 단계 실습)
- 예외를 의도적으로 `throw`시켜 핸들러 동작을 검증하는 테스트 엔드포인트 설계
- React Router의 `useNavigate` + `state` 전달로 에러 페이지에 메시지/상태코드를 넘기는 패턴

---

## 1. 컨트롤러 단위 예외 처리 (`controller/MemoController.java`)

### 설명
- `FileNotFoundException`, `ArithmeticException`, 그리고 포괄적인 `Exception`까지 총 3단계로 핸들러를 등록해 처리 우선순위(구체적 예외 → 포괄 예외) 구조를 학습
- `list1~list4`는 각기 다른 예외를 고의로 발생시켜 위 핸들러들이 정상 동작하는지 확인하는 실습용 엔드포인트

### 핵심 코드
```java
@ExceptionHandler(FileNotFoundException.class)
public ResponseEntity<Exception> error1(Exception ex){ ... }
@ExceptionHandler(ArithmeticException.class)
public ResponseEntity<Exception> error2(Exception ex){ ... }
@ExceptionHandler(Exception.class)
public ResponseEntity<Exception> error3(Exception ex){ ... }

@GetMapping("/list3/{n1}/{n2}")
public void list3(@PathVariable int n1, @PathVariable int n2) {
    System.out.println("계산결과 : " + (n1/n2)); // n2=0이면 ArithmeticException 유발
}
```

## 2. 프론트 에러 페이지 (`components/Exception.jsx`)

### 설명
- axios 에러 발생 시 `navigate('/exception', { state:{ message, status } })`로 라우팅하면서 에러 정보를 함께 전달
- `useLocation().state`로 전달받은 값을 그대로 렌더링하는 공용 에러 화면 구성

### 핵심 코드
```jsx
const location = useLocation();
const { message, status } = location.state || {};
return (<div>{status && <p>Status Code: {status}</p>}{message && <p>Message: {message}</p>}</div>)
```

### 💡 메모
- `config/DataSource.java`는 빈 클래스(구현 전 스텁)로, 이 단계에서는 아직 DB 연동 없이 예외처리 구조만 익히는 단계임.

# 📅 04_JPA | React + Spring Boot

## 🔖 태그
#SpringBoot #JPA #Hibernate #HikariCP #Entity #Repository #Service

## 🧠 오늘 배운 것
- DataSource → JPA(EntityManagerFactory) → TransactionManager로 이어지는 3단 Config 구조
- Entity–Repository–Service–Controller 계층형 아키텍처 확립 (03_EXCEPTION 대비 Service 계층이 새로 추가됨)
- `JpaRepository` 상속만으로 기본 CRUD가 제공되는 Spring Data JPA의 이점

---

## 1. 3단 설정 분리 (`config/DataSourceConfig`, `JpaConfig`, `TxConfig`)

### 설명
- **DataSourceConfig**: HikariCP 커넥션 풀 Bean 등록 (DB 연결 자체)
- **JpaConfig**: `EntityManagerFactory` Bean 생성, `@EntityScan`/`@EnableJpaRepositories`로 엔티티·리포지토리 패키지 지정, hibernate 속성(ddl-auto, show_sql 등) 설정
- **TxConfig**: `JpaTransactionManager` Bean 등록, `@Transactional` 동작의 기반

### 핵심 코드
```java
@Bean
public HikariDataSource dataSource(){
    return DataSourceBuilder.create().type(HikariDataSource.class)
        .username("root").password("1234")
        .driverClassName("com.mysql.cj.jdbc.Driver")
        .url("jdbc:mysql://localhost:3306/testdb").build();
}
```
```java
properties.put("hibernate.hbm2ddl.auto", "update");
properties.put("hibernate.dialect", "org.hibernate.dialect.MySQLDialect");
```

## 2. Entity / Repository / Service 계층 (`domain/entity`,`repository`,`service`)

### 설명
- `Memo` 엔티티에 `@Id @GeneratedValue(IDENTITY)`로 auto-increment PK 지정
- `MemoRepository`는 `JpaRepository<Memo,Long>` 상속만으로 `save/findAll` 등 제공
- `MemoServiceImpl`에서 `@Transactional(rollbackFor=Exception.class)`로 저장 로직을 트랜잭션 처리, DTO→Entity 변환 후 저장

### 핵심 코드
```java
@Entity @NoArgsConstructor @AllArgsConstructor @Data
public class Memo {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private long id;
    private String text; private String writer; private LocalDateTime regdate;
}

@Transactional(rollbackFor=Exception.class)
public boolean addMemo(MemoDto dto) throws Exception{
    Memo memo = new Memo();
    memo.setText(dto.getText()); memo.setRegdate(LocalDateTime.now()); memo.setWriter(dto.getWriter());
    memoRepository.save(memo);
    return true;
}
```

### 💡 메모 / 리스크
- DB 계정정보(`root/1234`)가 소스에 하드코딩됨 → 실제 배포 전 `application.properties`/환경변수로 분리 필요.

# 📅 07_SPRINGSECURITY | React + Spring Boot

## 🔖 태그
#SpringSecurity #JWT #OAuth2 #Redis #PrincipalDetails #Authentication

## 🧠 오늘 배운 것
- Spring Security 필터체인 기반 인가 규칙(`authorizeHttpRequests`) 설정과 역할(Role) 기반 접근 제어
- `UserDetails` + `OAuth2User`를 동시에 구현하는 `PrincipalDetails`로 로컬 로그인과 소셜 로그인을 하나의 인증 주체로 통합
- JWT 발급(`JwtTokenProvider`) → 쿠키 저장 → 매 요청마다 `OncePerRequestFilter`에서 검증하는 Stateless 인증 흐름
- 로그인 성공/실패, 로그아웃, 인가 실패(403)/인증 실패(401)에 대한 커스텀 핸들러 분리 설계
- Redis를 토큰 관리(RefreshToken 등)에 활용하는 구조 도입

---

## 1. 인가 규칙 & 필터체인 설정 (`config/SecurityConfig.java`)

### 설명
- CSRF는 REST API 특성상 비활성화(`csrf.disable()`)
- 정적 리소스/회원가입/로그인은 `permitAll()`, `/user`,`/manager`,`/admin`은 각각 역할별로 접근 제한
- 로그인 성공/실패, 로그아웃(성공/처리), 인증진입점 예외(`AuthenticationEntryPoint`), 인가 거부(`AccessDeniedHandler`)를 모두 별도 핸들러 클래스로 분리해 등록

### 핵심 코드
```java
http.csrf((config)->config.disable());
http.authorizeHttpRequests((auth)->{
    auth.requestMatchers("/", "/join", "/login").permitAll();
    auth.requestMatchers("/user").hasAnyRole("USER","ADMIN");
    auth.requestMatchers("/manager").hasAnyRole("MANAGER");
    auth.requestMatchers("/admin").hasAnyRole("ADMIN");
    auth.anyRequest().authenticated();
});
```

## 2. 인증 주체 통합 (`config/auth/PrincipalDetails.java`)

### 설명
- `UserDetails`(폼 로그인용)와 `OAuth2User`(소셜 로그인용) 인터페이스를 동시 구현 → 인증 방식이 달라도 컨트롤러/서비스 로직에서 동일한 타입으로 사용자 정보 접근 가능
- `role` 문자열(`"ROLE_USER,ROLE_ADMIN"`)을 split해 `GrantedAuthority` 목록으로 변환

### 핵심 코드
```java
public Collection<? extends GrantedAuthority> getAuthorities() {
    Collection<GrantedAuthority> authorities = new ArrayList<>();
    String[] roles = userDTO.getRole().split(",");
    for(String role : roles) authorities.add(new SimpleGrantedAuthority(role));
    return authorities;
}
```

## 3. JWT 발급/검증 (`config/auth/jwt/JwtTokenProvider.java`, `JwtAuthorizationFilter.java`)

### 설명

- 필터에서 매 요청마다 쿠키에서 access-token을 꺼내 유효성 검증 후, 통과 시 `SecurityContextHolder`에 인증 정보를 세팅
