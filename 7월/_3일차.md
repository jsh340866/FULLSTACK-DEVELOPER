## 1. Swagger(OpenAPI) 적용 (`23_SWAGER_UI/.../build.gradle`)

### 설명

SpringDoc 라이브러리를 추가하면 Controller를 분석하여 Swagger UI를 자동 생성합니다. 별도의 문서를 작성하지 않아도 브라우저에서 API 목록과 요청/응답을 확인할 수 있습니다.

### 실제 코드

```gradle
dependencies {
    implementation 'org.springdoc:springdoc-openapi-starter-webmvc-ui'
}
```

### 코드 설명

| 코드                | 설명            |
| ----------------- | ------------- |
| springdoc-openapi | OpenAPI 문서 생성 |
| starter-webmvc-ui | Swagger UI 제공 |

### 한 줄 흐름

```
라이브러리 추가
      ↓
프로젝트 실행
      ↓
Swagger UI 자동 생성
```

### 예상 출력

```
http://localhost:8080/swagger-ui/index.html
```

### 핵심 포인트

* API 문서를 자동 생성한다.
* 테스트까지 브라우저에서 가능하다.

## 2. Swagger Annotation으로 API 문서 작성 (`23_SWAGER_UI/.../controller/UserController.java`)

### 설명

Swagger Annotation을 이용해 API 설명과 응답 정보를 문서에 함께 기록했습니다.

### 실제 코드

```java
@Tag(name = "User API")
@RestController
@RequestMapping("/api/users")
public class UserController {

    @Operation(summary = "사용자 조회")
    @ApiResponse(responseCode = "200")
    @GetMapping
    public List<UserDto> findAll() { ... }

    @Operation(summary = "사용자 등록")
    @PostMapping
    public ResponseEntity<UserDto> create(...) { ... }
}
```

### 코드 설명

| Annotation   | 역할        |
| ------------ | --------- |
| @Tag         | API 그룹 생성 |
| @Operation   | API 설명    |
| @ApiResponse | 응답 정보     |
| @Parameter   | 파라미터 설명   |

### 한 줄 흐름

```
Controller 작성
      ↓
Swagger Annotation 추가
      ↓
API 문서 자동 생성
```

### 예상 출력

```
User API

GET    /api/users
POST   /api/users
PUT    /api/users/{id}
DELETE /api/users/{id}
```

### 핵심 포인트

* 코드와 문서를 함께 관리한다.
* API 변경 사항이 자동 반영된다.

## 3. ConcurrentHashMap으로 메모리 CRUD 구현 (`23_SWAGER_UI/.../controller/UserController.java`)

### 설명

DB 대신 `ConcurrentHashMap`을 저장소로 사용하여 CRUD를 구현했습니다. `AtomicLong`으로 ID를 자동 증가시켜 간단한 REST API를 만들었습니다.

### 실제 코드

```java
private final Map<Long, UserDto> store = new ConcurrentHashMap<>();
private final AtomicLong seq = new AtomicLong();

Long id = seq.incrementAndGet();
dto.setId(id);

store.put(id, dto);
```

### 코드 설명

| 코드                | 설명       |
| ----------------- | -------- |
| ConcurrentHashMap | 메모리 저장소  |
| AtomicLong        | ID 자동 증가 |
| store.put()       | 데이터 저장   |

### 한 줄 흐름

```
요청
   ↓
ID 생성
   ↓
Map 저장
   ↓
JSON 응답
```

### 예상 출력

```json
{
  "id": 1,
  "name": "홍길동",
  "email": "hong@test.com"
}
```

### 핵심 포인트

* DB 없이 CRUD를 연습할 수 있다.
* AtomicLong은 스레드 안전성을 제공한다.

## 4. Properties와 Profile 분리 (`24_PROPERTIES_SETTING/.../resources`)

### 설명

공통 설정은 `application.properties`에 작성하고, 개발과 운영 환경은 Profile별 Properties 파일로 분리했습니다.

### 실제 코드

```properties
spring.profiles.active=dev

app.name=Property Sample
```

```properties
# application-dev.properties
app.api.key=DEV-API-KEY
```

```properties
# application-prod.properties
app.api.key=${API_KEY}
```

### 코드 설명

| 파일                          | 역할    |
| --------------------------- | ----- |
| application.properties      | 공통 설정 |
| application-dev.properties  | 개발 환경 |
| application-prod.properties | 운영 환경 |

### 한 줄 흐름

```
Profile 선택
      ↓
Properties 로드
      ↓
환경별 설정 적용
```

### 예상 출력

```
Active Profile : dev
```

### 핵심 포인트

* 환경마다 다른 설정을 사용할 수 있다.
* 운영 환경의 민감한 정보는 환경변수로 관리한다.

## 5. @Value와 @ConfigurationProperties (`24_PROPERTIES_SETTING/.../config/ApiProperties.java`)

### 설명

설정값 하나는 `@Value`, 관련된 여러 설정은 `@ConfigurationProperties`를 이용하여 객체 단위로 관리했습니다.

### 실제 코드

```java
@Value("${db.url}")
private String dbUrl;

@ConfigurationProperties(prefix = "app.api")
public class ApiProperties {

    private String key;
    private String url;
}
```

### 코드 설명

| 방식                       | 특징         |
| ------------------------ | ---------- |
| @Value                   | 설정 하나 주입   |
| @ConfigurationProperties | 설정을 객체로 관리 |

### 한 줄 흐름

```
Properties 읽기
      ↓
객체 생성
      ↓
자동 주입
```

### 예상 출력

```
db.url
app.api.key
app.api.url
```

### 핵심 포인트

* 설정이 적으면 `@Value`
* 설정이 많으면 `@ConfigurationProperties`

## 6. ConfigController로 설정값 확인 (`24_PROPERTIES_SETTING/.../controller/ConfigController.java`)

### 설명

현재 활성 Profile과 설정값을 확인하는 API를 작성했습니다. API Key와 DB Password는 `mask()` 메서드로 일부만 보여주도록 구현했습니다.

### 실제 코드

```java
result.put("activeProfiles", activeProfiles);
result.put("db.url", dbUrl);
result.put("db.password", mask(dbPassword));
result.put("app.api.key", mask(apiProperties.getKey()));
```

```java
private String mask(String value) {
    return value.substring(0, 2) + "*".repeat(value.length() - 2);
}
```

### 코드 설명

| 코드            | 설명            |
| ------------- | ------------- |
| Environment   | 현재 Profile 확인 |
| mask()        | 민감 정보 마스킹     |
| LinkedHashMap | 응답 데이터 구성     |

### 한 줄 흐름

```
/config 요청
      ↓
Properties 조회
      ↓
민감 정보 마스킹
      ↓
JSON 반환
```

### 예상 출력

```json
{
  "activeProfiles": ["dev"],
  "db.url": "jdbc:mysql://localhost:3306/devdb",
  "db.password": "de********",
  "app.api.key": "DE***********"
}
```

### 핵심 포인트

* 민감한 정보는 그대로 노출하지 않는다.
* Profile별 설정이 정상 적용되었는지 쉽게 확인할 수 있다.

# 오늘 핵심 정리

* SpringDoc을 이용하여 Swagger UI를 자동 생성하고 API를 문서화하였다.
* `@Tag`, `@Operation`, `@ApiResponse`, `@Parameter`를 이용해 API 정보를 코드와 함께 관리하였다.
* `ConcurrentHashMap`과 `AtomicLong`으로 메모리 기반 CRUD를 구현하였다.
* `application.properties`와 Profile을 이용해 개발·운영 환경을 분리하였다.
* `@Value`와 `@ConfigurationProperties`를 활용하여 설정값을 주입하고 관리하였다.
* `ConfigController`에서 현재 Profile과 설정값을 확인하고, `mask()`로 API Key와 비밀번호를 안전하게 마스킹하여 반환하였다.
