# 1. Docker란?

## 오늘 배운 내용

Docker는 애플리케이션과 실행 환경을 하나로 묶어 어느 PC에서든 동일한 환경으로 실행할 수 있게 해주는 컨테이너 플랫폼이다.

기존에는

> 개발 PC에서는 실행되는데
> 서버에서는 라이브러리 버전이 달라 오류가 발생하는 경우가 많았다.

Docker는 필요한 프로그램과 라이브러리를 Image에 모두 포함하여 동일한 환경을 제공한다.

---

## 핵심 명령어

```bash
docker --version
docker info
docker images
docker ps
```

---

## 코드 설명

| 명령어              | 설명               |
| ---------------- | ---------------- |
| docker --version | Docker 버전 확인     |
| docker info      | Docker Engine 정보 |
| docker images    | 이미지 목록 조회        |
| docker ps        | 실행 중인 컨테이너 조회    |

---

### 실행 흐름

```
Docker 설치
        ↓
Docker Engine 실행
        ↓
CLI 명령 실행
```

---

### 예상 결과

* Docker 정상 설치 확인
* Engine 상태 확인
* Image 목록 출력

---

## 핵심 정리

* Docker Engine이 실행되어야 명령 사용 가능
* Image와 Container는 서로 다른 개념

---

# 2. Image 이해하기

## 오늘 배운 내용

Image는 컨테이너를 생성하기 위한 설계도이다.

Image 자체는 실행되지 않으며 Image를 이용해 Container를 생성한다.

```
Image
 ↓
Container 생성
 ↓
실행
```

---

## 핵심 명령어

```bash
docker pull nginx

docker images
```

---

## 코드 설명

| 명령어           | 설명           |
| ------------- | ------------ |
| docker pull   | 이미지 다운로드     |
| docker images | 다운로드된 이미지 확인 |

---

### 실행 흐름

```
Docker Hub
      ↓
Image 다운로드
      ↓
Local 저장
```

---

### 예상 결과

```
REPOSITORY TAG IMAGE ID

nginx latest ...
```

---

## 핵심 정리

* Image는 읽기 전용
* 여러 개의 Container가 하나의 Image를 사용할 수 있다.

---

# 3. Dockerfile 작성

## 오늘 배운 내용

Dockerfile은 새로운 이미지를 만들기 위한 설정 파일이다.

필요한 라이브러리와 실행 명령을 순서대로 작성하면 Docker가 새로운 이미지를 생성한다.

---

## 핵심 코드

```dockerfile
FROM openjdk:21

COPY build/libs/app.jar app.jar

ENTRYPOINT ["java","-jar","app.jar"]
```

---

## 코드 설명

| 명령         | 설명     |
| ---------- | ------ |
| FROM       | 기본 이미지 |
| COPY       | 파일 복사  |
| ENTRYPOINT | 실행 명령  |

---

### 실행 흐름

```
Dockerfile
      ↓
docker build
      ↓
Image 생성
```

---

### 예상 결과

```
Successfully built
Successfully tagged
```

---

## 핵심 정리

* Dockerfile은 Image 생성 스크립트
* FROM이 가장 먼저 실행된다.

---

# 4. Image 생성

## 오늘 배운 내용

Dockerfile을 기반으로 이미지를 생성하였다.

---

## 핵심 명령어

```bash
docker build -t my-app .
```

---

## 코드 설명

| 옵션 | 설명                  |
| -- | ------------------- |
| -t | 이미지 이름 지정           |
| .  | 현재 폴더 Dockerfile 사용 |

---

### 실행 흐름

```
Dockerfile
      ↓
Build
      ↓
Image 생성
```

---

### 예상 결과

```
my-app latest
```

---

## 핵심 정리

* build 명령으로 새로운 이미지를 생성한다.
* Image는 여러 번 재사용 가능하다.

---

# 5. Container 생성

## 오늘 배운 내용

Container는 Image를 실행한 실제 프로세스이다.

Image 하나로 여러 개의 Container를 만들 수 있다.

---

## 핵심 명령어

```bash
docker run my-app
```

---

## 코드 설명

| 명령         | 설명                |
| ---------- | ----------------- |
| docker run | Container 생성 및 실행 |

---

### 실행 흐름

```
Image
   ↓
Container 생성
   ↓
프로그램 실행
```

---

### 예상 결과

프로그램이 실행되며 로그가 출력된다.

---

## 핵심 정리

* Image는 설계도
* Container는 실행 중인 프로그램

---

# 6. Container 관리

## 오늘 배운 내용

컨테이너의 실행, 종료, 삭제 방법을 학습하였다.

---

## 핵심 명령어

```bash
docker ps

docker ps -a

docker stop 컨테이너명

docker start 컨테이너명

docker rm 컨테이너명
```

---

## 코드 설명

| 명령           | 설명      |
| ------------ | ------- |
| docker ps    | 실행 중 조회 |
| docker ps -a | 전체 조회   |
| docker stop  | 종료      |
| docker start | 재실행     |
| docker rm    | 삭제      |

---

### 실행 흐름

```
Run
 ↓
Stop
 ↓
Start
 ↓
Remove
```

---

### 예상 결과

Container 상태가 변경된다.

---

## 핵심 정리

* stop은 종료
* rm은 삭제
* 삭제 후에는 다시 run 해야 한다.

---

# 7. 포트 매핑

## 오늘 배운 내용

컨테이너 내부 포트를 외부 PC와 연결하였다.

---

## 핵심 명령어

```bash
docker run -p 8080:8080 my-app
```

---

## 코드 설명

| 옵션 | 설명              |
| -- | --------------- |
| -p | 호스트와 컨테이너 포트 연결 |

---

### 실행 흐름

```
8080(PC)
      ↓
8080(Container)
```

---

### 예상 결과

브라우저에서

```
http://localhost:8080
```

접속 가능

---

## 핵심 정리

* 외부 접속을 위해 반드시 Port Mapping 필요

---

# 8. Volume 연결

## 오늘 배운 내용

컨테이너가 삭제되어도 데이터를 유지하기 위해 Volume을 연결하였다.

---

## 핵심 명령어

```bash
docker run -v C:/data:/app/data my-app
```

---

## 코드 설명

| 옵션 | 설명              |
| -- | --------------- |
| -v | 호스트와 컨테이너 폴더 연결 |

---

### 실행 흐름

```
Host Folder
      ↕
Container Folder
```

---

### 예상 결과

컨테이너를 삭제해도 데이터는 유지된다.

---

## 핵심 정리

* Volume은 데이터 영속성을 제공한다.
* DB나 업로드 파일 저장 시 반드시 사용한다.

---

# 📌 오늘 핵심 정리

* Docker는 실행 환경을 동일하게 만드는 컨테이너 플랫폼이다.
* Image는 실행 파일이 아닌 설계도 역할을 한다.
* Dockerfile을 이용해 원하는 이미지를 생성할 수 있다.
* Container는 Image를 실행한 실제 프로세스이다.
* `docker run`, `docker stop`, `docker rm`으로 컨테이너를 관리한다.
* `-p` 옵션으로 포트를 연결하고 `-v` 옵션으로 데이터를 유지한다.
