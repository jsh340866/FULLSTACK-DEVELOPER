# 1. Docker Compose란?

## 오늘 배운 내용

Docker Compose는 여러 개의 컨테이너를 하나의 설정 파일(`docker-compose.yml`)로 관리하는 도구이다.

기존에는 React, Spring Boot, MySQL, Redis를 각각 `docker run`으로 실행해야 했지만, Compose를 사용하면 하나의 명령으로 모든 컨테이너를 동시에 생성하고 실행할 수 있다.

---

## 핵심 코드

```yaml
services:
  frontend:
  backend:
  mysql:
  redis:
```

---

## 코드 설명

| 항목       | 설명               |
| -------- | ---------------- |
| services | 실행할 컨테이너 목록      |
| frontend | React 컨테이너       |
| backend  | Spring Boot 컨테이너 |
| mysql    | MySQL DB         |
| redis    | Redis 서버         |

---

### 실행 흐름

```text
docker-compose.yml
        ↓
서비스 읽기
        ↓
모든 컨테이너 생성
        ↓
동시에 실행
```

---

### 예상 결과

* React 실행
* Spring Boot 실행
* MySQL 실행
* Redis 실행

---

## 핵심 정리

* 여러 컨테이너를 하나의 파일에서 관리한다.
* 프로젝트 실행이 매우 간단해진다.

---

# 2. docker-compose.yml 작성

## 오늘 배운 내용

Compose 파일에는 사용할 이미지, 포트, 볼륨, 환경변수 등을 작성하여 프로젝트 전체 구성을 정의하였다.

---

## 핵심 코드

```yaml
services:
  backend:
    build: .
    ports:
      - "8080:8080"
```

---

## 코드 설명

| 항목       | 설명            |
| -------- | ------------- |
| build    | Dockerfile 이용 |
| ports    | 포트 연결         |
| services | 컨테이너 등록       |

---

### 실행 흐름

```text
Compose 읽기
      ↓
Dockerfile Build
      ↓
Container 실행
```

---

### 예상 결과

Spring Boot가 8080 포트에서 실행된다.

---

## 핵심 정리

* Compose는 Dockerfile도 함께 사용할 수 있다.
* 설정 변경 후 다시 실행하면 변경 사항이 반영된다.

---

# 3. 서비스 간 네트워크

## 오늘 배운 내용

Compose로 생성된 컨테이너들은 같은 네트워크에 자동으로 연결되어 서비스 이름만으로 서로 통신할 수 있다.

---

## 핵심 코드

```yaml
services:
  backend:
    depends_on:
      - mysql
```

---

## 코드 설명

| 항목         | 설명        |
| ---------- | --------- |
| depends_on | 선행 서비스 실행 |

---

### 실행 흐름

```text
MySQL 실행
      ↓
Backend 실행
      ↓
DB 연결
```

---

### 예상 결과

Spring Boot가 MySQL에 정상 연결된다.

---

## 핵심 정리

* IP 대신 서비스 이름으로 통신 가능
* 컨테이너 간 연결이 쉬워진다.

---

# 4. Volume 설정

## 오늘 배운 내용

MySQL 데이터를 유지하기 위해 Volume을 Compose에 등록하였다.

---

## 핵심 코드

```yaml
volumes:
  mysql-data:
```

```yaml
services:
  mysql:
    volumes:
      - mysql-data:/var/lib/mysql
```

---

## 코드 설명

| 항목         | 설명        |
| ---------- | --------- |
| volumes    | 영구 저장소    |
| mysql-data | DB 데이터 저장 |

---

### 실행 흐름

```text
Container 종료
      ↓
Volume 유지
      ↓
재실행
      ↓
기존 데이터 유지
```

---

### 예상 결과

DB가 삭제되지 않는다.

---

## 핵심 정리

* DB는 반드시 Volume을 사용하는 것이 좋다.
* 컨테이너를 삭제해도 데이터는 유지된다.

---

# 5. Compose 실행 및 종료

## 오늘 배운 내용

Compose 명령으로 모든 서비스를 한 번에 실행하고 종료하였다.

---

## 핵심 명령어

```bash
docker compose up
```

```bash
docker compose down
```

---

## 코드 설명

| 명령   | 설명         |
| ---- | ---------- |
| up   | 전체 실행      |
| down | 전체 종료 및 삭제 |

---

### 실행 흐름

```text
Compose 실행
      ↓
Image Build
      ↓
Container 생성
      ↓
서비스 실행
```

---

### 예상 결과

모든 컨테이너가 동시에 실행된다.

---

## 핵심 정리

* 여러 개의 docker run 명령이 필요 없다.
* 프로젝트 전체를 쉽게 관리할 수 있다.

---

# 6. Docker Hub란?

## 오늘 배운 내용

Docker Hub는 Docker 이미지를 저장하고 공유하는 공식 저장소이다.

직접 만든 이미지를 업로드(Push)하고 다른 환경에서 다운로드(Pull)하여 사용할 수 있다.

---

## 핵심 명령어

```bash
docker login
```

```bash
docker pull nginx
```

---

## 코드 설명

| 명령           | 설명       |
| ------------ | -------- |
| docker login | Hub 로그인  |
| docker pull  | 이미지 다운로드 |

---

### 실행 흐름

```text
Docker Hub
      ↓
Image 다운로드
      ↓
Local 저장
```

---

### 예상 결과

원격 이미지를 사용할 수 있다.

---

## 핵심 정리

* Docker Hub는 이미지 저장소이다.
* 필요한 이미지를 언제든 다운로드할 수 있다.

---

# 7. 이미지 업로드(Push)

## 오늘 배운 내용

직접 만든 이미지를 Docker Hub에 업로드하는 방법을 학습하였다.

---

## 핵심 명령어

```bash
docker tag my-app username/my-app

docker push username/my-app
```

---

## 코드 설명

| 명령   | 설명             |
| ---- | -------------- |
| tag  | 업로드용 이름 변경     |
| push | Docker Hub 업로드 |

---

### 실행 흐름

```text
Image 생성
      ↓
Tag 지정
      ↓
Docker Hub 업로드
```

---

### 예상 결과

Docker Hub Repository에 이미지가 등록된다.

---

## 핵심 정리

* Push 전에 반드시 로그인해야 한다.
* Repository 이름 형식을 맞춰야 한다.

---

# 8. 이미지 다운로드(Pull)

## 오늘 배운 내용

Docker Hub에 업로드한 이미지를 다른 PC에서 내려받아 실행하였다.

---

## 핵심 명령어

```bash
docker pull username/my-app

docker run username/my-app
```

---

## 코드 설명

| 명령   | 설명       |
| ---- | -------- |
| pull | 이미지 다운로드 |
| run  | 컨테이너 실행  |

---

### 실행 흐름

```text
Docker Hub
      ↓
Pull
      ↓
Image 생성
      ↓
Container 실행
```

---

### 예상 결과

다른 환경에서도 동일한 프로그램이 실행된다.

---

## 핵심 정리

* 개발 환경과 운영 환경을 동일하게 유지할 수 있다.
* 이미지를 공유하여 배포가 쉬워진다.

---
