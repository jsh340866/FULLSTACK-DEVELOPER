# TIL: AWS EC2 포트 개방 + GitHub ↔ Jenkins 연동

> 📅 2026-07-08
> 주제: EC2 보안 그룹에 Jenkins용 포트(9090) 추가, PuTTY로 접속해 Jenkins 설치, GitHub와 Jenkins 연결

---

## 1. 학습 목표

- AWS EC2 인스턴스의 **보안 그룹(Security Group)** 에 인바운드 규칙을 추가해 외부에서 Jenkins에 접근할 수 있도록 포트를 개방한다
- **GitHub 저장소와 Jenkins를 연동**해 코드 변경 시 자동으로 빌드/배포가 가능한 CI/CD 기반을 만든다

---

## 2. EC2 보안 그룹에 포트 9090 추가

### 왜 필요한가?

- EC2는 기본적으로 보안 그룹에 허용된 포트만 외부 접근이 가능하다 (기본: SSH 22)
- Jenkins를 9090 포트로 띄웠다면, 브라우저에서 `http://<퍼블릭 IP>:9090` 으로 접속하기 위해 해당 포트를 열어야 한다

### 설정 방법

1. AWS 콘솔 → **EC2** → 인스턴스 선택
2. 하단 탭에서 **보안(Security)** → 연결된 **보안 그룹** 클릭
3. **인바운드 규칙(Inbound rules)** → **규칙 편집(Edit inbound rules)**
4. **규칙 추가(Add rule)** 후 아래와 같이 입력

| 항목 | 값 |
|---|---|
| 유형 | 사용자 지정 TCP (Custom TCP) |
| 포트 범위 | `9090` |
| 소스 | `0.0.0.0/0` (모든 IP 허용) 또는 내 IP |
| 설명 | Jenkins |

5. **규칙 저장(Save rules)**

### 접속 확인

```
http://<EC2 퍼블릭 IP 또는 퍼블릭 DNS>:9090
```

> ⚠️ 소스를 `0.0.0.0/0` 으로 열면 전 세계 어디서든 접근 가능하므로, 실습 후에는 내 IP로 제한하거나 규칙을 삭제하는 것이 안전하다.
> ⚠️ EC2를 중지 후 재시작하면 퍼블릭 IP가 바뀐다 (탄력적 IP를 쓰지 않는 경우).

## 3. PuTTY로 EC2 접속 후 Jenkins 설치

### 3-1. PuTTY로 EC2 접속

1. **PuTTYgen**으로 EC2 키 페어(`.pem`)를 PuTTY용 키(`.ppk`)로 변환
   - PuTTYgen 실행 → **Load** 로 `.pem` 선택 → **Save private key** 로 `.ppk` 저장
2. **PuTTY** 실행 후 접속 정보 입력

| 항목 | 값 |
|---|---|
| Host Name | `ec2-user@<EC2 퍼블릭 IP>` |
| Port | `22` |
| Connection → SSH → Auth → Credentials | 변환한 `.ppk` 파일 지정 |

3. **Open** → 접속 성공 시 EC2 터미널 진입

> ⚠️ 보안 그룹에 SSH(22) 인바운드 규칙이 열려 있어야 접속된다.

### 3-2. Java 설치 (Jenkins 실행에 필요)

```bash
# Jenkins는 Java 기반이므로 먼저 설치
sudo dnf install -y java-17-amazon-corretto

# 설치 확인
java -version
```

### 3-3. Jenkins 설치

```bash
# Jenkins 공식 저장소 등록
sudo wget -O /etc/yum.repos.d/jenkins.repo https://pkg.jenkins.io/redhat-stable/jenkins.repo
sudo rpm --import https://pkg.jenkins.io/redhat-stable/jenkins.io-2023.key

# Jenkins 설치
sudo dnf install -y jenkins
```

### 3-4. Jenkins 포트를 9090으로 변경

```bash
# 기본 포트는 8080 → 9090으로 변경
sudo vi /usr/lib/systemd/system/jenkins.service
```

```ini
# 아래 항목을 찾아 수정
Environment="JENKINS_PORT=9090"
```

```bash
# 설정 반영 후 Jenkins 시작
sudo systemctl daemon-reload
sudo systemctl enable jenkins
sudo systemctl start jenkins

# 실행 상태 확인
sudo systemctl status jenkins
```

### 3-5. 초기 접속 및 잠금 해제

1. 브라우저에서 `http://<EC2 퍼블릭 IP>:9090` 접속
2. 초기 관리자 비밀번호 확인 후 입력

```bash
sudo cat /var/lib/jenkins/secrets/initialAdminPassword
```

3. **Install suggested plugins** 선택 → 관리자 계정 생성 → 설정 완료

> ⚠️ EC2 프리티어(t2.micro)는 메모리가 1GB뿐이라 Jenkins가 느리거나 죽을 수 있다. 스왑 메모리를 추가하면 안정적이다.

## 4. GitHub와 Jenkins 연결

### 전체 흐름

```
GitHub (코드 push)
   │  Webhook 또는 Poll SCM
   ▼
Jenkins (EC2:9090)
   │  Clone → Build → Deploy
   ▼
애플리케이션 배포
```

### 4-1. Jenkins에 GitHub 플러그인 설치

1. Jenkins 접속 → **Jenkins 관리(Manage Jenkins)** → **Plugins**
2. `GitHub Integration`, `Git` 플러그인 설치 확인 (대부분 기본 설치됨)

### 4-2. GitHub 자격 증명 등록

1. GitHub → **Settings → Developer settings → Personal access tokens** 에서 토큰 발급
   - 권한: `repo` (프라이빗 저장소인 경우 필수)
2. Jenkins → **Jenkins 관리 → Credentials → Global → Add Credentials**
   - Kind: `Username with password`
   - Username: GitHub 아이디
   - Password: 발급받은 토큰

### 4-3. Jenkins Job(프로젝트) 생성 및 저장소 연결

1. **새로운 Item** → 이름 입력 → **Freestyle project** (또는 Pipeline) 선택
2. **소스 코드 관리(Source Code Management)** → **Git** 선택
   - Repository URL: `https://github.com/<사용자명>/<저장소명>.git`
   - Credentials: 위에서 등록한 자격 증명 선택
   - Branch: `*/main` (저장소 기본 브랜치에 맞게)
3. 저장 후 **지금 빌드(Build Now)** 로 클론이 정상 동작하는지 확인

### 4-4. GitHub Webhook 설정 (push 시 자동 빌드)

1. GitHub 저장소 → **Settings → Webhooks → Add webhook**

| 항목 | 값 |
|---|---|
| Payload URL | `http://<EC2 퍼블릭 IP>:9090/github-webhook/` |
| Content type | `application/json` |
| Events | Just the push event |

2. Jenkins Job 설정 → **빌드 유발(Build Triggers)** → ✅ **GitHub hook trigger for GITScm polling** 체크
3. 코드를 push하면 Jenkins가 자동으로 빌드를 시작한다

> ⚠️ Payload URL 끝의 `/github-webhook/` 슬래시까지 정확히 입력해야 한다.
> ⚠️ 보안 그룹에 9090이 열려 있어야 GitHub가 Webhook을 전달할 수 있다.

---

## 5. 오늘 배운 것 요약

- EC2는 보안 그룹 인바운드 규칙에 포트를 추가해야 외부 접근이 가능하다 → Jenkins용 **9090** 개방
- **PuTTY**로 EC2에 SSH 접속해 Java + Jenkins를 설치하고, 기본 포트 8080을 **9090**으로 변경했다
- Jenkins는 **자격 증명(토큰) + Repository URL** 로 GitHub 저장소와 연결한다
- **Webhook**을 걸면 push → 자동 빌드로 이어지는 CI 파이프라인의 첫 단계가 완성된다
