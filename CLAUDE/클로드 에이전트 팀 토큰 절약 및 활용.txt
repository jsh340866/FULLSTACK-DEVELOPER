

[섹션 2 · PLAN APPROVAL]

계획 먼저, 코딩 나중

팀원이 바로 코딩하면 방향이 틀어질 때 토큰 전부 낭비. 한 줄만 추가하세요.

01 팀 생성 — plan approval
02 계획 분석 — Plan Mode
03 계획 제출 — 리드에게 보고
04 승인/거절 — 리드가 판단
05 구현 시작 — 승인 후 실행

# 프롬프트에 이 한 줄만 추가
각 팀원이 변경하기 전에 plan approval을 받도록 해줘.




[섹션 2 · 승인 기준]

프롬프트로 자동 판단 기준 설정

리드가 알아서 판단하도록 기준을 미리 정해두세요.

✏️ "테스트 커버리지를 포함하는 계획만 승인해."
   → 테스트 없는 계획은 자동 거절

🛡️ "데이터베이스 스키마를 수정하는 계획은 거절해."
   → DB 변경은 무조건 차단

⚡ "성능 영향 분석이 포함된 계획만 승인해."
   → 성능 고려 없으면 거절

💡 혼자 쓸 때든 팀으로 쓸 때든, "계획 먼저" 원칙은 변하지 않습니다. 이 습관 하나만 들여도 토큰 낭비가 확 줄어들어요.



[섹션 3 · 비용 절감]

4가지 비용 절감 전략

01 팀이 진짜 필요한지 판단
   소통 불필요한 작업은 서브에이전트 사용. 조율 오버헤드 제거.

02 최소 인원으로 시작
   3~5명이면 충분. 10명은 수확 체감이 심함.

03 끝난 팀원은 즉시 종료
   세션이 살아있으면 계속 토큰 소모. 바로 종료 요청.

04 CLAUDE.md에 비용 지침
   broadcast 금지, 완료 후 즉시 종료, 반복 3회 제한.


[섹션 4 · HOOKS]

Hooks = 이벤트 기반 자동화

"어떤 일이 일어나면, 이 스크립트를 자동으로 실행해라"

이벤트 발생 — 팀원이 작업 완료 또는 idle 상태
       ↓
셸 스크립트 실행 — 테스트, lint, 타입 체크 등
       ↓
결과에 따라 제어 — exit 0 = 통과 / exit 2 = 차단

💡 exit code는 스크립트가 끝날 때 보내는 신호 번호. 0 = "OK, 통과!", 2 = "문제 있어!" — 이 신호에 따라 Claude Code가 다음 동작을 결정합니다.



[섹션 4 · 훅 비교]

TeammateIdle vs TaskCompleted

■ TeammateIdle
팀원이 할 일을 끝내고 쉬고 있을 때 발동
exit 2 → 피드백을 전달해서 팀원이 계속 작업하도록
"쉬고 있는 직원에게 추가 업무를 주는 것"

# 활용 예시
"작업 끝나면 요약 보고서를 작성해라"

■ TaskCompleted
팀원이 태스크를 "완료" 처리할 때 발동
exit 2 → 완료 자체를 차단하고 피드백 전달
"팀장이 결과물 검토 후 돌려보내는 것"

# 자동 테스트 게이트
npm test || exit 2
