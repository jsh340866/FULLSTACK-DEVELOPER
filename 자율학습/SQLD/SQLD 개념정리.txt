1. 이력 데이터의 종류 (시험 단골!)
시험에서는 이 데이터를 어떤 성격으로 관리하느냐에 따라 크게 세 가지로 분류해요.
- 상태 이력: 특정 시점의 상태가 어떻게 변했는지 기록 (예: 주문 상태가 '결제 완료' → '배송 중' → '배송 완료'로 변하는 과정)
- 변경 이력: 데이터의 값 자체가 수정된 내역을 기록 (예: 고객의 주소지 변경, 전화번호 변경 내역)
- 발생 이력: 어떤 사건이 발생할 때마다 쌓이는 기록 (예: 로그 기록, 입출금 내역)

2. 선분이력 (SQLD 핵심 포인트!)
이력 관리 기법 중에서 가장 중요한 게 바로 '선분이력'이에요. 특정 데이터가 "언제부터 언제까지 유효했는지" 기간(선분)으로 관리하는 방식입니다.
- 관리 방식: 시작일자와 종료일자 두 개의 컬럼을 사용합니다.
- 장점: 특정 시점(예: 2026년 1월 1일)에 이 데이터가 어떤 상태였는지 조회하기가 매우 편리해요.
- 주의점: 현재 유효한 데이터의 종료일자는 보통 '9999-12-31' 같은 먼 미래의 날짜로 설정해둡니다.

3. 이력 데이터 설계 시 고려사항
- 정규화와의 관계: 이력 데이터는 데이터가 계속 쌓이기 때문에 성능을 위해 반정규화를 고민해야 할 때가 많아요.
- PK(기본키) 설정: 보통 원래의 PK + 시작일자를 묶어서 새로운 PK로 설정하는 경우가 많습니다.



### 모델링 단계별 주요 수행 작업

개념 모델링: 핵심 엔터티(Entity) 도출 및 엔터티 간의 관계 정의 (ERD 작성)

논리 모델링: 전체 속성(Attribute) 도출, 식별자(PK/FK) 지정, 정규화(Normalization) 수행

물리 모델링: 특정 DBMS 선정, 구체적인 데이터 타입 및 크기 지정, 인덱스(Index) 설계 및 반정규화 수행


### 데이터 독립성

논리적 독립성: 테이블(개념) 구조가 바뀌어도 **응용 프로그램(외부)**은 그대로 유지.

물리적 독립성: 디스크 저장 방식(내부)이 바뀌어도 테이블(개념) 구조는 그대로 유지.

■ SQLD 식별자 분류 체계 총정리

1. 대표성 여부
- 주식별자: 엔터티를 대표하는 유일한 식별자 (PK 변환, Not Null, Unique, 상속 가능)
- 보조식별자: 유일성은 가지나 대표성이 없는 식별자 (Unique 인덱스 변환, 상속 불가능)

2. 스스로 생성되었는가
- 내부식별자: 엔터티 내부에서 스스로 생성된 식별자
- 외부식별자: 타 엔터티와의 관계를 통해 부모에게 물려받은 식별자 (FK 변환, 조인 고리 역할)

3. 속성의 개수
- 단일식별자: 1개의 속성으로만 구성된 식별자 (예: 사원번호)
- 복합식별자: 2개 이상의 속성을 합쳐서 만든 식별자 (예: 주문번호 + 일련번호)

4. 대체 여부 (업무 구성 방식)
- 본질식별자: 원래 업무 프로세스에 자연스럽게 존재하는 식별자 (예: 주민등록번호, 계좌번호)
- 인조식별자: 본질식별자가 복잡하거나 보안상 이유로 쓸 수 없을 때 인위적으로 만든 대체 식별자 (예: 일련번호, 주문번호)


■ 식별자 분류 기준 요약

- 대표성 여부 -> 주식별자 / 보조식별자
- 생성 여부   -> 내부식별자 / 외부식별자
- 속성 수     -> 단일식별자 / 복합식별자
- 대체 여부   -> 본질식별자 / 인조식별자

# 🎖️ SQLD 시험 합격 보장 핵심 필수 개념 요약

## 📌 1과목: 데이터 모델링의 이해 (10문항)
1과목은 개념을 정확히 이해하고 매칭하는 문제가 주로 출제됩니다.

### 1) 데이터 모델링의 3가지 관점
* **데이터 관점 (What):** 업무가 어떤 데이터와 관련이 있는지, 데이터 간의 관계는 무엇인지 분석.
* **프로세스 관점 (How):** 업무가 실제로 어떻게 목적으로 진행되고 있는지 분석.
* **상관 관점 (Interaction):** 프로세스와 데이터가 서로 어떻게 영향을 주고받는지 분석 (CRUD 매트릭스).

### 2) 엔터티 (Entity)의 분류 (★ 발생 시점에 따른 분류 필수 암기!)
* **기본 엔터티 (키엔터티):** 다른 엔터티의 도움 없이 고유하게 존재하는 엔터티 (예: 고객, 상품, 사원).
* **중심 엔터티 (메인엔터티):** 기본 엔터티로부터 발생하며, 업무의 중심 역할을 함 (예: 주문, 접수, 계약).
* **행위 엔터티 (액티브엔터티):** 두 개 이상의 엔터티가 만나서 발생하는 자주 변하는 엔터티 (예: 주문내역, 결제이력).

####
발생시점 - 유무형
기본,중심,행위 - 개념,사건,유형
기 행 종(중) - 개 사 료(유)

도메인 : "속성이 가질 수 있는 원자값들의 범위(집합)"

### 3) 속성의 분류
* **기본 속성:** 업무로부터 추출된 가장 일반적인 속성 (예: 이름, 주소). 
		- 업무(현업)에서 쓰던 날것의 데이터
		- 자연스럽게 업무상 존재하는 데이터

* **설계 속성:** 업무에는 없으나 시스템 규칙을 위해 새로 만든 속성 (예: 일련번호, 상품코드).
		- 개발자(설계자)가 관리하려고 만든 코드
		- 시스템의 효율성을 위해 인위적으로 새로 정의한 속성

* **파생 속성:** 다른 속성에 의해 계산되거나 영향을 받아 생성된 속성 (예: 총액, 평균, 이수학점).
		- 계산기 두드려서 나온 결과물 (계산/집계)
		- "조회 성능을 빠르게 만들기 위해" 일부러 테이블에 칸을 파서 계산 결과를 저장

### 4) 식별자 (Identifier)의 분류
* **주식별자 고유성 특징 (필수 암기):** **주배유최** (주기성/배타성X -> 최소성, 고유성, 불변성, 존재성)
    * **고유성:** 엔터티 내의 모든 인스턴스들을 유일하게 구분함.
    * **최소성:** 주식별자를 구성하는 속성은 유일성을 만족하는 최소한의 수여야 함.
    * **불변성:** 한 번 지정되면 값이 변하지 않아야 함.
    * **존재성:** 데이터가 입력될 때 반드시 값이 있어야 함 (Null 불가).

### 5) 정규화 (Normalization) 효과 (★ 계산 문제 단골!)
* 1정규형(1NF): 모든 속성은 **원자값**을 가짐.
		- 원자값, 다중값 제거, 도메인이 원자값

* 2정규형(2NF): 기본키의 일부분에 종속되는 **부분 함수 종속성 제거**.
		- 부분 함수 종속성 제거, 완전 함수 종속, 복합키 분리

* 3정규형(3NF): 주식별자가 아닌 일반 속성 간의 종속성 제거 (**이행적 함수 종속성 제거**).
		- 이행적 함수 종속성 제거, 주식별자가 아닌 일반 속성 간의 종속
> 💡 **주의:** 정규화를 진행하면 입력/수정/삭제 성능은 향상되지만, 조인(Join)이 많아져 **조회(Select) 성능은 저하될 수 있음** (이때 반정규화를 고려함).

## 📌 2과목: SQL 기본 및 활용 (40문항)
2과목은 실제로 SQL 쿼리문의 실행 결과를 예측하는 문제가 많아 실전 연습이 중요해요!

### 1) SQL 명령어 종류 (★ 섞어놓고 고르는 문제 100% 출제)
| 분류 | 명령어 | 특징 |
| **DDL (정의어)** | `CREATE`, `ALTER`, `DROP`, `RENAME`, `TRUNCATE` | 실행 시 자동 커밋(Auto Commit) 됨 |
| **DML (조작어)** | `SELECT`, `INSERT`, `UPDATE`, `DELETE` | 테이블의 데이터를 조작, Rollback 가능 | 
			|  MERGE = UPDATE + INSERT (일명 UPSERT) |
| **DCL (제어어)** | `GRANT`, `REVOKE` | 권한을 부여하거나 회수함 |
| **TCL (트랜잭션)**| `COMMIT`, `ROLLBACK`, `SAVEPOINT` | 트랜잭션을 제어함 |
> ⚠️ **TRUNCATE(DDL) vs DELETE(DML) 차이점:** `TRUNCATE`는 용량을 완전히 초기화하고 롤백이 불가능하지만, `DELETE`는 데이터만 지우고 롤백이 가능해요!

### 2) NULL의 특성 (계산 문제 함정 주의!)
* NULL은 **알 수 없는 값(Unknown)**을 의미하며, 0이나 공백(' ')과 다릅니다.
* **NULL과의 모든 연산 결과는 NULL**입니다. (예: `NULL + 100 = NULL`)
* 집계 함수(`SUM`, `AVG`, `COUNT`)는 **NULL 값을 제외하고 계산**합니다. (단, `COUNT(*)`는 NULL 포함)
* NULL을 처리하는 함수: `NVL` (Oracle), `ISNULL` (SQL Server), `COALESCE` (공통)

### 3) JOIN 연산
* **INNER JOIN:** 양쪽 테이블에 모두 매칭되는 데이터만 출력.
* **LEFT/RIGHT OUTER JOIN:** 한쪽 테이블을 기준으로 매칭되지 않는 데이터도 NULL로 채워서 함께 출력.
* **NATURAL JOIN:** 이름과 데이터 타입이 같은 모든 컬럼을 자동으로 조인 (ON 절 생략, 중복 컬럼은 하나만 출력).

### 4) 서브쿼리 (Subquery) 특징
* **스칼라 서브쿼리:** `SELECT` 절에 사용되며, 반드시 **단일 행(1 row, 1 column)**을 반환해야 함.
* **인라인 뷰:** `FROM` 절에 사용되는 서브쿼리로, 가상의 테이블처럼 동작함.
* **중첩 서브쿼리:** `WHERE` 절에 사용됨.
    * 다중 행 반환 시 `IN`, `ANY`, `ALL`, `EXISTS` 등의 연산자를 필수 사용해야 함.

## 📌 WHERE 절 중첩 서브쿼리의 2대 분류 기준

| 분류 | 특징 및 동작 방식 | 시험 단골 키워드 |
| **비연관 서브쿼리**<br>(Uncorrelated) | • 서브쿼리가 메인쿼리의 컬럼을 가지고 있지 않음<br>• **서브쿼리가 독자적으로 먼저 실행**되어 값을 메인쿼리에 전달함 | `독립 실행`, `단방향 전달` |
| **연관 서브쿼리**<br>(Correlated) | • 서브쿼리 내부에 **메인쿼리의 컬럼이 포함**되어 있음<br>• 메인쿼리의 행을 하나씩 읽을 때마다 서브쿼리가 매번 실행됨 | `메인쿼리 종속`, `반복 수행` |

### . 어떤 모양의 결과를 뱉는가? (반환 형태 기준)

| 분류 | 특징 | 사용하는 핵심 연산자 |
| **단일 행 서브쿼리**<br>(Single-Row) | 서브쿼리의 결과가 **딱 1건(1행)**만 나오는 경우 | `=`, `>`, `<`, `>=`, `<=`, `<>` |
| **다중 행 서브쿼리**<br>(Multiple-Row) | 서브쿼리의 결과가 **여러 건(여러 행)** 나오는 경우 | `IN`, `ANY`, `SOME`, `ALL`, `EXISTS` |
| **다중 컬럼 서브쿼리**<br>(Multiple-Column) | 서브쿼리가 **여러 개의 컬럼(열)**을 동시에 뱉는 경우 | `WHERE (A, B) IN (SELECT A, B ...)` |



### 5) 그룹 함수 및 윈도우 함수
* **ROLLUP / CUBE / GROUPING SETS:** 그룹별 소계를 구할 때 사용. (특히 ROLLUP의 순서에 따른 결과 차이 주의!)
* **RANK vs DENSE_RANK vs ROW_NUMBER:**
    * `RANK`: 공동 순위 있으면 다음 순위 건너뜀 (1등, 2등, 2등, 4등)
    * `DENSE_RANK`: 공동 순위 있어도 연속된 순위 부여 (1등, 2등, 2등, 3등)
    * `ROW_NUMBER`: 무조건 고유한 일련번호 부여 (1등, 2등, 3등, 4등)

# 🎖️ SQLD 필수 암기: 엔터티(Entity)의 모든 분류 총정리

---

## 📌 1. 발생 시점(업무 흐름)에 따른 분류 (기 · 중심 · 행위)

### ① 기본 엔터티 (Key Entity)
* **정의:** 다른 엔터티의 도움 없이 독립적으로 생성되며, 고유한 주식별자를 가집니다.
* **예시:** `고객`, `상품`, `사원`, `부서`

### ② 중심 엔터티 (Main Entity)
* **정의:** 기본 엔터티로부터 발생하며, 업무의 핵심 역할을 수행하고 행위 엔터티를 생성합니다.
* **예시:** `주문`, `접수`, `계약`, `매출`

### ③ 행위 엔터티 (Active Entity)
* **정의:** 두 개 이상의 엔터티가 상호작용하여 발생하며, 데이터가 자주 변하고 지속적으로 누적됩니다.
* **예시:** `주문내역`, `계약이력`, `입출금내역`

---

## 📌 2. 유형 성격(유무형 형태)에 따른 분류 (유 · 개 · 사)

### ① 유형 엔터티 (Tangible Entity)
* **정의:** 물리적인 형태가 있어서 눈으로 볼 수 있고 만질 수 있는 개체입니다.
* **예시:** `사원`, `물품`, `강사`, `학생`

### ② 개념 엔터티 (Conceptual Entity)
* **정의:** 물리적인 형태는 없으나, 관리적·개념적 목적으로 존재하는 개체입니다.
* **예시:** `부서`, `학과`, `품목그룹`, `계정과목`

### ③ 사건 엔터티 (Event Entity)
* **정의:** 업무를 수행함에 따라 비즈니스 행위(사건)로 인해 발생하는 개체입니다.
* **예시:** `주문`, `청구`, `미납`, `계약`, `접수`

1. GROUP BY CUBE (다차원 집계)
-----------------------------------------------------------
- 지정한 컬럼들로 만들 수 있는 모든 조합(2^n)의 합계를 한 번에 계산.
- 중간 합계, 전체 총합계 자리에 데이터 구분을 위해 NULL이 대량 발생.
- (참고) ROLLUP은 순서대로 계층 구조만 집계, CUBE는 순서 상관없이 모든 조합 집계.


2. COALESCE 함수 (NULL 처리 해결사)
-----------------------------------------------------------
- 괄호 안의 인자들을 왼쪽부터 읽으며 NULL이 아닌 첫 번째 값을 반환.
- CUBE/ROLLUP이 만들어낸 NULL 자리에 '전체부서', '전체직급' 등 기본값을 채울 때 사용.
- 맨 마지막 자리에 확실한 상수(글자나 숫자)를 넣어두면 100% NULL 방어 가능.
  예) COALESCE(DEPTNO, '전체부서') AS 부서번호


3. SQL 데이터 타입과 출력 차이 ('05' vs 5)
-----------------------------------------------------------
- 문자형 ('05') : CONCAT, SUBSTR 등으로 처리된 데이터는 글자 형태라 앞의 '0'이 유지됨.
- 숫자형 (5)    : EXTRACT(MONTH FROM...)이나 순수한 숫자는 수학과 같아서 앞의 '0'이 제거됨.


4. 집계 함수 vs 윈도우 함수
-----------------------------------------------------------
- 집계 함수 : GROUP BY와 함께 사용. 여러 행을 그룹화하여 결과 행을 대폭 줄임 (SUM, AVG 등).
- 윈도우 함수 : OVER()와 함께 사용. 기존의 상세 행을 그대로 유지하면서 옆에 통계 컬럼만 추가.


5. PIVOT (행을 열로 회전)
-----------------------------------------------------------
- 세로로 길게 나오는 행(Row) 데이터를 가로로 넓게 펼쳐서 새로운 열(Column) 제목으로 변경.
- 구조: FOR 컬럼명 IN ('Q1', 'Q2') -> 여기에 적힌 값들이 가로 열 제목이 됨.
- 구조: SUM(amount) -> 바둑판 모양의 빈칸(교차점)을 채울 실제 데이터 값(집계 필수).


6. 오라클 (+) ↔ ANSI 표준 JOIN 변환
-----------------------------------------------------------
- 핵심 원리: 오라클 문법에서 (+) 기호가 "없는" 쪽이 데이터가 다 살아남는 [주인공] 테이블!
- 방향 결정: ANSI 표준에서는 JOIN 글자를 기준으로 테이블의 물리적 위치(좌/우)를 봄.
  
  예) WHERE EMP.부서코드(+) = DEPT.부서코드;
      -> (+)가 없는 DEPT가 주인공!
      -> ANSI 문법으로 배치할 때 DEPT가 우측에 위치하므로 [RIGHT OUTER JOIN] 사용.

  ※ 3초 컷 팁: (+) 기호가 왼쪽에 있으면 -> RIGHT JOIN / 오른쪽에 있으면 -> LEFT JOIN

SQLD 필수 암기: 시험에 무조건 나오는 윈도우 함수 총정리

★ 핵심 공통 문법 구조
   SELECT 함수명() OVER (PARTITION BY 그룹컬럼 ORDER BY 정렬컬럼) FROM 테이블명;
   - PARTITION BY : 그룹으로 나눌 기준 (GROUP BY와 유사하지만 행은 안 줄어듦!)
   - ORDER BY : 그 그룹 안에서 순서를 정할 기준


1. 순위 결정 함수 (★ 가장 많이 출제!)
-----------------------------------------------------------
데이터의 순위나 등수를 매기는 함수들입니다. (동점자 처리 방식이 핵심 시험문제!)

- RANK()       : 공동 순위가 있으면 그만큼 건너뛰고 다음 순위 부여.
                 예) 1등, 2등, 2등, 4등 (3등이 사라짐)
- DENSE_RANK() : 공동 순위가 있어도 건너뛰지 않고 빽빽하게 이어서 순위 부여.
                 예) 1등, 2등, 2등, 3등 (3등이 유지됨)
- ROW_NUMBER() : 값과 관계없이 행이 정렬된 순서대로 무조건 고유한 번호 부여.
                 예) 1등, 2등, 3등, 4등 (중복 없음)

- TOP (N): 정렬된 결과에서 상위 N개의 행만 딱 잘라서 가져옵니다.
- WITH TIES: (★핵심) 맨 마지막 등수(N번째 행)와 데이터 값이 완전히 같은 동점자가 있다면, $N$개를 초과하더라도 전부 화면에 다 출력하라는 마법의 옵션입니다.


2. 일반 집계 함수 (윈도우 버전)
-----------------------------------------------------------
우리가 잘 아는 집계 함수 뒤에 OVER()가 붙으면 윈도우 함수로 변신합니다.
행을 줄이지 않고, 사원별 상세 정보 옆에 집계 값을 그대로 출력해 줍니다.

- SUM()   : 특정 그룹의 합계 또는 누적합 계산
- AVG()   : 특정 그룹의 평균 계산
- COUNT() : 특정 그룹의 건수(행 수) 계산
- MAX()   : 특정 그룹의 최댓값 조회
- MIN()   : 특정 그룹의 최솟값 조회


3. 행 순서 관련 함수 (★ 계산 문제 단골!)
-----------------------------------------------------------
현재 행을 기준으로 앞이나 뒤에 있는 행의 값을 땡겨오거나 찾아내는 함수입니다.

- LAG(컬럼, N)  : 현재 행보다 'N번째 이전(위)' 행의 값을 가져옴. (주로 전날, 작년 데이터 비교)
- LEAD(컬럼, N) : 현재 행보다 'N번째 이후(아래)' 행의 값을 가져옴. (주로 다음날 데이터 비교)
- FIRST_VALUE() : 파티션(그룹) 안에서 가장 첫 번째(맨 위) 행의 값을 가져옴.
- LAST_VALUE()  : 파티션(그룹) 안에서 가장 마지막(맨 아래) 행의 값을 가져옴. 
                 ※ 단, 윈도우 기본 툴(Row Frame) 때문에 결과가 이상해질 수 있어서 
                    시험에서는 이 특성을 함정으로 자주 파놓음!


4. 비율 관련 함수

-----------------------------------------------------------
- CUME_DIST()    : 누적 백분율(0~1 사이 값)을 구함. 전체 건수 중 현재 행 이하의 비율.
- PERCENT_RANK() : 순위를 백분율(0~1 사이 값)로 환산함. 가장 첫 행은 0, 마지막 행은 1.
- NTILE(N)       : 전체 데이터를 N등분(N개의 버킷)으로 균등하게 분할하여 조 번호를 매김.
                   예) 10명을 NTILE(4) 하면 순서대로 1,1,1, 2,2,2, 3,3, 4,4 조가 됨.

SQLD 필수 암기: GROUP BY 확장 함수 (소계/총합계)

GROUP BY 뒤에 아래 함수들을 사용하면, 일반적인 그룹화 외에 
각종 중간 합계(소계)와 전체 총합계를 한 번에 구해줍니다.

★ 핵심 요약용 예시 기준: GROUP BY 함수(A, B) 일 때


1. ROLLUP(A, B) : 계층적/순차적 소계 (★ 순서가 중요!)
-----------------------------------------------------------
- 단어 뜻 그대로 '돌려 깎으며' 위로 올라가는 계층적 집계입니다.
- 인자의 순서(좌우)가 바뀌면 결과 테이블의 내용도 완전히 바뀝니다!
- 조합 개수: N + 1 개

[집계되는 조합] (오른쪽에서부터 하나씩 탈락시킴)
① (A, B)별 상세 집계
② (A)별 중간 소계  <-- (오른쪽 B가 탈락!)
③ () 전체 총합계   <-- (A까지 탈락!)
※ 주의: (B) 개별 소계는 절대 구하지 않습니다!


2. CUBE(A, B) : 다차원/모든 조합 집계 (★ 순서 상관없음!)
-----------------------------------------------------------
- 결합 가능한 모든 경우의 수를 큐브(입체)처럼 전부 다 집계합니다.
- 인자의 순서가 바뀌어도 집계 결과는 똑같습니다.
- 조합 개수: 2^N 개

[집계되는 조합]
① (A, B)별 상세 집계
② (A)별 중간 소계
③ (B)별 중간 소계  <-- (ROLLUP과 다른 점! 🌟)
④ () 전체 총합계


3. GROUPING SETS(A, B) : 개별 조합 집계 (★ 총합계 없음!)
-----------------------------------------------------------
- 평등하게 "A별로 한 번 묶고, B별로 한 번 묶어서 합쳐라"라는 뜻입니다.
- 각 컬럼별 집계를 따로따로 구해서 UNION ALL로 합친 것과 같습니다.
- 가장 중요한 특징: ★ '전체 총합계()'는 기본적으로 구하지 않습니다!

[집계되는 조합]
① (A)별 집계
② (B)별 집계
※ 만약 총합계도 보고 싶다면 GROUPING SETS(A, B, ()) 이렇게 공백 괄호를 직접 넣어줘야 합니다.


4. GROUPING(컬럼) 함수 : 가짜 NULL 감지기
-----------------------------------------------------------
- ROLLUP이나 CUBE 때문에 생성된 '합계용 NULL'인지, 실제 데이터의 NULL인지 구분해 주는 함수입니다.
- SELECT 절에서 사용되며, 무조건 숫자 [0] 또는 [1]을 반환합니다.

- 반환값 [1] : ROLLUP/CUBE가 합계를 내려고 억지로 만든 "가짜 NULL(공백)"이다! ➡️ 주로 '총계' 또는 '소계'라는 글자로 바꿀 때 사용.
- 반환값 [0] : 원래 데이터에 들어있던 실제 값이거나 실제 NULL이다!

예시 문법)
SELECT 
    CASE WHEN GROUPING(DEPTNO) = 1 THEN '모든부서' ELSE TO_CHAR(DEPTNO) END AS 부서
FROM EMP
GROUP BY ROLLUP(DEPTNO);

1. 특성에 따른 분류 (★시험 단골 출제!) - 속성 분류!!!( 일반 속성(PK, FK)은 속성 분류가 아님 )
속성이 가진 본질적인 데이터의 성격에 따라 기본, 설계, 파생 속성 3가지로 나뉘는데, 시험에서는 이 3개를 구별하는 문제가 정말 많이 나와요.

① 기본 속성 (Basic Attribute)
- 의미: 업무 분석을 통해 가장 자연스럽고 원초적으로 얻어진 속성이에요. (가장 많음)
- 특징: 원래부터 존재하던 데이터로, 다른 속성을 가공해서 만든 게 아니에요.
- 예시: 사원번호, 이름, 직급, 급여, 주민등록번호

② 설계 속성 (Designed Attribute)
- 의미: 원래 업무에는 없었지만, 데이터베이스에 저장하거나 관리하기 편하게 하려고 개발자가 인위적으로 새로 만든 속성이에요.
- 특징: 보통 고유한 일련번호나 코드를 부여할 때 많이 써요.
- 예시: 상품코드, 부서코드, 학생회원 일련번호

③ 파생 속성 (Derived Attribute)
- 의미: 기존에 있던 다른 속성의 값을 계산하거나 가공해서 새로 만들어낸 속성이에요.
- 특징: 값이 자꾸 변할 수 있고, 계산하느라 컴퓨터 성능에 영향을 줄 수 있어서 꼭 필요한 경우에만 최소한으로 설계해야 해요.
- 예시: 총액(수량*단가), 평균점수(국어+영어/2), 나이(현재연도-출생연도)

INNER JOIN과 OUTER JOIN 정리

1. INNER JOIN (내부 조인) 🤝
"커플 매칭 성공! 완벽하게 짝이 있는 애들만 데려간다!"

교집합이라고 생각하시면 돼요. 양쪽 테이블 모두에 조건이 딱 맞아떨어지는 데이터가 존재하는, 완벽한 커플들만 합쳐서 화면에 보여줍니다. 짝이 없는 솔로들은 가차 없이 탈락이에요.
- 컴퓨터의 행동: "A 테이블이랑 B 테이블이랑 짝을 맞춰봐. 어? 너 짝꿍이 없네? 그럼 넌 결과 화면에서 제외야!"
- 특징: 데이터가 아주 깔끔하게 떨어지지만, 짝이 없는 소중한 정보가 조회 결과에서 통째로 사라질 수 있다는 점을 조심해야 해요.

2. OUTER JOIN (외부 조인) 💔➡️💝
"솔로 구제 전형! 짝꿍이 없어도 내 데이터는 무조건 다 살려줘!"

한쪽 테이블을 기준으로 삼아서, 짝꿍이 있든 없든 그 기준 테이블의 데이터는 무조건 다 출력해 주는 방식이에요. 만약 상대방 테이블에 매칭되는 짝꿍이 없다면? 그 자리를 NULL(빈칸)로 채워서라도 억지로 화면에 내보내 줍니다.

기준을 어느 쪽 테이블로 잡느냐에 따라 3가지로 나뉘어요.

① LEFT OUTER JOIN (왼쪽 기준)
- 왼쪽(먼저 적은) 테이블이 주인공이에요. 왼쪽 데이터는 솔로든 커플이든 무조건 다 나옵니다.
- 오른쪽 테이블에 짝꿍이 없으면 오른쪽 데이터 자리는 전부 NULL로 채워집니다.

② RIGHT OUTER JOIN (오른쪽 기준)
- 오른쪽(나중에 적은) 테이블이 주인공이에요. 오른쪽 데이터는 무조건 다 살려줍니다.
- 반대로 왼쪽 테이블에 짝꿍이 없으면 왼쪽 데이터 자리가 NULL이 됩니다.

③ FULL OUTER JOIN (전체 기준)
- "싸우지 마! 둘 다 살려!" 왼쪽, 오른쪽 상관없이 양쪽 테이블의 모든 데이터를 다 긁어모아서 보여줍니다. 짝이 없는 애들은 서로서로 상대방 자리에 NULL을 채운 채로 같이 출력돼요.

🍱 아주 쉬운 예시로 1초 만에 이해하기
여기 [학생] 테이블과 [동아리] 테이블이 소개팅을 합니다.
- 학생: 김승원(축구 동아리), 이순신(야구 동아리), 홍길동(동아리 없음 - 솔로 😭)
- 동아리: 축구, 야구, 테니스(가입한 학생 없음 - 유령 동아리 👻)

1) INNER JOIN 결과
완벽하게 매칭된 커플만 출력!
- 김승원 — 축구
- 이순신 — 야구
(솔로인 홍길동과 유령 동아리 테니스는 흔적도 없이 사라집니다.)

2) LEFT OUTER JOIN (학생 기준) 결과
학생(왼쪽)은 솔로여도 다 살려줘!
- 김승원 — 축구
- 이순신 — 야구
- 홍길동 — NULL (홍길동을 살리는 대신 동아리 칸을 빈칸으로 채움!)

3) RIGHT OUTER JOIN (동아리 기준) 결과
동아리(오른쪽)는 유령이어도 다 살려줘!
- 김승원 — 축구
- 이순신 — 야구
- NULL — 테니스 (테니스를 살리는 대신 학생 칸을 빈칸으로 채움!)

📌 최종 합격 암기 팁!
- INNER ➔ "너랑 나랑 동시에 가진 것만 엮자!"
- OUTER ➔ "내가 가진 건 없어도(NULL) 일단 화면에 다 띄워줘!"

NATURAL CROSS SELF JOIN 정리

1. NATURAL JOIN (자연 조인) 🌿
	"조건문(ON) 쓰기 귀찮아! 이름 똑같은 컬럼끼리 알아서 붙어라!"

우리가 지금까지 조인을 쓸 때는 맨 뒤에 ON A.고객ID = B.고객ID 처럼 귀찮게 조건을 일일이 적어줬잖아요? NATURAL JOIN은 양쪽 테이블에서 '이름과 데이터 타입이 완벽하게 똑같은 컬럼'을 오라클이 자동으로 찾아내서 지가 알아서 슥 붙여버리는 영리한 조인이에요.
- 문법 특징: 자동으로 컬럼을 찾기 때문에 ON 절을 절대 적지 않아요! (만약 적으면 오라클이 에러를 뿜뿜합니다.)
- 예시: 고객 테이블에도 고객ID가 있고, 시간대별사용량 테이블에도 고객ID가 있다면?
SQL
SELECT *
FROM 고객 A
NATURAL JOIN 시간대별사용량 B; -- 알아서 고객ID로 묶어줍니다!
- 🚨 주의점: 만약 두 테이블에 이름만 똑같고 아무 상관 없는 컬럼(예: 양쪽 테이블에 둘 다 비고 사항을 적는 REMARK 컬럼이 있을 때)이 존재하면, 그것까지 조건으로 묶어버려서 데이터가 안 나오는 대참사가 날 수 있어요. 그래서 실무에선 조심히 써야 해요!

2. CROSS JOIN (교차 조인 / 카테시안 곱) 🎲
	"아무 조건도 필요 없어! 낼 수 있는 모든 조합(경우의 수)을 다 만들어봐!"
이 친구는 조건이고 뭐고 아무것도 안 보고, 왼쪽 테이블의 모든 행과 오른쪽 테이블의 모든 행을 무차별적으로 전부 다 짝지어 버리는 폭주족 같은 조인이에요. 수학에서 말하는 '경우의 수'나 '곱집합'을 만들 때 쓰입니다.
- 비유: 상의 3벌(빨, 주, 노)과 하의 4벌(청바지, 슬랙스, 면바지, 반바지)을 가지고 입을 수 있는 모든 옷 조합(3 X 4 = 12가지)을 다 뽑아내는 것과 같아요.
- 결과 행의 수: A 테이블 행 개수 X 테이블 행 개수 (데이터가 엄청나게 불어납니다!)
- 코드 예시:
SQL
SELECT *
FROM 상의 A
CROSS JOIN 하의 B;

3. SELF JOIN (셀프 조인) 🪞
	"외부에서 찾지 말고, 내 테이블 안에서 거울 보듯이 조인하자!"

말 그대로 다른 테이블을 불러오는 게 아니라, 자기 자신 테이블과 조인을 맺는 아주 독특한 기법이에요. 테이블은 하나인데, 마치 두 개인 것처럼 별칭(Alias)을 다르게 줘서 컴퓨터를 속이는(?) 방식을 씁니다.

주로 '조직도(사원-관리자 관계)'나 '댓글-대댓글(계층형 구조)'처럼 하나의 테이블 안에서 상하 관계나 꼬리물기 관계를 표현할 때 필수로 쓰여요.
- 비유: 사원 테이블에 '김승원 사원'의 데이터가 있고, 그 옆 칸에 내 직속 상사의 사원번호인 '1004(이순신 팀장)'가 적혀있다고 칠게요. 이순신 팀장의 진짜 이름을 알고 싶다면? 다시 내 테이블의 사원번호 리스트에서 '1004'를 찾아야겠죠? 이렇게 자기 손으로 자기를 뒤적거릴 때 씁니다.
- 코드 예시:
SQL
SELECT 사원.사원명 AS 직원, 상사.사원명 AS 직속상사
FROM EMP 사원
JOIN EMP 상사 ON 사원.상사사원번호 = 상사.사원번호; -- 똑같은 EMP 테이블을 두 번 엮음

📌 최종 조인 요약 지도!
- INNER JOIN 🤝: 교집합! 서로 딱 맞는 커플만 출력.
- OUTER JOIN 💔: 한쪽 기준 전부 출력! 짝 없으면 NULL 대입.
- NATURAL JOIN 🌿: 이름 똑같은 컬럼끼리 ON 없이 자동 매칭.
- CROSS JOIN 🎲: 조건 없이 모든 조합 다 만들기 (곱하기 계산).
- SELF JOIN 🪞: 하나의 테이블을 '직원용', '상사용'으로 변신시켜 자기끼리 조인.

### 🚨 SQL LIKE 와일드카드 탈출 (ESCAPE) 핵심 정리

1. 일반적인 LIKE 와일드카드 의미
   - `%` : 글자 수 제한 없음 (0글자 이상)
   - `_` : 아무 글자나 딱 1글자 매칭

2. 함정 분석: WHERE NAME LIKE '%_%'
   - 컴퓨터는 가운데 `_`를 '아무 글자 1개'로 해석함.
   - 즉, '글자가 1개라도 있는 모든 데이터'를 조회하므로 '언더바 자체'를 검색할 수 없음.

3. 해결책: ESCAPE 옵션 사용
   - 특정 기호 뒤의 와일드카드를 순수 문자로 인식하게 만듦.
   - 예시: WHERE NAME LIKE '%@_%' ESCAPE '@'
   - 해석: `@` 뒤에 오는 `_`는 와일드카드가 아닌 순수한 언더바('_') 글자 자체로 취급함!

1. 트랜잭션의 기본 시작 방식 (가장 중요!)
가장 큰 차이는 SQL 문을 딱 실행했을 때 "자동으로 커밋을 하느냐, 안 하느냐"예요.

- Oracle (기본: 수동 커밋 / 암시적 트랜잭션):
승원님이 INSERT나 UPDATE를 실행하면, 자동으로 트랜잭션이 시작되지만 COMMIT은 절대 자동으로 되지 않아요. 데이터가 임시 저장소에만 머물러 있는 상태라, 승원님이 마음에 안 들면 언제든 ROLLBACK으로 취소할 수 있죠. 확정 지으려면 반드시 COMMIT;을 입력해야 해요!

- SQL Server (기본: 자동 커밋 / Auto Commit):
따로 설정하지 않으면 문장 하나하나가 실행될 때마다 자동으로 COMMIT까지 완료되어 버려요. 즉, INSERT를 실행하는 순간 데이터베이스에 즉시 영구 반영되기 때문에 돌이킬 수 없답니다. 만약 여러 명령어를 묶어서 처리하고 싶다면 반드시 BEGIN TRANSACTION이라고 명시해 줘야 해요.

2. DDL(테이블 생성/수정 등)을 실행했을 때의 차이
CREATE, ALTER, DROP 같은 DDL 문을 실행할 때의 행동도 완전히 달라요.

- Oracle: DDL 문을 실행하면 내부적으로 COMMIT이 자동 실행돼요. 심지어 그전에 작업하던 DML(INSERT 등) 내용까지 세트로 같이 커밋되어 버리니 아주 조심해야 해요! 오라클에서 DDL은 롤백이 안 됩니다.

- SQL Server: 놀랍게도 SQL Server는 DDL 문도 트랜잭션 안에서 롤백이 가능해요! 예를 들어 BEGIN TRAN을 하고 테이블을 DROP 했다가, 아차 싶으면 ROLLBACK으로 테이블을 다시 살려낼 수 있답니다. (오라클 개발자들이 부러워하는 기능이에요 🤭)

3. 읽기 일관성 (데이터를 읽을 때의 매커니즘)
누군가 데이터를 수정하고 있는 와중에, 다른 사람이 그 데이터를 조회할 때의 방식 차이예요.

- Oracle (Undo 세그먼트 활용):
누군가 데이터를 열심히 수정하고 있어도, 조회하는 사람은 수정되기 직전의 안전한 데이터(Undo 데이터)를 아무런 대기 없이 바로 읽을 수 있어요. 즉, 읽는 사람과 쓰는 사람이 서로를 방해하지 않아요!

- SQL Server (잠금 - Lock 활용):
기본적으로 데이터에 수정(UPDATE) 작업이 일어나면 그 자리에 자물쇠(Lock)를 채워버려요. 그래서 수정이 끝날 때까지 조회하려는 다른 사용자는 하염없이 기다려야(대기 상태) 한답니다. 성능 저하를 막으려면 특별한 격리 수준 설정이 필요해요.

[Oracle vs SQL Server 트랜잭션/커밋 방식 최종 종결 표]
================================================================================
 구분           | Oracle (오라클)                  | SQL Server (MSSQL)
----------------+----------------------------------+----------------------------
 데이터 조작    | 무조건 [수동 커밋]               | 기본적으로 [자동 커밋]
 (DML)          | : INSERT, UPDATE, DELETE 등      | : INSERT, UPDATE, DELETE 등
                |   어떤 DML이든 실행 후 사용자가  |   실행하는 순간 즉시즉시 
                |   직접 COMMIT을 쳐야 반영됨.     |   데이터베이스에 저장됨.
----------------+----------------------------------+----------------------------
 테이블/구조    | 무조건 [자동 커밋]               | 기본적으로 [자동 커밋]
 (DDL)          | : CREATE, ALTER, DROP 등 실행 시 | : 평소에는 실행 즉시 저장되나,
                |   트랜잭션 여부 상관없이 무조건  |   [BEGIN TRAN]을 선언해두면
                |   그 즉시 강제로 커밋됨.         |   DDL도 롤백(취소) 가능함.
----------------+----------------------------------+----------------------------
 트랜잭션 시작  | [자동 시작]                      | [수동 시작]
                | : 사용자가 선언할 필요 없음.     | : 여러 작업을 하나로 묶으려면
                |   첫 DML 문장이 실행되는 순간     |   반드시 [BEGIN TRANSACTION]을
                |   알아서 트랜잭션이 오픈됨.      |   명시적으로 써서 켜야 함.

오라클 - DML 자동커밋 x DDL 자동커밋 o
SQL서버 - DML 자동커밋 o DDL 자동커밋 o

트랜잭션
오라클 - 상관없음 항상 자동 trans실행중
SQL서버 - DML 자동커밋 x DDL 자동커밋 x - 수동커밋
