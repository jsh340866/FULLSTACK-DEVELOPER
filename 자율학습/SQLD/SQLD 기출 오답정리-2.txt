문제

다음 ERD로 작성한 SQL문에서 오류가 발생하는 것은?
j552-1
답안과 정답

1번
정답
SELECT SUM(주문금액)
FROM 일자별주문내역
WHERE EXISTS(SELECT *
FROM 고객마스터
UNION ALL
SELECT *
FROM 일자별주문내역)
GROUP BY 회원번호
2번
내 답안
SELECT SUM(일자별주문내역,주문금액)
FROM 고객마스터, 일자별주문내역
WHERE 고객.회원번호 = 일자별주문내역,회원번호
GROUP BY 회원번호
3번
SELECT SUM(일자별주문내역,주문금액)
FROM 일자별주문내역
FULL
OUTER
JOIN 고객마스터
on 고객.회원번호 = 일자별주문이력.회원번호
GROUP BY 회원번호;
4번
SELECT (SELECT SUM(주문금액)
FROM 일자별주문내역)
FROM 고객마스터
GROUP BY 회원번호;

###
정답 : 1번

UNION 및 UNION ALL구를 사용할 때 나오는 SQL문은 칼럼 수와 데이터 타입이 완전 일치해야 한다. 하지만 ①번은 고객마스터와 일자별주문내역에 나오는 칼럼의 수가 일치하지 않는다.


🔍 승원 님이 고르신 2번을 포함해 다른 보기들이 헷갈렸던 이유 (오타 분석)
이 문제는 기출문제가 복원되면서 다른 보기들(2번, 3번)에도 자잘한 텍스트 오타들이 들어가 있어요. 실제 시험이었다면 수정되어서 나왔을 부분들이니 너무 걱정하지 마세요!

2번 보기 분석 (내 답안):

SUM(일자별주문내역, 주문금액)이나 일자별주문내역, 회원번호처럼 마침표(.) 대신 쉼표(,)가 찍힌 오타가 있어요.

그리고 고객마스터 테이블을 고객이라고 축약해서 부르는 등 문법적 오류가 있어 보여 승원 님이 정답으로 고르셨을 확률이 높아요! 승원 님의 문법적 매의 눈은 아주 정확했답니다. 다만 출제자는 1번의 '구조가 다른 테이블 간의 UNION ALL 오류'를 가장 큰 정답 포인트로 설계한 거예요.

3번 보기 분석:

이 역시 고객.회원번호, 일자별주문이력.회원번호(내역인데 이력으로 오타) 등 복원 과정에서의 텍스트 오타들이 눈에 띄어요.

4번 보기 분석:

스칼라 서브쿼리를 사용해서 전체 주문금액의 합계를 고객마스터 행 개수만큼 반복해서 보여주는 쿼리로, 문법적으로는 에러 없이 실행되는 구조예요.

32번 문제
다음 중 정상적으로 실행되지 않는 문장은? (단, DBMS는 오라클)

1번
정답
SELECT NVL(100, 'NULL')
FROM DUAL;
2번
SELECT TO_DATE('11', 'DD') + 10
FROM DUAL;
3번
SELECT TO_DATE('20240101', 'YYYYMMDD') - 10
FROM DUAL;
4번
내 답안
SELECT 100 + '1'
FROM DUAL;

###
정답 : 1번

💡 1번 문장에서 에러가 발생하는 결정적 이유!
오라클의 NVL(값1, 값2) 함수는 "값1이 NULL이면 값2를 출력하고, NULL이 아니면 값1을 출력해라"라는 함수예요. 그런데 아주 중요한 철칙이 하나 있어요!

🚨 NVL 함수의 철칙: 값1과 값2의 데이터 타입은 반드시 일치해야 합니다! 만약 다르면, 오라클은 값2를 값1의 데이터 타입으로 자동 형변환하려고 시도해요.

⭕ 4번 보기 (내 답안): SELECT 100 + '1' FROM DUAL;
- 오라클의 능력: 오라클은 숫자와 문자를 더하기 연산자(+)로 계산하려고 할 때, 문자 안에 들어있는 값이 숫자로 바뀔 수 있는 글자(예: '1')라면 자동으로 숫자로 바꿔서 계산해 줍니다!
- 즉, 내부적으로 100 + 1로 변환되어 에러 없이 101이라는 정답이 아주 잘 출력돼요. (이걸 묵시적 형변환이라고 해요!)

⭕ 2번 보기: SELECT TO_DATE('11', 'DD') + 10 FROM DUAL;
- '11'이라는 문자를 일(Day)을 뜻하는 DD 형식의 날짜(Date)로 바꿨어요. (연도와 월은 현재 시점의 연/월이 자동으로 들어갑니다.)
- 오라클에서 날짜에 숫자를 더하면(+ 10) '며칠 뒤'를 계산하라는 뜻이 돼요. 따라서 11일에 10일이 더해진 정상적인 날짜가 에러 없이 잘 출력됩니다.

⭕ 3번 보기: SELECT TO_DATE('20240101', 'YYYYMMDD') - 10 FROM DUAL;
- 2024년 1월 1일이라는 날짜 데이터에서 10을 뺐어요.
- 날짜에서 숫자를 빼는 것 역시 '며칠 전'을 계산하는 정상적인 문법이에요. 2024년 1월 1일에서 10일 전인 2023년 12월 22일이 아주 예쁘게 출력된답니다.
