
[문제] 다음 중 NULL의 설명으로 가장 부적절한 것은?

[지문]
1번 : NULL과의 모든 비교 (IS NULL 제외)는 알 수 없음 (Unknown) 을 반환한다.
2번 : 공백문자 (Empty String) 혹은 숫자 0을 의미한다.
3번 : 값의 부재를 의미한다.
4번 : 모르는 값을 의미한다.

--------------------------------------------------
[정답 및 결과 값]
2번 (공백문자 혹은 숫자 0을 의미한다.)

[핵심 해설]
1. 2번이 부적절한 이유 (정답):
   - 데이터베이스에서 NULL은 '아무것도 없는 상태', 즉 '값의 부재'를 뜻합니다.
   - 숫자 '0'은 '영'이라는 명확한 숫자 데이터값이고, 공백 문자(' ') 역시 '스페이스바'라는 문자 데이터값입니다.
   - 따라서 NULL을 숫자 0이나 공백 문자와 같다고 설명한 2번은 완전히 틀린 설명입니다. (※ 단, 오라클 등 일부 DBMS에서 아무 글자도 없는 문자열 ''을 내부적으로 NULL로 취급하는 예외는 있으나, 숫자 0과 공백 문자는 절대 NULL이 아닙니다.)

2. 1번(승원님의 답안)이 올바른 설명인 이유:
   - 우리가 맨 처음 풀었던 문제 기억하시나요? NULL은 크기를 비교하거나 같다 아니다(`=`, `!=`)를 비교할 수 없습니다.
   - 'A = NULL' 이나 'A != NULL' 같은 비교 연산은 무조건 '알 수 없음(Unknown)'을 반환합니다.
   - 오직 'IS NULL' 또는 'IS NOT NULL'이라는 특수 전용 연산자로만 확실한 참/거짓을 판별할 수 있으므로 1번은 아주 완벽한 설명입니다.

3. 다른 보기 요약:
   - 3번, 4번: NULL의 표준 정의입니다. 정의되지 않은 값, 모르는 값, 값의 부재를 의미합니다.


###
[개념 교정] IN / NOT IN 절 내부의 NULL 작동 원리

--------------------------------------------------
1. 결론: 문법 오류(Error)는 나지 않습니다! 정상 실행됩니다.
2. 문제점: 하지만 NOT IN 연산은 무조건 '0건(조회 결과 없음)'을 반환합니다.

3. 이유 (컴퓨터 내부의 계산 과정 분해):
- 쿼리: WHERE A.COL NOT IN (2, NULL)
- 이것을 컴퓨터가 논리 연산자로 풀어서 쓰면 다음과 같습니다.
  👉 WHERE (A.COL != 2) AND (A.COL != NULL)

- 여기서 'A.COL != NULL' 이 부분이 핵심입니다.
- 앞서 배웠듯이 NULL과의 모든 비교 연산은 '알 수 없음(Unknown)'이 됩니다.
- AND 연산은 양쪽 조건이 둘 다 '참(True)'이어야만 데이터를 보여줍니다.
- 하지만 한쪽이 'Unknown(알 수 없음)'이 되어버렸기 때문에, A.COL에 어떤 숫자가 들어와도 이 전체 조건식은 절대 참(True)이 될 수 없습니다.

4. 요약:
- IN (2, NULL)     -> '2인 데이터'는 정상 조회됨 (OR 연산이라서 하나만 참이면 됨)
- NOT IN (2, NULL) -> '아무것도 조회 안 됨' (AND 연산이라 NULL 비교에 발목 잡힘)

[문제] 다음 중 관계를 구성하는 요소가 아닌 것은?

[지문]
1번 : 관계정의
2번 : 선택성(Optionality)
3번 : 차수(Cardinality)
4번 : 관계명

--------------------------------------------------
[정답 및 결과 값]
1번 (관계정의)

[핵심 해설]
1. 데이터 모델링에서 엔티티 간의 '관계'를 구성하는 3가지 필수 요소는 다음과 같습니다.
   ① 관계명 (Relationship Name): 관계의 이름 (예: 주문한다, 소속된다)
   ② 차수 (Cardinality): 1:1, 1:N, M:N 등 참여하는 수량의 비율
   ③ 선택성 (Optionality): 필수 참여(Mandatory)인지, 선택 참여(Optional)인지 여부

2. 1번이 정답(요소가 아닌 것)인 이유:
   - '관계정의'는 관계를 설명하는 일반적인 서술일 뿐, 관계를 정형화하여 구성하는 '3대 핵심 요소'의 공식 명칭이 아닙니다. 말장난 함정 지문입니다.

3. 2번(승원님의 답안)이 구성 요소인 이유:
   - 선택성(Optionality)은 관계를 맺을 때 "반드시 데이터가 있어야 하는가?"를 결정하는 아주 중요한 구성 요소가 맞습니다.

🎯 시험장 꿀팁 (암기 공식)!
정처기 시험에서 "관계를 구성하는 3대 요소가 아닌 것은?" 하고 물어보면 앞 글자만 따서 **[명. 차. 선]**을 기억하세요!

- 명: 관계명
- 차: 관계차수 (Cardinality)
- 선: 관계선택성 (Optionality)

[문제] 제시된 SQL의 실행 결과로 가장 적절한 것은?

CREATE TABLE TAB1(COL1 NUMBER, COL2 NUMBER); 
 
INSERT INTO TAB1
VALUES(1,10);
INSERT INTO TAB1
VALUES(2,20);
INSERT INTO TAB1
VALUES(3,30);
COMMIT; 
 
ALTER TABLE TAB1 ADD (COL3 NUMBER); 
 
INSERT INTO TAB1
VALUES(4,40,100);
UPDATE TAB1
SET COL2 = 50
WHERE COL1 = 1;
DELETE TAB1
WHERE COL1 = 3;
 
ALTER TABLE TAB1 DROP COLUMN COL1; 
 
ROLLBACK; 
 
SELECT SUM(COL2 + COL3)
FROM TAB1;

--------------------------------------------------
[정답 및 결과 값]
1번 (140)

[핵심 해설]
1. 가장 중요한 핵심 원리 (DDL의 자동 커밋) ⭐⭐⭐
   - CREATE, ALTER, DROP 같은 DDL(데이터 정의어) 명령어는 실행되는 즉시 데이터베이스에 '자동 커밋(Auto Commit)'을 유반합니다.
   - 즉, 그 이전에 했던 DML(INSERT, UPDATE, DELETE) 작업들이 COMMIT을 쓰지 않았더라도 강제로 데이터베이스에 영구 저장됩니다.

2. 타임라인에 따른 테이블 상태 변화 (오라클 기준)
   ① 초기 INSERT 3건 후 COMMIT 완료
      -> (1, 10), (2, 20), (3, 30) 저장됨.
   ② ALTER TABLE로 COL3 추가 
      -> 기존 데이터들의 COL3 자리는 모두 NULL이 됨.
   ③ INSERT, UPDATE, DELETE 실행
      - 행 추가: (4, 40, 100)
      - 1번 행 수정: (1, 50, NULL)
      - 3번 행 삭제: (3, 30, NULL) 삭제됨
   ④ ⚠️ ALTER TABLE TAB1 DROP COLUMN COL1; (함정 발동!)
      - COL1 컬럼이 날아가면서, 방금 전까지 했던 ③번 작업들(INSERT, UPDATE, DELETE)이 '자동으로 커밋'되어 버립니다!
   ⑤ ROLLBACK; 실행
      - 이미 ④번 DDL 때문에 자동 커밋이 일어나서 롤백할 과거 데이터가 없습니다. 아무 일도 일어나지 않습니다.

3. 최종 계산 단계 (SUM 계산)
   현재 테이블에 남은 데이터 상태:
   - 1번 행이었던 데이터: COL2 = 50, COL3 = NULL
   - 2번 행이었던 데이터: COL2 = 20, COL3 = NULL
   - 4번 행이었던 데이터: COL2 = 40, COL3 = 100
   (3번 행은 삭제됨)

   - SQL: SELECT SUM(COL2 + COL3) FROM TAB1;
   - 연산 과정:
     * 1번 행: 50 + NULL ➡️ NULL (NULL이 들어간 더하기는 무조건 NULL)
     * 2번 행: 20 + NULL ➡️ NULL
     * 4번 행: 40 + 100 ➡️ 140
   - SUM 함수는 NULL 값을 무시하고 계산하므로, 최종 결과는 [140]이 됩니다!

###
[개념 교정] 만약 테이블에 NULL이 없고 모든 숫자가 채워져 있었다면? (정정 버전)

--------------------------------------------------
1. 가정된 데이터 상태 (각 행의 COL2, COL3 값)
- 1번 행: COL2 = 50, COL3 = 20
- 2번 행: COL2 = 20, COL3 = 30
- 4번 행: COL2 = 40, COL3 = 100
(※ 문제 조건에 따라 3번 행은 여전히 삭제된 상태입니다.)

2. 쿼리문 계산 과정: SUM(COL2 + COL3)
- 괄호 안의 더하기 연산(COL2 + COL3)이 각 행별로 먼저 일어납니다.
  * 1번 행: 50 + 20  ➡️ 70
  * 2번 행: 20 + 30  ➡️ 50
  * 4번 행: 40 + 100 ➡️ 140

- 마지막으로 SUM() 함수가 위에서 나온 결과들을 싹 다 더합니다.
  * 최종 계산: 70 + 50 + 140 = [ 260 ] ⭐

3. 결론: 
- NULL이 없을 때는 모든 행의 연산 결과가 안전하게 살아남기 때문에, 최종 결과는 [260]이 됩니다!

[문제] 제시된 계층형 질의 SQL의 실행 결과로 가장 적절한 것은?

--------------------------------------------------

SELECT 사원번호, 이름, LEVEL
FROM 사원
  START WITH 사원번호 IN (1006, 1001) 
CONNECT BY PRIOR 상위관리자코드 = 사원번호;

--------------------------------------------------

사원번호 | 이름   | 상위관리자코드
----------------------------------
1000     | 홍길동 | NULL
1001     | 박길동 | 1000
1002     | 최길동 | 1001
1003     | 이길동 | 1001
1004     | 구길동 | 1002
1005     | 안길동 | 1003
1006     | 송길동 | 1000
1007     | 강길동 | 1006
1008     | 공길동 | 1006

--------------------------------------------------
[정답 및 결과 값]
최종적으로 총 4개의 행이 아래와 같은 순서와 LEVEL로 조회됩니다.

사원번호 | 이름   | LEVEL
------------------------
1006     | 송길동 | 1
1001     | 박길동 | 1
1000     | 홍길동 | 2
1000     | 홍길동 | 2
(※ 주의: DBMS의 정렬 옵션에 따라 1006 계통과 1001 계통의 출력 순서는 바뀔 수 있습니다.)

[핵심 해설]
1. START WITH 사원번호 IN (1006, 1001)
   - 시작점(루트 노드)을 '송길동(1006)'과 '박길동(1001)' 두 군데로 잡습니다. 이들의 LEVEL은 1이 됩니다.

2. CONNECT BY PRIOR 상위관리자코드 = 사원번호 (★핵심 함정)
   - 'PRIOR(이전 행)의 상위관리자코드'가 '현재 행의 사원번호'와 같은 것을 찾아가라는 뜻입니다.
   - 즉, 부하 직원을 찾는 것이 아니라 나를 관리하는 **"상위 관리자(부모 노드)"를 향해 거꾸로 올라가는 '역방향 전개'**입니다.

3. 전개 과정 분석:
   - [송길동(1006) 계통]
     * 송길동(LEVEL 1)의 상위관리자코드는 '1000'입니다.
     * 사원번호가 '1000'인 사람을 찾으니 '홍길동(LEVEL 2)'이 나옵니다.
     * 홍길동(1000)의 상위관리자는 'NULL'이므로 여기서 전개가 종료됩니다.
   - [박길동(1001) 계통]
     * 박길동(LEVEL 1)의 상위관리자코드는 '1000'입니다.
     * 사원번호가 '1000'인 사람을 찾으니 '홍길동(LEVEL 2)'이 나옵니다.
     * 홍길동(1000)의 상위관리자는 'NULL'이므로 여기서 전개가 종료됩니다.

[문제] 표를 읽으면, BONUS 데이터에서 MAX(BONUS) 값은?

--------------------------------------------------
[ 원본 데이터 구조: <NULL Aggregate Data> 테이블 ]

EMP ID | SALARY | BONUS
------------------------
1      | 1000   | 100
2      | NULL   | 200
3      | 2000   | NULL
4      | NULL   | NULL

--------------------------------------------------
[정답 및 결과 값]
3번 (200)

[핵심 해설]
1. 가장 중요한 핵심 원리 (집계 함수와 NULL) ⭐⭐⭐
   - 데이터베이스의 집계 함수(SUM, MAX, MIN, AVG 등)는 연산을 수행할 때 데이터에 'NULL'이 섞여 있으면, 걔네들을 아예 없는 존재(무시) 취공하고 계산합니다.

2. MAX(BONUS)의 실제 계산 과정
   - BONUS 컬럼의 데이터는 차례대로 [100, 200, NULL, NULL] 입니다.
   - 이때 MAX 함수는 NULL 데이터 2건을 완전히 제외하고, 남은 숫자 데이터인 [100, 200] 중에서만 가장 큰 값을 찾습니다.
   - 100과 200 중 가장 큰 숫자는 200이므로, 최종 결과값은 200이 됩니다.

[문제] 제시된 집합 연산 SQL의 실행 결과 행 수는?

지문

SELECT val
FROM (
SELECT 1 AS val
UNION ALL
SELECT 2
UNION ALL
SELECT 2
UNION ALL
SELECT 3
) a
MINUS
SELECT val
FROM (
SELECT 2 AS val
UNION
SELECT 4
) b;

--------------------------------------------------
[정답 및 결과 값]
2번 (2개 행)

[최종 출력 데이터 결과 테이블]
VAL
----
1
3

[핵심 해설]
1. 위쪽 서브쿼리 (a 집합) 계산: UNION ALL
   - UNION ALL은 중복을 제거하지 않고 모든 데이터를 그대로 합칩니다.
   - 데이터 내용: [1, 2, 2, 3] (총 4개 행)

2. 아래쪽 서브쿼리 (b 집합) 계산: UNION
   - 순수 UNION은 중복된 데이터를 자동으로 제거(정렬 후 중복 제거)합니다.
   - 데이터 내용: [2, 4] (총 2개 행)

3. 최종 연산: a 집합 MINUS b 집합 (차집합) ⭐⭐⭐
   - 오라클의 MINUS(차집합) 연산자는 아주 중요한 절대 규칙이 있습니다.
     "앞의 집합(a)에서 뒤의 집합(b)에 있는 원소를 빼버리는데, 
      그 과정에서 결과 집합의 중복을 '자동으로 제거'하고 최종 결과를 보여준다!"
   
   - 연산 과정:
     * a 집합 [1, 2, 2, 3] 에서 b 집합에 있는 '2'와 '4'를 지웁니다.
     * 2가 지워지고 나면 [1, 3] 이 남습니다.
     * 결과 집합에 중복이 없으므로 그대로 [1, 3] 총 2개의 행이 최종 출력됩니다.

[문제] NULL에 대한 설명으로 가장 적절하지 않은 것은?

--------------------------------------------------
[지문 분석]
1번 : 공백문자 혹은 숫자 0과는 다른 의미를 갖는다. (오른 설명)
2번 : NULL로만 구성된 컬럼을 COUNT한 결과는 공집합이다. (★정답 - 틀린 설명)
3번 : NULL과의 모든 비교(IS NULL 제외)는 알 수 없음을 반환한다. (오른 설명)
4번 : 정해지지 않은 값을 의미한다. (오른 설명)

--------------------------------------------------
[정답 및 결과 값]
2번

[핵심 해설]
1. 2번이 '틀린 설명(정답)'인 이유: ⭐⭐⭐
   - 집계 함수인 COUNT(컬럼명)는 NULL 값을 제외하고 개수를 쏩니다.
   - 따라서 모든 행이 NULL인 컬럼을 COUNT(컬럼명)하면 데이터가 하나도 안 세어지므로 결과값으로 숫자 [ 0 ] 을 반환합니다.
   - '공집합(아무 행도 출력되지 않음)'이 아니라, [0이라는 숫자가 찍힌 1개의 행]이 결과로 나오기 때문에 틀린 지문입니다.

2. 다른 지문이 맞는 이유 복습:
   - 1번: NULL은 '값이 없음'을 뜻하므로, 눈에 보이는 빈칸(' ')이나 숫자 0과는 완전히 다릅니다.
   - 3번: 저번에 배웠듯이 'NULL = 2'나 'NULL != 3' 같은 비교는 맞다 틀리다가 아니라 전부 '알 수 없음(Unknown)'이 됩니다.
   - 4번: NULL은 미정(정해지지 않은 값), 미입력된 값을 뜻하는 표준 정의가 맞습니다.
