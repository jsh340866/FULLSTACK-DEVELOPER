■ 문제 출처: image_64e0a1.png
■ 문제: IP의 동작 과정에서의 전송 오류가 발생하는 경우 오류 정보를 전송하는 목적으로 사용하는 프로토콜로, Ping-of-Death에서도 사용하는 프로토콜은 무엇인가?

  - 보기: ICMP, RARP, IP, 라우팅 프로토콜, NAT, IGMP, ARP
  - 나의 답변: NAT (X)
  - 정답: ICMP (O)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 핵심 개념 정답 해설

1. 정답: ICMP (Internet Control Message Protocol)
  ○ 주요 역할
     - IP 프로토콜의 약점인 '비연결성' 및 '불완전성'을 보완하기 위해 사용됩니다.
     - 네트워크 내에서 전송 오류를 보고하고, 네트워크 상태를 진단(Ping)하는 역할을 수행합니다.
  ○ 문제 키워드 매칭
     - "전송 오류가 발생하는 경우 오류 정보를 전송" ➡️ ICMP의 고유 기능
     - "Ping-of-Death에서 사용" ➡️ ICMP 패킷(Ping)을 비정상적으로 크게 만들어 시스템을 다운시키는 공격 기법

2. 오답 체크: NAT (Network Address Translation)가 아닌 이유
  ○ 주요 역할
     - 제한된 '공인 IP'를 절약하기 위해, 내부 네트워크의 여러 '사설 IP'를 하나의 공인 IP 주소로 변환해 주는 기술입니다. (예: 가정용 공유기)
  ○ 탈락 이유
     - 오류 보고나 네트워크 진단과는 전혀 관련이 없는 '주소 변환 및 보안' 기술이므로 답이 될 수 없습니다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 함께 출제되는 중요 프로토콜 요약

- ICMP : 네트워크 오류 보고, Ping 진단, Ping-of-Death 공격에 악용
- ARP  : 논리 주소(IP) ➡️ 물리 주소(MAC)로 변환
- RARP : 물리 주소(MAC) ➡️ 논리 주소(IP)로 역변환
- IGMP : 멀티캐스트 그룹 관리 및 멤버십 유지
- IP   : OSI 3계층 프로토콜, 데이터 패킷의 경로 지정(라우팅) 담당

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

"네트워크에 오류가 나서 Ping(핑)을 날릴 땐, ICU(중환자실)가 연상되는 ICMP를 기억하자!"

■ 문제 출처: image_5887d4.png
■ 문제: 포트번호로 22번을 사용하며 인증, 암호화를 제공하고 Telnet보다 강력한 보안을 제공하는 프로토콜은?

  - 나의 답변: SHP (X)
  - 정답: SSH (O)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 핵심 개념 정답 해설

1. 정답: SSH (Secure Shell)
  ○ 주요 역할
     - 원격지에 있는 컴퓨터를 안전하게 제어하기 위한 보안 네트워크 프로토콜입니다.
     - 기존의 Telnet이 데이터를 평문으로 전송하던 취약점을 보완하여, 모든 통신 데이터를 암호화합니다.
  ○ 문제 키워드 매칭
     - "포트번호 22번" ➡️ SSH의 기본 Well-known 포트번호
     - "Telnet보다 강력한 보안" ➡️ 암호화 및 인증 기능 제공

2. 오답 체크: SHP가 오답인 이유
  ○ 단순 오타 또는 다른 도메인의 약어(예: 지리정보 파일 서식 .shp 등)로, 정처기 네트워크 파트에서 다루는 암호화 원격 접속 프로토콜과는 무관합니다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 함께 출제되는 중요 포트 및 프로토콜 요약

- SSH    : 포트 22번 / 암호화 원격 접속 (보안 강화)
- Telnet : 포트 23번 / 평문 원격 접속 (보안 취약)
- FTP    : 포트 20번(데이터), 21번(제어) / 파일 전송 프로토콜
- ESP   : 프로토콜 50번 / 데이터 암호화 및 인증 담당 (보안성 높음)
- HTTP   : 포트 80번 / 웹 문서 전송 기본 프로토콜
- HTTPS  : 포트 443번 / 암호화(SSL/TLS) 웹 전송 프로토콜

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

"쌍둥이처럼 헷갈리는 Telnet(23) 대신, '22'번 포트로 'S'ecure(보안)하게 접속하는 것은 SSH!"

■ 문제 출처: image_581eb7.png 변형 질문
■ 문제: Child 클래스의 'int x = 4000;' 코드가 없을 때, obj.getX()의 출력 결과는 무엇인가?

  - 정답: 500 (O)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

문제
class Parent {
    int x = 100;
    Parent() {
        this(500);
    }
    Parent(int x) {
        this.x = x;
    }
    int getX() {
        return x;
    }
}

class Child extends Parent {
    int x = 4000;
    Child() {
        this(5000);
    }
    Child(int x) {
        this.x = x;
    }
}

public class Gamja {
    public static void main(String[] args) {
        Child obj = new Child();
        System.out.println(obj.getX());
    }
}



■ 핵심 개념 해설

1. 소스코드 분석 (int x = 4000이 없을 때의 실행 흐름)
  ○ Child obj = new Child(); 호출 시
     - Child() 생성자가 실행되며 `this(5000);`을 호출합니다.
     - Child(int x) 생성자가 실행되는데, 이때 상속 관계에 의해 부모 생성자인 `super();`가 자동으로 먼저 호출됩니다.
     - 부모 생성자 Parent()는 `this(500);`을 호출하여 부모의 변수 x를 500으로 세팅합니다.
  ○ Child(int x) 내의 `this.x = x;` 실행 시
     - 자식 클래스(Child) 내부에 선언된 x가 없으므로, `this.x`는 상속받은 부모의 변수 x를 가리키게 됩니다.
     - 이에 따라 부모의 x값이 방금 전달된 인자값인 5000으로 덮어씌워집니다. (부모 x = 5000)

2. obj.getX() 호출 시 반환 값
  ○ getX() 메서드는 부모 클래스(Parent)에만 정의되어 있습니다.
  ○ 부모의 getX()는 자신이 가지고 있는 변수 x를 반환하므로, 최종적으로 변경된 값인 500이 아니라 5000이 출력되는 것처럼 보이지만...
  ★ 주의!! 자바 생성자 호출 순서의 함정:
     - `new Child()` ➡️ `Child()` ➡️ `this(5000)` ➡️ `Child(int x)` 진입 ➡️ `super()` 자동 호출 ➡️ `Parent()` ➡️ `this(500)` ➡️ `Parent(int x)` 실행 완료로 부모 x가 500이 됨.
     - 그 후 `Child(int x)`의 나머지 코드인 `this.x = 5000;`이 실행되면서 부모의 x를 5000으로 바꾸게 됩니다.
     - 따라서 최종적으로 부모의 x값은 5000이 됩니다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

💡 한 줄 암기 팁!
"자식 클래스에 변수가 없으면 this.x는 부모의 x를 건드리므로, 최종적으로 자식 생성자에서 덮어쓴 5000이 정답!"

■ 문제: 다음에서 설명하는 기술은?
  1. VPN에서 사용되는 프로토콜
  2. L2F와 PPTP 기능 결합하여 인터넷 상 두 지점 간 가상의 터널을 만들어 통신을 전송하는 기술

  - 정답: L2TP (Layer 2 Tunneling Protocol)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 핵심 개념 해설

1. 정의: L2TP (Layer 2 Tunneling Protocol)
  ○ 역할: OSI 2계층(데이터 링크 계층)에서 가상의 터널을 만들어 데이터를 안전하게 전송하는 VPN 터널링 프로토콜입니다.
  ○ 특징: Microsoft의 PPTP와 Cisco의 L2F 프로토콜의 장점을 결합하여 만든 데이터 링크 계층의 표준 기술입니다.
  ○ 주의: 자체적인 '암호화' 및 '인증' 기능이 없기 때문에, 보안을 강화하기 위해 대개 3계층 보안 프로토콜인 IPsec과 결합하여 사용합니다. (L2TP/IPsec)

2. 헷갈리기 쉬운 연관 VPN 프로토콜
  ○ PPTP : Microsoft사에서 개발한 2계층 터널링 프로토콜 (L2TP의 모태)
  ○ L2F  : Cisco사에서 개발한 2계층 터널링 프로토콜 (L2TP의 모태)
  ○ IPsec: 3계층(네트워크 계층)에서 암호화와 인증을 제공하는 VPN 프로토콜
  ○ SSL  : 4계층 이상(전송/응용 계층)에서 웹 브라우저 기반으로 동작하는 VPN 프로토콜

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

💡 한 줄 암기 팁!
"PPTP와 L2F가 결합(2개)하여 2계층(Layer 2) 터널을 뚫는 프로토콜은 L2TP!"

■ 문제 출처: image_55cd9b.png
■ 문제: 패킷 교환 방식에서 패킷이 전송되기 전에 송/수신 스테이션 간의 논리적인 통신 경로를 미리 설정하는 방식은 ( ① ) 방식이며, 연결 경로를 확립하지 않고 각각의 패킷을 순서에 무관하게 독립적으로 전송하는 방식은 ( ② ) 방식이다. 빈칸에 들어갈 알맞은 용어를 쓰시오.

  - 나의 답변: ① 동기 (X) / ② 비동기 (X)
  - 정답: ① 가상 회선 (O) / ② 데이터그램 (O)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 핵심 개념 정답 해설

1. 정답 ①: 가상 회선 (Virtual Circuit) 방식
  ○ 역할: 패킷을 전송하기 전에 송수신 측 사이에 논리적인 연결 경로(가상 회선)를 미리 맺고 데이터를 보냅니다.
  ○ 특징: 경로가 고정되어 있으므로 패킷이 보낸 순서대로 안정적으로 도착합니다. (연결 지향형 서비스)

2. 정답 ②: 데이터그램 (Datagram) 방식
  ○ 역할: 사전 연결 설정 없이, 각각의 패킷을 독립적인 개체로 취급하여 전송합니다.
  ○ 특징: 네트워크 혼잡도에 따라 패킷마다 서로 다른 경로로 이동할 수 있으며, 도착 순서가 바뀔 수 있어 수신 측에서 재조립해야 합니다. (비연결형 서비스)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 헷갈림 방지 요약 (동기/비동기와의 차이점)

- 가상회선 / 데이터그램 : 패킷을 보낼 때 '논리적 경로(길)'를 미리 닦아두느냐 아니냐의 차이입니다.
- 동기 / 비동기 : 데이터를 주고받을 때 '타이밍(클록 시그널이나 시작/정지 비트)'을 맞추느냐 아니냐의 차이이므로 문제의 본질과 다릅니다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 문제 출처: 기출[실기] 23년 1회 / 25년 3회
■ 문제: 다음은 데이터베이스에 관련된 내용이다. 각 괄호에 들어갈 답을 [보기]에서 골라 쓰시오.

  • ( ① )은/는 어떤 요소의 집합 혹은 행을 나타내며, 특정 속성이 중복된 값을 포함될 수 있다.
  • ( ② )은/는 특정 시점에 릴레이션의 내용, 저장된 데이터를 의미한다. 릴레이션 외연(Relation Extension)이라고도 표현한다.
  • ( ③ )은/는 데이터 집합 내에서 고유한(Unique) 값들의 총 개수를 나타낸다.

  - 보기: 릴레이션 스키마, 속성, 차수, 카디널리티, 릴레이션 인스턴스, 튜플
  - 정답: ① 튜플 (Tuple) / ② 릴레이션 인스턴스 (Relation Instance) / ③ 카디널리티 (Cardinality)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 핵심 개념 정답 해설

1. 정답 ①: 튜플 (Tuple)
  ○ 역할: 릴레이션(테이블)을 구성하는 각각의 행(Row)을 의미함
  ○ 특징: 하나의 레코드를 나타내며, 각 튜플은 고유하지만 특정 속성(열)의 값 자체는 다른 행과 중복될 수 있음

2. 정답 ②: 릴레이션 인스턴스 (Relation Instance)
  ○ 역할: 특정 시점에 테이블에 실제 저장되어 있는 데이터(튜플들)의 집합임
  ○ 특징: 데이터의 삽입, 삭제, 수정에 따라 수시로 변하며, 이를 릴레이션의 '외연(Extension)'이라고도 부름

3. 정답 ③: 카디널리티 (Cardinality)
  ○ 역할: 릴레이션에 존재하는 튜플(행)의 총 개수를 의미함
  ○ 특징: 문제에서는 데이터 집합 내에서 중복을 제외하고 '고유한 값들의 총 개수'라는 튜플 수 본연의 정의로 출제됨

## 정리 
스키마 = 속성들의 집합
속성 = 열 = 애트리뷰트 = 필드
튜플 = 행 = 레코드
차수 = 디그리 = 속성의 개수 
기수 = 카디널리티 = 열의 개수 = 데이터 집합 내에서 고유한 값들의 개수
인스턴스 = 튜플의 집합 = 데이터의 집합 = 릴레이션의 외면(Relation Extension)
튜플 = 행 한줄 = 어떤 요소의 집합 혹은 행, 중복 포함 가능
