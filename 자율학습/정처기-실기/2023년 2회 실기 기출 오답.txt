[정보처리기사 오답노트] 암호화 알고리즘
==================================================

▶ 문제
다음은 암호화 알고리즘에 대한 설명이다. 괄호 안에 들어갈 가장 적절한 용어를 쓰시오.
  
( 1 )은/는 암호화와 복호화에 사용하는 키가 동일하다. 비밀키 전달을 위한 키교환이 필요하다. 
( 2 )은/는 공개키와 개인키가 존재하며, 공개키는 모두에게 공개되고, 개인키는 소유자만 알 수 있다.

--------------------------------------------------

▶ 정답
( 1 ) : 대칭키 (Symmetric Key)
( 2 ) : 비대칭키 (Asymmetric Key) 또는 공개키 (Public Key)

--------------------------------------------------

▶ 핵심 요약 및 비교
1. 대칭키 (Symmetric Key Encryption)
   - 암호화 키 = 복호화 키 (동일함)
   - 장점: 연산 속도가 빠름
   - 단점: 키를 안전하게 공유해야 하는 '키 분배/교환 문제' 발생
   - 대표 알고리즘: AES, DES, 3DES, SEED, ARIA

2. 비대칭키 (Asymmetric Key Encryption)
   - 암호화 키 ≠ 복호화 키 (서로 다름 / 공개키-개인키 쌍)
   - 장점: 키 분배 문제 해결, 관리해야 하는 키의 개수가 적음
   - 단점: 대칭키에 비해 연산 속도가 느림
   - 대표 알고리즘: RSA, ECC, ElGamal

[정보처리기사 기출개념] 오류 제어 방식 (23년 2회 실기)
==================================================

▶ 문제
다음은 오류 제어 방식에 대한 설명이다. 괄호 ( ) 안에 들어갈 용어를 보기에서 찾아서 쓰시오.

• 오류 제어 방식에는 크게 ( ① ) 방식과 ( ② ) 방식이 있다.
• ( ① ) 방식은 데이터 전송 과정에서 발생한 오류를 검출하여 검출된 오류를 재전송 요구 없이 스스로 수정하는 방식이다. 대표적인 유형인 ( ③ ) 코드 방식은 수신측에서 오류가 발생한 비트를 찾아 재전송을 요구하지 않고 자신이 직접 오류를 수정하는 방식으로 1비트의 오류 수정이 가능하다.
• ( ② ) 방식은 데이터 전송 과정에서 오류가 발생하면 송신 측에 재전송을 요구하는 방식이다. 대표적인 유형에는 ( ④ ) 검사, ( ⑤ ) 등이 있다.
• ( ④ ) 검사는 7~8개의 비트로 구성되는 전송 문자에 패리티 비트를 추가하여 오류를 검출하는 방식이다.
• ( ⑤ )은/는 다항식을 통해 산출된 값을 토대로 오류를 검사하는 방식으로 집단 오류를 해결하기 위한 방식이다.

[ 보기 ]
Parity / Hamming / FEC / BEC / BCD / NAK / CRC / MD5

--------------------------------------------------

▶ 정답 및 매칭
① FEC (Forward Error Correction, 전진 오류 수정)
② BEC (Backward Error Correction, 후진 오류 수정)
③ Hamming (해밍 코드)
④ Parity (패리티 검사)
⑤ CRC (순환 중복 검사)

--------------------------------------------------

▶ 핵심 개념 완벽 정리

1. 순방향/전진 오류 수정 (FEC: Forward Error Correction)
   - 송신측에서 오류 제어 부호를 함께 전송하여, 수신측에서 오류를 '스스로 발견하고 수정'하는 방식입니다.
   - 재전송 요구(Feedback) 경로가 필요 없어 역채널이 없는 경우에 유용하지만, 대역폭 낭비가 있을 수 있습니다.
   - 대표 유형: Hamming Code (1비트 오류 수정), 상승 코드(Asending Code)
   - Hamming Code : 수신측에서 오류가 발생한 비트를 찾아 재전송을 요구하지 않고 자신이 직접 오류를 수정하는 방식으로 1비트의 오류 수정이 가능

2. 역방향/후진 오류 수정 (BEC: Backward Error Correction)
   - 수신측에서 오류를 검출하면 송신측에 '재전송을 요구(ARQ)'하여 오류를 수정하는 방식입니다.
   - 대표적인 오류 검출 방식:
     - Parity Check: 문자 단위 검사 (짝수/홀수 패리티, 1비트 오류 검출만 가능)
     - Block Sum Check (체크섬): 블록 단위 검사
     - CRC (Cyclic Redundancy Check): 생성 다항식을 이용한 정밀 검사, 버스트(집단) 오류 검출에 탁월

[정보처리기사 오답노트] 화이트박스 테스트 커버리지
==================================================

▶ 문제
결정문 내의 각 조건이 참, 거짓을 한 번 이상 갖도록 조합하는 커버리지는 무엇인가?

[ 보기 ]
Condition Coverage / Decision Coverage / Condition/Decision Coverage / Statement Coverage / MC/DC

--------------------------------------------------

▶ 정답
Condition Coverage (조건 커버리지)

--------------------------------------------------

▶ 💡 핵심 개념 및 함정 탈출하기 (암기 팁!)

문제를 풀 때 '전체 결정문'을 보는지, '개별 조건식'을 보는지 키워드를 잘 발라내야 합니다.

1. 구문 커버리지 (Statement Coverage)
   - 키워드: "모든 문장(소스 코드)"
   - 프로그램 내의 모든 문장이 최소한 한 번은 실행되도록 커버리지를 구성합니다.

2. 결정 커버리지 (Decision Coverage) = 분기 커버리지 (Branch Coverage)
   - 키워드: "전체 결정문(조건식 전체)의 참/거짓"
   - 만약 if (A > 0 && B > 0) 이라면, 이 전체 결과가 True 한 번, False 한 번 나오도록 합니다.

3. 조건 커버리지 (Condition Coverage) ★이번 문제의 정답!
   - 키워드: "각 조건(개별 조건식)이 참/거짓"
   - 전체 결과와 상관없이, if문 안에 들어있는 개별 조건인 'A > 0'과 'B > 0' 각각이 참 한 번, 거짓 한 번을 갖도록 조합합니다.

4. 조건/결정 커버리지 (Condition/Decision Coverage)
   - 키워드: "전체 결정문도 참/거짓 + 개별 조건도 참/거짓"
   - 2번과 3번의 요구사항을 동시에 모두 만족하는 조합을 만듭니다.

[정보처리기사 기출개념] HDLC 프레임 종류 및 전송 모드 (26년 1회 실기)
==================================================

▶ 문제
다음은 비트(Bit) 위주의 프로토콜로, 각 프레임에 데이터 흐름을 제어하고 오류를 보정할 수 있는 비트 열을 삽입하여 전송하는 역할을 하는 HDLC에 대한 설명이다. 다음이 설명하는 용어를 한글로 쓰시오.

• HDLC 프레임의 구조는 플래그(Flag), 주소부(Address Field), 제어부(Control Field)로 구성되어 있다.
• 여기에서 제어부는 프레임의 종류를 식별하기 위해 사용되는데, 제어부의 첫 번째, 두 번째 비트를 사용하여 프레임의 종류를 구별할 수 있다.
• 프레임의 종류 중 ( ① ) 프레임은 제어부가 '0'으로 시작되는 프레임으로, 사용자 데이터를 전달하는 역할을 하고, ( ② ) 프레임은 제어부가 '10'으로 시작되는 프레임으로, 오류 제어와 흐름 제어를 위해 사용된다. 또한, ( ③ ) 프레임은 제어부가 '11'로 시작되는 프레임으로, 링크의 동작 모드 설정과 관리를 한다.
• HDLC의 데이터 전송 모드는 세 가지로 구분되는데 ( ④ )은/는 포인트 투 포인트 균형 링크에서 사용하고, 혼합국이 허가 없이 언제나 전송할 수 있도록 설정하는 특징이 있다.
• ( ⑤ )은/는 전이중 통신을 하는 포인트 투 포인트 불균형 링크 구성에 사용하고, 종국은 주국의 허가 없이 송신할 수 있지만, 링크 설정이나 오류 복구 등의 제어 기능은 주국만 하는 특징이 있다.

[ 보기 ]
릴레이 / 정보 / 비동기 응답 모드 / 표준 응답 모드 / 의명 / 비동기 균형 모드 / 감독 / 비번호 / 동기 응답 모드 / 동기 균형 모드 / 양방향 응답 모드

--------------------------------------------------

▶ 정답
① 정보 (또는 I)
② 감독 (또는 S)
③ 비번호 (또는 U)
④ 비동기 균형 모드 (또는 ABM)
⑤ 비동기 응답 모드 (또는 ARM)

--------------------------------------------------

▶ 💡 핵심 개념 암기 가이드

HDLC 문제는 크게 '프레임의 종류(제어부 비트)'와 '데이터 전송 모드' 두 가지만 알면 끝납니다!

1. HDLC 프레임 종류 (제어부 첫 비트로 구분)
   - 정보 프레임 (I-Frame, Information): 제어부가 '0'으로 시작. 사용자 데이터(정보) 전송 및 피기백킹(흐름/오류 제어 포함) 수행.
   - 감독 프레임 (S-Frame, Supervisory): 제어부가 '10'으로 시작. 오류 제어와 흐름 제어(확인 응답 등) 담당.
   - 비번호 프레임 (U-Frame, Unnumbered): 제어부가 '11'으로 시작. 링크 연결 및 해제, 동작 모드 설정 등 관리 담당.

2. HDLC 데이터 전송 모드 (주국과 종국의 관계)
   - 표준 응답 모드 (NRM: Normal Response Mode): 불균형 링크. 종국은 주국이 '명령(Poll)'을 내려야만 '응답'하여 전송 가능.
   - 비동기 응답 모드 (ARM: Asynchronous Response Mode): 불균형 링크. 종국이 주국의 허가(명령) 없이도 '먼저' 전송 가능. 단, 링크 제어는 주국만 함.
   - 비동기 균형 모드 (ABM: Asynchronous Balanced Mode) ★가장 중요!: 균형 링크(동등한 혼합국끼리 연결). 누구든 허가 없이 언제나 전송 가능.

정보-0
감독-10
비번호-11

🎯 헷갈리지 않는 꿀팁!
프레임 암기: 앞 글자만 따서 '정·감·비' (정보='0', 감독='10', 비번호='11')로 외우시면 순서대로 비트 매칭이 쉬워집니다.

전송 모드 암기: 문제 키워드에서 '균형 링크', '혼합국'이라는 말이 보이면 무조건 '비동기 균형 모드(ABM)'가 정답입니다!

[정보처리기사 오답노트] 애플리케이션 보안 기술 (23년 2회 실기)
==================================================

▶ 문제
다음에서 설명하는 용어를 쓰시오.

소프트웨어의 위·변조가 발생할 경우, 소프트웨어가 정상적으로 실행되지 않도록 실행 코드를 변형하거나 동작을 중단시키는 기법으로, 외부 공격자나 악의적인 사용자가 소스 코드를 분석·변경하지 못하도록 하여 소프트웨어의 무결성을 보장하는 보호 기술이다.

--------------------------------------------------

▶ 정답
템퍼프루핑 (또는 Tamperproofing)

--------------------------------------------------

▶ 💡 핵심 개념 및 연관 키워드 완벽 정리

1. 템퍼프루핑 (Tamperproofing) ★이번 문제의 정답!
   - 개념: 소프트웨어를 함부로 변경하거나 변조(Tamper)하는 것을 방지(Proofing)하는 기술입니다.
   - 메커니즘: 프로그램이 변조되었다면 실행 코드를 스스로 바꾸거나 실행을 멈춰버려서, 공격자가 소스 코드를 분석하고 조작하는 것을 막아 소프트웨어의 무결성을 지킵니다.
   - 핵심 키워드: "위·변조 발생 시", "동작을 중단", "무결성 보장"

2. 같이 외우면 좋은 단골 보안 용어 세트
   - 코드 난독화 (Code Obfuscation): 소스 코드를 알아보기 힘든 복잡한 형태로 변환하여 역공학(리버스 엔지니어링)을 방지하는 기술 (키워드: "역공학 방지", "읽기 어렵게 만듦")
   - 워터마킹 (Watermarking): 저작권자의 정보를 디지털 콘텐츠에 보이지 않게 삽입하는 기술 (키워드: "저작권 보호", "보이지 않는 마크")
   - 핑거프린팅 (Fingerprinting): 콘텐츠 구매자의 정보를 삽입하여 유출 경로를 추적하는 기술 (키워드: "구매자 정보", "유출 추적")

▶ 문제
다음 C 프로그램에 홍길동, 김철수, 박영희 순서로 입력하였다. 프로그램의 출력 결과를 쓰시오.

```c
#include <stdio.h>
char n[30];
char *gamja(){
    gets(n);
    return n;
}
int main() {
    char *p1=gamja();
    char *p2=gamja();
    char *p3=gamja();
    printf("%s\n", p1);
    printf("%s\n", p2);
    printf("%s\n", p3);
    return 0;
}

▶ 💡 핵심 원리 파헤치기 (왜 '박영희'만 3번 나올까?)

이 문제의 핵심은 char n[30];이 함수 내부가 아닌 외부에 선언된 "전역 변수(Static 메모리 영역)"라는 점과 포인터의 작동 원리에 있습니다.

전역 배열 n[30]의 위치는 고정되어 있습니다.

gamja() 함수가 리턴하는 return n;은 배열의 '값'을 복사해서 주는 게 아니라, 전역 변수 n의 고유한 메모리 주소(예: 0x1000)를 리턴합니다.

따라서 p1, p2, p3 포인터 변수 3개 모두가 가리키는 주소는 동일하게 n 배열의 주소(0x1000)가 됩니다.

입력 단계별 메모리(n 배열) 상태 변화:

1번째 호출 (p1 = gamja();)
-> gets(n)에 의해 n 배열에 "홍길동" 저장. p1은 n의 주소를 가리킴.

2번째 호출 (p2 = gamja();)
-> 같은 n 배열에 "김철수"를 덮어씀! 기존 홍길동은 사라짐. p2도 n의 주소를 가리킴.

3번째 호출 (p3 = gamja();)
-> 같은 n 배열에 최종적으로 "박영희"를 덮어씀! p3도 n의 주소를 가리킴.

최종 출력 단계:

결과적으로 p1, p2, p3는 모두 똑같은 n 배열의 주소를 바라보고 있고, 그 주소에 마지막으로 남아있는 값은 "박영희"입니다.

그렇기 때문에 printf를 3번 실행하면 전부 "박영희"만 출력하게 됩니다.
