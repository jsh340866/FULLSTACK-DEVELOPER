■ 라우터 프로토콜 핵심 요약

1. 범위에 따른 분류
- IGP (내부 라우팅 프로토콜): AS(자율 시스템) 내부에서 사용 (예: RIP, OSPF, EIGRP)
- EGP (외부 라우팅 프로토콜): AS와 AS 사이에서 사용 (예: BGP)

2. 알고리즘에 따른 분류 (IGP)
- 거리 벡터 (Distance Vector): 거리(홉 카운트)와 방향만 고려, 이웃 라우터와 주기적 테이블 교환
  * RIP: 최대 15홉 제한, 소규모망, 홉 카운트 기준 최적 경로 결정
- 링크 상태 (Link State): 전체 네트워크 지형도를 기반으로 다익스트라 알고리즘 사용, 변경 시에만 전파
  * OSPF: 홉 제한 없음, 대규모망, 대역폭(속도) 기준 최적 경로 결정

3. 핵심 프로토콜 비교
[RIP]
- 분류: IGP
- 방식: 거리 벡터
- 기준: 홉 카운트
- 특징: 최대 15홉 제한, 소규모용, 설정 간단

[OSPF]
- 분류: IGP
- 방식: 링크 상태
- 기준: 대역폭 (Cost)
- 특징: 대규모용, 다익스트라 알고리즘 사용, 빠른 수렴

[EIGRP]
- 분류: IGP
- 방식: 하이브리드 (고급 거리 벡터)
- 기준: 대역폭, 지연시간 등 복합
- 특징: 시스코 개발, 매우 빠른 수렴 속도

[BGP]
- 분류: EGP
- 방식: 경로 벡터
- 기준: AS 경로 등
- 특징: 인터넷 백본망에서 사용, 대용량 라우팅 정보 교환

■ [실기] 24년 2회 기출문제 해설

[문제]
RIP 알고리즘을 이용하여 라우터 A에서 F까지 어떤 경로를 거쳐야 최단 경로로 갈 수 있는지 순서를 쓰시오.
A -> ( )
(정답 예시: B -> C -> D -> E -> F)

[정답]
D -> C -> F

[핵심 풀이 요약]
- 이 문제의 가장 큰 함정은 그래프 선에 적힌 '숫자(비용)'입니다.
- RIP(Routing Information Protocol) 알고리즘은 대역폭이나 선의 비용(숫자)을 완전히 무시합니다.
- 오직 '홉 카운트(Hop Count, 거쳐 가는 라우터의 개수)'만을 기준으로 최단 경로를 결정합니다. 즉, 숫자가 아무리 커도 "가장 적은 개수의 라우터를 거치는 경로"가 정답이 됩니다.

[구간별 상세 분석]
1. 전반부 (A에서 D까지 가는 경로)
- 경로 1) A -> D : 라우터 1개 거침 (1홉)
- 경로 2) A -> B -> D : 라우터 2개 거침 (2홉)
=> RIP 기준 최단 경로: A -> D

2. 중반부 (D에서 C까지 가는 경로)
- D -> C : 외길 (1홉)

3. 후반부 (C에서 F까지 가는 경로)
- 경로 1) C -> F : 라우터 1개 거침 (1홉) *선에 적힌 숫자 5는 무시!
- 경로 2) C -> E -> F : 라우터 2개 거침 (2홉)
=> RIP 기준 최단 경로: C -> F

[결론]
모든 구간에서 라우터를 가장 적게 거치는 최단 경로를 이으면 [ A -> D -> C -> F ]가 됩니다. 
따라서 괄호 ( ) 안에 들어갈 정답 순서는 'D -> C -> F'입니다.

■ [실기] 24년 2회 기출문제 해설 (디자인 패턴)

[문제]
컬렉션의 내부 구조를 노출하지 않고 요소에 순차적으로 접근하는 방법을 제공하는 패턴을 영어로 쓰시오.

[정답]
Iterator (또는 반복자 또는 이터레이터)

---

■ 문제 해설 및 보기 완벽 정리

★ 정답 패턴 분석
- Iterator (반복자 패턴) - 행위 패턴
  * 핵심 키워드: 컬렉션(리스트, 배열 등)의 내부 구조 노출 안 함, '순차적인 접근(반복)'
  * 쉽게 이해하기: 책의 내부 페이지가 어떻게 제본되었는지 몰라도, '책장 넘기기'라는 동일한 방법으로 첫 페이지부터 끝 페이지까지 읽을 수 있게 해주는 도구입니다. 자바의 `Iterator`나 `hasNext()`, `next()`를 생각하면 쉬워요!

---

■ 나머지 보기 오답 노트 및 핵심 키워드 정리

시험에 무조건 나오는 디자인 패턴의 핵심 정의와 키워드들입니다. 메모장에 저장해 두고 키워드 중심으로 매칭해 보세요!

1. Template Method (템플릿 메서드 패턴) - 행위 패턴
- 핵심 키워드: 상위 클래스에서 알고리즘의 '뼈대(구조)'를 정의, 하위 클래스에서 '구체적인 단계'를 재정의(오버라이딩)
- 쉽게 이해하기: 큰 틀이나 실행 순서는 부모가 정해두고, 세부적인 구현은 자식이 채우도록 하는 방식입니다.

2. Strategy (전략 패턴) - 행위 패턴
- 핵심 키워드: 알고리즘 '군(Family)'을 정의하고 각각을 '캡슐화'하여 '상호 교환'이 가능하도록 만듦
- 쉽게 이해하기: 게임에서 캐릭터가 무기(검, 활, 마법)를 바꿀 때마다 공격 방식(전략)이 실시간으로 교체되는 구조를 만들 때 쓰입니다.

3. Composite (컴포지트 패턴) - 구조 패턴
- 핵심 키워드: 객체들의 관계를 '트리 구조'로 구성, '단일 객체'와 '복합 객체'를 '동일하게 취급'
- 쉽게 이해하기: 컴퓨터의 파일 시스템(파일 = 단일 객체 / 폴더 = 복합 객체)처럼, 폴더 안에 파일도 들어가고 또 다른 폴더도 들어가는 트리 구조를 다룰 때 사용합니다.

4. Observer (옵저버 패턴) - 행위 패턴
- 핵심 키워드: '일대다(1:N)' 의존성, 한 객체의 상태가 바뀌면 다른 객체들에게 '자동 통지' 및 업데이트
- 쉽게 이해하기: 유튜브 채널을 '구독'해 두면, 유튜버가 영상을 올렸을 때 구독자 전원에게 자동으로 알림이 가는 시스템입니다.
