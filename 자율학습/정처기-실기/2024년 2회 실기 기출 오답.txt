■ 라우터 프로토콜 핵심 요약

1. 범위에 따른 분류
- IGP (내부 라우팅 프로토콜): AS(자율 시스템) 내부에서 사용 (예: RIP, OSPF, EIGRP)
- EGP (외부 라우팅 프로토콜): AS와 AS 사이에서 사용 (예: BGP)

2. 알고리즘에 따른 분류 (IGP)
- 거리 벡터 (Distance Vector): 거리(홉 카운트)와 방향만 고려, 이웃 라우터와 주기적 테이블 교환
  * RIP: 최대 15홉 제한, 소규모망, 홉 카운트 기준 최적 경로 결정
- 링크 상태 (Link State): 전체 네트워크 지형도를 기반으로 다익스트라 알고리즘 사용, 변경 시에만 전파
  * OSPF: 홉 제한 없음, 대규모망, 대역폭(속도) 기준 최적 경로 결정

3. 핵심 프로토콜 비교
[RIP]
- 분류: IGP
- 방식: 거리 벡터
- 기준: 홉 카운트
- 특징: 최대 15홉 제한, 소규모용, 설정 간단

[OSPF]
- 분류: IGP
- 방식: 링크 상태
- 기준: 대역폭 (Cost)
- 특징: 대규모용, 다익스트라 알고리즘 사용, 빠른 수렴

[EIGRP]
- 분류: IGP
- 방식: 하이브리드 (고급 거리 벡터)
- 기준: 대역폭, 지연시간 등 복합
- 특징: 시스코 개발, 매우 빠른 수렴 속도

[BGP]
- 분류: EGP
- 방식: 경로 벡터
- 기준: AS 경로 등
- 특징: 인터넷 백본망에서 사용, 대용량 라우팅 정보 교환

■ [실기] 24년 2회 기출문제 해설

[문제]
RIP 알고리즘을 이용하여 라우터 A에서 F까지 어떤 경로를 거쳐야 최단 경로로 갈 수 있는지 순서를 쓰시오.
A -> ( )
(정답 예시: B -> C -> D -> E -> F)

[정답]
D -> C -> F

[핵심 풀이 요약]
- 이 문제의 가장 큰 함정은 그래프 선에 적힌 '숫자(비용)'입니다.
- RIP(Routing Information Protocol) 알고리즘은 대역폭이나 선의 비용(숫자)을 완전히 무시합니다.
- 오직 '홉 카운트(Hop Count, 거쳐 가는 라우터의 개수)'만을 기준으로 최단 경로를 결정합니다. 즉, 숫자가 아무리 커도 "가장 적은 개수의 라우터를 거치는 경로"가 정답이 됩니다.

[구간별 상세 분석]
1. 전반부 (A에서 D까지 가는 경로)
- 경로 1) A -> D : 라우터 1개 거침 (1홉)
- 경로 2) A -> B -> D : 라우터 2개 거침 (2홉)
=> RIP 기준 최단 경로: A -> D

2. 중반부 (D에서 C까지 가는 경로)
- D -> C : 외길 (1홉)

3. 후반부 (C에서 F까지 가는 경로)
- 경로 1) C -> F : 라우터 1개 거침 (1홉) *선에 적힌 숫자 5는 무시!
- 경로 2) C -> E -> F : 라우터 2개 거침 (2홉)
=> RIP 기준 최단 경로: C -> F

[결론]
모든 구간에서 라우터를 가장 적게 거치는 최단 경로를 이으면 [ A -> D -> C -> F ]가 됩니다. 
따라서 괄호 ( ) 안에 들어갈 정답 순서는 'D -> C -> F'입니다.

4. Observer (옵저버 패턴) - 행위 패턴
- 핵심 키워드: '일대다(1:N)' 의존성, 한 객체의 상태가 바뀌면 다른 객체들에게 '자동 통지' 및 업데이트
- 쉽게 이해하기: 유튜브 채널을 '구독'해 두면, 유튜버가 영상을 올렸을 때 구독자 전원에게 자동으로 알림이 가는 시스템입니다.

■ [실기] C언어 포인터 및 문자열 복사 기출문제 해설

#include <stdio.h>
void fn(char *d, const char *s) {
    while(*s) {
        *d=*s;
        d++;
        s++;
    }
    *d='\0';
}

int main() {
    const char* str1="first";
    char str2[50]="teststring";
    int result=0;
    int i;

    fn(str2, str1);
    for(i=0;str2[i] !='\0';i++) {
        result+=i;
    }
    printf("%d", result);
    return 0;
}


[문제 코드 분석]
주어진 C언어 코드는 str1의 문자열을 str2에 복사한 뒤, 복사된 문자열의 길이를 이용해 특정 값을 계산하고 출력하는 문제입니다.

[정답]
10

---

■ 코드 실행 과정 상세 분석 (메모장 저장용)

1. 변수 초기화
- str1 = "first" (문자열 리터럴, 길이는 5)
- str2 = "teststring" (크기 50의 배열에 초기화됨)
- result = 0, i = 0

2. fn(str2, str1) 함수 호출 (문자열 복사 수행)
- s가 가리키는 str1("first")의 문자들을 하나씩 d가 가리키는 str2에 덮어씁니다.
- while(*s) 루프가 끝나면 s는 'first' 끝의 NULL 문자('\0')를 만나서 종료됩니다.
- 루프 직후 *d='\0'; 연산에 의해 str2의 5번째 인덱스 위치에 널 문자가 삽입됩니다.
- 결과적으로 str2는 기존의 "teststring"에서 앞부분이 덮어씌워져 "first\0tring" 형태가 됩니다. (C언어 문자열은 '\0'까지만 인식하므로 실제 str2는 "first"가 됩니다.)

3. for 루프를 통한 result 계산
- 조건식: str2[i] != '\0' (널 문자를 만날 때까지 반복)
- str2는 "first"이므로 글자 수가 5개입니다. 루프는 i가 0부터 4일 때까지 총 5번 돕니다.

- i = 0 일 때: result += 0  -> result = 0
- i = 1 일 때: result += 1  -> result = 1
- i = 2 일 때: result += 2  -> result = 3
- i = 3 일 때: result += 3  -> result = 6
- i = 4 일 때: result += 4  -> result = 10
- i = 5 일 때: str2[5]는 '\0'이므로 반복문 탈출!

4. 출력
- printf("%d", result); 에 의해 최종적으로 10이 출력됩니다.

---

★ 핵심 팁
- fn 함수는 C언어 표준 함수인 strcpy(d, s)와 완전히 동일한 역할을 하는 함수입니다.
- 기존 str2에 어떤 긴 문자열이 들어있었더라도, 앞부분에 "first"가 복사되고 바로 뒤에 널 문자('\0')가 붙기 때문에 문자열의 실제 길이는 "first"의 길이인 5가 됩니다.
- 0부터 4까지 더하는 수식(0 + 1 + 2 + 3 + 4)이 되므로 정답은 10입니다.

■ 코드 실행 과정 및 핵심 함정 분석 (메모장 저장용)

이 문제는 자바에서 배열을 '==' 연산자로 비교할 때 무엇을 비교하는지 정확히 알고 있는지 묻는 단골 기출 유형입니다. 

작성하신 답변(O, N, N)을 보면 a 배열과 b 배열의 알맹이 값({1, 2, 3, 4})이 똑같아서 첫 번째를 'O'라고 생각하셨을 가능성이 높습니다. 왜 틀렸는지 핵심 원리를 정리해 드릴게요.

1. 자바에서 배열의 '==' 연산자 의미 (가장 중요!)
- 자바에서 배열은 '참조형(Reference Type)' 변수입니다.
- 참조형 변수에서 '==' 연산자는 배열 내부의 값(알맹이)을 비교하는 것이 아니라, 메모리 상에서 해당 배열이 위치한 '주소값(참조값)'을 비교합니다.


2. 메모리 할당 상태 분석
- int a[] = new int[] {1, 2, 3, 4}; -> 메모리 방 100번지에 배열 생성 (a는 100번지를 가리킴)
- int b[] = new int[] {1, 2, 3, 4}; -> 메모리 방 200번지에 새로운 배열 생성 (b는 200번지를 가리킴)
- int c[] = new int[] {1, 2, 3};    -> 메모리 방 300번지에 새로운 배열 생성 (c는 300번지를 가리킴)

※ 아무리 a와 b 안에 들어있는 숫자 데이터가 완전히 일치하더라도, 'new' 키워드를 통해 각각 서로 다른 메모리 공간에 독립적으로 만들어졌기 때문에 두 배열의 주소값은 절대 같을 수 없습니다.

3. check() 함수 실행 과정
- check(a, b); -> a의 주소(100)와 b의 주소(200)를 비교함 -> 다름(false) -> "N" 출력
- check(b, c); -> b의 주소(200)와 c의 주소(300)를 비교함 -> 다름(false) -> "N" 출력
- check(a, c); -> a의 주소(100)와 c의 주소(300)를 비교함 -> 다름(false) -> "N" 출력

4. 출력 형식 주의점
- 코드의 출력문이 System.out.println이 아니라 줄바꿈이 없는 System.out.print("0") / print("N") 입니다.
- 따라서 개행(줄바꿈) 없이 옆으로 연달아 붙어서 출력되므로 최종 정답은 "NNN"이 됩니다.

---

★ 시험장 암기 팁
- 자바에서 배열이나 객체를 '=='로 비교하면 무조건 '주소값' 비교다!
- 만약 내부 알맹이 값들을 비교하고 싶다면 '=='가 아니라 `Arrays.equals(a, b)` 메서드를 사용해야 합니다.

이제 쌓여있던 함수들이 아래에서부터 차례대로 풀리면서 대기하던 if문을 실행합니다. 이 과정에서 seen 배열에 체크가 되면서 중복 문자가 걸러집니다.

- [fn(0) 실행] (c = 'a') -> 아직 'a' 없으므로 seen['a']=true -> 'a' + "" => "a" 리턴
- [fn(1) 실행] (c = 'b') -> 아직 'b' 없으므로 seen['b']=true -> 'b' + "a" => "ba" 리턴
- [fn(2) 실행] (c = 'a') -> 이미 'a'는 채워졌으므로 패스 -> 그대로 "ba" 리턴
- [fn(3) 실행] (c = 'c') -> 아직 'c' 없으므로 seen['c']=true -> 'c' + "ba" => "cba" 리턴
- [fn(4) 실행] (c = 'a') -> 이미 'a'는 있으므로 패스 -> 그대로 "cba" 리턴
- [fn(5) 실행] (c = 'b') -> 이미 'b'는 있으므로 패스 -> 그대로 "cba" 리턴
- [fn(6) 실행] (c = 'c') -> 이미 'c'는 있으므로 패스 -> 그대로 "cba" 리턴
- [fn(7) 실행] (c = 'd') -> 아직 'd' 없으므로 seen['d']=true -> 'd' + "cba" => "dcba" 리턴

5. 최종 출력

■ 문제 해설 및 핵심 함정 분석 (메모장 저장용)

- 핵심 키워드: 연결 경로 확립 없음, 독립적 전송, 순서 무관, 비 연결형 교환 방식
- 쉽게 이해하기: 편지봉투에 각각 주소를 적어 우체통에 던지는 것처럼, 패킷마다 독립적으로 최적의 경로를 찾아 날아가는 방식입니다. 네트워크 상황에 따라 1번 패킷보다 3번 패킷이 먼저 도착할 수도 있어서 수신 측에서 순서를 다시 맞춰야 합니다. (이 개념이 전송 계층으로 올라가서 구현된 프로토콜이 UDP입니다.)

■ 문제 해설 및 핵심 함정 분석 (메모장 저장용)

작성하신 답변(SSH)도 원격 접속이나 데이터 전송 시 암호화를 제공하는 대표적인 보안 프로토콜이 맞습니다! 네트워크 보안에 대해 고민하다 보니 떠올리셨을 텐데, 왜 'IPSec'이 정답이 되는지 명확한 차이점을 정리해 드릴게요.

1. IPSec(IP Security)이 정답인 이유 (핵심 키워드 매칭)
- 'IP계층(3계층) 보안': IPSec의 가장 강력한 특징입니다. OSI 7계층 중 네트워크 계층(IP 계층)에서 동작하므로 상위 애플리케이션에 구애받지 않고 투명하게 보안을 제공합니다.
- 'AH(Authentication Header)': 데이터가 전송 중에 변조되지 않았음을 증명하는 '무결성과 인증'을 담당합니다.
- 'ESP(Encapsulating Security Payload)': 데이터를 통째로 암호화하여 외부에서 내용을 볼 수 없게 만드는 '기밀성'을 담당합니다.
- 'VPN 기술의 기반': 공중망을 마치 전용선(사설망)처럼 안전하게 터널링할 때 사용하는 핵심 프로토콜입니다.

2. 작성하신 'SSH(Secure Shell)'가 오답인 이유
- SSH는 IP 계층(3계층)이 아니라 '애플리케이션 계층(7계층)'에서 동작하는 프로토콜입니다. (포트 번호 22번 사용)
- 주로 리눅스 서버 등에 원격으로 안전하게 접속하여 명령어를 실행(CLI 제어)하기 위해 사용하는 기술입니다. 
- AH나 ESP 같은 3계층 헤더 개념을 사용하지 않습니다.

■ 문제 해설 및 핵심 함정 분석 (메모장 저장용)

작성하신 답변(내용적, 기능적)은 응집도와 결합도 개념을 공부할 때 가장 강렬하게 외우는 단어들이라 먼저 떠오르셨을 것 같아요! (기능적 응집도는 가장 좋은 것, 내용적 결합도는 가장 나쁜 것)

하지만 이 문제는 응집도의 7가지 단계 중 "이전의 결과물이 다음의 입력값으로 릴레이 하듯 이어진다"는 단서를 통해 정확한 종류를 골라내야 하는 문제입니다. 왜 '순차적'이 정답인지와 시험에 잘 나오는 다른 유형들을 묶어서 정리해 드릴게요.

1. 순차적 응집도(Sequential Cohesion)가 정답인 이유
- 핵심 키워드: "이전 기능의 출력이 다음 기능의 입력으로 사용"
- 쉽게 이해하기: 공장의 '조립 라인(컨베이어 벨트)'을 생각하면 가장 쉽습니다. 앞사람이 인형의 '몸통'을 만들어서 넘겨주면(출력), 뒷사람이 그 몸통을 받아서(입력) '눈알'을 붙이는 과정처럼 기능들이 순서대로 톱니바퀴처럼 맞물려 있는 상태입니다.

2. 헷갈리기 쉬운 다른 응집도와의 차이점 확실히 잡기!

★ [교환적(통신적) 응집도] vs [순차적 응집도]
- 교환적(통신적) 응집도: "동일한 입력 데이터"를 가지고 서로 다른 여러 기능을 수행할 때입니다. (예: 학생 정보 데이터를 가져와서 성적도 계산하고, 주소록도 출력하는 모듈)
- 순차적 응집도: 동일한 데이터가 아니라, "A의 출력이 B의 입력"이 되는 릴레이 형태입니다.

★ [절차적 응집도] vs [순차적 응집도]
- 절차적 응집도: 그저 "실행 순서"만 정해져 있을 뿐, 앞의 결과물이 뒤의 입력값으로 전달되지는 않습니다. (예: 마트 계산 프로그램에서 '바코드 읽기' 다음에 '영수증 출력'이 순서대로 실행되는 모듈)

■ 시험장 암기 팁 (응집도 7단계 순서 암기법)

응집도는 "우주통교순기" 두문자로 외우면 순서대로 기억하기 좋습니다. (오른쪽으로 갈수록 응집도가 높고 좋은 모듈입니다.)

[ 우 -> 주 -> 통 -> 교 -> 순 -> 기 ]
1. 우연적 (Coincidental): 아무 관련 없는 기능들이 우연히 모임 (가장 나쁨)
2. 논리적 (Logical): 유사한 성격이나 형태로 분류되는 기능들이 모임
3. 시간적 (Temporal): 특정 시간(예: 초기화)에 함께 실행되는 기능들이 모임
4. 절차적 (Procedural): 순서가 정해진 몇 개의 기능을 수행
5. 교환적/통신적 (Communication): 동일한 입출력 자료를 공유하여 서로 다른 기능 수행
6. 순차적 (Sequential): [본 문제 정답] 한 기능의 출력이 다음 기능의 입력으로 사용됨
7. 기능적 (Functional): 모듈 내부의 모든 요소가 하나의 단일 기능을 수행 (가장 좋음)

문제 문장 자체에 "출력이 다음 기능의 입력으로"라는 명확한 힌트가 들어있으므로, 이 문구를 보면 바로 '순차적'을 떠올리시면 됩니다!

■ 핵심 알고리즘 이해하기 (SRT: Shortest Remaining Time)

SRT 스케줄링은 '선점형(Preemptive) SJF'라고도 부릅니다. 
새로운 프로세스가 도착할 때마다 "현재 실행 중인 프로세스의 남은 시간"과 "새로 도착한 프로세스의 서비스 시간"을 비교하여, 가장 시간이 짧게 남은 녀석에게 CPU를 뺏어오는(선점) 방식입니다.

[간트 차트(Gantt Chart) 흐름 분석]

- Time 0: P1 도착 (남은 시간: 8)
  * 실행 가능한 프로세스가 P1뿐이므로 P1 실행 시작.

- Time 1: P2 도착 (남은 시간: 4)
  * 현재 실행 중이던 P1의 남은 시간: 7 (8 - 1)
  * 새로 도착한 P2의 서비스 시간: 4
  * 비교: P1(7) > P2(4) -> P2가 더 짧으므로 CPU를 빼앗아 P2 실행 시작! (P1은 대기실로)

- Time 2: P3 도착 (남은 시간: 9)
  * 현재 실행 중이던 P2의 남은 시간: 3 (4 - 1)
  * 대기실에 있는 프로세스들의 남은 시간: P1(7), P3(9)
  * 비교: P2(3)가 가장 짧으므로 P2 계속 실행.

- Time 3: P4 도착 (남은 시간: 5)
  * 현재 실행 중이던 P2의 남은 시간: 2 (3 - 1)
  * 대기실에 있는 프로세스들의 남은 시간: P1(7), P3(9), P4(5)
  * 비교: P2(2)가 가장 짧으므로 P2 계속 실행.

- Time 5: P2 종료 (1초에 켜져서 총 4초 동안 실행 완료)
  * 현재 대기실에 남은 프로세스: P1(7), P3(9), P4(5)
  * 가장 짧은 P4(5) 실행 시작!

- Time 10: P4 종료 (5초에 켜져서 총 5초 동안 실행 완료)
  * 현재 대기실에 남은 프로세스: P1(7), P3(9)
  * 가장 짧은 P1(7) 실행 시작!

- Time 17: P1 종료 (10초에 다시 켜져서 남은 7초 실행 완료)
  * 마지막으로 남은 P3(9) 실행 시작!

- Time 26: P3 종료 (17초에 켜져서 총 9초 동안 실행 완료)

■ 대기시간 및 평균 대기시간 계산

* 대기시간 공식 = 종료시간 - 도착시간 - 서비스시간

- P1: 종료(17) - 도착(0) - 서비스(8) = 9
- P2: 종료(5) - 도착(1) - 서비스(4) = 0  (한 번도 안 쉬고 다 끝냄)
- P3: 종료(26) - 도착(2) - 서비스(9) = 15 (17초에 켜질 때까지 기다림)
- P4: 종료(10) - 도착(3) - 서비스(5) = 2  (3초에 와서 5초에 켜질 때까지 기다림)

★ 평균 대기시간 계산:
(9 + 0 + 15 + 2) / 4 = 26 / 4 = 6.5

★ 시험장 암기 팁
- SRT 문제는 시간이 흐를 때마다 메모장이나 시험지 여백에 '남은 시간 테이블'을 계속 업데이트하면서 풀어야 실수를 안 합니다.
- 계산 결과가 소수점으로 떨어질 수 있으니(6.5) 끝까지 정확하게 나누는 연습이 필요해요!

■ [실기] C언어 구조체 및 연결 리스트 기출문제 해설

[문제]
제시된 C언어 코드의 출력 결과를 쓰시오.

[정답]
20

---

■ 코드 핵심 동작 원리 및 메모리 구조 분석 (메모장 저장용)

이 문제는 변수들이 서로 포개지는 구조가 아니라, 독립된 공간에 살면서 화살표(주소)로만 연결되는 '연결 리스트(Linked List)'의 메커니즘을 이해하는 것이 핵심입니다.

1. 구조체 변수의 독립적인 메모리 상태
- 변수 a: [ n1 = 10 ] [ n2 = 0 ] -> (100번지)
- 변수 b: [ n1 = 20 ] [ n2 = 0 ] -> (200번지)
- 변수 c: [ n1 = 30 ] [ n2 = 0 ] -> (300번지)

2. 포인터 주소 연결 (화살표 잇기)
- head = &a;  -> head 표지판이 a의 주소(100번지)를 가리킴
- a.n2 = &b;  -> a의 n2 방에 b의 주소(200번지)를 저장함
- b.n2 = &c;  -> b의 n2 방에 c의 주소(300번지)를 저장함

★ 핵심 착각 포인트 교정!
- head는 (10, (20, c)) 처럼 모든 데이터를 품고 있는 거대한 보따리가 아닙니다.
- head 자체는 오직 첫 번째 집 주소(100번지)만 들고 있는 아주 가벼운 '이정표 표지판'일 뿐입니다.



3. head->n2->n1 컴퓨터의 탐색 과정 (징검다리 건너기)
컴퓨터는 화살표(->)를 만날 때마다 주소를 타고 다음 방으로 점프합니다.

- [1단계] head를 봄
  * "100번지(a의 집)로 가세요." -> 곧바로 a의 위치로 이동
- [2단계] ->n2를 봄
  * a의 집에 도착해 n2 방을 열어보니 "200번지(b의 집)로 가세요"라고 적혀있음 -> b의 위치로 점프!
- [3단계] ->n1을 봄
  * b의 집에 도착해서 n1 방을 열어보니 숫자 '20'이 들어있음 -> 최종적으로 값 20을 획득!

4. 최종 출력
- printf("%d", 20); 가 실행되므로 화면에는 "20"이 출력됩니다.

---

★ 시험장 직관 풀이 팁
- 연결 리스트에서 head->n2->n1 구조가 나오면 머릿속으로 큰 주머니를 상상하지 마세요.
- 시험지 여백에 [ a: 10 ] ──> [ b: 20 ] ──> [ c: 30 ] 처럼 기차 기찻길을 그려두고, head에서 출발해 화살표 개수만큼 칸을 건너가서(head에서 한 칸 건너가면 b) 알맹이 값인 n1을 읽어내면 절대 틀리지 않습니다!
