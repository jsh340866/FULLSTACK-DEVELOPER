
[문제]
제시된 C언어 코드를 실행했을 때의 출력 결과를 쓰시오.

#include <stdio.h>
void func(int **arr, int size){
    int i;
    for(i=0;i<size;i++){
        *(*arr+i)=(*(*arr+i)+i) % size;
    }
}
int main(){
    int arr[]={3, 1, 4, 1, 5};
    int *p=arr;
    int **pp=&p;

    func(pp, 5);
    printf("%d", arr[2]);
    return 0;
}


[정답]
1


[문제 핵심 분석 및 포인터 해석]

1. main 함수에서의 변수 관계
- arr은 크기가 5인 배열의 시작 주소(&arr[0])를 가리킵니다.
- p는 arr 배열의 시작 주소를 담고 있는 싱글 포인터 변수입니다. (p == arr)
- pp는 포인터 변수 p의 주소를 담고 있는 이중 포인터 변수입니다. (pp == &p)

2. func(pp, 5) 함수 호출 시 포인터 연산 구조
- 매개변수로 들어온 이중 포인터 'arr'에 대해 '*arr'을 하면, 원래 main 함수의 싱글 포인터인 'p'를 가리키게 됩니다.
- 즉, *arr은 main의 p(배열의 시작 주소)와 완벽히 같습니다.
- 따라서 코드의 '*(*arr + i)'는 '*(p + i)'와 같으며, 이는 배열의 각 요소인 'arr[i]'를 직접 가리키는 문법이 됩니다.
- 결과적으로 함수 내부의 핵심 수식은 다음과 같이 일반 배열 형태로 변환하여 해석할 수 있습니다:
  arr[i] = (arr[i] + i) % size;


[for 반복문 실행 과정 (size = 5)]

초기 배열 상태: arr[] = {3, 1, 4, 1, 5}

- i = 0 일 때:
  * arr[0] = (arr[0] + 0) % 5 = (3 + 0) % 5 = 3
  * 배열 상태: {3, 1, 4, 1, 5}

- i = 1 일 때:
  * arr[1] = (arr[1] + 1) % 5 = (1 + 1) % 5 = 2
  * 배열 상태: {3, 2, 4, 1, 5}

- i = 2 일 때:
  * arr[2] = (arr[2] + 2) % 5 = (4 + 2) % 5 = 6 % 5 = 1
  * 배열 상태: {3, 2, 1, 1, 5}

- i = 3 일 때:
  * arr[3] = (arr[3] + 3) % 5 = (1 + 3) % 5 = 4
  * 배열 상태: {3, 2, 1, 4, 5}

- i = 4 일 때:
  * arr[4] = (arr[4] + 4) % 5 = (5 + 4) % 5 = 9 % 5 = 4
  * 최종 배열 상태: {3, 2, 1, 4, 4}


[최종 출력 결과]
- main 함수에서 'printf("%d", arr[2]);'를 실행합니다.
- 위의 실행 과정에 의해 변해버린 arr[2]의 값은 1이므로, 최종 출력값은 1이 됩니다.

####

*(*arr+i) = arr[i]

arr[i] = (arr[i] + i) % size

답 : 1

[문제]
제시된 C언어 코드를 실행했을 때의 출력 결과를 쓰시오.

#include <stdio.h>
struct Node {
    int v;
    struct Node* next;
};
void func(struct Node* n) {
    while (n !=NULL && n->next !=NULL) {
        int t=n->v;
        n->v=n->next->v;
        n->next->v=t;
        n=n->next->next;
    }
}

int main() {
    struct Node n1={1, NULL};
    struct Node n2={2, NULL};
    struct Node n3={3, NULL};
    struct Node* c=&n1;

    n1.next=&n3;
    n3.next=&n2;
    func(&n1);
    while (c !=NULL) {
        printf("%d", c->v);
        c=c->next;
    }
    return 0;
}


[정답]
312


[문제 핵심 분석 및 실행 과정]

1. 연결 리스트 초기 구조 파악
- main 함수에서 노드 3개를 생성하고 다음과 같이 연결합니다.
- n1의 값은 1이며, 다음 노드로 n3을 가리킵니다.
- n3의 값은 3이며, 다음 노드로 n2를 가리킵니다.
- n2의 값은 2이며, 다음 노드는 NULL입니다.
- 즉, 전체적인 연결 순서는 [ n1(1) -> n3(3) -> n2(2) ] 가 됩니다.

2. func(&n1) 함수 호출 및 반복문 실행
- 함수 func는 현재 노드(n)와 다음 노드(n->next)가 존재할 때까지 2칸씩 이동하며 반복합니다.
- 내부 로직은 두 노드의 포인터(연결)를 바꾸는 것이 아니라, 노드가 가진 '값(v)'만 서로 바꾸는(Swap) 구조입니다.

- 첫 번째 반복 (n이 n1일 때):
  * 현재 노드 n1의 값(1)과 다음 노드 n3의 값(3)을 서로 바꿉니다.
  * 변경 후: n1의 값은 3이 되고, n3의 값은 1이 됩니다.
  * 그 후 n = n->next->next에 의해 n은 n3의 다음 노드인 n2로 이동합니다.

- 두 번째 반복 시도 (n이 n2일 때):
  * 현재 노드 n2는 존재하지만, n2->next가 NULL이므로 while 조건문(n->next != NULL)을 만족하지 못하고 반복문이 종료됩니다.

3. 최종 출력 결과
- 값 교환이 완료된 후의 리스트 순서와 값은 다음과 같습니다.
  * n1의 값: 3
  * n3의 값: 1
  * n2의 값: 2
- main 함수의 출력용 반복문이 n1 -> n3 -> n2 순서대로 값을 이어 붙여 출력하므로 최종 결과는 312가 됩니다.

[문제]
제시된 Java 코드를 실행했을 때의 출력 결과를 쓰시오.

class Printer {
    void print(Integer x) {
        System.out.print("A" + x);
    }
    void print(Object x) {
        System.out.print("B" + x);
    }
    void print(Number x) {
        System.out.print("C" + x);
    }
}
class Collection<T> {
    T value;
    public Collection(T t) {
        value = t;
    }
    public void print() {
        new Printer().print(value);
    }
}
class Gamja {
    public static void main(String[] args) {
        new Collection<Integer>(0).print();
    }
}


[정답]
B0


[문제 핵심 분석 및 핵심 개념]

1. 자바의 제네릭 타입 소거 (Type Erasure)
- 자바의 제네릭은 컴파일 타임에만 타입을 체크하고, 컴파일이 완료되면 제네릭 타입(<T>)을 제거합니다.
- 제한 범위가 없는 일반적인 제네릭 클래스 'class Collection<T>'는 컴파일러에 의해 내부적으로 'T'가 가장 상위 클래스인 'Object'로 변경(소거)됩니다.
- 즉, 컴파일된 실제 Collection 클래스의 내부 코드는 다음과 같이 변환됩니다.
  
  class Collection {
      Object value; // T가 Object로 변환됨
      public Collection(Object t) {
          value = t;
      }
      public void print() {
          new Printer().print(value); // 호출 시점에 value의 컴파일 타임 타입은 Object임
      }
  }

2. 오버로딩(Overloading)의 결정 시점
- 자바에서 메서드 오버로딩은 '컴파일 시점(Compile-time)'에 매개변수의 참조 타입에 따라 어떤 메서드를 호출할지 미리 결정(정적 바인딩)합니다.
- main 함수에서 'new Collection<Integer>(0)'로 객체를 만들었더라도, Collection 클래스 내부의 print() 메서드가 컴파일될 때 'value' 변수의 타입은 이미 'Object'로 확정되어 있습니다.
- 따라서 'new Printer().print(value)' 코드는 Printer 클래스의 여러 print 메서드 중 'print(Object x)'를 호출하도록 컴파일됩니다.


[실행 과정]

1. main 함수에서 'new Collection<Integer>(0).print()'를 호출합니다.
2. Collection의 print() 메서드가 실행되는데, 이때 'value'의 컴파일 타입은 'Object'입니다.
3. 이에 따라 Printer 클래스의 'void print(Object x)' 메서드가 매칭되어 실행됩니다.
4. 'print(Object x)' 내부의 'System.out.print("B" + x);' 가 실행되며, x의 실제 값인 0이 더해져 "B0"이 출력됩니다.

[제네릭 타입 소거의 작동 방식]

1. 컴파일러의 시선 (컴파일할 때)
- 개발자가 작성한 'new Collection<Integer>(0)'를 보고, "아, main 함수에서는 Integer로 타입을 잘 맞춰서 넣었구나!" 하고 문법 검사를 끝냅니다.

2. 컴파일 이후 (실제 실행 파일이 될 때)
- 검사가 끝나면 자바 컴파일러는 제네릭 코드(<Integer>)를 전부 지워버립니다.
- 그리고 Collection 클래스 내부의 모든 'T' 자리를 자바 객체의 최상위 부모인 'Object'로 전부 바꾸어 버립니다.

3. 오버로딩 메서드 선택 시점
- 'new Printer().print(value);' 코드가 실행될 때, Collection 내부에서 바라보는 value의 명함(타입)은 이미 'Object'로 세팅되어 있습니다.
- 자바는 메서드를 고를 때 실제 들어있는 내용물(Integer 0)이 아니라, 현재 겉에 씌워져 있는 명함(Object)을 보고 매칭할 메서드를 찾습니다.
- 그래서 Printer 클래스에 있는 print(Integer x)나 print(Number x) 대신, 명함이 딱 맞아떨어지는 print(Object x)를 찾아가서 실행하게 됩니다.

[문제]
다음 설명에 맞는 테스트 커버리지 유형을 영어로 쓰시오.

① 모든 명령문을 적어도 한 번 실행되도록 조합하는 커버리지
② 각 결정문의 결과가 참/거짓을 각각 한 번 이상 갖도록 테스트하는 커버리지
③ 각 결정문 내 각 조건식의 결과가 참/거짓을 각각 한 번 이상 갖도록 테스트하는 커버리지

보기: Condition/Decision, Modified Condition/Decision, Branch, Condition, Statement


[정답]
①: Statement
②: Branch
③: Condition


[문제 핵심 분석 및 키워드 암기법]

1. ①번 분석 (구문 커버리지 / 문장 커버리지)
- 키워드: "모든 명령문", "라인(Line) 수행"
- 설명: 소스 코드의 모든 한 줄(문장)이 한 번 이상 실행되는 것을 목표로 합니다. 보기의 'Statement'가 정답입니다.

2. ②번 분석 (분기 커버리지 / 결정 커버리지) branch
- 키워드: "각 결정문의 결과가 참/거짓"
- 설명: if문 전체 조건식의 결과(전체 결과가 True가 되는 케이스, False가 되는 케이스)를 한 번 이상 실행하는 커버리지입니다. 분기점을 뜻하는 보기의 'Branch'가 정답입니다. (Decision 커버리지라고도 부르지만, 보기에는 Branch만 존재하므로 Branch가 정확한 답입니다.)

3. ③번 분석 (조건 커버리지)
- 키워드: "각 결정문 내 각 조건식의 결과가 참/거짓"
- 설명: if(A > 0 && B < 0)이 있을 때, 전체 결과와 상관없이 내부에 있는 '개별 조건식'(A > 0 조건, B < 0 조건)들이 각각 독립적으로 참/거짓을 한 번씩 가지면 만족하는 커버리지입니다. 개별 조건을 뜻하는 보기의 'Condition'이 정답입니다.


[오답 원인 파악하기]

- ②번 문항에서 '결정문'이라는 단어가 나와 보기의 Condition/Decision(조건/결정) 등을 고민하기 쉬우나, ②번은 개별 조건에 대한 언급 없이 오직 '결정문 전체의 결과'만 다루므로 분기(Branch)를 뜻합니다.
- ③번 문항에서 '결정문 내 각 조건식'이라는 표현 때문에 복합적인 의미의 Condition/Decision을 고르셨으나, 문장 전체를 보면 결국 '각 조건식의 결과'만 독립적으로 검증하는 형태이므로 순수 'Condition'에 해당합니다.


[화이트박스 테스트 커버리지 핵심 종류]

화이트박스 테스트 커버리지는 소스 코드의 구조를 얼마나 꼼꼼하게 훑었는지를 측정하는 기준입니다. 정보처리기사 시험에는 아래 5가지가 주로 출제됩니다.

1. 구문 커버리지 (Statement Coverage)
- 정의: 프로그램 내의 모든 명령문(문장)을 적어도 한 번은 실행하는 것을 목표로 하는 커버리지입니다.

2. 분기 커버리지 / 결정 커버리지 (Branch / Decision Coverage)
- 정의: 프로그램 내의 모든 조건문(if문 등)의 전체 결과가 참(True)인 경우와 거짓(False)인 경우가 각각 한 번 이상 실행되도록 하는 커버리지입니다.

3. 조건 커버리지 (Condition Coverage)
- 정의: 조건문 내부에 포함된 개별 조건식(예: A > 0, B < 0 등)이 각각 참(True)인 경우와 거짓(False)인 경우가 한 번 이상 실행되도록 하는 커버리지입니다. (전체 조건문의 결과와는 무관합니다.)

4. 조건/결정 커버리지 (Condition/Decision Coverage)
- 정의: 분기 커버리지와 조건 커버리지를 모두 만족하는 방식입니다. 즉, 전체 조건문도 참/거짓이 한 번씩 나와야 하고, 그 안의 개별 조건식들도 각각 참/거짓이 한 번씩 나오도록 조합하는 커버리지입니다.

5. 변경 조건/결정 커버리지 (Modified Condition/Decision Coverage - MC/DC)
- 정의: 각 개별 조건식이 다른 개별 조건식의 영향을 받지 않고, 독립적으로 전체 조건문의 결과에 어떻게 영향을 미치는지 검증하는 가장 까다롭고 안전한 커버리지입니다.


[시험에 나오는 관계 및 난이도 순서]
- 커버리지 달성 난이도 및 신뢰도 순서:
  구문 커버리지  <  분기(결정) 커버리지  <  조건 커버리지  <  조건/결정 커버리지  <  MC/DC

[문제]
다음에서 설명하는 공격 기법을 영어로 쓰시오.

출발지 주소를 공격 대상의 IP로 변조하여 네트워크 전체에게 ICMP Echo 패킷을 직접 브로드캐스팅(Directed Broadcasting)하여 타깃 시스템을 마비시키는 공격

보기: udp flooding, syn flooding, smurf, land attack, tear drop, ping of death


[정답]
smurf


[문제 핵심 분석 및 키워드]

- 핵심 키워드: "출발지 주소를 공격 대상의 IP로 변조(Spoofing)", "ICMP Echo 패킷", "브로드캐스팅(Broadcasting)"
- 설명: 공격자가 출발지 IP를 피해자 IP로 속인 뒤, 수많은 컴퓨터가 모여 있는 네트워크에 브로드캐스트로 핑(Ping)을 날립니다. 이를 받은 수많은 컴퓨터가 변조된 출발지 IP(피해자 컴퓨터)로 동시에 응답(Echo Reply)을 보내면서 피해자 시스템을 마비시키는 기법입니다.


[시험 필수! 보기의 다른 공격 기법들 핵심 요약]

1. syn flooding
- 특징: TCP 연결 과정인 3-Way Handshaking의 약점을 이용합니다. 공격자가 SYN 패킷만 계속 보내고, 서버가 보낸 SYN+ACK 패킷에 대해 응답(ACK)을 하지 않아 서버의 접속 대기 큐(Queue)를 가득 채워 마비시키는 공격입니다.

2. land attack
- 특징: 패킷을 보낼 때 출발지 IP 주소와 목적지 IP 주소를 '피해자의 IP 주소'로 똑같이 만들어서 보냅니다. 패킷을 받은 피해자 시스템은 자기 자신에게 계속 응답하게 되어 시스템에 과부하가 걸립니다.

3. tear drop
- 특징: IP 패킷을 쪼개서 보낼 때 사용하는 '오프셋(Offset)' 값을 고의로 겹치게 하거나 어긋나게 조작하여 보냅니다. 수신 측 시스템이 이 패킷들을 다시 재조합하는 과정에서 오류가 발생해 먹통이 되도록 만듭니다.

4. ping of death
- 특징: 허용된 일반적인 크기(65,535바이트)보다 훨씬 큰 대형 ICMP 패킷을 강제로 만들어서 보냅니다. 네트워크를 통해 이동하면서 수많은 조각으로 쪼개진 패킷들을 수신 측 시스템이 처리하고 재조합하는 과정에서 과부하가 발생하게 합니다.

5. udp flooding
- 특징: 대량의 UDP 패킷을 임의의 포트로 무차별 전송하여 수신 측 시스템이 응답 패킷(ICMP Destination Unreachable)을 보내느라 자원을 고갈시키게 만드는 공격입니다.

[문제]
다음은 URL 구조에 관한 문제이다. URL의 각 구간에 해당하는 항목을 보기에서 골라 쓰시오.

URL: foo://localhost:8080/over/there?name=ferret#nose

위 URL의 각 구간:
- (1) = foo
- (2) = localhost:8080
- (3) = /over/there
- (4) = name=ferret
- (5) = nose

[보기 설명]
- query : 서버에 전달할 추가 데이터
- path : 서버 내의 특정 자원을 가리키는 경로
- scheme : 리소스에 접근하는 방법이나 프로토콜
- authority : 사용자 정보, 호스트명, 포트 번호
- fragment : 특정 문서 내의 위치

보기: path, query, authority, fragment, scheme


[정답]
(1): scheme
(2): authority
(3): path
(4): query
(5): fragment


[문제 핵심 분석 및 구간별 정리]

제시된 URL 전체 구조는 다음과 같이 나뉩니다.
[ scheme ]://[ authority ][ path ]?[ query ]#[ fragment ]

1. (1) = foo -> [ scheme ]
- 보통 http, https, ftp 등이 들어가는 자리로 리소스에 접근하기 위한 프로토콜을 정의합니다. 문제에서는 'foo'라는 가상의 프로토콜이 쓰였습니다.

2. (2) = localhost:8080 -> [ authority ]
- 도메인 이름(호스트명)이나 IP 주소, 그리고 콜론(:) 뒤에 붙는 포트 번호(8080)까지를 묶어서 권한을 가진 주체라는 의미의 'authority'라고 부릅니다.

3. (3) = /over/there -> [ path ]
- 슬래시(/)로 구분되는 영역으로, 서버 컴퓨터 내부의 어떤 디렉터리나 파일(자원)에 접근할 것인지 경로를 나타냅니다.

4. (4) = name=ferret -> [ query ]
- 물음표(?) 뒷부분에 위치하며, 서버에 전달할 'Key=Value' 형태의 추가 파라미터(데이터)들입니다. 

5. (5) = nose -> [ fragment ]
- 샵(#) 뒷부분에 위치하며, 가져온 페이지(문서) 내부에서 특정 스크롤 위치나 앵커(ID 위치)로 바로 이동하기 위해 브라우저 안에서만 사용하는 식별자입니다.


[오답 원인 분석]
- (3)번 경로(/over/there) 자리에 보기의 다른 명칭인 fragment를 넣거나, (5)번 웹페이지 내부 위치 자리에 path를 넣는 식의 교차 혼동이 발생하기 쉽습니다. 기호 기준으로 외워두시면 명확합니다.
  * '/'로 시작하면 -> path
  * '?'로 시작하면 -> query
  * '#'로 시작하면 -> fragment

[학생] 테이블 (기본키: 학번)

학번 1002 / 이름 이영희 / 전공 소프트웨어공학
학번 NULL / 이름 박민준 / 전공 정보통신

위 '학생' 테이블은 (  ) 무결성 제약조건을 위반했다. 괄호 안에 들어갈 단어를 쓰시오.


[정답]
개체 또는 Entity 또는 개체 무결성 또는 Entity Integrity


[핵심 해설: 개체 무결성 vs 객체 무결성 차이]

1. 개체 무결성 (Entity Integrity) -> 본 문제의 정답인 이유
- 대상: 관계형 데이터베이스(RDB)의 테이블
- 규칙: "테이블의 기본키(Primary Key)는 절대로 널(Null) 값이나 중복된 값을 가질 수 없다."
- 분석: 위 문제에서 기본키인 '학번'에 NULL이 들어갔으므로, 관계형 DB 규칙인 '개체 무결성'을 위반한 것입니다.

2. 객체 무결성 (Object Integrity) -> 오답 함정 카드
- 대상: 객체지향 데이터베이스(OODB)의 객체
- 규칙: "시스템에 존재하는 모든 객체는 독립적이며, 고유한 객체 식별자(OID)를 가져야 한다."
- 분석: 자바의 Object처럼 독립된 하나의 '객체' 단위를 다룰 때 쓰는 개념입니다. 문제처럼 일반적인 DB 테이블과 기본키(PK) 구조를 다룰 때는 '객체'가 아니라 '개체' 무결성이라고 해야 맞습니다.

[문제]

괄호 안에 공통으로 들어갈 단어(영어 약자)를 적으시오.

이 단어는 공중 인터넷 망을 하나의 사설망 처럼 사용할 수 있는 기술입니다. SSL 방식과 IPSec 방식이 있는데, 공통점은 모두 암호화를 적용하는 것입니다.

SSL ( )은 6~7계층에서 소프트웨어적으로 동작하므로 별도의 장치가 필요없으며 가격이 저렴합니다.
IPSec ( )은 3계층에서 동작하며 IP 헤더를 조작해야 하므로 별도의 하드웨어 장치가 필요하나 보안성이 뛰어납니다.


[정답]
VPN


[핵심 해설: SSL VPN vs IPsec VPN 차이점 분석]

1. VPN (Virtual Private Network, 가상 사설망) 개요
- 공중 인터넷망을 터널링과 암호화 기술을 이용해 마치 전용선(사설망)처럼 안전하게 사용하는 기술입니다.

2. SSL VPN (6~7계층)
- 작동: OSI 7계층 중 전송(Transport)/응용(Application) 계층에서 소프트웨어적으로 동작합니다.
- 특징: 웹 브라우저만 있으면 별도의 하드웨어 장비나 클라이언트 프로그램 설치 없이 어디서나 쉽게 접속할 수 있어 비용이 저렴하고 간편합니다.

3. IPsec VPN (3계층)
- 작동: OSI 7계층 중 네트워크(Network) 계층에서 IP 패킷 단위로 암호화를 진행합니다.
- 특징: IP 헤더를 조작하고 전체 통신을 제어해야 하므로 별도의 VPN 전용 하드웨어 장비(게이트웨이 등)가 양 끝단에 필수로 필요합니다. 설정은 복잡하지만 네트워크 전반에 걸친 강력한 보안을 제공합니다.
