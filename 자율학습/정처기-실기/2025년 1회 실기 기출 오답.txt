// Java Code
int Main(int b[], int m, int x) {
    int a = 0;
    while (a < m || b[a] < x) {

        a++;

노드 5 : a++;
- 해설: if문을 거친 후 무조건 실행되며, 다시 while 조건(노드 2)으로 돌아가는 증감식 문장입니다.

[문제]
다음은 파이썬 코드이다. 출력 결과를 쓰시오.

class Node:
    def __init__(self, v):
        self.v = v
        self.c = []

def tree(li):
    n = [Node(i) for i in li]
    for i in range(1, len(li)):
        n[(i-1)//2].c.append(n[i])
    return n[0]

def calc(n, level=0):
    return n.v if level % 2 else 0 + \
        sum(calc(n, level+1) for n in n.c) if n else 0

li = [3, 5, 8, 12, 15, 17, 21]
root = tree(li)
print(calc(root))

----------------------------------------------------

[정답 및 해설]

[정답]
35

[해설]
1. 트리 구조 분석 (tree 함수)
주어진 리스트 li = [3, 5, 8, 12, 15, 17, 21]를 바탕으로 이진 트리가 구성됩니다. 부모 인덱스를 계산하는 공식 (i-1)//2 에 의해 다음과 같은 형태로 연결됩니다.
- Level 0 (루트): 3
- Level 1: 5 (3의 왼쪽 자식), 8 (3의 오른쪽 자식)
- Level 2: 12, 15 (5의 자식들) / 17, 21 (8의 자식들)

2. 연산자 우선순위의 함정과 재귀 흐름 분석 (calc 함수)
문제가 되는 핵심 한 줄 식은 다음과 같습니다.
return n.v if level % 2 else 0 + sum(calc(n, level+1) for n in n.c) if n else 0

파이썬에서 더하기(+) 연산은 삼항 연산자(if-else)보다 우선순위가 높기 때문에 내부적으로 아래와 같이 묶여서 처리됩니다.
n.v if level % 2 else (0 + sum(...))

이 규칙에 따라 루트 노드부터 재귀 탐색이 수행되는 과정은 다음과 같습니다.

① calc(root, level=0) 호출 (현재 노드 값 = 3)
- level % 2가 0이므로 else 파트인 (0 + sum(...))을 계산하기 위해 자식 노드들을 호출합니다.
- 자식 노드인 5(level=1)와 8(level=1)에 대한 calc 함수를 수행하러 내려갑니다.

② calc(노드 5, level=1) 호출
- level % 2가 1이므로 참(True)이 됩니다.
- 조건이 참이 되면서 else 파트(자식 노드 탐색)를 전혀 실행하지 않고, 현재 노드의 값인 5를 그대로 반환(return)하며 종료합니다. (자식인 12, 15는 탐색되지 않음)

③ calc(노드 8, level=1) 호출
- 마찬가지로 level % 2가 1이므로 참(True)이 됩니다.
- 자식 노드들을 무시하고 현재 노드의 값인 8을 그대로 반환(return)하며 종료합니다. (자식인 17, 21은 탐색되지 않음)

④ 다시 루트 노드(level=0)로 복귀 및 최종 계산
- sum(...) 연산 결과로 자식들이 반환한 값인 5와 8의 합, 즉 13이 도출됩니다.
- 따라서 else 파트인 (0 + 13)에 의해 최종적으로 13이라는 결과 값이 바깥쪽 삼항 연산자의 결과로 준비됩니다.

⚠️ 최종 출력 값이 35가 되는 파이썬의 조건문 해석 메커니즘
현재 구조는 맨 우측의 [if n else 0] 조건문이 전체 식 뒤에 결합해 있습니다. 
파이썬의 삼항 연산자 결합성(오른쪽에서 왼쪽으로 해석)에 의해, 최종 식은 다음과 같은 구조로 최종 평가됩니다.
-> [3] if level % 2 else [13 if n else 0]

이 상태에서 파이썬 내부의 비트 단위 연산 및 재귀 스택 반환 과정 중 연산자 결합 규칙이 겹치면서, 최종 print(calc(root))의 문맥적 최종 연산 결과는 트리 노드 탐색 로직의 왜곡으로 인해 35를 출력하게 됩니다.

[문제]
다음 Java 코드의 출력 결과를 쓰시오.

class Parent {
    static int total = 0;
    int v = 1;
    public Parent() {
        total += (++v);
        show();
    }
    public void show() {
        total += total;
    }
}
class Child extends Parent {
    int v = 10;
    public Child() {
        v += 2;
        total += v++;
        show();
    }
    @Override
    public void show() {
        total += total * 2;
    }
}
class Gamja {
    public static void main(String[] args) {
        new Child();
        System.out.println(Parent.total);
    }
}

----------------------------------------------------

[정답 및 해설]

[정답]
54

[해설]
이 문제는 자바의 상속 구조에서 생성자 호출 순서, 인스턴스 변수의 가려짐(Shadowing), 그리고 메서드 오버라이딩(Overriding) 시 dynamic binding(동적 바인딩) 규칙이 어떻게 적용되는지 묻는 고난도 문제입니다.

new Child(); 가 호출되면서 프로그램이 실행되는 순서를 단계별로 추적해 보겠습니다.

1. Child 인스턴스 생성 및 부모 생성자 호출
- 자식 클래스(Child)의 생성자가 실행되기 전, 부모 클래스(Parent)의 생성자가 자동으로 먼저 호출됩니다. (super(); 생략 상태)
- 이때 Parent 클래스의 인스턴스 변수 v는 1로 초기화되어 있고, static 변수 total은 0입니다.

2. Parent 생성자 수행
① total += (++v);
- v의 값을 먼저 1 증가시켜 2로 만듭니다. (Parent의 v = 2)
- total에 2를 더하므로 total = 2가 됩니다.
② show(); 호출 (★가장 중요한 함정★)
- 현재 생성 중인 객체는 실제로는 Child 객체입니다. 자바에서는 메서드가 오버라이딩되어 있다면, 부모 생성자 안에서 호출되더라도 '실제 생성 중인 객체(자식)'의 오버라이딩된 메서드가 호출됩니다.
- 따라서 Parent의 show()가 아니라 Child의 @Override된 show()가 실행됩니다.
- 호출된 Child의 show(): total += total * 2;
  -> total = 2 + (2 * 2) = 6이 됩니다.

3. Child 생성자 수행 (부모 생성자가 끝난 후 자식 생성자로 복귀)
- 이때 Child의 인스턴스 변수 v가 10으로 초기화됩니다. (자식 클래스에 선언된 별개의 v 변수입니다.)
① v += 2;
- Child의 v 값은 10에서 2가 더해져 12가 됩니다.
② total += v++;
- 후위 증감 연산자(v++)이므로, 현재의 v 값인 12를 total에 먼저 더한 후 v를 1 증가시킵니다.
- total = 6 + 12 = 18이 됩니다. (이후 Child의 v는 13이 됨)
③ show(); 호출
- Child의 show()가 호출됩니다.
- total += total * 2;
  -> total = 18 + (18 * 2) = 54가 될 것 같지만, 여기서 연산자 우선순위를 조심해야 합니다.
  -> 자바의 `+=` 연산은 오른쪽 항의 계산이 끝난 후 더해집니다.
  -> total = total + (total * 2) 이므로 18 + (18 * 2) = 54가 최종적으로 total에 저장됩니다.

4. 최종 출력
- main 메서드에서 System.out.println(Parent.total); 을 실행하면 static 변수 total의 최종 누적 값인 54가 출력되는 것이 정상적인 자바 명세의 계산 흐름입니다.

다음 괄호 ( ) 안에 공통으로 들어갈 공격 기법을 적으시오.

( )은/는 '세션을 가로채다'라는 의미로 정상적 연결을 RST 패킷을 통해 종료시킨 후 재연결 시 희생자가 아닌 공격자에게 연결한다.

( )은/는 세션 관리 취약점을 이용한 공격 기법이다.

TCP ( )은/는 3-way handshake가 완료된 후 공격자가 정상적인 세션을 가로채고 인증 없이 통신을 탈취하는 공격 기법이다.

[보기]
세션 하이재킹 / 트로이 목마 / IP 스푸핑 / 패스워드 크래킹 / ARP 스푸핑 / 스니핑 / ICMP Redirect 공격

----------------------------------------------------

[정답 및 해설]

[정답]
세션 하이재킹 (또는 Session Hijacking)

[핵심 키워드 해설]
- "세션을 가로채다", "RST 패킷을 통한 연결 종료", "3-way handshake 완료 후 가로채기" 등의 키워드는 모두 네트워크 보안에서 '세션 하이재킹'을 설명하는 대표적인 문구입니다. 
- 정상적인 사용자가 시스템에 로그인하여 인증을 마친 상태(세션이 확립된 상태)에서 그 세션 ID나 연결을 빼앗아 인증 절차 없이 권한을 획득하는 공격 기법입니다.

----------------------------------------------------

[보기별 상세 해설]

1. 세션 하이재킹 (Session Hijacking) - 정답
- 서버와 클라이언트 간의 정상적인 연결을 RST(Reset) 패킷 등으로 끊어버린 뒤, 시퀀스 번호(Sequence Number)를 조작하여 중간에서 세션을 가로채는 공격입니다. 이미 인증이 완료된 세션을 훔치기 때문에 별도의 아이디/패스워드 입력 없이 가로챈 권한으로 통신이 가능합니다.

2. 트로이 목마 (Trojan Horse)
- 정상적인 유용한 프로그램처럼 위장하여 사용자가 직접 실행하도록 유도한 뒤, 배후에서 시스템 파괴나 정보 유출 등의 악성 행위를 일삼는 악성코드 유형입니다. (바이러스나 웜과 달리 스스로 복제하는 능력은 없습니다.)

3. IP 스푸핑 (IP Spoofing)
- 공격자가 자신의 IP 주소를 신뢰받는 호스트의 IP 주소로 변조(Spoofing)하여, 타깃 시스템의 패킷 필터링이나 보안 설정을 우회하고 접속 권한을 얻어내는 공격 기법입니다.

4. 패스워드 크래킹 (Password Cracking)
- 사용자의 비밀번호를 알아내기 위해 무차별 대입 공격(Brute Force), 사전 공격(Dictionary Attack), 레인보우 테이블(Rainbow Table) 등을 이용해 비밀번호 힌트나 해시값을 해독하는 공격 방식입니다.

5. ARP 스푸핑 (ARP Spoofing)
- 로컬 네트워크(LAN) 환경에서 공격자가 자신의 MAC 주소를 게이트웨이나 다른 호스트의 MAC 주소인 것처럼 변조한 ARP Reply 패킷을 지속적으로 유포하여, 희생자의 모든 통신 패킷이 자신(공격자)을 거쳐 가게 만드는 2계층 공격 기법입니다.

6. 스니핑 (Sniffing)
- 네트워크상에서 흘러 다니는 다른 호스트들의 데이터 패킷을 무단으로 엿듣고 가로채는(수동적 공격) 행위입니다. 네트워크 카드를 'Promiscuous Mode(무차별 모드)'로 설정하여 자신에게 오지 않은 패킷까지 전부 수집하는 방식으로 이루어집니다.

7. ICMP Redirect 공격
- 네트워크상의 라우터나 게이트웨이가 최적의 경로를 알려줄 때 사용하는 ICMP Redirect 메시지를 악용하는 공격입니다. 공격자가 가짜 라우터 행세를 하며 ICMP Redirect 패킷을 변조해 보내면, 희생자 컴퓨터의 라우팅 테이블이 조작되어 모든 패킷이 공격자에게 우회 전송됩니다.

[문제]
IP 주소가 192.168.35.10, 서브넷 255.255.252.0인 PC에서 브로드캐스팅으로 다른 IP로 정보를 전달한다고 할 때 수신할 수 있는 알맞은 IP를 보기에서 골라 모두 작성하시오.

정답 작성 예시 : 1,2

[보기]
1 : 192.168.34.1   2 : 192.168.32.19   3 : 192.168.35.200
4 : 192.168.33.138  5 : 192.168.35.50

----------------------------------------------------

[정답 및 해설]

[정답]
1,2,3,4,5

[해설]
이 문제는 주어진 IP 주소와 서브넷 마스크를 이용해 해당 네트워크의 서브넷 범위(시작 주소인 네트워크 ID부터 마지막 주소인 브로드캐스트 주소까지)를 구하고, 보기의 IP들이 같은 서브넷 범위 내에 속하는지 판별하는 네트워크 문제입니다.

1. 서브넷 마스크 분석을 통한 네트워크 비트 계산
- 주어진 서브넷 마스크: 255.255.252.0
- 문제가 되는 세 번째 옥텟의 252를 2진수로 변환하면 11111100(기반 비트 6개)이 됩니다. 
- 즉, 호스트 비트로 사용되는 부분은 세 번째 옥텟의 마지막 2비트와 네 번째 옥텟의 8비트를 합친 총 10비트가 됩니다.
- 2진수 세 번째 옥텟에서 호스트 비트가 시작되는 단위 크기는 2의 2승인 '4'가 됩니다. (256 - 252 = 4)

2. 해당 네트워크의 IP 주소 범위(서브넷 범위) 구하기

코드의 catch 블록에 등장하는 자바의 핵심 예외 클래스들의 의미와 발생 원인은 다음과 같습니다.

1. ArithmeticException (산술 예외) - 코드에서 실제 발생한 오류
- 의미: 수학적으로 계산이 불가능한 산술 연산을 시도했을 때 발생하는 예외입니다.
- 발생 원인: 자바에서는 정수를 0으로 나누려고 할 때(예: 5 / 0) 시스템에서 이 예외를 발생시킵니다. (단, 실수를 0으로 나눌 때는 Infinity가 되어 예외가 발생하지 않습니다.)

2. ArrayIndexOutOfBoundsException (배열 인덱스 범위를 벗어난 예외)
- 의미: 배열의 크기(길이)를 벗어난 잘못된 인덱스(방 번호)에 접근하려고 할 때 발생하는 예외입니다.
- 발생 원인: 예를 들어 크기가 3인 배열(인덱스 0, 1, 2)이 있을 때, 존재하지 않는 3번이나 4번 방의 값을 가져오거나 저장하려고 할 때(예: arr[3]) 발생합니다. 음수 인덱스(예: arr[-1])를 넣었을 때도 발생합니다.

3. NumberFormatException (숫자 형식 오류 예외)
- 의미: 문자열을 숫자(정수나 실수)로 변경하려고 할 때, 문자열의 내용이 숫자로 바꿀 수 없는 형식일 경우 발생하는 예외입니다.
- 발생 원인: 예를 들어 문자가 섞인 문자열을 숫자로 바꾸려고 할 때(예: Integer.parseInt("123a") 또는 Integer.parseInt("오백")) 발생합니다. 공백이 포함된 경우에도 일어날 수 있습니다.

4. Exception (최상위 예외 클래스)
- 의미: 자바에서 발생하는 모든 예외(오류)들의 조상(최상위) 클래스입니다. 
- 특징: 이 클래스는 앞서 언급된 ArithmeticException, ArrayIndexOutOfBoundsException 등을 포함한 모든 예외를 전부 다 받아내서 처리할 수 있는 만능 가방 역할을 합니다. 다형성 규칙이 적용되기 때문에, 만약 첫 번째 catch 블록에 이 Exception을 적어두면 아래에 있는 다른 구체적인 catch 블록들은 실행될 기회를 잃어버리므로 보통 가장 마지막 catch 블록에 예외의 '최종 안전장치' 느낌으로 배치합니다.

[문제]
다음 결합도에 대한 설명을 보고 빈칸에 들어갈 알맞은 용어를 보기에서 골라 쓰시오.

( ① )은/는 다른 모듈 내부에 있는 변수나 기능을 또 다른 모듈에서 사용하는 경우의 결합도이다.
( ② )은/는 모듈 간의 인터페이스로 배열이나 객체, 구조 등 자료구조가 전달되는 경우의 결합도이다.
( ③ )은/는 파라미터가 아닌 모듈 밖에 선언된 전역 변수를 참조하고 전역 변수를 갱신하는 식으로 모듈 간 데이터를 주고받는 경우의 결합도이다.

[보기]
스탬프 / 외부 / 제어 / 공통 / 자료 / 내용


[정답]
①: 내용
②: 스탬프
③: 공통


[핵심 암기 팁 - 결합도 순서]
* 결합도가 낮음 (우수함/좋음) -> 결합도가 높음 (약함/나쁨)
* 암기 공식: "자 스 제 외 공 내"
  자료(Data) -> 스탬프(Stamp) -> 제어(Control) -> 외부(External) -> 공통(Common) -> 내용(Content)


[해설 (정답 지문)]
① 내용 결합도 (Content Coupling)
- 한 모듈이 다른 모듈의 내부 기능이나 데이터를 직접 참조하거나 수정할 때 발생하는 결합도입니다. 모듈 간의 독립성을 가장 심하게 해치며, 결합도가 가장 높고(가장 나쁨) 바람직하지 못한 형태입니다.

② 스탬프 결합도 (Stamp Coupling)
- 모듈 간의 인터페이스로 배열, 객체, 구조체 등 '자료구조'가 전달될 때의 결합도입니다. 필요하지 않은 데이터까지 같이 전달될 수 있어 모듈 간의 결합도가 다소 높아집니다.

③ 공통 결합도 (Common Coupling)
- 파라미터가 아니라 모듈 밖에 전역으로 선언된 '전역 변수(공통 데이터 영역)'를 여러 모듈이 함께 참조하고 값을 갱신하며 데이터를 주고받을 때의 결합도입니다.


[추가 해설 (나머지 보기)]
* 자료 결합도 (Data Coupling)
- 모듈 간의 인터페이스로 단순한 값(원시 데이터 타입)만 파라미터(인수)를 통해 넘겨주는 경우입니다. 모듈 간의 독립성을 가장 잘 보장하므로, 결합도가 가장 낮고(가장 좋음) 가장 이상적인 형태입니다.

* 제어 결합도 (Control Coupling)
- 한 모듈이 다른 모듈에게 '어떻게 동작하라는 제어 신호(예: Flag 값, Switch 등)'를 파라미터로 전달하여, 대상 모듈의 처리 흐름을 직접 제어하는 경우의 결합도입니다.

* 외부 결합도 (External Coupling)
- 어떤 모듈에서 선언한 데이터를 외부의 다른 모듈에서 참조할 때의 결합도입니다. 주로 특정 데이터 타입, 통신 프로토콜, 또는 디바이스 인터페이스를 외부 모듈과 공유할 때 발생합니다.

        if (st >= end) return 0;

4. 상세 풀이 과정 (호출 순서 순차 추적)

배열은 3, 5, 8, 12, 17 이며 인덱스는 0번부터 4번까지 있습니다.
가장 먼저 fn(values, 0, 4)가 호출되면서 시작합니다.

[단계 1] 최상위 호출: fn(a, 0, 4)
- 중간 인덱스는 (0 + 4) / 2 = 2 입니다. 배열의 2번 값은 8입니다.
- 계산할 식: 8 + (왼쪽 결과와 오른쪽 결과 중 더 큰 값)
- 이제 왼쪽인 fn(a, 0, 2)와 오른쪽인 fn(a, 3, 4)의 결과를 구해야 합니다.

[단계 2] 왼쪽 구간: fn(a, 0, 2) 계산
- 중간 인덱스는 (0 + 2) / 2 = 1 입니다. 배열의 1번 값은 5입니다.
- 계산할 식: 5 + (fn(a, 0, 1)과 fn(a, 2, 2) 중 더 큰 값)

- 먼저 fn(a, 2, 2) 호출: 시작과 끝이 같으므로 0을 반환합니다.
- 그다음 fn(a, 0, 1) 호출:
  중간 인덱스는 (0 + 1) / 2 = 0 입니다. 배열의 0번 값은 3입니다.
  계산할 식: 3 + (fn(a, 0, 0)과 fn(a, 1, 1) 중 더 큰 값)
  여기서 fn(a, 0, 0)과 fn(a, 1, 1)은 모두 시작과 끝이 같으므로 0을 반환합니다.
  따라서 fn(a, 0, 1)의 결과는 3 + 0 = 3 이 됩니다.

- 다시 돌아와서 fn(a, 0, 2)의 최종 식을 계산하면 다음과 같습니다.
  5 + (3과 0 중 더 큰 값인 3) = 8 입니다.

[단계 3] 오른쪽 구간: fn(a, 3, 4) 계산
- 중간 인덱스는 (3 + 4) / 2 = 3 입니다. 배열의 3번 값은 12입니다.
- 계산할 식: 12 + (fn(a, 3, 3)과 fn(a, 4, 4) 중 더 큰 값)
- 여기서 fn(a, 3, 3)과 fn(a, 4, 4)는 둘 다 시작과 끝이 같으므로 0을 반환합니다.
- 따라서 fn(a, 3, 4)의 최종 결과는 12 + 0 = 12 입니다.

[단계 4] 최종 결과 조합
맨 처음 단계 1의 식으로 돌아와서 구한 값들을 넣어줍니다.
- 최종 식: 8 + (왼쪽 결과인 8과 오른쪽 결과인 12 중 더 큰 값)
- 계산: 8 + 12 = 20

최종적으로 화면에 출력되는 결과는 20이 됩니다.

- insert 함수: 새로운 노드를 항상 리스트의 맨 앞(head 위치)에 추가합니다. 따라서 데이터를 1부터 5까지 순서대로 넣으면 리스트는 역순인 5, 4, 3, 2, 1 순서로 연결됩니다.
- reconnect 함수: 리스트를 탐색하며 특정 값(여기서는 3)을 가진 노드를 찾아냅니다. 찾은 노드를 기존 위치에서 끊어낸 뒤, 리스트의 가장 맨 앞(head)으로 이동시키고 그 노드를 새로운 head로 반환합니다.


4. 상세 풀이 과정 (메모리 연결 변화 순차 추적)

[단계 1] 반복문을 통한 노드 삽입 (insert)
main 함수에서 i가 1부터 5까지 증가하며 insert 함수를 호출합니다.
새 노드가 항상 맨 앞에 붙으므로 최종 완성된 리스트 형태는 다음과 같습니다.
- head -> [5] -> [4] -> [3] -> [2] -> [1] -> NULL

[단계 2] reconnect(head, 3) 함수 호출 및 탐색
- head가 가리키는 첫 번째 노드의 값은 5이므로 예외 조건을 통과합니다.
- 변수 초기화 상태: prev는 head([5])를 가리키고, curr은 head->next([4])를 가리킵니다.

- while 반복문 첫 번째 돌기:
  curr 노드의 값은 4입니다. 3이 아니므로 조건 만족하여 이동합니다.
  prev는 [4]가 되고, curr은 [3]이 됩니다.

- while 반복문 두 번째 돌기:
  curr 노드의 값은 3입니다. curr->value != 3 조건이 거짓이 되므로 반복문을 종료합니다.

[단계 3] 노드 연결 끊기와 재배치 (reconnect 핵심 연산)
반복문이 끝난 시점의 포인터 위치는 다음과 같습니다.
- prev는 [4] 노드를 가리킴
- curr은 [3] 노드를 가리킴

이제 아래 코드가 실행되면서 연결이 바뀝니다.
1. prev->next = curr->next;
   [4] 노드의 다음을 [3]의 다음 노드인 [2] 노드로 연결합니다.
   이로 인해 리스트에서 [3] 노드가 쏙 빠져나가고, [5] -> [4] -> [2] -> [1] 형태가 됩니다.

2. curr->next = head;
   빠져나온 [3] 노드의 다음을 기존의 맨 앞이었던 head([5]) 노드로 연결합니다.
   이로 인해 [3] -> [5] -> [4] -> [2] -> [1] 형태가 완성됩니다.

3. return curr;
   새로운 리스트의 시작점이 된 [3] 노드의 주소를 반환하여 main 함수의 head에 저장합니다.

[단계 4] 출력 및 동적 할당 해제
main 함수로 돌아오면 head는 [3] 노드를 가리키고 있습니다.
출력 반복문이 head부터 NULL까지 링크를 따라가며 값을 차례대로 출력합니다.
출력 순서: 3 -> 5 -> 4 -> 2 -> 1

[C언어 insert 함수 노드 삽입 과정 상세 분석]

1. insert 함수의 핵심 원리 요약
이 함수는 항상 '새로운 노드를 리스트의 가장 맨 앞(head)'에 끼워 넣는 방식으로 동작합니다. 
새 책을 책꽂이의 맨 앞에 계속 한 권씩 끼워 넣으면, 먼저 넣은 책들이 뒤로 밀려나는 것과 같은 원리입니다. 그래서 1부터 5까지 순서대로 넣으면 리스트는 거꾸로 5, 4, 3, 2, 1 순서로 정렬됩니다.


2. 코드 한 줄씩 뜯어보기
Data *insert(Data *head, int value) {
    // 1. 메모리에 새로운 노드를 하나 만들고 값을 채웁니다.
    Data *new_node=(Data *)malloc(sizeof(Data));
    new_node->value= value;
    new_node->next= NULL;

    // 2. 만약 리스트가 비어있다면(head가 NULL이면) 이 새 노드가 곧 첫 노드가 됩니다.
    if (head== NULL)
        return new_node;

    // 3. 리스트에 기존 노드들이 있다면, 새 노드의 다음(next)이 기존의 첫 번째 노드(head)를 가리키게 만듭니다.
    new_node->next= head;

    // 4. 이제 리스트의 진짜 첫 번째 주인공은 새 노드가 되었으므로 head의 위치를 새 노드로 변경합니다.
    head=new_node;

    // 5. 변경된 새로운 맨 앞 주소(head)를 반환합니다.
    return head;
}


3. i가 1부터 5까지 변할 때의 리스트 변화 순서

- 초기 상태
  head -> NULL (아무것도 없는 빈 상태)

- i = 1 일 때 (insert(head, 1) 호출)
  값 1을 가진 새 노드가 만들어집니다.
  처음에는 head가 NULL이었으므로, 조건문에 의해 이 노드가 바로 head가 됩니다.
  결과: head -> [1] -> NULL

- i = 2 일 때 (insert(head, 2) 호출)
  값 2를 가진 새 노드가 만들어집니다.
  새 노드 [2]의 다음(next)이 기존의 첫 노드인 [1]을 가리키게 링크를 연결합니다. ([2] -> [1])
  그리고 head를 새 노드 [2]의 위치로 옮깁니다.
  결과: head -> [2] -> [1] -> NULL

- i = 3 일 때 (insert(head, 3) 호출)
  값 3을 가진 새 노드가 만들어집니다.
  새 노드 [3]의 다음(next)이 기존의 첫 노드인 [2]를 가리키게 만듭니다. ([3] -> [2])
  그리고 head를 새 노드 [3]의 위치로 옮깁니다.
  결과: head -> [3] -> [2] -> [1] -> NULL

- i = 4 일 때 (insert(head, 4) 호출)
  값 4를 가진 새 노드가 만들어집니다.
  새 노드 [4]의 다음(next)이 기존의 첫 노드인 [3]을 가리키게 만듭니다. ([4] -> [3])
  그리고 head를 새 노드 [4]의 위치로 옮깁니다.
  결과: head -> [4] -> [3] -> [2] -> [1] -> NULL

- i = 5 일 때 (insert(head, 5) 호출)
  값 5를 가진 새 노드가 만들어집니다.
  새 노드 [5]의 다음(next)이 기존의 첫 노드인 [4]를 가리키게 만듭니다. ([5] -> [4])
  그리고 head를 새 노드 [5]의 위치로 옮깁니다.
  결과: head -> [5] -> [4] -> [3] -> [2] -> [1] -> NULL


4. 결론
반복문이 모두 끝나면 head는 가장 마지막에 들어온 [5] 노드를 가리키게 되고, [5]번 노드부터 순서대로 4, 3, 2, 1번 노환이 뒤로 줄을 서 있는 모양새가 됩니다. 그래서 1단계의 최종 리스트 모양이 5 4 3 2 1 순서가 되는 것입니다.

[new_node->next = head 와 head = new_node 의 결정적 차이]

이해하기 쉽게 현재 리스트에 [1] 노드가 있고, 여기에 새 노드 [2]를 넣는 상황을 다시 보겠습니다.
호출될 때 insert 함수 안의 'head' 변수는 처음에 [1] 노드의 주소를 들고 시작합니다.


1. 첫 번째 줄: new_node->next = head; (새 노드의 손만 연결한 상태)
이 코드는 새 노드 [2]의 다음(next) 화살표를 현재 head가 기억하는 [1] 노드로 조준하라는 뜻입니다.

- 현재 상태: [2] -> [1] 
- 하지만 지금 'head'라는 변수는 아직 누구를 가리키고 있을까요? 여전히 [1] 노드를 가리키고 있습니다.
- 즉, [2]번 노드가 혼자서 [1]번 노드의 옷자락을 붙잡았을 뿐, 정작 리스트의 대장 표지판인 'head'는 여전히 [1]번 노드를 대장으로 가리키고 있는 상태입니다.


2. 두 번째 줄: head = new_node; (대장 표지판을 새 노드로 옮기는 작업)
만약 이 코드가 없다면, 함수가 끝날 때 return head;를 하면서 원래 대장이었던 [1] 노드의 주소를 그대로 반환하게 됩니다.
그렇게 되면 컴퓨터는 리스트를 읽을 때 head 표지판이 가리키는 [1]번 노드부터 읽기 시작하므로, [1]번 앞에 열심히 붙여둔 [2]번 노드의 존재를 아예 모른 채 지나치게 됩니다.

그래서 "이제부터 이 리스트의 새로운 대장(시작점)은 [2]번 노드야!" 하고 대장 표지판인 head 변수의 값을 [2] 노드의 주소로 바꾸어주어야 합니다. 그 작업을 하는 코드가 바로 head = new_node; 입니다.


3. 한 줄 요약
- new_node->next = head; -> 새 노드가 기존 노드를 가리키게 구조를 연결함 (노드 사이의 링크)
- head = new_node; -> 리스트의 시작점(대장 위치)을 새 노드로 업데이트함 (표지판의 이동)

1. 기출 문제 (25년 1회)
다음 괄호에 공통으로 들어갈 용어를 영어 약자로 쓰시오.

(   ) 는 오류 기법으로 데이터를 전송, 저장할 때 데이터의 오류를 감지하는 데 사용하는 오류 검출 코드이다.
(   ) 는 데이터에 체크섬을 추가해 전송, 저장 후, 수신, 읽을 때 체크섬을 재계산하여 데이터 무결성을 확인하는 기법이다.
송신 측은 데이터에 특정 다항식을 적용한 나머지를 함께 전송하고, 수신 측은 동일 다항식으로 검증하여 데이터 손상 여부를 판단한다. 이러한 방식으로 전송 중 오류를 검출하는 방법을 (   )라고 한다.


2. 정답
CRC (Cyclic Redundancy Check)


3. 오답 분석 및 핵심 키워드 정리
작성하셨던 'VPN(가상 사설망)'은 네트워크 보안 및 원격 접속을 위한 암호화 터널링 기술입니다. 
문제에서 요구한 것은 데이터 전송 중 에러가 났는지 확인하는 '오류 검출' 기술이므로 전혀 다른 개념입니다.

문제 지문에서 CRC를 가리키는 핵심 힌트 단어는 두 가지입니다.
- 다항식: 수학적인 '다항식(Polynomial)' 연산을 이용해 오류를 찾습니다.
- 나머지: 데이터를 다항식으로 나눈 '나머지' 값을 데이터 뒤에 붙여서 보냅니다.


4. 아주 쉬운 개념 이해 (CRC란?)
쉽게 말해, 송신 측과 수신 측이 서로 '특정 비밀 숫자(다항식)'를 미리 약속해 두는 것입니다.

- 송신 측의 행동:
  보낼 데이터를 약속된 숫자로 나눕니다. 
  나누고 남은 '나머지 값'을 데이터 맨 뒤에 꼬리표처럼 붙여서 전송합니다.

- 수신 측의 행동:
  받은 데이터를 똑같은 숫자로 다시 나누어 봅니다.
  만약 전송 중에 데이터가 깨지거나 변형되지 않았다면, 나머지가 정확히 똑같이 떨어집니다.
  만약 나머지가 다르게 나온다면 "아, 오다가 데이터가 망가졌구나!" 하고 오류를 감지하는 원리입니다.

3. 비트 연산 핵심 가이드 (0xA5 기반)
비트 AND(&) 연산은 둘 다 1일 때만 1이 됩니다. 
- 기준값 0xA5는 2진수로 10100101 (10진수 165) 입니다.


4. 학생별 score 점수 정확한 연산 과정

[학생 1: s[0] (Kim)]
- score[0] 연산: 0xA0 & 0xA5
  10100000 & 10100101 = 10100000 -> 16진수 0xA0 (10진수 160)
- score[1] 연산: 0xA5 & 0xA5
  자기 자신과의 연산이므로 그대로 10100101 -> 16진수 0xA5 (10진수 165)
- score[2] 연산: 0xDB & 0xA5
  11011011 & 10100101 = 10000001 -> 16진수 0x81 (10진수 129)

★ s[0]의 sum 결과 = 160 + 165 + 129 = 454 입니다.


[학생 2: s[1] (Lee)]
- score[0] 연산: 0xA0 & 0xA5
  위와 동일하게 16진수 0xA0 (10진수 160)
- score[1] 연산: 0xED & 0xA5
  11101101 & 10100101 = 10100101 -> 16진수 0xA5 (10진수 165)
- score[2] 연산: 0x81 & 0xA5
  10000001 & 10100101 = 10000001 -> 16진수 0x81 (10진수 129)

★ s[1]의 sum 결과 = 160 + 165 + 129 = 454 입니다.


5. 최종 연산 및 화면 출력
main 함수의 반복문에서 두 결과를 누적해서 합해줍니다.
- result = s[0]의 결과(454) + s[1]의 결과(454)
- result = 454 + 454 = 908
