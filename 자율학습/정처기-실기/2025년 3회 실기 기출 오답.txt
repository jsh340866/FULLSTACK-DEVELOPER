[문제]
다음 SQL의 실행 결과를 쓰시오.

[A] 테이블
NO  NAME
1   SMITH
2   ALLEN
3   SCOTT

[B] 테이블
RNO  RULE
1    S%
2    %T%

SQL 문:
SELECT COUNT(*) FROM A CROSS JOIN B WHERE A.NAME LIKE B.RULE;

정답: 4

[해설]

1. 교차 조인 처리
CROSS JOIN은 두 테이블의 모든 행을 서로 곱해 모든 조합을 만듭니다. A 테이블 3행과 B 테이블 2행이 결합하여 총 6개의 조합이 생깁니다.
2. WHERE 조건 비교
B 테이블의 두 가지 규칙을 각 이름에 대입해 조건에 맞는 항목을 찾습니다.

첫 번째 규칙인 S%는 S로 시작하는 이름을 의미합니다. 이에 해당하는 이름은 SMITH와 SCOTT으로 총 2개입니다.

두 번째 규칙인 %T%는 글자 위치 상관없이 T를 포함하는 이름을 의미합니다. 이에 해당하는 이름은 SMITH와 SCOTT으로 총 2개입니다.

3. 최종 결과 계산
조건에 부합하는 총 조합의 수가 4개이므로, 행의 개수를 구하는 COUNT(*)의 결과는 4가 됩니다.

OTP, JWT, OAuth, Kerberos, SSO

방금 질문하셨던 SSO와 OAuth의 차이점이 고스란히 담긴 문제입니다! 오답으로 SSO를 고르기 아주 쉬운 문제 유형이에요.

문제 문장들을 보면 핵심 키워드가 숨어 있습니다. '비밀번호를 제공하지 않고 접근 권한을 부여', '개방형 표준기술', '토큰을 이용'이라는 표현이 나옵니다.

방금 정리해 드렸듯이, 자신의 비밀번호를 노출하지 않은 채 외부 사이트의 권한이나 토큰을 빌려와 신원을 증명하고 로그인하게 해주는 개방형 표준 프로토콜은 바로 OAuth입니다.

[나머지 보기 용어 정리]

1. SSO (Single Sign-On)
한 번의 인증(로그인)으로 연동된 여러 독립적인 시스템을 추가 로그인 없이 모두 이용할 수 있게 해주는 통합 로그인 기술입니다.
2. JWT (JSON Web Token)
당사자 간에 정보를 JSON 객체 형태로 안전하게 전송하기 위한 개방형 표준 토큰 형식입니다. 인증이나 정보 전달에 주로 사용되며, 토큰 자체에 정보가 암호화되어 포함되어 있다는 특징이 있습니다.
3. OTP (One-Time Password)
로그인할 때마다 매번 무작위로 생성되는 일회용 비밀번호 기술입니다. 고정된 비밀번호의 취약점을 보완하기 위해 금융 거래나 2차 인증용으로 널리 쓰입니다.
4. Kerberos (커베로스)
개방된 컴퓨터 네트워크 내에서 서비스 요청에 대해 대칭키 암호화 기법을 바탕으로 사용자 신원을 검증하는 컴퓨터 네트워크 인증 프로토콜입니다. 주로 티켓 기반 시스템을 활용하여 클라이언트와 서버 간의 안전한 상호 인증을 제공합니다.

[문제]
다음 Java 코드의 실행 결과를 작성하세요.

코드:
enum Tri {
AB("A"), A("AB"), C("ABC");

```
private String code;

Tri(String code) {
    this.code = code;
}

public String code() {
    return code;
}

```

}
public static void main(String[] args) {
Tri t = Tri.values()[Tri.A.name().length()];
System.out.print(t.code());
}

정답: AB

[해설]
이 문제는 열거형(enum)의 선언 순서에 따른 인덱스 위치(배열 구조)와 내부 메서드를 정확히 매칭할 수 있는지 묻는 함정 문제입니다. 순서대로 쪼개서 보면 쉽게 풀립니다.

1. Tri.values() 배열 확인하기
values() 메서드는 열거형에 선언된 상수들을 순서대로 배열로 반환합니다. 인덱스는 0번부터 시작합니다.

* 인덱스 0: AB
* 인덱스 1: A
* 인덱스 2: C

2. 대괄호 안의 인덱스 식 계산하기: Tri.A.name().length()

* Tri.A.name()은 열거형 상수 'A'의 이름 자체를 문자열로 가져옵니다. 즉, 문자열 "A"가 됩니다.
* 뒤에 붙은 .length()는 문자열의 길이를 구하는 메서드입니다. 문자열 "A"는 1글자이므로 결과는 1이 됩니다.

3. 배열에서 값 추출하기
대괄호 안의 숫자가 1이 되었으므로, 식은 Tri.values()[1]이 됩니다.
위의 1번 단계에서 정리한 인덱스 1번에 위치한 상수는 바로 'A'입니다. 따라서 변수 t에는 Tri.A 상수가 저장됩니다.
4. t.code() 출력하기
마지막으로 Tri.A 상수가 가진 code() 메서드를 호출합니다.
상수 선언부를 보면 A("AB") 형태로 정의되어 있습니다. 즉, 상수 A의 내부 변수 code에 저장된 값은 문자열 "AB"입니다.
따라서 System.out.print(t.code())의 실행 결과는 AB가 출력됩니다.


Java의 열거형(enum)은 단순한 상수의 모음이 아니라 일종의 특수한 클래스이기 때문에, 개발 편의를 위한 유용한 내장 메서드들을 기본적으로 가지고 있습니다. 자주 쓰이는 핵심 메서드들을 정리해 드릴게요.

[1. values()]

* 기능: 열거형에 선언된 모든 상수를 선언된 순서대로 배열에 담아 반환합니다.
* 특징: 컴파일러가 자동으로 추가해 주는 메서드입니다. 전체 상수를 순회(반복문)할 때 가장 많이 사용됩니다.
* 예시: Tri.values()를 하면 [AB, A, C] 형태의 배열이 반환됩니다.

[2. name()]

* 기능: 열거형 상수가 선언된 이름 그대로를 문자열(String)로 반환합니다.
* 특징: 방금 문제에서 사용된 메서드입니다. 상수의 이름과 똑같은 문자열이 필요할 때 씁니다.
* 예시: Tri.A.name()의 결과는 문자열 "A"입니다.

[3. ordinal()]

* 기능: 열거형 상수가 정의된 순서 위치(0부터 시작하는 인덱스 번호)를 정수로 반환합니다.
* 특징: 선언된 순서에 의존하기 때문에 코드 순서가 바뀌면 이 값도 바뀌므로, 실제 비즈니스 로직에서는 버그를 유발할 수 있어 가급적 사용을 권장하지 않습니다.
* 예시: Tri.AB.ordinal()은 0, Tri.C.ordinal()은 2를 반환합니다.

[4. valueOf(String name)]

* 기능: 매개변수로 넘겨진 문자열과 정확히 일치하는 열거형 상수를 찾아 반환합니다.
* 특징: 외부에서 문자열로 된 데이터를 받아와 실제 enum 상수로 변환할 때 아주 유용합니다. 만약 존재하지 않는 상수 이름을 넣으면 IllegalArgumentException 에러가 발생합니다.
* 예시: Tri.valueOf("C")를 호출하면 열거형 상수인 Tri.C를 반환합니다.

[5. compareTo(E o)]

* 기능: 같은 열거형 타입의 상수끼리 선언된 순서를 비교합니다.
* 특징: 기준 상수보다 앞에 선언되어 있으면 음수, 같은 상스면 0, 뒤에 선언되어 있으면 양수를 반환합니다. 정렬할 때 유용하게 쓰입니다.
* 예시: Tri.AB.compareTo(Tri.C)를 하면 AB가 C보다 앞에 있으므로 음수(-2)가 나옵니다.

[6. equals(Object other)]

* 기능: 두 열거형 상수가 같은지 비교하여 같으면 true, 다르면 false를 반환합니다.
* 특징: enum은 내부적으로 싱글톤(단 하나의 객체)으로 관리되기 때문에 일반 equals() 외에도 동등 연산자(==)를 사용해 동일성을 비교할 수 있습니다. 가독성과 널 포인터 예외 방지를 위해 보통은 == 연산자를 더 많이 씁니다.

[문제]
다음 [A]테이블에 대한 [SQL문]의 실행 [결과] 테이블의 빈칸을 채우시오.

[A] 테이블
C1  C2
2   NULL
3   6
2   3
NULL 5
4   5

[SQL문]
SELECT COUNT(C2) FROM A WHERE C1 IN(2,3) OR C2 IN(3,5);

정답: 3

[해설]
이 문제는 WHERE 절의 논리 연산(OR)과 집계 함수 COUNT의 NULL 처리 방식을 정확히 알고 있는지 묻는 문제입니다. 단계별로 나누어 풀어볼게요.

1. WHERE 조건 필터링 수행
조건식은 `C1 IN(2,3) OR C2 IN(3,5)` 입니다. 즉, C1이 2 또는 3이거나, C2가 3 또는 5인 행을 찾습니다. 둘 중 하나만 만족해도 통과(OR)합니다. 테이블의 각 행을 한 줄씩 대입해 보겠습니다.

* 1행 (2, NULL): C1이 2이므로 만족합니다. (통과)
* 2행 (3, 6): C1이 3이므로 만족합니다. (통과)
* 3행 (2, 3): C1이 2이고 C2도 3이므로 양쪽 다 만족합니다. (통과)
* 4행 (NULL, 5): C2가 5이므로 만족합니다. (통과)
* 5행 (4, 5): C2가 5이므로 만족합니다. (통과)

결과적으로 테이블 A의 모든 행(총 5개)이 WHERE 조건 필터링을 통과하게 됩니다.

2. SELECT COUNT(C2) 계산
조건을 통과한 5개의 행에 대해 `COUNT(C2)`를 계산합니다.
여기서 아주 중요한 규칙이 있습니다. 집계 함수 `COUNT(컬럼명)`은 해당 컬럼의 값 중 **NULL을 제외한 행의 개수**만 세어줍니다.

조건을 통과한 5개 행의 C2 값들만 모아서 살펴보면 다음과 같습니다.

* 1행의 C2: NULL (제외)
* 2행의 C2: 6 (포함)
* 3행의 C2: 3 (포함)
* 4행의 C2: 5 (포함)
* 5행의 C2: 5 (포함)

전체 5개의 행 중에서 1행의 C2 값이 NULL이므로 이를 제외하면, 실제로 세어지는 행의 개수는 4행, 3행, 2행, 5행의 데이터인 총 3개가 됩니다. (값의 중복 여부와 상관없이 데이터의 개수를 셉니다.)

따라서 빈칸에 들어갈 최종 실행 결과 숫자는 3이 됩니다.

[문제]
다음 괄호 안에 들어갈 보안 용어를 영어 약어로 쓰시오.

( )은 금융권에서 주로 사용하며 유효 시간 세션이 끝나면 사라지는 인증 수단이다. ( )은 단방향 해시함수를 이용하여 일회용 비밀번호를 생성하는 방식을 사용한다. ( )은 한 번 사용 후 즉시 폐기되어 재사용이 불가능하다. ( ) 방식은 일회용 비밀번호를 사용하므로, 쉽게 비밀번호를 유출할 수 없다는 장점이 있다.

정답: OTP

[해설]
이 문제는 정보처리기사 실기 시험에 아주 단골로 등장하는 보안 인증 수단에 대한 문제입니다. 문제 지문 속에 명확한 힌트들이 흩어져 있습니다.

가장 결정적인 힌트는 '일회용 비밀번호'라는 표현입니다. 영어로 일회용 비밀번호를 One-Time Password라고 부르며, 이를 영어 약어로 줄인 것이 바로 OTP입니다.

지문에 나와 있는 OTP의 핵심 특징들을 눈에 익혀두시면 다음 시험에 다른 형태로 나와도 쉽게 맞출 수 있습니다.

1. 금융권에서 주로 사용 (은행 뱅킹 앱이나 보안카드 대신 쓰는 OTP 기기 등)
2. 유효 시간 세션이 끝나면 사라짐 (보통 30초나 1분마다 비밀번호가 새로 갱신됨)
3. 단방향 해시함수 이용 (역추적이 불가능하도록 안전하게 생성)
4. 한 번 사용 후 즉시 폐기되어 재사용 불가능 (재사용 공격 차단)

[문제]
다음 테이블에 대하여 R ÷ S 연산을 수행한 결과를 쓰시오.

[R] 테이블
A  B
a1 b1
a2 b2
a1 b3

[S] 테이블
B
b1
b3

결과 테이블
( 1 )
( 2 )
( 3 )
( 4 )
(만약 빈칸이라고 생각되는 경우 x로 채우세요.)

정답:
( 1 ): A
( 2 ): a1
( 3 ): x
( 4 ): x

[해설]
이 문제는 관계 대수 연산 중 나눗셈(Division, ÷) 연산의 원리를 알고 있는지 묻는 문제입니다. 시험에서 은근히 복잡하게 느껴질 수 있지만, 핵심 원리만 기억하면 의외로 간단합니다.

1. 결과 테이블의 컬럼(속성) 결정하기
나눗셈 연산의 결과로 만들어지는 테이블은 [나누어지는 테이블(R)의 컬럼]에서 [나누는 테이블(S)의 컬럼]을 제외한 나머지 컬럼들로만 구성됩니다.

* R 테이블의 컬럼: A, B
* S 테이블의 컬럼: B
* 결과 컬럼: A에서 B를 뺀 'A' 컬럼만 남게 됩니다.
따라서 결과 테이블의 헤더인 ( 1 ) 위치에는 속성명인 A가 들어갑니다.

2. 결과 데이터 찾기
나눗셈 연산의 데이터 필터링 조건은 다음과 같습니다.
"S 테이블에 있는 B 컬럼의 모든 값(b1과 b3 둘 다)을 가지고 있는 R 테이블의 A 값을 찾는다."

R 테이블을 기준으로 A의 값들이 S의 모든 조건(b1, b3)과 매칭되는지 확인해 보겠습니다.

* a1의 경우: R 테이블에서 (a1, b1)과 (a1, b3) 조합을 모두 가지고 있습니다. 즉, b1과 b3을 모두 만족하므로 최종 결과에 포함됩니다.
* a2의 경우: R 테이블에서 (a2, b2)만 가지고 있고, b1이나 b3 조합은 전혀 없습니다. 따라서 탈락합니다.

결과적으로 S 테이블의 모든 조건(b1, b3)을 만족하는 A의 값은 a1 하나뿐입니다.

3. 최종 테이블 채우기

* 첫 번째 줄 ( 1 )은 컬럼 이름이 와야 하므로 A가 됩니다.
* 두 번째 줄 ( 2 )는 결과 데이터인 a1이 들어갑니다.
* 세 번째 줄 ( 3 )과 네 번째 줄 ( 4 )는 더 이상 들어갈 행 데이터가 없으므로 문제 조건에 따라 x로 채워줍니다.

[문제]
다음은 오류 제어 방식에 대한 설명이다. 괄호 ( ) 안에 들어갈 용어를 보기에서 찾아서 쓰시오.

* ( 1 ) 코드 방식은 수신측에서 오류가 발생한 비트를 찾아 재전송을 요구하지 않고 자신이 직접 오류를 수정하는 방식으로 1비트의 오류 수정이 가능하다. ( 1 ) 코드 방식은 ( 2 ) 방식으로 이루어진다. ( 2 ) 방식은 데이터 전송 과정에서 발생한 오류를 검출하여 검출된 오류를 재전송 요구 없이 스스로 수정하는 방식이다. ( 2 ) 방식과 반대되는 ( 3 )방식은 데이터 전송 과정에서 오류가 발생하면 송신 측에 재전송을 요구하는 방식이다. 대표적인 유형에는 ( 4 ) 검사, ( 5 ) 등이 있다. 7~8개의 비트로 구성되는 전송 문자 끝에 1비트를 추가하여 검사하는 ( 4 ) 검사 방식이 있고, 체크섬을 추가하여 다항식을 통해 산출된 값을 토대로 오류를 검사하는 ( 5 ) 방식이 있다.

[보기]
BCD, NAK, FEC, BEC, Hamming, MD5, Parity, CRC

정답:
( 1 ): Hamming
( 2 ): FEC
( 3 ): BEC
( 4 ): Parity
( 5 ): CRC

[해설]
네트워크 통신에서 오류를 제어하는 여러 가지 방식의 정의와 특징을 통째로 묻는 문제입니다. 지문이 길지만 키워드를 매칭하면 명확하게 풀 수 있습니다.

1. ( 1 ) Hamming (해밍 코드)

* 힌트: '재전송 요구 없이 자신이 직접 오류를 수정', '1비트의 오류 수정이 가능'
* 해밍 코드는 수신 측에서 오류의 위치를 스스로 찾아내어 1비트 오류를 자동 수정할 수 있는 대표적인 오류 수정 코드입니다.

2. ( 2 ) FEC (전진 오류 수정, Forward Error Correction)

* 힌트: '재전송 요구 없이 스스로 수정하는 방식'
* 송신 측이 데이터에 오류 수정용 부가 정보를 담아 보내면, 수신 측이 이를 이용해 일방적으로 오류를 고치는 방식입니다. 앞으로(Forward) 그냥 가면서 고친다고 생각하면 쉽습니다.

3. ( 3 ) BEC (후진 오류 수정, Backward Error Correction)

* 힌트: 'FEC 방식과 반대', '오류가 발생하면 송신 측에 재전송을 요구'
* 수신 측에서 오류를 발견하면 송신 측에 다시 보내달라고 거꾸로(Backward) 요청하여(ARQ 방식 등) 오류를 해결하는 방식입니다.

4. ( 4 ) Parity (패리티 검사)

* 힌트: '전송 문자 끝에 1비트를 추가하여 검사'
* 가장 단순한 오류 검출 방식으로, 에러가 있는지 없는지만 확인하기 위해 데이터 끝에 1개의 비트(패리티 비트)를 덧붙입니다.

5. ( 5 ) CRC (순환 중복 검사, Cyclic Redundancy Check)

* 힌트: '다항식을 통해 산출된 값을 토대로 오류를 검사'
* 동기식 전송에서 주로 사용하며, 미리 정해진 다항식을 이용해 생성된 비트(체크섬)를 데이터 뒤에 부착하여 에러를 검출하는 정밀한 방식입니다.

[나머지 보기 용어 정리]

* BCD: 10진수 1글자를 4비트의 이진수로 표현하는 코드 형식입니다.
* NAK: 데이터 수신 측에서 송신 측에 "데이터가 제대로 오지 않았다"고 알리는 부인 응답 신호입니다. (재전송 요구 시 사용)
* MD5: 128비트 암호화 해시 함수로, 주로 데이터 무결성 검증(위변조 확인)에 사용됩니다. (오류 제어 방식과는 거리가 있습니다.)
