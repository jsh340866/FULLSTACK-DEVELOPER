
[문제]
다음이 설명하는 공격 기법을 보기에서 골라 쓰시오.

* 공격자가 조직의 사용자들이 자주 방문하는 웹사이트를 추측하거나 관찰한 다음, 해당 웹사이트 중 하나 이상을 사용하여 악성코드를 배포하는 컴퓨터 공격 전략이다.
* 제로데이 취약점 악용이 자주 활용되며, 개인보다는 기업·조직 등 특정 집단을 대상으로 한다.

[보기]
Watering Hole, Phishing, Pharming, Ransomware, Cyber Kill Chain, Drive by Download, Business SCAM

정답: Watering Hole

[해설]
이 문제는 특정 대상을 노리는 표적 공격 기법의 정의를 정확히 이해하고 있는지 묻는 문제입니다.

가장 결정적인 힌트는 '자주 방문하는 웹사이트를 관찰한 다음 해당 웹사이트를 사용하여 악성코드를 배포', '특정 집단을 대상'이라는 점입니다.

사자가 사냥하기 위해 표적이 자주 찾는 '물웅덩이(Watering Hole)' 근처에 매복하는 모습에서 유래한 용어로, 타깃 집단이 주로 방문하는 정상 웹사이트를 먼저 해킹하여 악성코드를 심어두고 방문하기를 기다리는 기법입니다. 따라서 정답은 Watering Hole이 됩니다.

[나머지 보기 용어 정리]

1. Phishing (피싱)
불특정 다수에게 공공기관이나 금융기관을 사칭하는 이메일이나 메시지를 보내, 가짜 사이트로 유도하여 개인정보나 금융정보를 탈취하는 사기 기법입니다.

2. Pharming (파밍)
사용자의 PC를 악성코드에 감염시켜 도메인 네임 시스템(DNS) 또는 호스트 파일을 변조함으로써, 사용자가 정상적인 홈페이지 주소를 올바르게 입력해도 대포 사이트(가짜 사이트)로 강제 접속되도록 하여 정보를 가로채는 기법입니다.

3. Ransomware (랜섬웨어)
사용자의 컴퓨터 시스템에 침투하여 내부 파일들을 암호화한 뒤, 이를 인질로 삼아 암호 해독(복구)을 대가로 금전을 요구하는 악성 프로그램입니다.

4. Cyber Kill Chain (사이버 킬체인)
공격자가 조직을 해킹할 때 거치는 공격 단계를 정형화한 보안 모델입니다. 정찰, 무기화, 전달, 악용, 설치, 명령 및 제어, 행동 등의 단계를 분석하여 각 단계별로 방어 전략을 세우는 데 활용됩니다.

5. Drive by Download (드라이브 바이 다운로드)
사용자가 악성코드가 숨겨진 웹사이트에 방문하기만 해도, 어떠한 링크나 다운로드 버튼을 누르지 않았음에도 시스템의 취약점을 악용하여 백그라운드에서 악성코드가 자동으로 다운로드되고 실행되도록 하는 공격 형태입니다. (워터링 홀 공격을 수행할 때 주로 쓰이는 기술적 수단이기도 합니다.)

6. Business SCAM (비즈니스 이메일 침해, BEC)
기업의 거래처나 경영진의 이메일을 해킹하거나 유사한 주소로 사칭하여, 무역 거래 대금이나 송금 계좌를 가짜 계좌로 변경하도록 유도하는 금융 사기 기법입니다.

마지막으로 올려주신 세 번째 이미지(Java 상속과 다형성 문제)의 문제와 해설을 마크다운 문법 없이 깔끔하게 정리해 드릴게요. 이 문제는 상속 구조에서의 메서드 오버라이딩(Overriding)과 오버로딩(Overloading)의 작동 원리를 정확히 구분해야 하는 고난도 함정 문제입니다.

[문제]
다음 Java 코드의 출력 결과를 쓰시오.

코드:
class A {
String f(Object x) { return "1"; }
String g() { return f("a"); }
}

class B extends A {
String f(Object x) { return "2"; }
String f(String x) { return "3"; }
}

public class Test {
public static void main(String[] args) {
A a = new B();
System.out.println(a.g());
}
}

정답: 2

[해설]
코드의 실행 흐름을 추적해 보면 왜 정답이 3이 아니라 2가 되는지 명확히 알 수 있습니다.

1. 객체 생성과 참조 변수의 타입 (A a = new B();)
실제 생성된 객체는 서브 클래스인 B 객체이지만, 이를 가리키는 참조 변수 a의 타입은 부모 클래스인 A 타입입니다.
참조 변수가 A 타입이므로, 변수 a를 통해서 접근할 수 있는 메서드의 범위는 오직 A 클래스에 정의된(또는 상속해 준) 메서드들로만 제한됩니다.
2. a.g() 호출 단계
메서드 g()는 부모 클래스 A에만 정의되어 있습니다. 따라서 B 객체 내부에 상속된 A 클래스의 g() 메서드가 실행됩니다.
g() 메서드의 내부 코드는 return f("a"); 입니다. 즉, 자기 자신 내부에서 f("a")를 호출하여 그 결과를 반환하려고 합니다.
3. f("a")의 컴파일 시점 결정 (가장 중요)
Java에서 메서드를 호출할 때, "어떤 메서드 시그니처(이름과 매개변수 타입)를 실행할 것인가"는 컴파일 시점에 결정됩니다.
g() 메서드는 클래스 A 내부에 작성되어 있습니다. 클래스 A의 관점에서는 사용할 수 있는 f 메서드가 오직 f(Object x) 하나뿐입니다. 매개변수로 문자열 "a"가 들어왔으므로, 문자열은 Object의 자식이기 때문에 컴파일러는 f(Object x)를 호출하는 것으로 매핑을 확정 짓습니다.
B 클래스에 새로 추가된 f(String x)는 부모 클래스인 A의 코드 안에서는 존재 자체를 알 수 없으므로 고려 대상에서 완전히 제외됩니다. (오버로딩이 적용되지 않음)
4. 런타임 시점의 다형성 (동적 바인딩) 적용
실제 프로그램이 실행되는 런타임 시점에는 가상 메서드 테이블에 의해 오버라이딩(재정의)된 메서드가 있으면 그것을 우선적으로 호출합니다.
우리가 호출하기로 확정한 메서드는 f(Object x)입니다. 그런데 자식 클래스 B를 보면 f(Object x)를 오버라이딩하여 return "2"; 로 재정의해 두었습니다.
따라서 런타임 시점에 변수 a가 실제로 가리키는 B 객체의 오버라이딩된 f(Object x)가 실행되면서 문자열 "2"가 반환됩니다.

최종적으로 System.out.println(a.g())를 통해 화면에 출력되는 값은 2가 됩니다.

새로 올려주신 이미지(image_0a935d.png)의 C언어 코드 문제와 해설을 마크다운 문법 없이 알기 쉽게 풀어드릴게요.

이 문제는 구조체 멤버로 포인터를 다루는 방법, 함수 포인터의 활용, 그리고 C언어에서 배열과 포인터 연산(주소 연산)의 특징을 종합적으로 묻는 문제입니다.

[문제]
다음 C언어 코드의 출력 결과를 쓰시오.

코드:
#include <stdio.h>

struct fns {
int* (*fn)(int*);
} mine;

int* dummy(int* d) {
return d + 1;
}

int main() {
int n[] = {16, 32};
mine.fn = dummy;
printf("%x", *mine.fn(n));
return 0;
}

정답: 20

[해설]
코드의 동작 과정을 한 단계씩 따라가 보면 포인터 연산의 비밀이 풀립니다.

1. 구조체와 함수 포인터 선언
상단에 struct fns 구조체가 정의되어 있고, 전역 변수로 mine이라는 구조체 변수가 선언되었습니다.
내부 멤버인 int* (*fn)(int*)는 'int형 포인터를 매개변수로 받아서 int형 포인터를 반환하는 함수 포인터 fn'을 의미합니다.
2. 배열 선언과 함수 매핑 (main 함수 시작)

* int n[] = {16, 32}; 코드를 통해 크기가 2인 정수형 배열이 메모리에 연속적으로 생성됩니다. n[0]에는 16, n[1]에는 32가 저장됩니다.
* mine.fn = dummy; 를 통해 구조체의 함수 포인터 멤버에 dummy 함수의 주소를 대입합니다. 이제 mine.fn을 호출하면 dummy 함수가 실행됩니다.

3. 함수 호출과 포인터 연산 (mine.fn(n))

* printf 문 안에서 mine.fn(n)이 먼저 실행됩니다. 이때 배열의 이름인 n은 배열의 첫 번째 요소의 주소(&n[0])를 의미합니다.
* dummy 함수로 배열 n의 주소값이 전달되고, 함수 내부에서는 return d + 1; 연산을 수행합니다.
* 여기서 아주 중요한 C언어의 규칙이 있습니다. 포인터(주소)에 1을 더하는 것은 단순히 정수 1을 더하는 것이 아니라, 가리키는 자료형의 크기만큼 주소를 가리키는 칸을 다음 칸으로 이동하라는 뜻입니다.
* d는 int형 포인터이므로 d + 1은 현재 주소에서 int 크기(4바이트)만큼 뒤에 있는 다음 주소, 즉 배열의 두 번째 요소인 n[1]의 주소(&n[1])가 됩니다. dummy 함수는 이 주소값을 반환합니다.

4. 역참조 연산과 최종 출력 (*mine.fn(n))

* 함수가 반환한 값은 n[1]의 주소입니다. 그 주소 앞에 역참조 연산자 기호인 *가 붙어 있으므로, 주소가 가리키는 실제 공간의 데이터 값을 꺼내오게 됩니다.
* n[1]에 저장된 데이터 값은 정수 32입니다.
* 마지막으로 printf("%x", ...) 구문을 통해 이 값을 16진수(small x) 형태로 출력합니다. 정수 32를 16진수로 변환하면 20이 됩니다. (16이 2번 들어감)

따라서 화면에 출력되는 최종 결과는 20이 됩니다.

새로 올려주신 이미지(image_0a93bf.png 및 image_0a93d9.png)는 정보처리기사 실기 시험 데이터 통신 파트에서 단골로 출제되는 **HDLC(High-level Data Link Control) 프로토콜**에 대한 문제입니다.

마크다운 문법 없이 보기 항목과 매칭하여 깔끔하게 정리해 드릴게요.

[문제]
다음은 비트(Bit) 위주의 프로토콜인 HDLC에 대한 설명이다. ( 1 ) ~ ( 5 )에 들어갈 알맞은 용어를 보기에서 쓰시오.

[HDLC 프레임의 종류]

* ( 1 ) 프레임은 사용자 데이터를 전달하는 역할을 하며, 프레임 구조는 다음과 같다. (그림 생략)
* ( 2 ) 프레임은 오류 제어와 흐름 제어를 위해 사용되며, 대표적으로 RR(Receive Ready, 수신 준비 완료) 등이 있다.
* ( 3 ) 프레임은 링크의 동작 모드 설정과 관리를 한다.

[HDLC 데이터 전송 모드]

* NRM (정규 응답 모드): 불균형 링크에서 종국이 주국의 허가(Poll)를 받아야만 전송할 수 있다.
* ( 4 ): 포인트 투 포인트 균형 링크에서 사용하며, 혼합국이 허가 없이 언제나 전송할 수 있다.
* ( 5 ): 전이중 통신을 하는 포인트 투 포인트 불균형 링크 구성에 사용하며, 종국은 주국의 허가 없이 송신할 수 있지만 링크 설정, 오류 복구 등의 제어 기능은 주국만 한다.

[보기]
비번호, 정보, 비동기 균형 모드, 동기 응답 모드, 동기 균형 모드, 의명, 비동기 응답 모드, 감독, 정규 응답 모드, 릴레이, 양방향 응답 모드, 표준 응답 모드

정답:
( 1 ): 정보
( 2 ): 감독
( 3 ): 비번호
( 4 ): 비동기 균형 모드
( 5 ): 비동기 응답 모드

[해설]

1. HDLC 프레임 종류 삼총사 ( 1, 2, 3 )
HDLC 프레임은 제어부(Control Field)의 형태에 따라 크게 3가지로 나뉩니다. 영어 약어와 함께 한글 명칭을 기억해 두시면 좋습니다.

* ( 1 ) 정보 프레임 (I-Frame, Information Frame): 순수한 사용자 데이터(데이타)를 전송하는 역할을 합니다.
* ( 2 ) 감독 프레임 (S-Frame, Supervisory Frame): 오류 제어(REJ, SREJ)나 흐름 제어(RR, RNR)를 위해 사용되며, 사용자 데이터 필드가 없는 것이 특징입니다.
* ( 3 ) 비번호 프레임 (U-Frame, Unnumbered Frame): 번호가 붙지 않은 프레임이라는 뜻으로, 링크의 연결 및 해제, 그리고 동작 모드 설정 등 관리 목적으로 쓰입니다.

2. HDLC 데이터 전송 모드 ( 4, 5 )
HDLC의 전송 모드는 주국(Master)과 종국(Slave), 혹은 대등한 혼합국(Combine)의 관계에 따라 3가지로 나뉩니다.

* NRM (Normal Response Mode, 정규 응답 모드): 종국이 주국의 허락(Poll)을 기다렸다가 신호를 보냅니다.
* ( 4 ) ABM (Asynchronous Balanced Mode, 비동기 균형 모드): 균형 링크에서 대등한 권한을 가진 혼합국들이 서로 상대방의 허락 없이 언제든지 독립적으로 전송할 수 있는 가장 대중적인 모드입니다.
* ( 5 ) ARM (Asynchronous Response Mode, 비동기 응답 모드): 불균형 링크에서 주국이 관리하지만, 종국이 주국의 허락을 받지 않고도 비동기적으로 먼저 데이터를 보낼 수 있는 모드입니다.

[문제]
조직의 정보 자산을 보호하기 위한 정보보호 관리체계를 뜻하는 영어 약자를 쓰시오.

정답: ISMS

[해설]
보안 관리 및 인증 제도 파트에서 단골로 출제되는 핵심 용어 문제입니다.

문제에 나온 '정보보호 관리체계'를 그대로 영어로 직역하면 힌트가 명확히 보입니다.

* 정보 (Information)
* 보호/보안 (Security)
* 관리 (Management)
* 체계 (System)

이 단어들의 앞 글자를 딴 영어 약자가 바로 ISMS입니다.

조직이 주요 정보자산을 안전하게 보호하기 위해 수립·운영하는 관리체계가 일정한 인증 기준에 적합한지 심사하여 인증을 부여하는 제도를 말합니다.

[추가 팁: 연관 용어 정리]

시험에서는 발전된 형태인 ISMS-P가 출제되기도 하므로 함께 눈에 익혀두시는 것이 좋습니다.

1. ISMS-P (정보보호 및 개인정보보호 관리체계)
기존의 정보보호 관리체계(ISMS)와 개인정보보호 관리체계(PIMS)를 하나로 통합한 제도입니다. 정보보호 중심의 보안 조치뿐만 아니라, 개인정보의 수집·유용·파기 등 흐름에 따른 보호 조치까지 종합적으로 심사하는 대한민국 대표 인증 제도입니다.
2. PIMS (개인정보보호 관리체계)
기업이 개인정보 보호 활동을 체계적이고 지속적으로 수행하기 위해 필요한 관리체계를 갖추었는지 인증하던 과거 제도입니다. (현재는 ISMS-P로 통합됨)

[문제]
다음은 비기능적 요구사항의 유형에 대한 설명이다. 각 설명에 해당하는 비기능적 요구사항 유형을 보기에서 골라 쓰시오.

* (1) 유닉스, 윈도우, 리눅스 등 여러 운영체제에서 프로그램을 사용할 수 있어야 한다.
* (2) 일정 메모리 이상을 확보해야 하며, 그래픽 카드 등 다양한 입력·출력 장치를 지원해야 한다.
* (3) 모든 요청은 1초 이내에 응답해야 하며, 트랜잭션이 즉시 반영되어 자유로운 쿼리가 가능해야 한다.

[보기]
성능, 운영, 품질, 보안, 자원, 문화/정책적 요구사항

정답:
(1): 운영
(2): 자원
(3): 성능

[해설]
소프트웨어 공학의 요구사항 분석 단계에서 출제되는 비기능적 요구사항(Non-functional Requirements)의 세부 유형 분류 문제입니다. 시스템이 '무엇을' 하는지가 기능적 요구사항이라면, 비기능적 요구사항은 시스템의 장비 사양, 처리 속도, 운영 환경 등 '어떤 제약과 품질'을 만족해야 하는지를 다룹니다.

1. (1) 운영 (구동 환경 및 호환성)

* 힌트: '유닉스, 윈도우, 리눅스 등 여러 운영체제에서 프로그램을 사용할 수 있어야 한다.'
* 시스템이 구동될 특정 하드웨어나 소프트웨어 운영체제(OS), 인터페이스 등 어떤 제약 환경 속에서 상호 운용되고 운영되어야 하는지를 규정하는 유형입니다.

2. (2) 자원 (하드웨어 및 시스템 사양 리소스)

* 힌트: '일정 메모리 이상을 확보', '그래픽 카드 등 다양한 입출력 장치 지원'
* 소프트웨어가 정상적으로 돌아가기 위해 필요한 하드웨어 장치의 물리적 리소스 제약(CPU 성능, 메모리 용량, 디스크 공간 등)을 의미합니다.

3. (3) 성능 (속도 및 효율성)

* 힌트: '1초 이내에 응답', '트랜잭션 즉시 반영'
* 시스템의 응답 시간, 처리량, 처리 속도 등 사용자가 체감할 수 있는 시스템의 실제 동작 효율성에 대한 정량적인 기준을 명시하는 유형입니다.

[문제]
다음이 설명하는 디자인 패턴을 보기에서 골라 영어로 쓰시오.

* (1) 추상부와 구현부를 분리하여 두 계층이 서로 영향을 받지 않고 독립적으로 확장될 수 있도록 다리 역할을 하는 구조 패턴은 무엇인가?
* (2) 한 객체의 상태가 변경되었을 때, 그 객체에 의존하는 다른 객체들에게 변경 사실을 자동으로 통지(알림)하는 행위 패턴은 무엇인가?

[보기]
Composite, Bridge, Decorator, Adapter, Visitor, Observer, Mediator, Facade, Proxy, Interpreter

정답:
(1): Bridge
(2): Observer

[해설]
소프트웨어 설계 파트에서 단골로 출제되는 GoF(Gang of Four) 디자인 패턴 문제입니다. 지문 속 핵심 키워드를 파악하면 아주 명확하게 맞출 수 있습니다.

1. (1) Bridge (브릿지 패턴)

* 힌트: '추상부와 구현부를 분리', '다리 역할'
* 말 그대로 두 계층 사이에 다리(Bridge)를 놓아 결합도를 낮추는 패턴입니다. 기능 클래스 계층과 구현 클래스 계층을 아예 독립적인 클래스로 나누어, 어느 한쪽을 수정하더라도 다른 쪽에 영향을 주지 않도록 설계할 때 사용합니다.

2. (2) Observer (옵저버 패턴)

* 힌트: '상태가 변경되었을 때', '다른 객체들에게 변경 사실을 자동으로 통지'
* 감시자라는 뜻의 단어처럼, 어떤 객체의 상태 변화를 주변 객체들이 관찰(Observe)하고 있다가 이벤트가 발생하면 알림을 받아 반응하는 패턴입니다. 1:N 의존 관계를 가질 때 주로 사용되며, 분산 이벤트 처리나 퍼블리셔-서브스크라이버(Pub-Sub) 모델의 기반이 됩니다.

[보기 중 자주 출제되는 핵심 패턴 요약]

* Composite (컴포지트): 복합 객체와 단일 객체를 동일하게 취급하여 전체-부분 관계를 트리 구조로 표현하는 패턴입니다.
* Decorator (데코레이터): 객체에 동적으로 새로운 책임(기능)을 추가할 수 있게 확장해 주는 패턴입니다.
* Adapter (어댑터): 호환성이 없는 인터페이스 때문에 함께 사용할 수 없는 클래스들을 연결해 주는 패턴입니다.
* Facade (퍼사드): 서브시스템들의 복잡한 인터페이스들을 뒤로 숨기고, 다루기 쉬운 단순한 통합 인터페이스(창구)를 제공하는 패턴입니다.
* Proxy (프록시): 실제 객체에 접근하기 전, 대리자(Proxy)를 거치게 하여 제어나 보안, 로딩 지연 등을 처리하는 패턴입니다.

정처기 실기 단골 문제인 **모듈의 응집도(Cohesion)** 문제네요!

올려주신 기출문제의 정답과 각 응집도 유형이 왜 정답이 되는지 이해하기 쉽게 정리해 드릴게요.

---

## 📌 정답 안내

* **① : 절차적** (절차적 응집도)
* **② : 교환적** (교환적/통신적 응집도)
* **③ : 기능적** (기능적 응집도)

---

## 💡 왜 이 답이 될까요? 핵심 키워드 풀이

### ① 절차적 응집도 (Procedural Cohesion)

* **문제 속 힌트:** `정해진 순서대로 실행되지만`, `데이터 자체가 직접 전달·공유되지는 않는`
* **핵심 포인트:** 모듈 안의 기능들이 다른 기능을 수행하지만 순차적인 실행 흐름(절차)을 따를 때를 말합니다. 만약 데이터까지 직접 주고받았다면 '순차적 응집도'가 되지만, 문제에서 **데이터가 공유되지 않는다**고 명시했기 때문에 **절차적**이 정답입니다.

### ② 교환적 응집도 (Transactional / Communication Cohesion)

* **문제 속 힌트:** `동일한 입력 데이터를 사용하거나 동일한 출력 데이터를 생성하는`
* **핵심 포인트:** 동일한 입력/출력 자료(데이터)를 가지고 서로 다른 기능을 수행하는 기능들을 모아놓은 경우입니다. '교환적'이라는 표현 대신 '통신적' 응집도라고도 부릅니다.

### ③ 기능적 응집도 (Functional Cohesion)

* **문제 속 힌트:** `단일 목적을 수행하기 위해 구성된`
* **핵심 포인트:** 모듈 내부의 모든 기능이 단 하나의 핵심 목적(단일 기능)만을 위해 똘똘 뭉쳐있는 상태입니다. 응집도 중에서 **가장 좋은(가장 높은) 품질**의 응집도입니다.

---

## 덤으로 외우는 응집도 순서 (우-시-논-절-교-순-기)

시험장 들어가기 전, 응집도가 낮은 것(나쁨)부터 높은 것(좋음) 순서대로 한 번 더 눈에 익혀두세요!

> **우**연적 ➔ **시**간적 ➔ **논**리적 ➔ **절**차적 ➔ **교**환적 ➔ **순**차적 ➔ **기**능적
