Q11. UML 모델에서 사물의 명세가 바뀌면 다른 사물에 영향을 주는 관계는?

정답: ② Dependency (의존 관계)

해설: 한 사물의 변화가 그것을 사용하는 다른 사물에 영향을 미치는 짧은 기간 동안의 관계를 의미합니다. 특히 한 클래스가 다른 클래스를 메서드의 **매개 변수**로 사용할 때 나타나는 전형적인 관계입니다.

나머지 보기 설명:
① Association (연관 관계): 두 사물 간의 구조적 관계로, 사물 사이가 비교적 장기간 유지되는 연결입니다.
③ Realization (실제화 관계): 인터페이스와 이를 실제로 구현한 클래스 사이의 관계입니다.
④ Generalization (일반화 관계): 하나의 사물이 다른 사물보다 더 일반적인 개념을 가질 때 나타나는 상속 관계입니다.

📚 데이터 모델의 구성 요소 (문제 57번)
✅ 정답 해설
정답: ④ Operation (연산)

이유: 데이터 모델은 크게 구조(Structure), 연산(Operation), 제약 조건(Constraint)의 세 가지 요소로 구성됩니다. 그중에서 데이터 구조에 따라 실제로 표현된 값들을 처리(조작)하는 동적인 작업을 의미하는 것은 바로 연산(Operation)이에요.

❌ 오답 해설 (데이터 모델의 3요소)
② Data Structure (구조): 데이터베이스에 표현될 대상들의 정적인 성질을 의미해요. 데이터가 어떤 형태로 저장되는지(개체, 속성, 관계)를 정의합니다.
③ Constraint (제약 조건): 데이터베이스에 저장될 수 있는 실제 데이터 값에 대한 결함 없는 규칙(무결성 규칙)을 의미해요. (예: "나이" 필드에는 음수가 들어올 수 없다.)
① Relation (릴레이션): 관계형 데이터베이스에서 데이터를 표(Table) 형태로 표현한 것을 의미하며, 모델의 구성 요소라기보다 모델이 구현된 형태에 가까워요.

💡 한눈에 정리하는 암기 팁!
데이터 모델의 3요소는 앞 글자만 따서 '구-연-제'라고 외우면 편해요!
구조: 정적인 모습 (틀) Structure
연산: 동적인 작업 (처리) Operation
제약 조건: 데이터의 규칙 (허용 범위) Constraint

## 10번 정답 3번
✅ 정답 해설
정답: ③ Maintenance (유지보수)

이유: 시스템의 5대 구성 요소는 입력(Input), 처리(Process), 출력(Output), 제어(Control), 피드백(Feedback)입니다. 유지보수(Maintenance)는 시스템 개발 생명주기(SDLC)의 한 단계이지, 시스템 자체를 이루는 기본 구성 요소에는 포함되지 않아요.

❌ 오답 해설 (시스템의 5대 구성 요소)
나머지 보기들은 시스템이 목적을 달성하기 위해 유기적으로 작동하는 핵심 요소들입니다.

① Process (처리): 입력된 데이터를 정해진 규칙에 따라 변환하여 결과를 만드는 과정이에요.
② Feedback (피드백): 출력된 결과가 예정된 목표에 부합하는지 검사하고, 차이가 있다면 다시 입력 단계로 보내 수정하도록 하는 과정이에요.
④ Control (제어): 각 구성 요소들이 정해진 계획대로 정확하게 작동하는지 감시하고 지시하는 역할을 해요.

추가 팁:
Input (입력): 처리할 데이터나 조건을 시스템에 넣는 것
Output (출력): 처리가 끝난 후 만들어진 결과물

시스템의 5대 구성 요소 : 입력(Input), 처리(Process), 출력(Output), 제어(Control), 피드백(Feedback)
'처리'를 중심으로 '제어'와 '피드백'이 감싸고 있는 그림




## 12번 정답 3번
✅ 정답 해설
정답: ③번 (동적 다이어그램보다는 정적 다이어그램에 가깝다.)

이유: 순차 다이어그램은 객체들 사이의 메시지 교환을 시간의 흐름에 따라 나타내는 대표적인 동적 다이어그램(Dynamic Diagram)입니다. 시스템의 구조를 보여주는 정적 다이어그램(예: 클래스 다이어그램)과는 성격이 완전히 달라요.

❌ 오답 해설 (순차 다이어그램의 특징)
나머지 보기들은 순차 다이어그램의 핵심 정의를 잘 설명하고 있습니다.

① 객체들의 상호 작용: 시스템 구성 요소(객체)들이 서로 어떻게 협력하는지 보여주기 위해 사용해요.
② 시간의 흐름 강조: 수직 방향으로 흐르는 '생명선(Lifeline)'을 통해 메시지가 오가는 순서와 시간을 시각적으로 강조해요.
④ 교류 다이어그램(Interaction Diagram): UML에서 객체 간의 상호작용을 나타내는 교류 다이어그램에는 순차 다이어그램, 통신 다이어그램 등이 포함돼요.

핵심 요약:
정적 다이어그램: 클래스, 객체, 컴포넌트, 배치 다이어그램 등 (구조 중심)
동적 다이어그램: 순차(교류), 상태, 활동, 통신(교류) 다이어그램 등 (행위/흐름 중심)






## 32번 정답 1번

이유: 스터브와 드라이버는 테스트 케이스 자동 생성 도구가 아니라, 통합 테스트(Integration Test) 단계에서 하위 모듈이나 상위 모듈이 아직 개발되지 않았을 때 사용하는 테스트 하네스(Test Harness) 도구입니다. 테스트 데이터를 찾아내는 직접적인 생성 기법이 아니에요.

③ 랜덤(Random) 테스트: 입력값의 범위를 무작위로 선택하여 테스트 데이터를 생성하는 방식이에요.
④ 자료 흐름도: 소스 코드 내에서 변수의 정의와 사용 흐름을 분석하여 테스트 경로와 데이터를 찾아내는 기법입니다.





## 40번 정답 1번
✅ 정답 해설
정답: ① 정의 기능 (Definition Facility)

이유: 데이터베이스에 저장될 데이터의 타입, 구조, 이용 방식, 제약 조건 등을 명시하여 데이터의 논리적/물리적 구조를 설정하는 기능이기 때문이에요. 모든 응용 프로그램이 요구하는 데이터 구조를 지원하기 위해 프레임워크를 짜는 단계라고 생각하면 쉬워요.

## 90번 정답 1번
✅ 정답 해설
정답: ①번 (Ping of Death)

이유: 문제의 핵심 키워드는 ICMP 패킷과 허용 범위 이상(거대 패킷)입니다. Ping of Death는 규정된 크기 이상의 ICMP 패킷을 전송하여 수신 측에서 패킷을 재조합하는 과정에서 부하를 일으키거나 시스템을 마비시키는 서비스 거부(DoS) 공격 기법입니다.

시험 대비 팁
네트워크 공격 기법 중 ICMP를 활용하는 단골 유형 2가지를 꼭 구분하세요!
Ping of Death: 아주 큰 패킷을 보내서 마비시킴 (재조합 부하)
Smurf(스머프) 공격: 엄청난 양의 ICMP 응답을 유도해서 마비시킴 (트래픽 폭주)
