##28번 정답 3번
문제: 해싱 함수(Hashing Function)의 종류가 아닌 것은?

✅ 정답 해설
정답: ③번 (개방주소법 - Open Addressing)

이유: 개방주소법은 해시 함수를 통해 나온 주소에 이미 다른 데이터가 있을 때(충돌 발생 시), 빈 공간을 찾아 데이터를 저장하는 충돌 해결 방법(Collision Resolution) 중 하나입니다. 해시 함수 그 자체의 종류는 아니기 때문에 정답입니다.

❌ 오답 해설 (해시 함수의 종류인 것들)
①번 제급법(Mid-Square): 키 값을 제곱한 후, 그 중간 부분의 자릿수를 해시 주소로 사용하는 방법입니다.
②번 숫자 분석법(Digit Analysis): 키 값을 구성하는 숫자들의 분포를 파악하여 편중되지 않은 숫자를 골라 해시 주소로 사용하는 방법입니다.
④번 제산법(Division): 키 값을 해시 테이블의 크기로 나눈 나머지를 해시 주소로 사용하는 가장 일반적인 방법입니다.



##32번 정답 1번

✅ 정답 해설
정답: ①번 (RCS - Revision Control System)

이유: RCS는 소스 파일의 수정을 한 사람만 할 수 있도록 제한하는 '파일 잠금(Locking)' 방식을 사용하는 초기 버전 관리 시스템입니다. 여러 사람이 동시에 같은 파일을 고쳐서 발생하는 충돌을 방지하고, 변경 이력을 관리하는 데 사용되었습니다.

❌ 오답 해설 (다른 용어들의 의미)
②번 RTS (Reliable Transfer Service): OSI 7계층에서 신뢰성 있는 데이터 전송을 지원하는 서비스로, 버전 관리와는 무관합니다.
③번 RPC (Remote Procedure Call): 별도의 원격 제어를 위한 코딩 없이 다른 주소 공간에 있는 함수나 프로시저를 실행할 수 있게 하는 통신 기술입니다.
④번 RVS (Relative Version System): 실제 존재하는 표준적인 버전 관리 도구 명칭이 아니며, 수험생을 헷갈리게 하기 위한 가짜 용어입니다.

RCS: 파일 잠금 방식 (한 명만 수정 가능)
CVS/SVN: 중앙 집중형 관리 방식
Git: 분산형 관리 방식 (승원 님이 학원에서 주로 쓰시는 방식!)


##33번 정답 1번
문제: 블랙박스 테스트 기법으로 거리가 먼 것은?

✅ 정답 해설
정답: ①번 (기초 경로 검사)

이유: 기초 경로 검사(Base Path Testing)는 소스 코드의 내부 논리적 흐름과 경로를 분석하여 테스트 케이스를 설계하는 기법으로, 블랙박스가 아닌 화이트박스 테스트(White-Box Testing)의 대표적인 기법입니다.

❌ 오답 해설 (블랙박스 테스트 기법인 것들)
블랙박스 테스트는 내부 구조를 모르는 상태에서 입력값에 따른 출력 결과(기능)를 확인하며, 다음과 같은 기법들이 있습니다.
②번 동치 클래스 분해 (Equivalence Partitioning): 입력 데이터를 유사한 특징을 가진 그룹으로 나누고, 각 그룹의 대표값을 테스트 케이스로 선정하는 방식입니다.
③번 경계값 분석 (Boundary Value Analysis): 입력 데이터의 경계 부분(최솟값, 최댓값 등)에서 오류가 발생할 확률이 높다는 점을 이용해 경계값을 테스트하는 방식입니다.
④번 원인 결과 그래프 (Cause-Effect Graphing): 입력 데이터 간의 관계와 출력 결과의 논리적 관계를 그래프로 표현하여 테스트 케이스를 설계하는 방식입니다.

동치 클래스 분해 : 프로그램의 '내부 코드'를 전혀 들여다보지 않고, 오로지 '입력값과 출력값의 명세(요구사항)'만 보고 테스트를 짜기 때문에 블랙박스 테스트에 해당해요.

❌ 오답 해설 (다른 용어들의 의미)

##56번 정답 4번
문제: 분산 데이터베이스의 투명성(Transparency)에 해당 하지 않는 것은?

✅ 정답 해설
정답: ④번 (Media Access Transparency)

이유: 분산 데이터베이스의 4대 투명성(또는 6대 투명성) 목록에 'Media Access Transparency(매체 접근 투명성)'라는 용어는 존재하지 않습니다. 이는 수험생을 헷갈리게 하기 위해 만든 오답입니다.

❌ 오답 해설 (주요 투명성 종류)
분산 데이터베이스가 갖춰야 할 진짜 투명성들은 다음과 같습니다:
①번 Location Transparency (위치 투명성): 데이터가 물리적으로 어느 서버에 저장되어 있는지 몰라도 데이터 이름만으로 접근할 수 있어야 합니다.
②번 Replication Transparency (복제 투명성): 데이터가 여러 곳에 복제되어 있어도 사용자는 마치 하나의 데이터만 있는 것처럼 사용할 수 있어야 합니다.
③번 Failure Transparency (장애 투명성): 특정 지역의 서버에 장애가 발생해도 시스템 전체는 멈추지 않고 데이터의 무결성을 유지해야 합니다.
Fragmentation Transparency (분할 투명성): 하나의 논리적 릴레이션이 여러 단편으로 분할되어 저장되어도 사용자는 원래의 전체 릴레이션으로 인식해야 합니다.

분산 데이터베이스 투명성은 앞 글자만 따서 '위-복-장-분'으로 기억하세요!
위치(Location) - 복제(Replication) - 장애(Failure) - 분산(Fragmentation) - 병행(Concurrency)

④번: 딕셔너리 출력 시 키인 'a'를 출력하는 것이 아니라 그 키에 매핑된 값(Value)인 90을 가져와야 하므로 오답입니다.




##66번 정답 2번 ( 또 틀림 )
✅ 정답 해설
정답: ②번 (LUF - Least Used First)

이유: 페이지 교체 알고리즘 중에서 사용 빈도가 가장 적은 페이지를 교체하는 알고리즘의 정확한 명칭은 LFU(Least Frequently Used)입니다. 보기의 LUF는 존재하지 않는 용어이거나 단순히 수험생을 헷갈리게 하기 위해 만든 오답이에요.

❌ 오답 해설 (실제 알고리즘들)
①번 FIFO(First-In-First-Out): 가장 먼저 메모리에 들어온 페이지를 가장 먼저 교체하는 방식입니다.
③번 Optimal (최적 교체): 앞으로 가장 오랫동안 사용되지 않을 페이지를 예측하여 교체하는 방식입니다. 이론적으로는 가장 효율적이지만 실현은 불가능합니다.
④번 LRU(Least Recently Used): 최근에 가장 오랫동안 사용되지 않은 페이지를 교체하는 방식입니다.
 - LRU (Recently): 최근 사용 시점 기준
 - LFU (Frequently): 사용 횟수 기준


##78번 정답 3번
✅ 정답 해설
정답: ③번 (버퍼 오버플로)

이유: 버퍼 오버플로(Buffer Overflow)는 데이터가 지정된 메모리 공간(버퍼)의 범위를 벗어나서 인접한 메모리 영역을 덮어쓰는 취약점입니다. 이 과정에서 프로그램의 흐름을 바꾸거나 악성 코드를 실행할 수 있게 되는 대표적인 메모리 관리 오류입니다.

❌ 오답 해설 (다른 취약점들)
①번 FTP 바운스 공격: FTP 프로토콜의 취약점을 이용해 공격자가 다른 시스템을 거쳐서 타깃을 공격하는 스캔 방식입니다. 메모리 오류와는 직접적인 관련이 없습니다.
②번 SQL 삽입 (SQL Injection): 웹 애플리케이션의 입력란에 SQL 쿼리를 주입하여 데이터베이스를 조작하는 공격입니다. 이는 데이터베이스 질의문 관련 취약점입니다.
④번 디렉토리 접근 공격: 경로 조작을 통해 허용되지 않은 상위 디렉토리의 파일에 접근하는 공격입니다. 파일 시스템 경로 제어 관련 취약점입니다.



##79번 정답 4번
문제: 배치 프로그램의 필수 요소에 대한 설명으로 틀린 것은?

✅ 정답 해설
정답: ④번 (무결성은 주어진 시간 내에 처리를 완료할 수 있어야 하고, 동시에 동작하고 있는 다른 애플리케이션을 방해하지 말아야 한다.)

이유: ④번에서 설명하는 내용은 '무결성'이 아니라 '성능(Performance)'에 대한 설명입니다. 무결성(Integrity)은 데이터에 오류가 없이 정확하고 일관되게 유지되는 성질을 의미합니다.

❌ 오답 해설 (배치 프로그램의 5대 필수 요소)
배치 프로그램이 갖춰야 할 진짜 요소들은 다음과 같습니다:
①번 자동화(Automation): 심각한 오류 상황 외에는 사용자의 개입 없이 자동으로 동작해야 합니다.
②번 안정성/신뢰성(Reliability): 어떤 문제가 생겼는지, 언제 발생했는지 등을 추적할 수 있어야 합니다.
③번 대용량 데이터(Massive Data): 대용량의 데이터를 처리할 수 있어야 합니다.
견고성(Robustness): 잘못된 데이터가 입력되어도 시스템이 중단되지 않고 오류를 처리할 수 있어야 합니다.





##83번 정답 4번

문제: CMMI의 단계가 아닌 것은?

✅ 정답 해설
정답: ④번 (반복)

이유: CMMI(Capability Maturity Model Integration)의 성숙도 5단계에는 '반복'이라는 단계가 없습니다. '반복'은 과거 CMM 모델의 단계 명칭이거나 일반적인 개발 모델에서 쓰이는 용어이며, CMMI에서는 관리(Managed) 또는 정의(Defined) 단계를 사용합니다.

❌ 오답 해설 (CMMI의 실제 5단계)
CMMI의 성숙도 레벨은 다음과 같이 5단계로 구성되어 있습니다:
① 초기(Initial): 프로세스가 규정되어 있지 않고 혼란스러운 상태.
② 관리(Managed): 프로젝트별로 프로세스가 규칙화되어 관리가 이루어지는 상태.
③ 정의(Defined): 조직 차원의 표준 프로세스가 확립된 상태.
정량적 관리(Quantitatively Managed): 프로세스가 통계적으로 측정되고 통제되는 상태.
최적화(Optimizing): 지속적인 개선을 통해 프로세스가 최적화되는 상태.

CMMI : 초기 - 관리 - 정의 - 정략정관리 - 최적화

##100번 정답 1번
문제: 세션 하이재킹을 탐지하는 방법으로 거리가 먼 것은?

✅ 정답 해설
① FTP SYN SEGMENT 탐지
세션 하이재킹(Session Hijacking)은 이미 TCP 3-Way Handshake를 마치고 정상적으로 연결된(Established) 세션을 가로채는 공격 방식이에요.
반면, SYN 세그먼트는 연결을 처음 시작할 때 사용하는 패킷이기 때문에, 이미 연결된 세션을 공격하는 하이재킹을 탐지하는 방법으로는 적절하지 않답니다.

❌ 오답 해설 (탐지 방법인 것들)
② 비동기화 상태 탐지
공격자가 중간에서 패킷을 가로채서 서버에 보내면, 서버의 시퀀스 번호와 클라이언트가 알고 있는 시퀀스 번호가 서로 달라지게 돼요. 이 '어긋난 상태'를 감지하여 공격을 알아낼 수 있어요.
③ ACK STORM 탐지
시퀀스 번호가 맞지 않으면 서버와 클라이언트는 서로 번호를 맞추기 위해 대량의 ACK 패킷을 주고받게 되는데, 네트워크 부하가 갑자기 늘어나는 이 현상을 통해 공격을 의심할 수 있어요.
④ 패킷의 유실 및 재전송 증가 탐지
공격자가 패킷을 가로채거나 변조하는 과정에서 정상적인 패킷이 전달되지 못해 유실되거나, 이를 복구하려고 계속 다시 보내는(Retransmission) 작업이 급증하게 됩니다.
