## 3번 정답 1번
정답: ① 클래스 다이어그램
보기 ①번의 설명은 클래스 다이어그램이 아니라 커뮤니케이션 다이어그램(Communication Diagram)에 대한 설명입니다.

 - 클래스 다이어그램(Class Diagram): 시스템 내 클래스들의 정적인 구조와 그들 간의 관계(의존, 상속 등)를 표현하는 대표적인 정적 다이어그램입니다. 메시지를 주고받는 동작을 표현하지는 않습니다.
 - 커뮤니케이션 다이어그램: 동작에 참여하는 객체들이 주고받는 메시지를 표현하며, 객체들 간의 연관 관계까지 함께 나타내는 동적 다이어그램입니다.

오답 해설 (옳은 설명들)
나머지 보기들은 각 다이어그램의 용도를 정확하게 설명하고 있습니다.
② 배치 다이어그램 (Deployment Diagram): 결과물, 프로세스, 컴포넌트 등 물리적 요소들이 실제 하위 시스템이나 하드웨어 어디에 위치하는지 물리적 구조를 표현합니다.
③ 유스케이스 다이어그램 (Use Case Diagram): 사용자의 요구를 분석하여 시스템이 제공해야 하는 기능을 사용자 관점에서 모델링하는 데 사용합니다.
④ 활동 다이어그램 (Activity Diagram): 시스템이 어떤 기능을 수행하는지 객체의 처리 로직이나 조건에 따른 처리 흐름을 순서대로 표현합니다. (일종의 플로우차트와 비슷합니다.)


## 5번 정답 1번
정답: ① 싱글톤(Singleton) 패턴
싱글톤 패턴: 클래스의 인스턴스가 딱 하나만 생성되도록 보장하는 패턴입니다.

오답 해설
다른 디자인 패턴들도 정보처리기사 시험에 자주 나오니 간단히 짚고 넘어갈게요!
② 옵서버(Observer) 패턴: 한 객체의 상태가 변하면 그 객체에 의존하는 다른 객체들에게 연락이 가고 자동으로 내용이 갱신되는 방식입니다. (예: 유튜브 구독 알림)
③ 프로토타입(Prototype) 패턴: 원형이 되는 인스턴스를 복사해서 새로운 객체를 생성하는 방식입니다. 객체 생성 비용이 클 때 사용합니다.
④ 상태(State) 패턴: 객체의 내부 상태에 따라 스스로 행동을 변경할 수 있게 허용하는 패턴입니다.



## 7번 정답 4번
정답: ④ 모듈의 크기를 가능한 작게 구성하여 병행성 수준을 높여야 한다.
 - 모듈은 무조건 작게 만드는 것이 아니라, 적당한 크기를 유지하면서 독립성을 갖도록 설계하는 것이 바람직합니다.


오답 해설
나머지 보기들은 아주 훌륭한 소프트웨어 설계 지침들입니다.

① 결합도를 최소화하고 응집도를 최대화한다:
 - 응집도(Cohesion): 모듈 내부의 요소들이 얼마나 밀접하게 관련되어 있는지를 나타냅니다. 높을수록 좋습니다.
 - 결합도(Coupling): 모듈과 모듈 사이의 관계가 얼마나 끈끈한지를 나타냅니다. 낮을수록(독립적일수록) 좋습니다.
② 복잡도와 중복성을 줄이고 일관성을 유지시킨다: 
	- 코드가 복잡하면 유지보수가 힘들고, 중복이 많으면 수정할 때 실수가 생기기 쉽습니다. 일관된 코딩 스타일은 협업의 핵심이죠.
③ 하나의 입구와 하나의 출구를 갖도록 해야 한다: 
	- 구조적 프로그래밍의 원칙입니다. 제어 흐름이 이리저리 튀지 않고 입구와 출구가 명확해야 코드의 흐름을 이해하고 테스트하기 쉽습니다.

모듈 크기 vs 로킹 단위 비교 정리
구분			모듈의 크기 (Module Size)		로킹 단위 (Locking Granularity)
분야			소프트웨어 설계 (구조)			데이터베이스/운영체제 (병행 제어)
목적			유지보수성, 재사용성 향상		데이터 일관성 유지 및 공유 최대화
작을 때 장점		기능이 명확해지고 이해하기 쉬움	여러 사용자가 동시에 접근할 수 있는 범위가 넓어짐 (병행성 증가)
작을 때 단점		모듈 간 연결 비용(Overhead) 증가	관리해야 할 잠금(Lock)이 많아져 시스템 부하 증가


## 8번 정답 4번
정답: ④ ISP : 객체는 단 하나의 책임만 가져야 한다는 원칙

객체지향 설계 원칙(SOLID)
S : SRP (Single Responsibility Principle, 단일 책임 원칙)
	- 객체 하나당 하나의 책임만 가져야 한다는 원칙
O : OCP (Open-Closed Principle, 개방-폐쇄 원칙) 
	- 소프트웨어 요소는 확장에는 열려있고, 변경에는 닫혀야한다.
	- 기존 코드를 수정하지 않고 새로운 기능을 추가하도록 설계해야한다.
L : LSP (Liskov Substituion Principle, 리스코프 치환 원칙)
	- 자식 클래스는 언제나 부모 클래스를 대체할 수 있어야 한다.
	- 즉, 부모 클래스 인스턴스 대신 자식 클래스 인스턴스를 사용해도 문제 없어야한다.
I : ISP (Interface Segregation Principle, 인터페이스 분리 원칙)
	- 사용하지 않는 인터페이스는 구현하지 않도록 인터페이스를 구체적이고 작게 분리해야한다.
D : DIP (Dependency Inversion Principle, 의존 역전 원칙)  
	- 각 객체들 간의 의존 관계가 성립될 때, 추상성이 낮은 클래스보다 추상성이 높은 클래스와
	  의존 관계를 맺어야 한다는 원칙

## 11번 정답 4번
정답: ④ 표의 숫자 코드 (Significant Digit Code)
표의 숫자 코드는 대상 항목의 물리적인 성질인 길이, 넓이, 부피, 지름, 무게 등의 수치를 코드의 일부나 전부로 사용하는 방식입니다.

오답 해설
① 연상 코드 (Mnemonic Code): 명칭이나 약어를 이용해서 기억하기 쉽게 만든 코드예요. (예: TV, LCD 등)
② 블록 코드 (Block Code): 공통성이 있는 항목들을 일정 범위(블록)로 묶어서 그 안에서 일련번호를 부여하는 방식입니다. (예: 100~200번은 영업부, 201~300번은 총무부)
③ 순차 코드 (Sequence Code): 데이터가 발생한 순서대로 1, 2, 3... 처럼 단순하게 일련번호를 부여하는 방식입니다.



## 18번 정답 3번
정답: ③ 배치 방식
배치 처리(Batch(일괄) Processing)는 데이터를 실시간으로 하나씩 처리하는 대신, 일정 기간이나 일정량의 데이터를 모았다가 한꺼번에(일괄적으로) 처리하는 방식이에요.

① 실시간 방식 (Real-time Processing): 데이터가 발생하는 즉시 처리하는 방식이에요. 대량의 데이터를 모아서 처리하기보다는 즉각적인 응답이 중요한 은행 업무나 예약 시스템에 쓰여요.
② 분산 처리 방식 (Distributed Processing): 하나의 거대한 작업을 여러 대의 컴퓨터가 나누어 처리하는 방식이에요. 처리량보다는 시스템의 부하를 분산시키거나 안정성을 높이는 데 목적이 있어요.
④ 지연 처리 방식 (Deferred Processing): 데이터 처리를 즉시 하지 않고 나중으로 미룬다는 개념이지만, 정보처리기사 등 시험에서 '대량 데이터 처리'의 표준 정답은 보통 '배치 방식'으로 정의돼요.

## 45번 정답 1번
오답 분석 (정답인 이유)
① 오너-멤버(Owner-Member) 관계라고도 한다. (X)
설명: '오너-멤버'라는 용어는 망형(네트워크형) 데이터 모델에서 사용하는 용어예요. E-R 모델은 현실 세계를 개체와 관계로 표현할 뿐, 데이터를 주인(Owner)과 구성원(Member)이라는 수직적 구조로 정의하지 않아요.

기억 팁: "망형 모델 = 오너-멤버"라고 세트로 외워두시면 나중에 헷갈리지 않으실 거예요!

## 2. 옳은 보기 설명

## 82번 정답 3번
정답: ③ SSO
해설:
문제에서 설명하는 기술은 SSO(Single Sign-On)입니다.

SSO는 '단 한 번의 로그인'으로 여러 개의 시스템이나 서비스에 재차 로그인할 필요 없이 접근할 수 있도록 해주는 통합 인증 솔루션입니다.

장점: 사용자는 여러 개의 아이디와 비밀번호를 기억할 필요가 없어 편의성이 높아지고, 관리 측면에서는 사용자 인증 관리를 중앙 집중화하여 효율성을 높일 수 있습니다.

오답 분석 (기타 용어 정리)
① SOS (System of Systems): 여러 개의 독립적인 시스템들이 모여 더 큰 기능을 수행하는 '체계의 체계'를 의미합니다.
② SBO (Service-Based Organization): 서비스 기반 조직 혹은 업무 처리 모델 중 하나를 뜻하며, 본 문제의 인증과는 거리가 멉니다.
④ SOA (Service Oriented Architecture): 서비스 지향 아키텍처. 소프트웨어 기능을 서비스 단위로 나누어 유연하게 결합하는 설계 방식을 의미합니다.

학습 팁:
**"한 번 인증하면 다른 곳도 통과!"**라는 문맥이 나오면 무조건 **SSO**를 떠올리세요. 우리가 포털 사이트 한 곳에 로그인하면 메일, 카페, 블로그를 모두 이용할 수 있는 것과 같은 원리입니다.

SAN(Storage Area Network)은 서버와 저장 장치를 연결하기 위해 광케이블과 고가의 전용 스위치(FC 스위치)를 사용하여 구성하는 초고속 전용 네트워크입니다.

③ 저장장치 및 파일 공유: 여러 서버가 하나의 거대한 저장 장치 풀을 공유하여 자원을 효율적으로 사용할 수 있습니다.

시험 팁:
저장 장치 연결 방식 비교 문제는 단골 출제 포인트입니다!
DAS: 서버에 직접 연결 (비용 저렴, 공유 불가)
NAS: 일반 LAN망 이용 (비용 보통, 파일 단위 공유)
SAN: 전용 광네트워크 이용 (비용 비쌈, 블록 단위 공유, 고성능)



## 86번 정답 2번 (또 틀림)
정답: ② 고정된 길이의 입력 데이터나 메시지를 임의의 길이의 값이나 키로 변환한다.
해설:
해시 함수(Hash Function)의 핵심 특징을 반대로 설명한 문장입니다.

옳은 설명: 해시 함수는 임의의 길이의 입력 데이터를 넣더라도 항상 고정된 길이의 값(해시값)으로 출력합니다. 예를 들어, 아주 긴 소설 책 한 권을 해시 함수에 넣어도, 짧은 단어 하나를 넣어도 결과값은 똑같이 256비트(SHA-256 기준)의 고정된 길이를 가집니다.

다른 선택지 분석
① 해시값/해시키: 해시 알고리즘을 거쳐 나온 결과물을 해시값(Hash Value) 또는 해시키(Hash Key)라고 부릅니다.
③ 암호화 및 무결성 검증: 해시는 원래 데이터가 조금만 바뀌어도 결과값이 완전히 달라지는 '쇄도 효과(Avalanche Effect)'가 있어, 데이터가 변조되지 않았는지 확인하는 무결성 검증에 필수적입니다.
④ 대표 알고리즘: 보안 등급에 따라 SHA-1, SHA-256(SHA 시리즈)이나 과거에 많이 쓰였던 MD5(MD 시리즈) 등이 있습니다.

사용자 인증 방법은 크게 4가지 유형으로 나뉩니다. 문제에서 묻는 '소유 기반 인증'은 사용자가 직접 가지고 있는 물건을 이용하는 방식입니다.

① i-PIN (지식 기반): 인터넷상에서 주민등록번호를 대신하여 본인을 확인하는 수단으로, 사용자가 알고 있는 아이디와 비밀번호 등을 이용하므로 지식 기반(Something you know) 인증에 해당합니다.
② OTP (소유 기반): 하드웨어 토큰이나 스마트폰 앱 등 일회용 비밀번호 생성기를 소유해야 합니다.
③ 스마트 카드 (소유 기반): IC칩이 내장된 카드를 직접 소유하고 리더기에 삽입해야 합니다.
④ 신분증 (소유 기반): 주민등록증, 운전면허증 등 물리적인 신분증을 소유하고 제시해야 합니다.

인증의 4요소 정리
지식 기반(Something You Know): 비밀번호, PIN, i-PIN, 질문 답변 등
소유 기반(Something You Have): 스마트 카드, OTP, 신분증, 토큰 등
생체 기반(Something You Are): 지문, 홍채, 정맥, 목소리, 얼굴 등
위치/행동 기반(Somewhere You Are / Something You Do): 접속 IP, GPS 위치, 서명 패턴 등


## 91번 정답 4번
정답: ④ Meta Data

해설:
문제에서 설명하는 용어는 메타데이터(Meta Data)입니다.
메타데이터는 '데이터에 관한 데이터(Data about Data)'라고 불립니다. 어떤 일련의 데이터를 정의하고 설명해 주는 데이터를 의미하며, 컴퓨터 시스템에서는 데이터 사전(Data Dictionary)의 내용이나 스키마(Schema) 등이 대표적인 예시입니다.

대량의 정보 중에서 원하는 데이터를 빠르게 찾거나, 데이터의 내용을 체계적으로 관리하기 위해 사용됩니다. 예를 들어 디지털 사진 파일에서 촬영 날짜, 위치, 조리개 값 등이 적힌 정보가 바로 메타데이터입니다.

오답 분석 (기타 용어 정리)
① View: 데이터베이스에서 하나 이상의 테이블로부터 유도된 가상 테이블입니다. 사용자에게 필요한 데이터만 보여주거나 보안을 위해 사용됩니다.
② Broad Data: 빅데이터보다 데이터의 '다양성'과 '연결성'에 초점을 맞춘 개념으로, 서로 다른 분야의 데이터를 융합하여 새로운 가치를 창출하는 데이터를 의미합니다.
③ Big Data: 기존의 방식으로는 수집, 저장, 분석하기 어려울 정도로 규모가 크고 생성 속도가 빠른 방대한 데이터를 의미합니다.

핵심 암기 팁:
**"데이터를 설명하는 데이터", "데이터 사전", "스키마"**라는 표현이 나오면 정답은 무조건 메타데이터입니다. 문제 은행 방식으로 자주 출제되는 키워드이니 꼭 기억해 두세요!



## 95번 정답 3번
정답: ③ USN
USN(Ubiquitous Sensor Network)
USN은 각종 센서에서 수집한 정보를 무선으로 수집할 수 있도록 구성한 네트워크를 말합니다. 필요한 모든 사물에 **RFID 태그**를 부착하고, 이를 통해 사물의 식별 정보 및 주변 환경 정보를 실시간으로 네트워크에 연결하여 관리하는 기술입니다.

오답 분석 (기타 용어 정리)
① GIS (Geographic Information System): 지리 정보 시스템. 지형 및 지리 정보를 수집, 저장, 분석, 출력하는 시스템입니다. (예: 구글 맵, 내비게이션)
② SON (Self Organizing Network): 자가 구성 네트워크. 주변 상황에 맞춰 스스로 망을 구성하고 설정하는 통신 네트워크 기술입니다.
④ UWB (Ultra Wide Band): 초광대역 무선 기술. 매우 넓은 대역폭을 사용하여 저전력으로 대용량의 데이터를 근거리에서 전송하는 무선 통신 기술입니다.

 - 수명 연장: 유지보수성이 향상되어 시스템을 더 오래 사용할 수 있게 됩니다. (맞는 설명)

## 97번 정답 4번
정답: ④ HASH

단방향 암호화 (④ Hash): 암호화는 가능하지만 복호화(원래대로 되돌리는 것)가 불가능한 방식입니다. 주로 비밀번호 저장이나 데이터 무결성 확인에 사용됩니다. (예: SHA-256, MD5)

양방향 암호화: 암호화한 데이터를 다시 평문으로 복호화할 수 있는 방식입니다.
 - 대칭키(개인키): 암호화와 복호화에 같은 키를 사용합니다. (① DES, ② SEED, AES 등)
 - 비대칭키(공개키): 암호화와 복호화에 서로 다른 키를 사용합니다. (③ RSA 등)
