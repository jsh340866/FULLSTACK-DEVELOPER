# 사용 라이브러리 정리 — 2026-08-05

## 검증 방법
`valuepick/build.gradle`에 선언된 의존성 전부를, 실제 소스 코드에서 import/사용 여부를 grep으로 대조해 확인. "선언만 되고 안 쓰이는 것"과 "실제 동작에 쓰이는 것"을 구분하는 게 목적.

## 1. Backend (`valuepick/build.gradle`)

Spring Boot 3.5.15 / Java 21

| 라이브러리 | 버전 | 역할 | 실제 사용 근거 |
|---|---|---|---|
| spring-boot-starter-web | - | REST API, MVC, `RestTemplate` 제공 | 전체 `domain/controller/*` (14개 컨트롤러) |
| spring-boot-starter-security | - | 인증/인가 필터 체인 | `SecurityConfig`, `JWTAuthorizationFilter`, `PrincipalDetailsService` 등 |
| io.jsonwebtoken:jjwt-api/impl/jackson | 0.13.0 | JWT 발급 · 검증 | [`JWTTokenProvider.java`](../../valuepick/src/main/java/com/example/demo/config/auth/jwt/JWTTokenProvider.java) — `Jwts.builder()`로 Access/Refresh 토큰 생성(58, 67, 143, 151행), `Jwts.parser()`로 검증(84, 124행) |
| spring-boot-starter-data-jpa | - | ORM, Repository 계층 | 전체 `domain/entity/*`(`@Entity`), `domain/repository/*` |
| com.mysql:mysql-connector-j | - | MySQL 드라이버 (runtimeOnly) | `application.properties`의 `spring.datasource.url=${DB_URL}` |
| spring-boot-starter-validation | - | 요청 값 검증 (`@Valid`) | `RegisterRequest`, `LoginRequest`, `UpdatePasswordRequest` 등 DTO 11개 파일에서 `@NotBlank`/`@Email` 등 사용, `GlobalExceptionHandler`에서 검증 실패 처리 |
| spring-boot-starter-actuator | - | 헬스체크/모니터링 엔드포인트 | **의존성만 추가된 상태.** `application.properties`에 `management.endpoint*` 관련 설정 없음 → 기본값인 `/actuator/health`만 노출, 추가 활용 없음 |
| org.jsoup:jsoup | 1.18.1 | 네이버 금융 종목뉴스 페이지 HTML 크롤링·파싱 | [`NewsCrawlService.java`](../../valuepick/src/main/java/com/example/demo/domain/service/NewsCrawlService.java) — `Jsoup.connect(url).get()`으로 요청 → `doc.select("a.tit")`로 CSS 셀렉터 파싱 → `News` 엔티티로 변환해 `newsRepository.save()`까지 저장 |
| org.springdoc:springdoc-openapi-starter-webmvc-ui | 2.8.5 | Swagger UI 자동 문서화 | 컨트롤러 14개 파일에서 `@Tag`/`@Operation` 사용 확인 |
| org.projectlombok:lombok | - | 보일러플레이트 제거 (compileOnly/annotationProcessor) | 전 도메인 클래스에서 `@Getter`/`@Builder`/`@RequiredArgsConstructor` 등 |
| org.junit.platform:junit-platform-launcher | - | 테스트 실행기 (testRuntimeOnly) | `src/test` 전반 |
| spring-security-test | - | 시큐리티 테스트 지원 (`@WithMockUser` 등) | **build.gradle에 선언만 되어 있고, `src/test` 전체에서 `@WithMockUser` 등 실사용 흔적 없음** |

### 주의할 점
- `RestTemplate`은 별도 의존성이 아니라 `spring-boot-starter-web`에 포함된 클래스. `AsyncConfig.java`(53행), `SimpleInfoServiceImpl.java`(65행)에서 `new RestTemplate()`으로 DART/공공데이터포털/KRX/한국수출입은행 API를 호출.
- **spring-boot-starter-actuator**와 **spring-security-test**는 의존성 목록엔 있지만 실질적인 사용 근거가 없음. README나 포트폴리오에 "적극 활용"처럼 쓰면 과장이 됨 — "의존성 추가됨" 정도로 표현하는 게 정확.
- `spring-boot-starter-oauth2-client`는 build.gradle 24행에 주석 처리된 상태 (미사용, 향후 소셜 로그인용).

## 2. Frontend (`front/`)

`front/**/*.html` 전체에서 `<script src="cdn...">`, `unpkg`, `jsdelivr`, `googleapis`, `cdnjs` 패턴을 grep했으나 매치 0건. 외부 라이브러리 의존성 없이 HTML5 · CSS3 · Vanilla JavaScript(`front/js/*.js`)로만 구현. 차트도 Canvas API 직접 사용(README 주요 기능 섹션 참고).

---

## 3. Infra

Docker · Nginx · Jenkins · AWS EC2 · Let's Encrypt — `docker-compose.yml`, `DB/Dockerfile`, README의 Jenkins Execute Shell 스크립트에서 확인. Gradle 의존성이 아닌 별도 배포/운영 도구라 build.gradle에는 잡히지 않음.

---

## 결론

- build.gradle 선언 항목 대부분은 실제 코드에서 사용 근거를 찾을 수 있음.
- **actuator, spring-security-test 2개는 선언만 되고 실사용 흔적이 없는 상태** — README/포트폴리오 작성 시 이 둘은 다른 항목과 같은 비중으로 서술하지 않는 게 근거 있는 표현.
- 프론트엔드는 외부 라이브러리 완전 배제, 순수 구현.
