# 3. TOP100 스코어 — 원값이 아닌 백분위 순위로 정규화

## 문제 상황

TOP100은 PER·PBR·ROE·ROA·부채비율·EPS성장률·모멘텀 7개 지표를 가중합산해서 하나의 점수로 만든다. 그런데 이 지표들은 단위와 스케일이 완전히 다르다.

- PER: "몇 배"(예: 15.2)
- ROE: "%"(예: 22.5)
- 모멘텀: "수익률 %"(예: -30 ~ +200처럼 범위가 클 수 있음)

**원값**(DB `STOCK_INDICATOR`에 저장된, 있는 그대로의 계산된 수치)을 그대로 가중치와 곱해서 합산하면, 절대값 크기가 큰 지표가 다른 지표를 무시하고 전체 점수를 지배해버린다. 실제로 원하는 건 "상대적으로 얼마나 좋은 순위인가"이지 "절대값이 얼마나 큰가"가 아닌데, 원값을 그대로 쓰면 이 둘이 섞여버린다.

## 적용된 해결책

[Top100Service.scoreAll()](../../../valuepick/src/main/java/com/example/demo/domain/service/Top100Service.java#L121)에서 원값을 곧바로 쓰지 않고, 순위(rank) → 백분위(0~1) 순으로 변환한 뒤에야 가중치를 곱해 합산한다.

### 1단계 — null 값 보정

```java
// 낮을수록 좋은 지표(PER 등)는 null → MAX_VALUE, 높을수록 좋은 지표(ROE 등)는 null → -MAX_VALUE
double[] pers = indicators.stream().mapToDouble(i -> { Double v = i.getPer(); return v != null ? v : Double.MAX_VALUE;  }).toArray();
double[] roes = indicators.stream().mapToDouble(i -> { Double v = i.getRoe(); return v != null ? v : -Double.MAX_VALUE; }).toArray();
```

값이 없는 종목이 순위 계산에서 항상 최하위가 되도록 미리 처리한다.

### 2단계 — 원값을 순위(rank)로 변환

```java
int[] perRank = ascRank(pers);   // PER은 낮을수록 좋으니 오름차순 순위 (가장 작은 값 → rank 0)
int[] roeRank = descRank(roes);  // ROE는 높을수록 좋으니 내림차순 순위 (가장 큰 값 → rank 0)
```

이 시점에서 원값(15.2배, 22.5% 등)은 계산에서 더 이상 쓰이지 않고, "전체 중 몇 번째로 좋은가"라는 순서 정보만 남는다.

### 3단계 — 순위를 0~1 백분위로 변환 후 가중합산

```java
private double percentileFraction(int rank, int n) {
    if (n <= 1) return 1.0;
    return (double) (n - 1 - rank) / (n - 1);
}
```

1등(rank=0) → 1.0, 꼴찌(rank=n-1) → 0.0. 모든 지표를 이 방식으로 0~1 범위에 맞춘 뒤에 가중치를 곱해 더한다.

```java
// 팩터별 가중치 (합계 1.0) - PER25%/PBR15%/ROE20%/ROA10%/부채비율15%/EPS성장률5%/모멘텀10%
double total = percentileFraction(perRank[i], n) * WEIGHT_PER
        + percentileFraction(pbrRank[i], n) * WEIGHT_PBR
        + percentileFraction(roeRank[i], n) * WEIGHT_ROE
        + percentileFraction(roaRank[i], n) * WEIGHT_ROA
        + percentileFraction(debtRatioRank[i], n) * WEIGHT_DEBT_RATIO
        + percentileFraction(epsGrowthRank[i], n) * WEIGHT_EPS_GROWTH
        + percentileFraction(momentumRank[i], n) * WEIGHT_MOMENTUM;
```

모든 항이 이미 0~1 범위이므로, 최종 점수는 순수하게 가중치 비율대로만 반영된다.

## 원값 vs 순위 vs 백분위 — 개념 구분

| 단계 | 의미 | 예시 |
|---|---|---|
| **원값** | DB에 저장된, 있는 그대로의 계산된 수치 | PER = 15.2배, ROE = 22.5% |
| **순위(rank)** | 원값을 정렬해서 나온 등수 (원값 자체는 이후 계산에 안 쓰임) | PER 15.2배 → 전체 중 300등(rank=299) |
| **백분위(percentileFraction)** | 등수를 0~1 사이 값으로 재변환 | 300등/2,555개 → 0.883 |

예: 상장 종목이 2,555개일 때, 모멘텀이 극단적으로 튀는 값(+500%)이라도 그 종목이 모멘텀 1등이면 `percentileFraction = 1.0`으로 취급된다. 원래 숫자가 500이든 50이든 상관없이 "1등이다"라는 사실만 점수에 반영되므로, 스케일이 다른 지표들을 공평하게 합산할 수 있다.

## 참고 — 구현 스타일 차이 (기능 문제 아님)

[ascRank()](../../../valuepick/src/main/java/com/example/demo/domain/service/Top100Service.java#L162)는 `Comparator.comparingDouble`로 정렬하고, [descRank()](../../../valuepick/src/main/java/com/example/demo/domain/service/Top100Service.java#L178)는 `Double.compare(values[b], values[a])`로 순서를 뒤집어 정렬한다. 구현 방식이 통일되어 있진 않지만 둘 다 올바른 순위를 만들어내며 동작에는 문제없다.

## 결론

7가지 지표를 원값(있는 그대로의 값) 그대로 가중합산하지 않고, 각각을 백분위 순위(0~1)로 정규화한 뒤 가중치를 곱해 합산했다. 단위와 스케일이 제각각인 지표들을 "전체 종목 중 몇 등이냐"라는 공통 기준 위에서 공평하게 비교·합산하기 위한 설계다.
