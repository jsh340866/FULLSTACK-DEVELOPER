# valuepick-batch 01~03단계 구현 및 검증 (2026-07-29)

## 2. `01_ingest_raw.py` 확장

- `--dart-limit` 옵션 추가: 공공데이터(KRX/주가)는 기준일 1회 호출로 전 종목을 받아 종목 수 제한이 무의미하지만, DART(재무제표/배당)는 종목별 개별 호출이라 DART 일일 10,000콜 제한을 지키기 위해 이 옵션으로 종목 수를 별도 제한
- 모멘텀/F-Score(신주발행 여부) 계산에 필요한 1개월전·12개월전 주가 스냅샷을 추가 수집 (`snapshot_type`: current/1m_ago/12m_ago 컬럼으로 구분). `months_ago()`로 실제 월 단위 날짜 계산, `fetch_stock_prices_on_or_before()`로 목표일 이하 가장 가까운 거래일 탐색
- Python 3.8(Spark 이미지 기본) 호환을 위해 `from __future__ import annotations` 추가 (PEP604 `dict | None` 문법 대응)

## 3. `02_clean_prices.py` 신규 작성

- 결측 거래일 보간: 종목×거래일 전체 격자를 만들고 원본에 없는 날짜를 직전 종가로 forward-fill, `is_interpolated` 플래그
- 액면분할/병합 의심 탐지: 전일 대비 등락률이 -40%/+67% 임계치를 벗어나면 `split_suspected`로 표시만 하고 자동 보정하지 않음 (원천 데이터에 분할 이벤트 필드가 없어 확정 판정 불가)
- 관측 기간 내내 시세가 한 번도 없던 종목(직전 유효값 자체가 없어 보간 불가)은 제거
- `snapshot_type="current"`만 정제 대상으로 분리, 1m_ago/12m_ago 스냅샷은 원본 그대로 통과 후 재합류 (스냅샷 날짜가 캘린더에 섞이면 그 사이 날짜가 전부 결측으로 오인되는 문제 방지)

## 4. `03_build_indicators.py` 신규 작성

- DART 재무제표 응답의 당기(thstrm)/전기(frmtrm)/전전기(bfefrmtrm) 3개 컬럼을 `stack(3,...)`으로 언피벗해 3개년 시계열 확보 (추가 API 호출 없이 재무제표 한 건으로 F-Score/EPS성장률 계산에 필요한 전년도 비교 가능)
- `DartFinancialCollector.pick()`과 동일하게 account_id 우선/account_nm 차선 매칭으로 재무 항목 컬럼화, CFS(연결) 우선 OFS(별도) 폴백
- 한국수출입은행 API로 환율 조회 → CNY 등 외화표시 재무제표 KRW 환산 (`CURRENCY_UNIT_MAP`, 100단위 통화 JPY/IDR 보정)
- EPS/BPS/PER/PBR/ROE/부채비율/배당수익률/ROA/모멘텀/F-Score/EPS성장률 전체 계산
- 한계(문서화): 업종코드 미수집으로 금융업 F-Score 스킵 판정 불가, 모멘텀 기준일이 여러 리밸런싱 시점이 아닌 단일 시점

## 5. verify_indicators 검증 (핵심 성과)

### 검증 방법
기존 ValuePick MySQL이 로컬에 없어, `docker-compose-local.yml`로 ValuePick(`db`, `bn`)을 로컬 기동한 뒤 01번이 받은 Parquet 원본을 그대로 MySQL 스키마에 역주입(`_seed_valuepick_db.py`)하고, `/admin/indicator/calculate/{year}/{reprtCode}` API로 Java가 실제 계산한 값을 우리 03번 결과와 대조.

- 로컬 검증 중 스케줄러의 대량 API 자동 호출(DART/공공데이터 콜 소모, 같은 키를 프로덕션과 공유) 위험을 막기 위해 `DemoApplication.java`의 `@EnableScheduling`을 검증 동안만 주석 처리 → **검증 완료 후 원상복구함**
- 회원가입 후 DB에서 직접 `role='ADMIN'`으로 승격, JWT 로그인 토큰으로 지표 계산 API 호출
- Spark 컨테이너를 ValuePick의 별도 docker network(`valuepick-local_custom-network`)에 연결해 `db` 서비스명으로 JDBC 접속 (검증 종료 후 연결 해제 및 네트워크 삭제)

### 발견 및 수정한 버그
`pivot_financials`가 `account_id`만으로 매칭할 때, DART 응답에서 `ifrs-full_Equity`(자본총계)가 재무상태표(BS)뿐 아니라 자본변동표(SCE)에도 지분 항목별로 수백 건 중복 등장하는 것을 발견. Java는 API 응답 순서 그대로 "처음 만난 값"을 채택(HashMap)해 정상적으로 BS 값을 잡지만, Spark는 분산 처리 특성상 `F.first()`의 순서가 보장되지 않아 SCE의 엉뚱한 하위 항목을 자본총계로 잘못 채택하는 사례 발생(종목 000020: bps 14573.4가 나와야 하는데 자본변동표 오염으로 다른 값 산출 위험).

**해결**: `sj_div`(BS/CIS/IS/CF)를 계정별 허용 범위로 명시 필터링. Java에는 없는 필드(`DartItem.java`에 `sj_div` 자체가 없음)를 활용해 순서 의존성을 원천 제거 — Java보다 오히려 더 안정적인 방식으로 개선.

### 검증 결과
- 대조 대상 79종목 중 **78종목 EPS/BPS/PER/PBR/ROE/부채비율/배당수익률/ROA 8개 지표 완전 일치**
- 1종목만 PER 계산에서 반올림 순서 차이로 0.08 오차 (무시 가능한 수준)
- momentum/F-Score/EPS성장률은 Java 쪽이 NULL로 나왔는데, 이는 계산 로직 문제가 아니라 검증용으로 역주입한 시세가 연속 시계열이 아닌 스냅샷 방식이라 Java의 "기준일 이하 최근값" 탐색이 하루 경계에서 어긋난 것 (검증 환경 한계, 03번 결함 아님)

- Jupyter 노트북 커널을 탭만 닫고 종료하지 않으면 클러스터 코어를 계속 점유해 다른 작업이 대기 상태에 빠짐 → 작업 끝나면 반드시 `spark.stop()` 호출 또는 Kernel Shut Down

- Windows Git Bash에서 `docker exec`에 절대경로 인자를 쓸 때는 `MSYS_NO_PATHCONV=1`을 앞에 붙여야 경로 자동변환 오류를 피할 수 있음
